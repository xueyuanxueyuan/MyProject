## 不能只看“SQL不报错”的问题

### 1. 期间、余额和空值

- 116—120、132的_qfq查询原来按月份分组筛季度，且部分SUBSTRING(tjzq,5,1)与1—9比较。若TJZQ为YYYYMM，202501取到0；若是YYYYQ，则一个季度又被套成三个月。必须先取得真实TJZQ样本，再决定按季度编码还是按月份范围筛选。本次只消除布尔CASE，不猜该格式。
- 122—124、147对季度内多期余额SUM。如果每期都是余额快照，不能当发生额跨期累加。需要确认表粒度和季末记录，不能仅凭表名推断。
- 115、142假设TJZQ可转成YYYYMM整数；空串、非数字和其它期间编码均未实库验证。115回收金额仍保留原多字段相加逻辑，某分量NULL可能丢失该行贡献；是否每分量补0需结合数据质量确认。
- 127—130、148—150的BFRQ按DATE/TIMESTAMP日期快照比较，月末必须零时。如果是文本或含时分秒，应依实际类型改为规范转换或当日范围；不能依赖隐式转换。
- 129、149等账户连接需确认同账户同快照日期唯一，否则重复行会放大金额；缺失快照与真实0余额必须区分。

### 2. 单位、同比与财务口径

- 115、148输出亿元；142保留原金额单位；126金额为亿元，zzsyjsje为万元，增长率为百分数。其余候选不统一改单位，必须和Word模板表头逐一核对。
- 117明细金额除10000，原合计金额未除10000，候选保留并标为待处理，不能直接出正式报告。118、119原同比未防分母0，120占比同样存在分母0风险；应确认无基期数据时显示空值或其他业务标识，不应擅自把未知增长率置0。
- 125与126支出构成不同，且125某项列名与文字标签不一致。不能用“SQL执行成功”证明会计口径正确。
- 126本次修正为所选单季度对上年同季度，修复了原同年自连接和重复累计，并采用(本期-上期)/上期*100。上期0仍沿用原零值约定；正式报告要确认此约定。114若采用年初累计，不能直接拿两项互相对账。
- 130、150的jnczj保留原计算，原年初余额份额以本期总余额作分母。若指标含义为占比较年初变化，应确认是否改成各自时点的总余额分母。
