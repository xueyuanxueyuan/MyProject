# 一户通挡板达梦建库与迁移

## 适用范围

现有 DM8 实例内新建 YHT_MOCK 用户、同名 Schema 和独立 YHT_MOCK_DATA 表空间。不执行 dminit，不接触结算业务表。脚本无 DROP、无真实密码，未在真实达梦实例执行；上线前必须在隔离测试库演练。

## 新建空库执行顺序

1. 停止全部旧挡板实例，保留 data/mock-state.json 和 .bak；复制时确保文件不再变化。保留旧镜像和原 JSON，用于切换前回退。
2. DBA 使用 DIsql 交互登录（不要把密码写在命令行），在已确认的实例执行 00-create-user.disql.sql。按提示输入数据库服务器上的绝对数据文件路径和新密码。路径不能与已有数据文件相同；确保目录存在且达梦进程可写。输入通过 DIsql 文本替换，路径不能含单引号、密码不能含双引号，均不能含换行或 &；如环境密码策略需要这些字符，应由 DBA 使用受控管理工具建用户，不通过此交互脚本输入。关闭 SQL 回显，密码不写入仓库。
3. 改用 YHT_MOCK 用户连接，确认当前 Schema 为 YHT_MOCK 后执行 01-schema.sql。建议先设置 WHENEVER SQLERROR EXIT FAILURE ROLLBACK。本脚本仅用于空 Schema，遇到同名对象立即停止，禁止直接删除重建。DDL 可能已生效，失败后由 DBA 核对已创建对象，不依赖 ROLLBACK 撤销全部 DDL。
4. 建表后 DBA 可执行 REVOKE CREATE TABLE FROM YHT_MOCK，应用只使用自有表读写，不需要 DBA、RESOURCE、ANY TABLE 权限。已有用户/表空间不得直接套用 00 脚本。
5. 配置环境变量后，先执行一次性历史迁移，再启动普通服务。不要先打开新 UI，否则会写入默认配置，迁移会因非空库而拒绝。
6. 执行 02-verify.sql，核对迁移输出各类记录数、指纹、旧时间、配置和 UNKNOWN 去重状态。通过后再部署普通服务并验证页面。

## 已有数据库从版本 1 升级到版本 2

本次版本 2 新增银行对手账户表及批次中心银行列。该步骤升级到2后，必须继续执行版本3、版本4、版本5升级，当前应用要求 SCHEMA_VERSION=5；不会自动建表或升级。

1. 停止全部挡板实例并暂停测试流量，备份现有挡板 Schema；不要重跑 00/01，不导入旧 JSON 覆盖现有库。
2. 由 DBA 使用挡板 Schema 核对控制表版本为 1，确认 YHT_MOCK_BANK_ACCOUNT 和 YHT_MOCK_BATCH.C_CENTER_BANK_ID 尚不存在。此前若撤销 CREATE TABLE 权限，需要由 DBA 临时授权并在升级后收回。
3. 在隔离库先演练 03-upgrade-v1-to-v2.sql，然后在批准的挡板库执行。脚本检查版本，创建银行配置表、添加中心银行列，最后将控制版本改为 2。DIsql 指令及匿名块尚未在真实 DM8 验证。
4. DDL 可能部分生效，ROLLBACK 不作为全部恢复保证。执行失败立即停止，由 DBA 根据备份和现有对象修复，不盲目重跑、删除对象或手工只改版本号。
5. 查询控制表确认版本为 2、原数据计数未减少；完成版本3升级后再执行新版 02-verify.sql。新表应为空，历史批次 centerBankId 为 NULL，程序不会猜测其所属银行。
6. 继续升级到版本3后再启动新版本，页面逐银行录入对手账户并按中心银行精确匹配；没有配置的银行不发送动账通知。已有显式动账接口地址不覆盖，原统一虚拟账户仅保留作兼容数据，不自动迁移为任意银行映射。
7. 回退必须停流并核对升级后的新交易及已发送通知，由 DBA 使用经过验证的备份方案恢复与旧程序相匹配的版本；禁止单独把 SCHEMA_VERSION 改回 1。

新建库的 01-schema.sql 已直接创建版本 5，不应再运行 03/04/05/06。H2 回归只验证增量脚本中的建表、加列和版本更新部分，不覆盖 DIsql 前置检查。

## 已有数据库从版本 2 升级到版本 3

1. 停止全部挡板实例及测试流量，备份挡板 Schema，确认 SCHEMA_VERSION=2。版本1必须先执行03。不要重跑00/01或删除现有去重记录。
2. 确认 YHT_MOCK_FLOW 与 YHT_MOCK_FLOW_ATTEMPT 尚不存在，在隔离达梦环境演练04-upgrade-v2-to-v3.sql后再审批执行。必要的建表权限由 DBA 临时授予并收回。
3. 04创建资金流水、独立操作记录及查询索引，最后将版本更新为3；保留银行配置和原交易数据，不自动发送或重放。发生 DDL 错误立即停止核对，不假定 ROLLBACK 能撤销全部对象。
4. 执行02核对版本、原表计数与新表。启动新代码后在资金流水标签点击同步已有成功交易；缺少原始请求的旧交易无法可靠恢复企业标识，会报告跳过。旧发送记录缺少通知快照时仍受保护，不能重推。
5. 资金流水与操作记录、发送者标识及版本校验保留于数据库；普通历史清理不删除。所有节点必须使用同版程序和同一数据库。回退必须停流、核对新推送并用受控备份方案恢复，不能只改版本号。

当前未在真实 DM8 执行04的DIsql指令及匿名块；不将H2回归当作真实达梦验收。

## 已有数据库从版本 3 升级到版本 4

本次版本 4 为动账通知配置增加「对手账户兜底开关」列 C_FALLBACK_ENABLED。开关开启后，所有动账通知统一使用动账配置中的默认兜底账户，不再按中心账户所属银行查询 YHT_MOCK_BANK_ACCOUNT，因此未配置对手账户的银行也能生成通知。

1. 停止全部挡板实例及测试流量，备份挡板 Schema，确认 SCHEMA_VERSION=3。版本2必须先执行04，版本1必须先执行03再执行04。不要重跑00/01，不删除现有去重记录与资金流水。
2. 确认 YHT_MOCK_MOVEMENT_CFG 尚无 C_FALLBACK_ENABLED 列，在隔离达梦环境演练 05-upgrade-v3-to-v4.sql 后再审批执行。此前若撤销 CREATE TABLE 权限，需由 DBA 临时授权并在升级后收回。
3. 05脚本先校验版本为3，随后加列（默认0，即兜底关闭，行为与升级前一致），最后把控制版本更新为4；不修改原有配置值、不动资金流水与发送记录。
4. 执行02核对版本为4、各表计数未减少；启动新程序后页面动账配置区可见「对手账户兜底」下拉，升级后默认关闭。
5. 加列属 DDL，失败即停止并核对已生效对象，不重跑、不手工只改版本号。回退需停流并用受控备份恢复，同时换回与旧版本匹配的程序。
6. 脚本首行 WHENEVER SQLERROR 为 SQL*Plus 语法，达梦图形化工具会直接报语法错误；使用 DIsql 时按工具能力等价设置，图形化客户端执行需删除该行。匿名块与 ALTER 加列语句尚未在真实 DM8 验证，H2 回归只验证改写后的 DDL 与版本更新部分。

## 已有数据库从版本 4 升级到版本 5

本次版本 5 为接口记录增加「解密后报文」两列：C_DECRYPTED_REQUEST_BODY 与 C_DECRYPTED_RESPONSE_BODY。加密报文仍存于 C_REQUEST_BODY / C_RESPONSE_BODY 原列，新增列仅在请求走 CAPS 信封加密时写入明文，供链路追踪对比「加密报文 vs 解密后报文」。

1. 停止全部挡板实例及测试流量，备份挡板 Schema，确认 SCHEMA_VERSION=4。版本1/2/3 必须按 03 → 04 → 05 顺序补齐后，再执行 06。不要重跑 00/01，不删除现有去重记录与资金流水。
2. 确认 YHT_MOCK_RECORD 尚无两列解密字段，在隔离达梦环境演练 06-upgrade-v4-to-v5.sql 后再审批执行。此前若撤销 CREATE TABLE 权限，需由 DBA 临时授权并在升级后收回。
3. 06 脚本先校验版本为4，随后为接口记录加两个 CLOB 列（历史记录该两列为空，表示该笔报文未加密或产生于升级前），最后把控制版本更新为5。
4. 执行 02 核对版本为 5、各表计数未减少；启动新程序后「链路追踪」页可分别查看原始报文与解密后报文。
5. 加列为 DDL，失败即停止并核对已生效对象，不重跑、不手工只改版本号。回退需停流并用受控备份恢复，同时换回与旧版本匹配的程序。
6. 脚本首行 WHENEVER SQLERROR 为 SQL*Plus 语法，达梦图形化工具会直接报语法错误；使用 DIsql 时按工具能力等价设置，图形化客户端执行需删除该行。匿名块与 ALTER 加列语句尚未在真实 DM8 验证，H2 回归只验证改写后的 DDL 与版本更新部分。

## 数据源环境变量

- YHT_MOCK_DB_URL：完整 JDBC 地址，例如 jdbc:dm://数据库主机:5236?schema=YHT_MOCK；实际地址由运维提供。
- YHT_MOCK_DB_USERNAME：YHT_MOCK。
- YHT_MOCK_DB_PASSWORD：通过 K8s Secret 注入，不写入 ConfigMap 或 Git。

服务未配置数据库、未建表或连接失败时不允许回退文件存储。应用不自动执行 SQL。数据库索引键按 VARCHAR(256) 保存，长报文、结果文件及说明字段为 CLOB，原金额字符串不转浮点数。

## 显式迁移命令

在正常构建得到的新包上执行（挂载原 JSON 只读）：

~~~shell
java -jar yht-mock-server-1.0.0-SNAPSHOT.jar --yht-mock.migrate-file=/data/migration/mock-state.json
~~~

该命令选择专用非 Web 配置，不启动 HTTP、SVS、回调或动账工作线程，执行后退出。参数必须是一个非空文件路径。可显式指定经过人工确认的 .bak；不会自动选择或覆盖备份。

- 单事务导入配置、场景、日志、协议、交易、批次和动账幂等；保留 ID、时间与业务状态。
- 源文件只读，不删除、不改名；按源字节 SHA-256 记录指纹。相同文件重复执行返回 alreadyImported=true，不重放数据；不同文件拒绝覆盖。
- 目标必须未使用：各数据表为空、编号未分配、无其他迁移指纹。初始化默认配置也算已使用。
- 原快照未知字段、重复字段、重复 ID、键值不一致、JSON 损坏、字段超长或 SQL 失败均报错；数据库写入失败整体回滚。
- 不把 PROC 自动改成 SUCC，不重试历史回调或 UNKNOWN 动账；迁移不解决旧批次状态推进问题。
- 迁移成功后普通启动保留页面配置；若启用 YHT_MOCK_CALLBACK_OVERRIDE_STORED_SETTINGS=true，则仍按原约定覆盖回调配置，迁移期间不要启用。

## 表清单

| 表 | 用途 |
|---|---|
| YHT_MOCK_CONTROL | Schema 版本、跨实例写锁、编号、迁移指纹/计数 |
| YHT_MOCK_SETTINGS | 回调、加密模拟及默认业务结果配置 |
| YHT_MOCK_MOVEMENT_CFG | 动账通知配置：开关、兜底开关、通知地址与兜底对手账户、鉴权环境变量名 |
| YHT_MOCK_BANK_ACCOUNT | 中心银行标识对应的对手账号、户名、行号及启用状态 |
| YHT_MOCK_RECORD | 网关、回调、加密与动账调用记录（含加密报文与解密后报文） |
| YHT_MOCK_PROTOCOL | 协议状态 |
| YHT_MOCK_TRADE | 单笔交易状态 |
| YHT_MOCK_BATCH | 批次状态、结果文件内容、原请求中心银行标识 |
| YHT_MOCK_SCENARIO | 场景匹配条件和结果规则 |
| YHT_MOCK_MOVEMENT | 动账占位和最终状态，唯一键防重复 |
| YHT_MOCK_FLOW | 成功交易模拟资金流水、固定通知快照及版本状态 |
| YHT_MOCK_FLOW_ATTEMPT | 生成/推送/恢复审计，含发送者标识及尝试版本 |

## 清理、保留与回退

“清除历史数据”仅清空记录、协议、交易、批次四张表；保留配置（含银行对手账户）、资金流水、操作记录、规则、动账幂等、编号和迁移凭据。旧 JSON 不参与运行，删除与否由管理员自行安排。普通接口日志不再有旧版 5000 条自动截断限制，需监控表空间；本脚本默认最大 4 GB，DBA 按测试数据量调整。接口 listRecords 默认返回 100 条，UI 查询 500 条；业务状态列表行为维持原样。

数据库写操作通过控制行串行化，适合测试挡板，不宣称高吞吐。所有节点必须使用相同数据库，禁止多个文件存储旧实例同时对外服务。跨节点读后改写的业务竞争仍需业务流水层面控制，本次仅保证单个存储操作事务与动账唯一占位。

切换后产生新交易时，不能直接用旧 JSON 回滚，必须先停流并核对新库状态、回调及动账结果。不要删除去重表或迁移指纹来强行重放。DDL 和数据均需数据库备份保障，不提供一键 DROP 回滚脚本。

## 验证

项目根目录：mvn test；前端：node --test src/test/js/static-page.test.cjs src/test/js/movement-page.test.cjs。默认数据库测试使用 H2 Oracle 模式，不等同于真实 DM8。

真实达梦验收使用单独用户 YHT_MOCK_TEST，先执行同一建表脚本，保持库为空。设置 YHT_MOCK_DM_ACCEPTANCE=true、YHT_MOCK_DM_TEST_URL、YHT_MOCK_DM_TEST_USERNAME=YHT_MOCK_TEST、YHT_MOCK_DM_TEST_PASSWORD 后执行 mvn -Dtest=DamengAcceptanceTest test。该测试不建用户、不建表；仅在事务内验证写入并回滚，禁止指向真实业务库。
