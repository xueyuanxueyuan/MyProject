# 系统优化设计方案

> 目标：在**尽量不改变外部 Feign 接口入口**的前提下，解决代码膨胀、耦合过高、多地区多渠道兼容的问题。
> 设计原则：接口兼容 → 渐进重构 → 领域驱动 → 策略化
> 日期：2026-05-18

---

## 二、第一阶段：低风险快速优化（不改接口）

### 2.1 gm-agg 聚合层改造方案

**问题**：gm-agg 的 `YwglServiceImpl`/`CwhsServiceImpl`/`ZhglServiceImpl` 90%+ 是纯代代码

**方案 A（推荐）**：注解驱动 + 统一代理

```java
// 现状（~8,000 行手写代码）：
@Service
public class YwglServiceImpl {
    @Resource private YwglFeignClient ywglFeignClient;
    
    public R<Page<...>> queryYwlxSfgx(ReqDTO dto) {
        return ywglFeignClient.queryYwlxSfgx(dto); // 纯透传
    }
    // ... 50+ 个类似方法
}

// 改造后（统一 FeignDelegate 注解）：
@Service
public class YwglServiceImpl {
    
    // ✅ 有真实业务逻辑的方法保留
    public R<...> processWithRegionLogic(...) {
        // 地区策略分派
        RegionStrategy strategy = strategyFactory.getStrategy();
        return strategy.processBusinessAccounting(...);
    }
    
    // ✅ 纯透传方法 → 用 @FeignDelegate 标注，自动路由
    // 或者干脆使用网关层统一处理，不经过 gm-agg 的 Service 层
}
```

**推荐实现**：在 gm-agg 模块**仅保留有真实业务逻辑的 Controller**，纯透传的 Controller 改为通过 **Spring Cloud Gateway** 或 **自定义注解 `@AggProxy`** 自动生成路由规则。

```
改造前: 前端 → gm-agg Controller → gm-agg Service → Feign → 业务模块
改造后: 前端 → GM API 网关路由规则 → 直接到业务模块 Feign
         （需保留的聚合逻辑放在 gm-agg 单独的领域 Service 中）
```

### 2.2 V1/V2 双版本统一方案

**方案**：保留 V1/V2 URL 路径不变，在路由层做版本兼容

```java
// 方式A：统一 Controller（推荐）
@RestController
@RequestMapping("/api/{version}/ywgl")
public class YwglUnifiedController {
    
    @PostMapping("/addFkywDbfk")
    public R<...> addFkywDbfk(
        @PathVariable String version,
        @RequestBody @Validated BaseReqDTO reqDTO
    ) {
        // V1 和 V2 参数可能不同，通过 DTO 适配器统一
        UnifiedReqDTO unified = dtoAdapter.adapt(version, reqDTO);
        return ywglDomainService.addFkywDbfk(unified);
    }
    
    // ... 共用方法体，version 仅影响参数适配
}

// 方式B：保留现有 Controller 签名不变，
// 抽象出公共 Service 方法（推荐用于过渡期）
public class YwglController {  // V1 保留
    @Resource private YwglDomainService ywglDomainService;
    @PostMapping("/addFkywDbfk")
    public R<...> addFkywDbfk(V1ReqDTO dto) {
        return ywglDomainService.addFkywDbfk(adapter.toUnified(dto));
    }
}
public class YwglV2Controller { // V2 保留
    @Resource private YwglDomainService ywglDomainService;
    @PostMapping("/addFkywDbfk")
    public R<...> addFkywDbfk(V2ReqDTO dto) {
        return ywglDomainService.addFkywDbfk(adapter.toUnified(dto));
    }
}
```

**对外影响**：✅ 零影响。V1/V2 的 URL 路径、入参格式、返回格式完全不变。

### 2.3 Fallback 统一降级方案

```java
// 现状：每个 FeignClient 都要写：
@FeignClient(name = "...", fallbackFactory = CwhsFallbackFactory.class)

// CwhsFallbackFactory.java (2,939行) + CwhsFeignClientFallback.java (2,932行)
// → 6,000 行全是 return R.fail("服务不可用")

// 改造：自定义 Sentinel Feign 适配器
@FeignClient(name = "...", fallbackFactory = SentinelFallbackFactory.class)
// ↑ 不再需要手写每个 Client 的 Fallback

// SentinelFallbackFactory（一次性代码，~50行）：
public class SentinelFallbackFactory implements FallbackFactory<Object> {
    @Override
    public Object create(Throwable cause) {
        // 对任意 FeignClient 的方法，返回统一的降级响应
        return (Object) (proxy, method, args) -> 
            R.fail("服务[" + method.getDeclaringClass().getSimpleName() 
                 + "." + method.getName() + "]不可用：" + cause.getMessage());
    }
}
```

**效果**：消除 **~15,000 行** Fallback 模板代码，对外接口完全不变。

## 三、第二阶段：上帝类拆分（核心重构）

### 3.1 YwglServiceImpl（13,218行）拆分方案

按业务领域拆分为 6 个领域 Service：

| 领域 Service | 职责 | 提取自原文件的行号范围 | 预估行数 |
|-------------|------|---------------------|---------|
| `FkywDomainService` | 付款业务：单笔付款、批量付款、对账、冲正 | 原 `addFkyw*`, `execFkyw*`, `selectFkyw*` 系列方法 | ~2,500 |
| `SkywDomainService` | 收款业务：单笔收款、批量收款 | 原 `addSkyw*`, `execSkyw*`, `selectSkyw*` 系列方法 | ~2,000 |
| `TransferDomainService` | 转账业务：转入、转出、联动 | 原 `zrsq*`, `zrbj*`, `zcf*` 系列方法 | ~1,500 |
| `AccountDomainService` | 账户管理：银行账户、往来户、科目 | 原 `getWlkh*`, `getYhzh*`, `getKmxx*` 系列方法 | ~2,000 |
| `ReconDomainService` | 对账：银企对账、住建部对账、差异处理 | 原 `dzhd*`, `mnSk*`, `mnFk*` 系列方法 | ~1,500 |
| `SettlementDomainService` | 结算核心：POS、钱包、日终 | 原 `wallet*`, `corpWallet*`, `receiveDailyProcess*` 系列方法 | ~1,000 |

**对外兼容策略**：
```java
// 旧 YwglServiceImpl 保留但变薄，仅做方法委托
@Service("ywglService")  // 保持 @Resource name 不变！
public class YwglServiceImpl implements YwglService {
    
    @Resource private FkywDomainService fkywDomainService;
    @Resource private SkywDomainService skywDomainService;
    @Resource private TransferDomainService transferDomainService;
    @Resource private AccountDomainService accountDomainService;
    @Resource private ReconDomainService reconDomainService;
    @Resource private SettlementDomainService settlementDomainService;
    
    // 原方法签名完全不变
    @Override
    public R<...> addFkywDbfk(ReqDTO dto) {
        return fkywDomainService.addFkywDbfk(dto);  // 委托
    }
    
    @Override
    public R<...> addSkywDbsk(ReqDTO dto) {
        return skywDomainService.addSkywDbsk(dto);  // 委托
    }
    // ... 所有方法保持不变但变薄
}
```

> **所有调用方（Controller、其它Service、XxlJob）的 @Resource YwglService 引用完全不变**。

### 3.3 解除循环依赖方案

**现状**：`ywgl-busi → cwhs-api → zhgl-api` 双向依赖

**方案**：引入**防腐层（Anti-Corruption Layer）**/内部 SPI

```java
// 方式A：将跨模块调用的接口抽到 API 层（推荐）
// ywgl 如果必须调用 cwhs 的逻辑：
// ① 在 ywgl-api 中定义 YwglCwhsFacade 接口
// ② cwhs-busi 实现该接口
// ③ ywgl-busi 仅依赖 ywgl-api（不再直接依赖 cwhs-busi）

// ywgl-api/src/main/java/.../facade/
public interface YwglCwhsFacade {
    R<...> syncPzToCwhs(PzSyncReqDTO dto);
}

// cwhs-busi/src/main/java/.../facade/impl/
@Service
public class YwglCwhsFacadeImpl implements YwglCwhsFacade {
    @Resource private PzDomainService pzDomainService;
    
    @Override
    public R<...> syncPzToCwhs(PzSyncReqDTO dto) {
        return pzDomainService.createPzFromYwgl(dto);
    }
}
```

**效果**：
- `ywgl-busi` 不再直接依赖 `cwhs-api`，改为依赖自己 `ywgl-api` 中的接口
- 依赖方向变为：`ywgl-busi → ywgl-api ← cwhs-busi`（依赖倒置）

## 四、第三阶段：多地区多渠道策略架构

### 4.1 地区策略架构升级

**现状**：一个 `RegionBusinessStrategy` 接口包含全部方法，粒度过粗

**升级方案**：按业务领域拆分为多个策略接口

```java
// 收付款策略（单独接口）
public interface PaymentRegionStrategy {
    R<...> processPayment(PaymentReqDTO req);
    R<...> processCollection(CollectionReqDTO req);
    boolean shouldNotifyTransferClaim(String zhaiyao, String beizhu);
    String getSupportedHsdwdm();
}

// 凭证策略（单独接口）
public interface VoucherRegionStrategy {
    R<...> generateVoucher(VoucherReqDTO req);
    String getAccountCode(String hsdwdm, String bizType);
    String getSupportedHsdwdm();
}

// 渠道配置策略
public interface ChannelConfigStrategy {
    String getChannelEndpoint(String channelCode);
    boolean isChannelAvailable(String channelCode);
    String getSupportedHsdwdm();
}
```

**策略注册**：统一工厂 + Spring 自动装配

```java
@Component
public class PaymentRegionStrategyFactory {
    @Resource
    private List<PaymentRegionStrategy> strategies;
    private final Map<String, PaymentRegionStrategy> strategyMap = new HashMap<>();
    
    @PostConstruct
    public void init() {
        for (PaymentRegionStrategy s : strategies) {
            strategyMap.put(s.getSupportedHsdwdm(), s);
        }
    }
    
    public PaymentRegionStrategy getStrategy(String hsdwdm) {
        return strategyMap.getOrDefault(hsdwdm, defaultStrategy);
    }
}
```

**已知地区的 HSDWDM 策略映射**：

| 地区 | HSDWDM | 当前策略 | 是否需要独立策略 |
|------|--------|---------|---------------|
| 北京（基线） | 110000000000000 | DefaultRegionStrategy | 基线 |
| 温州 | 330300000000000 | WzStrategy | ✅ 已实现 |
| 临沂 | 371300000000000 | DefaultRegionStrategy | ⚠️ 有差异化逻辑 |
| 枣庄 | 370400000000000 | DefaultRegionStrategy | ⚠️ 需评估 |

## 五、对外接口兼容性保证

### 5.1 接口兼容清单

| 接口类型 | 是否变更 | 说明 |
|---------|---------|------|
| FeignClient 接口名 | ❌ 不变 | `@FeignClient(name=...)` 不变 |
| URL 路径（/api/v1/*） | ❌ 不变 | V1/V2 路径保留 |
| 请求 DTO 字段 | ❌ 不变 | 不修改现有 DTO 字段 |
| 响应 DTO 字段 | ❌ 不变 | 不修改现有 DTO 字段 |
| `@Resource YwglService` | ❌ 不变 | bean name 保留 |
| 新增接口 | ✅ 新增 | 在保留旧接口的基础上新增更清晰的领域接口 |

### 5.2 重构不影响的外部调用方

## 六、技术选型补充建议

| 场景 | 推荐方案 | 替代方案 |
|------|---------|---------|
| 统一降级 | Sentinel + Feign 适配器 | Hystrix（已停维） |
