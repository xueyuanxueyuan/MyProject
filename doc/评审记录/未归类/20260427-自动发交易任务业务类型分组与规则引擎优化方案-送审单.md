# 自动发交易任务“业务类型分组 + 规则引擎驱动”优化方案送审单

## 1. 送审对象

- 方案文档：`doc/设计文档/20260427-自动发交易任务业务类型分组与规则引擎优化方案.md`
- 评审范围：
  - 现有自动发交易任务核心流程分析是否完整
  - 业务类型分组抽象是否可扩展
  - 规则引擎集成规范是否可实施
  - 并发、性能、监控、回退方案是否闭环
  - 测试与验收口径是否足以支撑实施

## 2. 送审背景

当前自动发交易任务已经具备稳定的发送出口，但“业务类型语义隐式、规则控制粒度过细、配置治理不足、监控不成体系”等问题，已成为后续持续扩展的主要障碍。为控制实施风险，本次先提交设计方案，待评分达到准入标准后再进入开发阶段。

## 3. 评审要求

- 评审组请在收到方案后 `3` 个工作日内完成评审。
- 请优先核对以下高风险项：
  - 是否破坏现有事务与幂等边界
  - 规则异常兜底是否会造成不可控错发
  - 业务类型分组是否过度依赖硬编码
  - 热加载与灰度回退机制是否真实可落地
  - 性能目标是否与现网容量匹配

## 6. 重点检查清单

请评审组逐项确认：

- 是否认可将 `Plyw`、`Dbyw`、`Plcx`、`Dbcx` 等定义为显式业务类型
- 是否认可“预检先于发送”的两阶段模型
- 是否认可规则超时/异常时默认可发送但必须告警的容错策略
- 是否认可预检结果 `30s` 缓存与按业务类型并行预检
- 是否认可批量发送阶段继续沿用 `20` 笔/批与原有事务、重试逻辑
- 是否认可 Apollo/Nacos 配置化治理与动态推送方案
- 是否认可新增 JSON 日志与 Grafana 大盘指标设计
- 是否认可一键切回“无规则”原始模式的回退策略
