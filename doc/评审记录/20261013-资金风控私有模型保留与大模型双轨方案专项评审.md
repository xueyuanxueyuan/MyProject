## 复评顺序与证据归属

1. **模型与业务**：锁定预测时点的数据可得性、多步预测定义、同口径新旧回测及事前阈值；通过遮蔽/泄漏负例。不得拿旧训练集分数决定新路由。
2. **API、Python、DBA 和报告**：补全全写者和调用方清单；签任务未知态/制品哈希、达梦互斥、报告槽位与文件回执完整契约；提交接口、并发、故障注入测试。
3. **安全、法务、业务和运维**：按环境授权数据/用途/目的地，分别审批真实数据出域、影子、灰度和生产变更；缺签署时只能停在获准的合成 PoC。
4. **复评检查点**：责任方按 ID 附源码差异、构建/测试退出码、回测报告、目标达梦/文件环境记录、签署件和回滚演练材料；AI 本次未执行训练、真实数据联调、投产操作，故所有相关证据状态为“未验证”。

建议将 M1、A1、A2、S1、S2 作为设计冻结前优先关闭的 P0；不要为满足进度而将 P0 改为“上线后观察”。本评审记录不改原设计与旧评审结论，问题闭环后由真实责任人正式评审签字。
