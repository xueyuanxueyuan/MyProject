# **1** ***\*引言\****

## 1.1 编写目的

为规范住建部结算应用系统（以下简称结算应用系统）与各公积金中心IT系统之间的交易接口和通讯，特制定本公共接口标准，作为相关方开发工作的前提和基础。

本文档预期读者为结算应用系统项目主管部门、项目实施部门有关人员、系统操作用户和公积金中心有关人员。

## 1.2 背景

为规范公积金管理中心与各支付结算银行间支付结算业务，提高各地公积金管理中心支付结算效率、统一中心资金支付结算通道，住房城乡建设部决定建设全国统一的住房公积金银行结算结算应用系统。

# **3** ***\*通信接口\****

## 3.1 基本通信协议

### 3.1.1 TCP接入方式

TCP接入采用短连接。报文格式为：header+ leng + data

Header共16字节，前6位字节为系统节点号，第7个字节为交易类型标识(0-业务类交易，1-签到交易)，8-14位为7位长交易码（不足7位后补‘\0’）,后2位字节保留备用(全部为‘\0’),leng是32bit的网路字节序的整数，标识整个报文的长度，data是报文数据。

目前，Header第15-16位字节已启用作为密钥类型标识，取值如下：01-结算交易、10-商贷查询交易。如果商贷查询业务复用结算密钥该密钥类型值为01；如果商贷查询业务复用组合贷款密钥该密钥类型值为05；如果商贷查询业务采用单独会话密钥该密钥类型值为10。

报文数据的格式统一采用后面报文接口规范章节中描述的格式。 

## 3.2 通讯安全

结算应用系统和外部网络系统之间的交互，采用openssl 安全加密。

### 3.2.1 Openssl简介

SSL是Secure Socket Layer（安全套接层协议）的缩写，可以在Internet上提供秘密性传输。SSL采用公开密钥技术。其目标是保证两个应用间通信的保密性和可靠性,可在服务器端和用户端同时实现支持。目前，利用公开密钥技术的SSL协议，已成为Internet上保密通讯的工业标准。

OpenSSL是套开放源代码的SSL套件，其函式库是以C语言所写成，实现了基本的传输层资料加密功能。

### 3.2.2 证书的产生

![img](file:///C:\Users\Sour\AppData\Local\Temp\ksohtml27816\wps2.png)  通过openssl，结算应用系统为每个外接系统产生一对非对称密钥，private key结算应用系统使用，public key 颁发给公积金中心、支付结算银行。

### 3.2.3 证书的更新

根据住建部、公积金中心、支付结算银行要求，间隔一定的时间，公积金中心、支付结算银行申请、住建部审批更换秘钥。公积金中心、支付结算银行应妥善保管证书密钥，制定使用规定，确保密钥安全。

### 3.2.4 同步会话密钥

会话秘钥由结算应用系统产生，公积金中心、支付结算银行调用签到交易获得会话秘钥，步骤如下所示：

1. 公积金中心、支付结算银行系统向结算应用系统发起签到交易 
2. 结算应用系统产生会话密钥明文，用对应公积金中心、支付结算银行系统的 private key 加密产生会话密钥密文
3. 结算应用系统将会话密钥密文返回给公积金中心、支付结算银行系统
4. 公积金中心、支付结算银行系统用public key解密获得得到会话密钥明文。
5. 公积金中心、支付结算银行应用3DES算法加密发送报文（除签到交易）。

注意：会话秘钥是所有交易的基础，公积金中心、支付结算银行在发起其它交易前必须签到成功并且获得会话秘钥，推荐每日进行签到交易更新会话密钥。

### 3.3.2 多记录的分页查询处理

第一页由发送请求的系统控制，上送BeginRec=1、MaxRec=n(n为每次显示的记录数)的报文，表示从第一条记录开始，查询n条记录；响应请求的系统返回BkRecNum=10、BkTotNum=49的结果，表示当前返回10条记录，共49条记录。可以控制向下翻页，向下翻页则上送BeginRec=11、MaxRec=10的报文，表示从第十一条记录开始，查询10条记录，如此类推，判断下翻到最后一页的情况是BeginRec+MaxRec>BkTotNum，判断上翻到第一页的情况是BeginRec=1。

如果只有一页或响应请求的系统不支持翻页，BkRecNum，BkTotNum银行按实际返回条数返回。

每次查询记录数不超过300条。

### 3.3.3 交易文件传输

**n** ***\*总体规范\****

1) 交易文件经过编码处理后，嵌入到交易报文中，和交易报文一起发送或接收；
2) 文件使用换行符’\n’划分记录，按分割符划分字段，数据项中不能有半个汉字、分割符、 换行符’\n’；
3) 文件命名必须本机构内唯一，建议以机构节点号作为前缀；
4) 交易接收方解析文件按照约定格式进行解析，**但也需要支持字段可拓展**。

 

**n** ***\*文件内容压缩、编码\****

1) 发送方传输文本信息(纯字符串信息)时，将文件内容读出进行BCD编码，得到文件内容报文域；接收方接收时,先将文件内容报文域取出BCD码字符串,解码后得到原始文件内容。
2) 发送方传输影像信息(如PDF/JPG)时，将文件内容进行ZIP压缩后再进行Base64编码，得到文件内容报文域；接收方接收时,先将文件内容报文域取出Base64编码字符串,解码后再进行ZIP解压缩，得到原始文件内容。

2. 超过5000笔，部分银行处理结果下载可能会超时。

#### 4.2.2.8 职工偿还商业个人住房贷款约定提取签约信息查询(BDC157) 

##### **4.2.2.8.1** ***\*功能说明\****

缴存中心未成功接收到BDC166接口所推送的约定提取签约信息时，可使用该接口重新获取。

缴存公积金中心以时间段等维度查询在公共服务平台登记的由职工通过住建部小程序自行发起的职工偿还商业个人住房贷款约定提取签约申请,每次最多返回本中心最近时间的300笔约定提取签约申请。
