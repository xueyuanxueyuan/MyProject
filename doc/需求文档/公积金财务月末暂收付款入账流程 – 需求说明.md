***\*公积金财务月末暂收/付款入账流程 – 需求说明\****

***\*一、需求概述\****

**·** ***\*需求名称\****：公积金暂收/付款月末入账及对冲管理

**·** ***\*业务目标\****：

o 确保暂收/付款业务***\*按发生月份挂账\****，不跨期

**o** ***\*锁定\*******\*跨月资金未挂账情况下\****的业务匹配/认领权限

**o** ***\*月初自动对上月未挂账资金补偿挂账\****

o 支持***\*正负资金流水手工对冲\****，简化资金清理



------



***\*二、核心控制基础\****

***\*2.1 财务账套月结年月\****

账套的基本属性：

**·** ***\*当前财务月结月份\****（格式：YYYY-MM）

· 该月份之前（含）的业务视为“已结账”，该月份之后的业务视为“未结账”

***\*2.2 暂收/付款记录关键字段\****

| 字段             | 说明                          |
| ---------------- | ----------------------------- |
| 业务日期         | 资金实际发生日期              |
| 入账状态（rzzt） | 0=未入账，1=已入账            |
| 匹配领用状态     | 暂收/付款是否已匹配到具体业务 |

 

***\*三、月末自动补充挂账（需求2.1）\****

***\*3.1 执行时间\****

每月1日 ***\*凌晨 2:00\****（或按用户要求的7点，建议2点避开业务高峰）

***\*3.2 功能描述\****

自动扫描***\*上一个月\****（业务日期 between 上月1日 and 上月最后一天）的所有银行流水/资金记录，若发现仍未挂账（dzzt='0'），则***\*自动生成暂收或暂付\*******\*并执行\*******\*挂账\****，入账日期记为该业务发生日（不跨月）。

***\*3.3 处理规则\****

| 资金来源   | 挂账科目                                                     |
| ---------- | ------------------------------------------------------------ |
| 收款类流水 | 暂收款（其他应付款-其他应付款）21904，按机构辅助核算，默认会计科 |
| 付款类流水 | 暂付款（其他应收款）119按银行大类辅助核算                    |

***\*四、\*******\*日\*******\*结后权限控制（需求2.2、2.3、2.4）\****

***\*4.1 控制判断逻辑\****

sql

**-- 判断是否允许操作（匹配/认领/查询）**

允许条件 = 资金交易日期 和 业务日期同月 OR rzzt = '1'

不允许条件 = 资金交易日期 和 业务日期不同月 AND rzzt = '0'

***\*4.2 功能限制明细\****

| 功能模块              | 限制规则                       | 说明                               |
| --------------------- | ------------------------------ | ---------------------------------- |
| 暂收款 → 收款业务匹配 | ❌ 不允许匹配上述“不允许”的数据 | 已结账月份的未入账数据不允许匹配   |
| 暂付款 → 付款退款匹配 | ❌ 同上                         |                                    |
| 暂收款 → 相关查询     | 直接过滤，查询不到             | 查询接口自动增加过滤条件           |
| 暂付款 → 相关查询     | 直接过滤，查询不到             |                                    |
| 暂付款 → 认领功能     | ❌ 不允许认领                   | 提示“该业务跨月且未挂账，无法认领” |

***\*4.3 错误提示文案\****

“该笔暂收/付款交易日期为 [YYYYMMDD]，已超过当前业务日期 [yyyy-mm-dd]，且未挂账，不允许进行[匹配/认领/查询]操作。请先完成入账或联系财务。”

***\*五、正负资金流水对冲功能（需求3）\****

***\*5.1 业务场景\****

支持三中对冲场景：

| 场景             | 收款（正数） | 付款/退款（负数） | 操作前提                                                     |
| ---------------- | ------------ | ----------------- | ------------------------------------------------------------ |
| 3.1 双方都未挂账 | ✅ 未入账     | ✅ 未入账          | 手工勾选两条日记账流水，生成对冲凭证                         |
| 3.2 双方都挂账   | ✅ 已入账     | ✅ 已入账          | 手工勾选暂付，弹出列表选择暂收生成对冲凭证，同时冲销两笔挂账 |
| 3.3 单方挂账     | ✅ 已入账     | ❌ 未入账          | 先做未挂账的挂账                                             |

***\*5.3 对冲后处理\****

| 操作项       | 处理方式                               |
| ------------ | -------------------------------------- |
| 生成对冲凭证 | 借：暂收款 / 贷：暂付款（或相反）      |
| 更新流水状态 | 两笔流水标记为“已对冲”，并记录对冲单号 |
| 入账状态     | 若之前未入账，对冲后自动标记为“已入账” |
| 业务匹配     | 已领用，不允许再对该流水进行匹配/认领  |

***\*5.4 对冲限制条件\****

| 限制项       | 说明                             |
| ------------ | -------------------------------- |
| 金额必须相等 | 收方金额= 付方金额               |
| 同一账户     | 两笔流水必须为同一个银行账户     |
| 不可重复对冲 | 已对冲过的流水不允许再次参与对冲 |
| 跨月限制     | 双方均未挂账且不同月份时不可对冲 |
