## 1. 设计目标

本文件定义前端工作台真正应该调用的平台内部聚合接口，而不是让前端直接拼接多个 `GJJ` 原始接口。

设计目标：

1. 屏蔽下游 `GJJ` 接口差异
2. 将一个柜面步骤收敛成一个平台接口
3. 统一页面返回结构和错误提示
4. 为后续接入 `OCR`、自动机审、流程流转预留扩展点

## 2. 平台接口总览

| 接口名称 | 方法 | 用途 | 对应柜面步骤 |

## 12. 统一返回建议

建议平台内部接口统一采用如下返回结构：

```json
{
  "code": "0000",
  "message": "success",
  "data": {}
}
```

建议错误码分层：

1. `PLAT-VALID-*`：页面参数校验失败
2. `PLAT-BIZ-*`：平台业务规则未通过
3. `PLAT-DOWN-*`：下游 GJJ 或外部服务失败
4. `PLAT-SYS-*`：平台内部异常

## 13. 结论

当前平台内部聚合接口已经可以覆盖“柜面购房提取”从初始化、房屋查询、材料分类、金额测算、银行卡校验、业务提交、自动机审到人工审批的完整首期闭环。下一步建议继续输出开发任务拆分，把这些接口正式转成实现任务。
