## 4. 审计发现

### 4.1 高风险：本次功能改动混入了明显超范围的环境切换配置，存在串环境/误连风险

**现象**
- `application.yml` 不仅为本功能增加 `city` profile，还同步改了：
  - `spring.cloud.nacos.discovery.namespace`
  - `spring.cloud.nacos.discovery.server-addr`
  - 删除整段 `gjj.*` 默认配置
- `application-city-zaozhuang.yml` 不仅增加 `voucher.*`，还同时修改了：
  - `xxljob.admin.adminAddresses`
  - `tinyid.server`
  - `hsjg.hsjgbh`
  - 新增 `gjj.capinfo-gjj-busi-cszd-cxfw-basic-svc`

**风险**
- 这些改动与“凭证汇总按 yhzhhm+ywfl 改造”无直接业务关系，却会改变服务连接的 Nacos、任务调度、分布式 ID、核算机构配置。
- 一旦和本次功能一起进入测试或提交，很难区分故障是“凭证汇总逻辑问题”还是“环境连错/配置漂移”导致。
- 这类配置污染会放大排障成本，也破坏原子提交边界。

**建议**
- 将本次凭证汇总改造只保留 `voucher.*` 相关配置。
- 其余环境迁移类配置拆为独立任务、独立提交、独立验证。

### 4.2 中风险：`mapYwflName` 的“多 ywlx 一致性校验”仍然无法真正触发

**现象**
- `JzpzDOMapper.xml#getJzpzhz` 已在 SQL 层把同组数据先做 `MIN(a.ywlx) AS ywlx`。
- `CwhsServiceImpl#mapYwflName(xtlx, List<String> ywlxsInGroup, ywfl)` 仍尝试在 Java 层遍历 `ywlxsInGroup` 做“同一 `ywfl` 下多个 `ywlx` 名称是否一致”的校验。

**风险**
- 如果一个 `ywfl` 下真实存在多个 `ywlx`，SQL 已先把它们压成一个 `MIN(ywlx)`，Java 层看到的 `ywlxsInGroup` 只会剩下被压缩后的值。
- 结果是：
  - 金额、附件数、回写口径本身大概率是正确的；
  - 但“摘要名称一致性告警”不会真实触发；
  - 若字典中 `codeNameZl1` 存在脏数据不一致，系统会静默选中某一个 `MIN(ywlx)` 对应名称。

**建议**
- 若要保留该告警能力，需在汇总前增加一次按 `(yhzhhm, ywfl, jzrq, ztbh)` 反查 `distinct ywlx`；
- 或由 SQL 输出完整 `ywlx` 列表，再在 Java 侧做一致性校验。

### 4.3 中风险：空串值未与 `NULL` 统一归并，历史脏数据可能被拆成额外分组

**现象**
- SQL 使用 `COALESCE(a.yhzhhm, '其他账号')`、`COALESCE(a.ywfl, '其他分类')`，只处理 `NULL`。
- Java 二级分组和维度取值使用 `StrUtil.nullToDefault(...)`，同样只处理 `null`。
- 但生成链路 `ywjzPz` 注入时，使用的是 `StrUtil.isNotBlank(yhzhhm)`，逻辑上已把“空串/空白”视为无效值。

**风险**
- 若历史数据或人工修数写入了空串 `''` / 空白字符，而不是 `NULL`：
  - SQL 不会把它归并到“其他账号/其他分类”
  - Java 也不会归并
  - 可能出现“空字符串分组”和“其他账号分组”并存的情况
- 这会导致：
  - 汇总结果被额外拆组
  - 摘要出现空值语义
  - 回写条件不能完全沿用“其他账号/其他分类”的兼容分支

**建议**
- 统一把分组与查询口径从“只兜底 `NULL`”改为“兜底空白值”。
- Java 侧建议改为 `StrUtil.isNotBlank(...) ? value : defaultValue`。
- SQL 侧若数据库函数允许，建议对空串做 `TRIM + NULLIF` 后再 `COALESCE`。

### 4.4 低风险：`P2 日志参数化全部完成` 的表述不准确，财务记账主链路仍保留字符串拼接日志

**现象**
- `CwhsServiceImpl#asyncExecuteYwjz` 仍存在字符串拼接日志：
  - `log.info("******记账参数：" + ywjzReqDTO);`
  - `log.info("财务记账成功，业务流水号：" + ywjzReqDTO.getYwlsh());`
  - `log.error("财务记账失败，业务流水号：" + ywlszb.getYwlsh() + "，错误信息：" + ywjzResult.getMsg());`
- 这些代码位于财务记账异步主链路，不属于“临沂业务无关历史代码”那一处例外。

**风险**
- 该问题不会改变凭证汇总功能结果，但会让“P2 已全部完成”的结论失真。
- 字符串拼接日志会增加无谓对象拼装，也不利于统一日志检索与结构化治理。

**建议**
- 将上述 3 处日志改为参数化形式，再声称 P2 完成更稳妥。
