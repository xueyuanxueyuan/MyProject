# 住建部联行号每日同步任务开发记录

## 1. 任务背景
- 目标模块：`capinfo-gjj-busi-zjjs-ywgl-basic-svc-busi`
- 目标能力：新增一个每日执行一次的定时任务，批量调用住建部 `BDC112` 联行号查询接口，提前同步联行号数据。
- 关键入口：`WbjkServiceImpl.zjLhhcxcl`

## 2. 现状分析
- 当前联行号查询逻辑已经封装在 `wbjkService.zjLhhcxcl(ZjLhhcx)` 中。
- 现有业务查询场景采用“用户查询时，如果当天无缓存则临时触发一次”的方式。
- 项目定时任务统一采用 `XXL-Job` 的 `@XxlJob` 机制，而不是在代码中直接写 `@Scheduled` cron。

## 3. 实现方案
- 新增 `ZjbLhhSyncService`，专门负责每日联行号同步逻辑。
- 从 `BankConfig` 读取银行编码列表，过滤空值并去重。
- 从 `zjjs_zj_dqdm` 地区代码表读取地区代码列表，过滤空值并去重。
- 按“银行编码 × 地区代码”组合构造 `ZjLhhcx` 请求对象，逐个调用 `wbjkService.zjLhhcxcl`。
- 同步任务本身不再单独实现落库逻辑，而是明确复用原 `WbjkServiceImpl.zjLhhcxcl` 内已有的落库链路：
  - `zjLhhcxDmService.addZjlhhcxJl`
  - `zjLhhcxclDmService.deleteLhhcxcl`
  - `zjLhhcxclDmService.addBatchLhhcxcl`
- 单个组合失败时记录日志但不中断整批执行，最终汇总总数、成功数、失败数。
- 新增 `ZjbLhhSyncJobHandler` 作为 XXL-Job 执行入口。
- `XXL-Job` 的每日执行时间建议在调度平台配置为 `0 0 2 * * ?` 或按生产窗口另行调整。

## 5. 变更对比留痕
- 新增同步服务，将“组合枚举 + 复用旧联行号查询落库逻辑 + 汇总结果”的核心逻辑从 JobHandler 中解耦出来，便于单测与复用。
- 新增结果汇总对象，避免在 JobHandler 中直接拼接统计变量。
- 新增 XXL-Job Handler，负责接入现有调度体系，并根据汇总结果回传成功/失败状态。
- 新增单元测试，约束“去重、过滤空值、按组合复用旧落库逻辑”的关键行为。

## 7. 后续落地说明
- 代码发布后，需要在 XXL-Job 平台新增执行器任务，JobHandler 填写为 `zjbLhhSyncJobHandler`。
- 调度 cron 建议配置为“每日一次”，具体时间以生产可用窗口为准。
- 若后续希望减少全量组合调用量，可进一步增加“仅同步启用银行”或“按地区级别过滤”的业务参数化能力。
