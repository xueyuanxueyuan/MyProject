# 20260521-三省六部规则主文件同步与CLAUDE精简记录

## 1. 背景

近期三省六部相关技能已更新，但仓库主规则入口 `CLAUDE.md` 与最高优先级提示 `AGENTS.md` 尚未同步，导致以下问题：

- `AGENTS.md` 仍停留在只强调三省回显，未补充尚书省、翰林院与交付阶段协作关系。
- `CLAUDE.md` 已存在较多与技能主源重复的文字说明，维护成本偏高。
- `.cursorrules` 已明确要求同步 `AGENTS.md`，当前状态与入口规则存在差异。

## 2. 本次调整目标

1. 同步 `AGENTS.md`，使其与最新三省六部技能约束一致。
2. 简化 `CLAUDE.md`，保留不可删门禁，删除重复展开说明。
3. 保持 `CLAUDE.md` 作为“统一主规则主源”，同时把具体技能细节继续下沉到 `doc/技能库`。

## 3. 精简策略

### 3.1 `AGENTS.md`

- 保留“三省规范块 + 低风险同回合继续执行”的最高优先级要求。
- 增补默认联动技能：`anti-laziness-anti-hallucination`、`verification-before-completion`。
- 增补尚书省、翰林院、太子之间的回奏协作说明，避免交付阶段职责缺口。

### 3.2 `CLAUDE.md`

- 保留：默认工作流、三省六部主线、技能路由、项目通用规范、交付门禁、优先级。
- 收敛：把过度解释性段落合并为更短的规则清单。
- 补全：明确 `edict-dispatch`、`edict-hanlin` 的角色，保证与当前技能体系一致。
- 不删：任何“显式回显规范块”“TodoWrite 落地”“低风险不得中断”“无验证不报喜”类门禁。

## 4. 预期结果

- 入口文件职责清晰：`AGENTS.md` 管最高优先级动作，`CLAUDE.md` 管统一主规则与索引。
- 主规则更短、更稳，后续技能继续演进时只需维护少量锚点。
- 三省六部从识别、规划、审议、调度到回奏的链路表达完整。

## 5. 实际落地结果

- `AGENTS.md` 已补充默认联动技能、低风险同回合继续执行要求，以及 `edict-hanlin` -> `edict-triage` 的回奏协作链路。
- `CLAUDE.md` 已补充 `edict-dispatch`、`edict-hanlin` 主源引用，并将原有长段解释压缩为“默认工作流 / 三省六部主线 / 流程路由 / 项目规范 / 交付门禁 / 优先级”六段结构。
- 已保留不可删门禁：显式回显规范块、`TodoWrite` 落地、低风险不得中断、守卫扫描、无验证不报喜。
- 本次核对时发现 `AGENTS.md` 与 `CLAUDE.md` 当前位于工作区磁盘中，但未纳入 Git 索引；因此最终验证以文件内容读取、诊断结果和守卫扫描为准，而非 Git diff。
