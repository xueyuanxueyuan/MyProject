# 20260705-一户通加密机证书ID路由加解密签名验签改造记录

## 1. 背景

根据用户提供的四份材料，需要将一户通安全能力调整为更贴近加密机接入说明的调用方式：

- 证书参数图：确认加密机侧存在签名证书、解密证书、对端加密证书、对端验签证书等证书标识。
- 配置说明图：要求通过 `zayk4j.ini` 和证书标识配合厂商 Jar 调用。
- 加签方法图：要求优先采用 `ZaSVSApi.SignData(...)` 一类调用方式。
- 报文加密方法图：要求优先采用 `ZaSVSApi.EncryptData(...)` / `DecryptData(...)` 一类调用方式。

后续用户补充了 `doc/一户通` 下的厂商样例与证书材料，进一步明确了实际接口形态：

- `SVSTest.java`：签名主路径为 `ZaSVSApi.SignDataByCertId(certId, signerId, digestMethod, plainBytes, out)`；
- `SVSTest.java`：证书标识验签主路径为 `ZaSVSApi.VerifySignedData(3, null, certIdBytes, digestMethod, plainBytes, signBytes, 1)`；
- `SVSTest.java`：数字信封主路径为 `ZaSVSApi.EncryptData(certId.getBytes(), plainBytes)` / `ZaSVSApi.DecryptData(certId, cipherBytes)`；
- `集代城银证书-测试new.cer`：对端证书材料可能是 `.cer`，不能只按 `.csr` 处理。

当前该改造已要求同时落到 `prod` 与 `jiaxing` 两套项目。

## 2. 本次改造范围

### 2.1 核心实现

文件：

- `prod/.../SmCryptoUtil.java`
- `jiaxing/.../SmCryptoUtil.java`

改造要点：

1. 默认签名路由保持 `AUTO`，但判定规则已改为“优先 `sign-key-index`，其次 `sign-cert-id`，最后本地私钥文件”。
2. `encryptEnvelope(...)` 优先走 `yht.caps.svs.peer-encrypt-cert-id`，证书 ID 存在时走厂商 `EncryptData(certId)` 路径。
3. `decryptEnvelope(...)` 优先走 `yht.caps.svs.decrypt-cert-id`，证书 ID 存在时走厂商 `DecryptData(certId)` 路径。
4. `sign(...)` 在当前配置下优先读取 `yht.caps.svs.sign-key-index` + `sign-method`，走厂商 `SignData(signMethod, keyIndex, keyValue, inDataLen, plainBytes)` 路径；仅在显式选择 `CERT_ID` 且已配置 `sign-cert-id` 时才走 `SignDataByCertId(...)`。
5. 增加了按报文头 `OrigReceiver` 选择签名密钥号与对端加密证书标识的能力，对应配置：
   - `yht.caps.svs.orig-receiver-sign-key-index`
   - `yht.caps.svs.orig-receiver-encrypt-cert-id`
6. `CapsMessageSigner` / `CapsMessageEncryptor` 已将报文头 `OrigReceiver` 传入 `SmCryptoUtil`，确保映射项能实际生效。
7. 验签默认仍保持 `VerifySignedData_Ex(...)` 路由，以适配当前配置中 `peer-verify-cert-id` 留空、`peer-cert-path` 仍存在的现状。
8. 对厂商 Jar 的部分重载签名不确定，仍保留基于反射的加解密兜底调用：
   - 先尝试 `EncryptData(certId, plainBytes)`
   - 再回退 `EncryptData(certId, plainBytes, mode)`
   - 先尝试 `DecryptData(certId, cipherBytes)`
   - 再回退 `DecryptData(certId, cipherBytes, mode)`
9. 补上了厂商 SVS 连接初始化：
   - 启动时优先读取 `yht.caps.svs.ini-path`，调用 `ZaSVSApi.InitServiceConnect(iniPath)`；
   - 若未配置 `ini-path`，则读取 `server-host/server-port/socket-timeout/connect-count/select-time`，调用 `ZaSVSApi.InitServiceConnect(host, port, ...)`；
   - 若已启用 SVS 但上述初始化参数仍未配置，则保留 `InitServiceConnect(null)` 兼容回退，并在日志中明确告警。

### 2.2 测试同步

文件：

- `prod/.../SmCryptoUtilSvsTest.java`
- `jiaxing/.../SmCryptoUtilSvsTest.java`

调整要点：

1. 修正单测预期，从“文件材料优先”改为“加解密优先证书 ID、签名优先 sign-key-index、文件材料回退”。
2. 修正默认签名断言，从“证书 ID 签名”改为当前配置对应的 `SignData(keyIndex=8,SM3withSM2)`。
3. 修正加解密描述断言，改为 `EncryptData(certId)`、`DecryptData(certId)`。
4. 扩展 `RecordingSvsFacade`，补齐新增接口：
   - `encryptDataByCertId(...)`
   - `decryptDataByCertId(...)`
   - `signDataByCertId(...)`
5. 增加 `OrigReceiver` 映射项覆盖，验证按报文接收方切换签名密钥号和对方加密证书标识。

### 2.3 根据厂商样例追加修正

在参考 `doc/一户通/SVSTest.java` 后，又追加做了两处修正：

1. 默认证书 ID 签名路径从“猜测的 `SignData(certIdBytes, ...)` 重载”改为厂商样例明确给出的 `SignDataByCertId(...)`。
2. `peer-cert-path` 的文件加载从“仅支持 CSR”扩展为“支持 `.cer` / X.509 证书以及 CSR`”：
   - 若是证书文件，则先解析证书公钥用于本地公钥加密/验签；
   - 若是 CSR，则继续沿用 CSR 公钥解析；
   - 原始证书字节仍可用于 `VerifySignedData_Ex(...)` 场景。

## 3. 配置含义

当前实现依赖以下配置项决定优先路由：

- `yht.caps.svs.sign-key-index`
- `yht.caps.svs.sign-method`
- `yht.caps.svs.ini-path`
- `yht.caps.svs.server-host`
- `yht.caps.svs.server-port`
- `yht.caps.svs.socket-timeout`
- `yht.caps.svs.connect-count`
- `yht.caps.svs.select-time`
- `yht.caps.svs.decrypt-cert-id`
- `yht.caps.svs.peer-encrypt-cert-id`
- `yht.caps.svs.peer-verify-cert-id`
- `yht.caps.svs.orig-receiver-sign-key-index`
- `yht.caps.svs.orig-receiver-encrypt-cert-id`

文件材料配置仍保留为回退方案：

- `yht.caps.encrypt.peer-cert-path`
- `yht.caps.encrypt.private-key-path`

其中 `peer-cert-path` 现在既可以是原来的 `.csr`，也可以直接指向厂商给的 `.cer` 证书文件。

按当前配置文件，实际推荐路由为：

1. **签名**：优先 `sign-key-index` + `sign-method`
2. **加密**：优先 `peer-encrypt-cert-id`
3. **解密**：优先 `decrypt-cert-id`
4. **验签**：默认 `VerifySignedData_Ex(...)` + `peer-cert-path`
5. **SVS 建连**：优先 `ini-path`，其次 `server-host/server-port/socket-timeout/connect-count/select-time`
