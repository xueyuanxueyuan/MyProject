# 20260705-参照CLI-Anything创建本机工具桥接技能记录

## 背景

用户要求参照 `CLI-Anything` 项目，在当前 `d:\Probject\Gjj` 工作区中创建一个类似技能，以达到“可调用本机任意软件工具”的效果。

## 需求理解

该需求的关键不在于单纯“执行命令”，而在于：

1. 让 Trae 对本机软件形成统一的桥接调用方法
2. 让调用过程具备可发现、可复用、可验证的技能化结构
3. 在高权限本机操作场景下保留必要的安全边界

## 对外部项目的吸收取舍

参考 `CLI-Anything` 后，本次吸收的核心思想包括：

- 优先让代理通过真实软件后端能力工作，而不是依赖脆弱 GUI 操作
- 将“发现 → 调用 → 验证 → 文档化”组织为固定流程
- 让技能本身成为代理发现能力入口的一部分

本次未直接复制的部分包括：

- 外部项目的完整 7 阶段自动生成 CLI 流水线
- 插件市场、CLI Hub、自动发布、自动测试等完整生态
- 特定平台插件目录结构与运行时约束

原因是当前工作区处于 Trae 环境中，更适合做“本地桥接技能 + 模板化单工具适配”，而不是复刻整个外部工程体系。

## 落地方案

本次创建了一个新的本地桥接技能：

- 技能名：`cli-anything-local-tools`

并补齐以下文件：

- `doc/技能库/cli-anything-local-tools/SKILL.md`
- `doc/技能库/cli-anything-local-tools/TOOL-HARNESS-TEMPLATE.md`
- `.trae/skills/cli-anything-local-tools/SKILL.md`
- `doc/操作记录/20260705-参照CLI-Anything创建本机工具桥接技能记录.md`

## 技能能力定义

该技能在当前仓库中的能力边界为：

1. 统一本机软件调用优先级：
   - 原生命令行
   - 无头模式 / 脚本接口
   - 本地 API / MCP 桥接
   - 受控 GUI 自动化

2. 统一标准流程：
   - 探测
   - 建模
   - 最小可用调用
   - 结果校验
   - 适配固化

3. 统一单工具扩展方式：
   - 使用 `TOOL-HARNESS-TEMPLATE.md` 为具体软件补充专用规范

## 风险控制

虽然目标是“调用本机任意软件”，但本技能并未绕开 Trae 原生安全边界：

- 真正执行命令仍依赖 `RunCommand`
- 高风险操作仍需审批或显式风险提示
- 不将无法稳定自动化的 GUI 软件伪装为可靠 CLI

## 当前结果

- 当前仓库已具备 `cli-anything-local-tools` 技能入口
- 后续当用户指定某个具体本机软件时，可在此技能基础上继续补建该软件的专用调用约定
