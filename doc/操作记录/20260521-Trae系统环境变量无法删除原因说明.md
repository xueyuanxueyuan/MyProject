# Trae 中 3 个系统环境变量无法删除原因说明

## 现象

- Trae 环境变量界面检测到 3 个冲突变量：
  - `ANTHROPIC_AUTH_TOKEN`
  - `ANTHROPIC_BASE_URL`
  - `ANTHROPIC_MODEL`
- 界面标记其来源为“系统环境变量”。
- 在当前界面中只能看到冲突提示，无法真正删除变量。

## 根因

- 这 3 个变量不是当前项目或当前终端临时创建的。
- 终端进程的父进程是 `trae` 主程序。
- 在父进程环境中已存在这 3 个变量，因此新开的 shell 会自动继承。
- 由于变量来源是上游进程环境，Trae 的当前冲突列表页面只能提示冲突，不能直接删除系统级来源的变量。

## 已核对证据

### 当前 shell 中存在变量

```bash
env | grep '^ANTHROPIC_'
```

### `~/.bashrc` 与 `~/.bash_profile` 中未找到变量定义

```bash
grep -n 'ANTHROPIC_' ~/.bash_profile
grep -n 'ANTHROPIC_' ~/.bashrc
```

### 父进程 `trae` 环境中存在同名变量

```bash
tr '\0' '\n' < /proc/$PPID/environ | grep '^ANTHROPIC_'
```

## 为什么界面删不掉

- 如果变量是当前工作区或某个配置文件中定义，界面通常可以跳转或允许移除。
- 现在它被识别为“系统环境变量”，说明其生命周期早于当前窗口和终端。
- 只要 Trae 主进程仍带着这些变量运行，当前会话下打开的新终端还会继续继承它们。

## 正确删除位置

需要去“Trae 启动之前”的环境来源删除，常见位置包括：

1. 桌面启动器或启动脚本
2. 登录会话注入的环境变量
3. `systemd --user` 环境
4. 图形桌面启动时读取的 profile 文件
5. 手工 `export` 后再启动 Trae 的外层终端

## 推荐排查步骤

1. 完全退出 Trae。
2. 在启动 Trae 的外层终端执行：

```bash
env | grep '^ANTHROPIC_'
```

3. 如果外层终端里也有，继续检查：

```bash
grep -R -n 'ANTHROPIC_' ~/.config ~/.profile ~/.bash_profile ~/.bashrc ~/.zshrc /etc/profile.d /etc/environment 2>/dev/null
systemctl --user show-environment | grep '^ANTHROPIC_'
```

4. 删除对应来源后，重新登录会话或重启 Trae。
5. 再次进入 Trae 检查冲突列表是否消失。

## 临时规避

- 如果只是当前 shell 不想使用它们，可以执行：

```bash
unset ANTHROPIC_AUTH_TOKEN ANTHROPIC_BASE_URL ANTHROPIC_MODEL
```

- 但这只对当前终端有效。
- 新开终端或重启 Trae 后，如果父进程环境还在，这 3 个变量仍会重新出现。

## 结论

- 这 3 个变量删不掉，不是删除按钮失效。
- 真正原因是它们来自 Trae 主进程继承的系统环境，而不是当前页面可管理的本地配置项。
- 要彻底删除，必须清理 Trae 启动前的上游环境来源，然后重启 Trae。
