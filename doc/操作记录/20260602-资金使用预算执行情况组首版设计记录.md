## 2. 本轮分析依据

## 3. 本轮识别出的关键差异

与前面两个预算组相比，本组有 4 个关键差异：

1. 本组是月度单表，不是“总表 + 附表”结构。
2. 本组由市中心统一制表，不是分中心逐机构填报。
3. 本组同时存在自动取数、手工填报、自动计算三类值。
4. 本组的 Excel 行已经展开为“业务项 + 指标项”，列固定为机构维度。

## 4. 真实表样关键信息

### 4.1 列结构

列方向为：

- 全市
- 市本级
- 嘉善县
- 平湖市
- 海盐县
- 海宁市
- 桐乡市

### 4.2 行结构

本表共 29 行业务项，分为：

- 归集提取区
- 个人贷款区
- 跨区块比率行

### 4.3 Excel 明确写出的规则

原表已直接写明：

- `201贷方科目`
- `201借方科目`
- `121科目`
- `121贷 + 122贷 - 122借 - 公转商转出`
- `手工填`
- `手工填，+/-`
- `上年末 + 归集 - 提取 + 统筹`
- `上年末 + 发放 - 回收 - 公转商转出`
- `逾期 / 期末余额`
- `水平之和`

这说明本表不是简单的结果录入表，而是“规则驱动的月报执行表”。

## 5. 本轮最终采用的建模方向

本轮最终采用以下模型：

- 主表：月报控制信息
- 机构执行明细表：一机构一行固定字段
- 行配置：用于前端和导出还原 Excel 行结构

未采用“总表/附表拆分”的原因：

- Excel 本身就是单表
- 本组由市中心统一制表
- 全市列只是系统汇总结果，不需要独立总表

## 7. 本轮最终结论

本轮已将资金使用预算执行情况组收敛为最终功能设计结果，核心结论如下：

1. 本组是月度单表，不拆总表/附表。
2. 本组采用市中心统一制表模式，分中心仅查看本机构列。
3. 本组最终采用“主表 + 机构执行明细表 + 行配置渲染”模型。
4. 全市列始终由系统汇总生成，不允许人工调整。
5. 自动取数失败只允许保存草稿，不允许人工补录兜底。
