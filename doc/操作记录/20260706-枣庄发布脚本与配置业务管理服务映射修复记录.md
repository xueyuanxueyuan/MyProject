## 1. 操作时间

## 2. 问题描述

用户要求发布“财务核算服务 + 业务管理服务”，但实际执行时误将第二个服务识别为“聚合服务（gm-agg）”。

本次要求是不重新发布，仅检查并修复发布脚本和配置文件，避免后续再次出现同类误判。

## 3. 核对结论

### 3.1 业务管理服务

- 模块：`capinfo-gjj-busi-zjjs-ywgl`
- 制品：`capinfo-gjj-busi-zjjs-ywgl-basic-svc-app.jar`
- Deployment：`capinfo-gjj-busi-zjjs-ywgl-basic-svc-depl`

依据：

- `capinfo-gjj-busi-zjjs-ywgl-basic-svc-app/pom.xml` 的 `artifactId` 为 `capinfo-gjj-busi-zjjs-ywgl-basic-svc-app`
- `k8s/test-tsp/capinfo-gjj-busi-zjjs-ywgl-basic-svc-test-tsp.yaml` 明确标注“资金结算-业务管理-基础服务”

### 3.2 聚合服务

- 模块：`capinfo-gjj-busi-jshs-gm-agg`
- 制品：`capinfo-gjj-busi-jshs-gm-agg-svc-app.jar`
- Deployment：`capinfo-gjj-busi-jshs-gm-agg-svc-depl`

依据：

- `capinfo-gjj-busi-jshs-gm-agg-svc-app/pom.xml` 的 `artifactId` 为 `capinfo-gjj-busi-jshs-gm-agg-svc-app`
- `k8s/test-tsp/capinfo-gjj-busi-jshs-gm-agg-svc-test-tsp.yml` 明确标注“结算核算-柜面-聚合服务”

## 4. 根因分析

原有发布配置虽然已经包含 `zjjs-ywgl` 和 `gm-agg` 两个独立制品映射，但缺少“显示名称 / 服务标识 / 别名”等人类可读语义。

同时，发布脚本原先只接受 jar 文件名作为输入，没有把“业务管理服务”“聚合服务”“gm-agg”“ywgl”等常用口径统一解析到配置中的标准制品名。

因此，用户使用业务语义描述时，容易在执行口径上把“业务管理服务”和“聚合服务”混淆。

## 5. 修复内容

### 5.1 配置文件修复

文件：`config/deploy_servers.json`

为各制品补充了以下元数据：

- `display_name`
- `service_key`
- `aliases`

其中关键修复为：

- `capinfo-gjj-busi-zjjs-ywgl-basic-svc-app.jar`
  - `display_name`: `业务管理服务`
  - `service_key`: `zjjs-ywgl`
  - `aliases`: `业务管理`、`业务管理服务`、`ywgl`、`zjjs-ywgl`
- `capinfo-gjj-busi-jshs-gm-agg-svc-app.jar`
  - `display_name`: `聚合服务`
  - `service_key`: `jshs-gm-agg`
  - `aliases`: `聚合`、`聚合服务`、`gm-agg`、`jshs-gm-agg`

### 5.2 脚本修复

文件：`scripts/deploy_config.py`

新增并修复的能力：

- 支持通过 `display_name`、`service_key`、`aliases`、`deployment`、`jar 名`、`去扩展名后的制品名` 来解析发布目标
- 新增 `resolve_artifact_name(...)` 统一做发布目标解析
- `selected_artifacts(...)` 改为先解析再校验聚合目录中的真实文件
- `deployment_for(...)` 改为支持按服务别名直接反查 deployment
- 对歧义选择器增加显式报错

文件：`scripts/remote_deploy.py`

- 更新命令帮助说明，明确脚本支持按服务名、别名、deployment 或 jar 名选择发布目标
