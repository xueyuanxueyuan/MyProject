# 20260706-枣庄凭证汇总摘要仍显示其他银行原因排查记录

## 1. 问题现象
- 用户反馈：枣庄财务核算系统凭证汇总功能中，已将生成汇总凭证摘要时“其他银行”“其他分类”的默认值改为 `""`，但发布到服务器后验证，摘要仍然拼接出“其他银行”。

## 3. 关键结论

### 3.1 当前源码确实已改为不再兜底“其他银行”
`VoucherSummaryDisplaySupport.buildBranchBusinessSummary()` 当前源码为：

```java
String branchDisplay = StrUtil.blankToDefault(branchName, StrUtil.blankToDefault(yhdm, ""));
String businessDisplay = StrUtil.blankToDefault(businessTypeName, "凭证汇总摘要");
return branchDisplay + businessDisplay;
```

对比 Git 差异可见，本地未提交改动是：

```diff
- String branchDisplay = StrUtil.blankToDefault(branchName, StrUtil.blankToDefault(yhdm, "其他银行"));
+ String branchDisplay = StrUtil.blankToDefault(branchName, StrUtil.blankToDefault(yhdm, ""));
```

说明“源码改为空串”这件事在当前工作区是成立的。

### 3.2 但该改动没有进入已发布 JAR
排查时间点文件时间如下：
- 发布产物 `capinfo-gjj-busi-cwhs-jzgl-basic-svc-app.jar` 最后修改时间：`2026/7/6 19:50:56`
- 源码 `VoucherSummaryDisplaySupport.java` 最后修改时间：`2026/7/6 20:43:32`

结论：当前源码修改时间晚于已发布产物时间，说明这次把“其他银行”改成空串的改动，至少在本地时间线里并未进入 `19:50:56` 生成的发布包。

### 3.3 页面查询汇总凭证时直接读取已落库摘要，不会因发版自动改历史数据
汇总凭证生成时，摘要 `codeName` 会直接落入：
- `cwhs_hzpz.zhaiyao`
- `cwhs_hzjzpz.zhaiyao`

对应代码：

```java
hzpz.setZhaiyao(codeName);
```

后续分页查询汇总凭证时，`getHzpzPage()` 直接分页查询 `HzpzDO`，并未重新计算摘要：

```java
Page<HzpzRespDTO> page = (Page<HzpzRespDTO>) hzpzDmService.page(query.toPage(HzpzDO.class), qw)
        .convert(item -> JoinBeanUtil.copyBean(item, HzpzRespDTO.class));
```

汇总分录展示时同样直接读取 `summaryRow.getZhaiyao()`：

```java
respDTO.setZhaiyao(summaryRow.getZhaiyao());
```

因此：
- 如果验证的是历史已生成的汇总凭证，那么即使代码重新发布，旧记录里的 `zhaiyao` 仍然还是“其他银行...”，不会自动变化。
- 必须重新生成汇总凭证，或对历史数据做专项修复，才能看到新摘要规则的效果。

## 4. 代码链路说明

### 4.1 汇总维度
`JzpzDOMapper.xml#getJzpzhz` 已按 `yhdm + ywfl` 聚合，并将空值统一归并为空串：

```sql
COALESCE(NULLIF(TRIM(a.yhdm), ''), '') AS yhdm,
COALESCE(NULLIF(TRIM(a.ywfl),   ''), '') AS ywfl
```

### 4.2 摘要组装
`CwhsServiceImpl` 中汇总摘要组装逻辑：

```java
String branchName = branchNameMap.get(hzYhdm);
String ywflName = mapYwflName(repXtlx, ywlxsInGroup, hzYwfl);
String codeName = VoucherSummaryDisplaySupport.buildBranchBusinessSummary(branchName, ywflName, hzYhdm);
```

因此“是否显示其他银行”最终取决于 `VoucherSummaryDisplaySupport` 被打进运行中的 JAR 的实际版本。

## 5. 本次排查判断
本次问题最可能由以下两点之一或共同导致：
1. **改动未进入发布包**：源码虽已改，但构建/聚合/上传时使用的仍是修改前产物。
2. **验证的是历史汇总数据**：历史 `cwhs_hzpz` / `cwhs_hzjzpz` 中已存量写入“其他银行”，发布后不会自动重算。

## 6. 建议处理
1. 重新确认目标模块 `capinfo-gjj-busi-cwhs-jzgl-basic-svc-app` 以最新源码重新打包。
2. 打包后校验产物时间、SHA256 或反编译关键类，确认 `VoucherSummaryDisplaySupport` 已为最新逻辑。
3. 发布后不要直接看旧汇总凭证，需用一笔新的测试数据重新执行“凭证汇总”。
4. 若必须修正历史数据，需要补充一次性数据修复脚本或重新生成历史汇总凭证。

## 7. 结论摘要
- 不是“代码明明改了但运行时还神秘拼接”的纯逻辑问题。
- 现有证据更支持：**改动尚未进入已发布 JAR**，且**历史已生成汇总凭证摘要不会因发版自动更新**。
