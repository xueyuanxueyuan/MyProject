## 3. 后端代码改造实施
### 3.1 模型与 DTO 更新
- **实体层**：
  - `SxfytDO` / `Sxfyt`：补充 `khhzje`, `yzfze`, `ztdjje`。
  - `SxfytMxDO` / `SxfytMx`：补充 `khbl`, `yzfje`。
- **Mapper XML**：
  - 修改 `SxfytDOMapper.xml` 与 `SxfytMxDOMapper.xml` 的 `BaseResultMap` 与 `Base_Column_List` 及各类查询 SQL。
- **DTO 层**：
  - `SxfytRespDTO` / `SxfytMxRespDTO` 同步补充上述字段。
  - `SxfytMxKhReqDTO` 补充 `khbl`。
  - `EditSxfytReqDTO` 补充 `sjzfje`。

### 3.2 核心业务逻辑重构 (`CwhsServiceImpl`)
- **考核保存 (`sxfmxKh`)**：持久化前端录入的 `khbl`，差额保留至 `yhkhjlje`。
- **考核确认 (`sxfKhQr`)**：考核通过时，将明细考核金额向上汇总至头表的 `khhzje`。
- **支付申请 (`sxfytZfsq`)**：
  - 引入了并发防超额校验：`sykfje = khhzje - yzfze - ztdjje`。
  - 发起支付时，将本次金额累加至头表 `ztdjje` 进行在途锁定。
- **支付回调更新 (`editSxfty`)**：
  - 收到资金审批通过事件后，释放 `ztdjje` 并累加至 `yzfze`。
  - **动态明细分摊**：依据本次实际支付总额 `sjzfje`，倒序冲减 `cwhs_sxfyt_mx`，并将冲减金额累加至各明细的 `yzfje`。

### 3.3 凭证记账算法重构 (`YwglServiceImpl.receiveCwjzxx`)
- 废弃了原先通过“明细反推剩余额度”组装借贷流水的做法。
- 从 `Cwzjzf` 获取本次实际支付金额 `sysxf`，以此作为游标，遍历明细。
- 逐笔比对 `明细考核额 - 明细已付额`，按可付额度进行拆分，精确生成明细级的 `CwjzYwlsMxDTO` 借贷流水。

## 4. 前端交互改造实施
- **考核录入 (`sxfkh.vue`)**：
  - 在明细抽屉增加 `el-input-number` 组件录入 `khbl`。
  - 实现未干预时的比例联动计算：`khhsxf = sxf * (khbl / 100)`。
  - 监听用户手动输入 `khhsxf`，通过标记 `_manual_khhsxf` 解除比例强绑定。
- **分批支付防超额 (`sxfzfLy.vue`)**：
  - 列表补充 `khhzje`, `yzfze`, `ztdjje`, `sykfje` 的格式化显示。
  - `handleZfsq`：支付前默认带入 `sykfje`（剩余可付金额）。
  - 在弹窗 `jeChange` 校验中，严格拦截大于 `sykfje` 的输入。
  - 在主按钮控制 `show()` 函数中加入硬拦截：当 `ztdjje > 0`（有在途审批）时，禁止发起下一笔支付。
