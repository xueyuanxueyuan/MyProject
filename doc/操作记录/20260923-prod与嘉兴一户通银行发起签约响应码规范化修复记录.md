# prod与嘉兴一户通银行发起签约响应码规范化修复记录

## 1. 背景

排查 `prod` 与 `嘉兴` 项目一户通银行发起签约回调 (`caps.305 -> caps.306`) 实现时，发现存在以下文档外响应码：

- 成功码使用 `00000000`
- 失败码使用 `B305VAL`、`B305BIZ`、`B306SEND`

上述编码不在《上海集中代收付系统报文交换规范 V1.2.7.7》以及项目内一户通接口设计/开发文档列出的错误码范围内，容易导致对端或本地解析按标准码表校验时报错。

## 2. 依据

本次修复以以下文档为准：

- `prod/IdeaProject/capinfo-gjj-busi-jshs/document/一户通相关文档/0.原始文档/上海集中代收付系统报文交换规范V1.2.7.7.md`
- `prod/IdeaProject/capinfo-gjj-busi-jshs/document/一户通相关文档/1.开发文档/3.协议管理相关接口/协议管理相关接口开发文档.md`
- `prod/IdeaProject/capinfo-gjj-busi-jshs/document/一户通相关文档/1.开发文档/6.公共报文相关接口/公共报文相关接口开发文档.md`

关键口径：

- `caps.306` 的 `ErrorCode` 为 `Max8Text`，需使用文档标准码
- 协议管理类错误码范围为 `E301-E315`、`E999`
- 平台成功码使用 `I000`

## 4. 修复内容

1. 将银行发起签约 `caps.306` 成功响应码统一由 `00000000` 改为 `I000`。
2. 去除 `B305VAL`、`B305BIZ`、`B306SEND` 等自定义错误码，改为文档内标准码：
   - 前置校验失败：`E039`
   - 本地业务处理失败默认码：`E311`
   - 账号不匹配：`E313`
   - 306 发送失败的任务落库码：`S907`
3. 在结果对象/业务门面/处理器侧统一引入标准码归一化：
   - 成功固定 `I000`
   - 失败通过 `Caps900CodeCatalog.normalizeFailureCode(...)` 收口，避免再次透出自定义码
4. 嘉兴日志服务补充 `I000` 成功判断，兼容标准成功码识别。
