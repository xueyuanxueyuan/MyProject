## 确认缺陷

### 1. CAPS 报文解析存在 XXE 注入面

- 触发条件：向 `POST /yht-mock/api/gateway` 发送带 `DOCTYPE` 和外部实体的 XML 报文。
- 执行路径：`YhtMockApiController.gateway()` -> `MockGatewayService.dispatch()` -> `CapsCodecService.parseXml()`。
- 影响：解析器会尝试处理外部实体，攻击者可借此读取本地文件或向内网地址发起探测；若报文类型命中业务分支，解析出的实体内容还可能被写入状态和日志接口。
- 修复：关闭 `DOCTYPE`、外部实体和外部 DTD/Schema 访问，并在 XML 解析失败时直接返回失败报文，不再继续执行业务分支。

### 2. 状态文件写入异常后存在静默数据丢失路径

- 触发条件：`mock-state.json` 在写入中途被中断或损坏后，服务重启进入 `MockStoreService.load()`。
- 执行路径：任意会触发 `save()` 的接口 -> `MockStoreService.save()` 直接覆盖主状态文件 -> 重启时 `MockStoreService.load()` 读取失败后回退为空快照。
- 影响：已保存的场景规则、回调配置、交易/批次/协议状态会在下次启动后被静默清空。
- 修复：改为临时文件写入后原子替换主文件，并维护最近一次成功写入的 `.bak` 备份；主文件损坏时优先从备份恢复。
