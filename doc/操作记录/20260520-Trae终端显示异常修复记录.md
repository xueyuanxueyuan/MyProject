# Trae 终端显示异常修复记录

## 问题现象

- Trae 内嵌终端存在显示异常，怀疑有文本样式或 ANSI 渲染串扰。
- 基础环境检查显示 `LANG=zh_CN.UTF-8`、`TERM=xterm-256color` 正常，中文输出与普通 ANSI 输出可用。

## 根因定位

- `~/.bashrc` 与 `~/.bash_profile` 中存在异常模型字符串 `opus[1m]`。
- 该字符串形态高度接近 ANSI 粗体控制序列 `\033[1m` 的残缺片段，说明此前配置写入时混入了样式残留。
- 该异常值不仅污染环境变量 `ANTHROPIC_MODEL`，还进入了 `claude()` wrapper 的默认参数，容易导致终端输出样式或展示文本异常。

## 对比留痕

### 修改前

```bash
# ~/.bash_profile
export ANTHROPIC_MODEL="opus[1m]"

# ~/.bashrc
export ANTHROPIC_MODEL="opus[1m]"
command "$claude_bin" --model 'opus[1m]' "$@"
command "$claude_bin" --model 'opus[1m]' --effort medium "$@"
```

### 修改后

```bash
# ~/.bash_profile
export ANTHROPIC_MODEL="opus"

# ~/.bashrc
export ANTHROPIC_MODEL="opus"
command "$claude_bin" --model 'opus' "$@"
command "$claude_bin" --model 'opus' --effort medium "$@"
```

## 修复思路

1. 清理启动脚本中的残缺 ANSI 片段。
2. 保持其他终端初始化逻辑不变，仅最小化修复受污染配置。
3. 重新加载 shell 并验证变量值、终端启动行为与相关输出。

## 验证项

- `grep` 确认 `opus[1m]` 已从 `~/.bashrc`、`~/.bash_profile` 清除。
- 新 shell 中 `ANTHROPIC_MODEL` 输出为 `opus`。
- 终端启动脚本可正常加载，无新增语法错误。

## 二次排查补充

- 用户反馈首次打开正常，但当终端输出累积较多后又出现显示错乱。
- 通过构造多种控制序列压测后确认：纯文本大输出、普通颜色、`OSC 0` 标题更新、`OSC 8` 超链接都不足以稳定复现。
- 但当输出包含“光标回退并重写前几行”的序列时可稳定复现，例如：
  - `\033[2A` 光标上移
  - `\033[2K` 擦除当前行
  - `\r` 行内重绘
  - `\033[?25l` / `\033[?25h` 隐藏/恢复光标
  - `\033[?1049h` / `\033[?1049l` 进入/退出备用屏
- 这说明根因不是普通滚动输出，而是 Trae 内嵌终端对“动态重绘型 CLI 输出”的滚动区回放兼容性有限。

## 二次缓解措施

- 在 `~/.bashrc` 中针对 Trae / VS Code 内嵌终端补充以下环境变量，尽量让常见 CLI 自动降级为静态输出：
  - `CI=1`
  - `NO_COLOR=1`
  - `FORCE_COLOR=0`
  - `CLICOLOR=0`
  - `CLICOLOR_FORCE=0`
- 增加 `resetTerminalState` 函数，用于在终端状态被隐藏光标或备用屏污染时快速恢复。
- 增加 `hermesQuiet` 函数，等价于 `hermes chat -Q`，用于在 Trae 终端中避免 `hermes` 的 banner、spinner 和 tool preview 动态输出。
- 增加 `hq` 函数，作为更短的安全入口：
  - 无参数时执行 `hermes chat -Q`
  - 有参数时执行 `hermes chat -Q -q "$*"`
- 增加 `hqa` 函数，用于查看 `hq`、`hermesQuiet` 与 `resetTerminalState` 的简要帮助。

## 二次验证结论

- 可稳定复现并定位为“动态重绘序列导致的滚动区错乱”。
- 当前修复策略属于兼容性缓解，不是修改 Trae 终端渲染内核。
- 后续在 Trae 终端中，优先使用静态输出模式，可显著降低再次出现乱码/错位的概率。

## 推荐使用方式

```bash
source ~/.bashrc
hq
hq 帮我总结当前目录代码结构
hqa
```
