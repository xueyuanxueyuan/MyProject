# 20260515-一户通后端分层修正说明

## 1. 问题背景
- 用户反馈：此前补充的一户通批量分页查询后端代码无法编译通过，并且 `YhtController` 中直接编写了 DAO 查询逻辑，不符合当前项目的分层规范。
- 处理目标：在用户已回退代码的基础上，重新按项目既有层级补齐一户通批量任务分页查询与批量明细分页查询能力。

## 2. 根因排查
- `YhtController` 中残留了直接依赖 `YhtBatchTaskDao`、`YhtBatchDetailDao` 的实现，违反 Controller 仅做入口编排的分层要求。
- `Controller` 里使用了项目中不存在的字段/方法，例如：
  - `YhtBatchTaskDO::getUpdatedTime`
  - `YhtBatchDetailDO::getTaskId`
  - `YhtBatchDetailDO::getDetailStatus`
  - `reqDTO.getPage()` / `reqDTO.getSize()`
- API 层缺少 `YhtBatchTaskPageReqDTO`、`YhtBatchDetailPageReqDTO` 两个请求 DTO 文件，但 `YhtController` 已存在对应 import。
- 项目现有分页风格参考 `YhtAuditController`，实际使用 `pageNum` / `pageSize` 字段，而不是通用 `BasePage`。
- `YhtBatchDetailDO` 实体未保存 `taskId` 字段，明细与批次任务的关联应通过任务主表查询后，按 `batchNo` 和 `reqId` 回查明细表。

## 3. 修正方案
### 3.1 Controller 分层修正
- 在 `YhtController` 中新增两个分页接口：
  - `/yht/batch/queryTaskPage`
  - `/yht/batch/queryDetailPage`
- Controller 仅负责：
  - 接收参数
  - 规范默认分页值
  - 调用 `yhtService` 转发处理
- 移除了 `Controller` 中直接依赖 DAO、`LambdaQueryWrapper`、`JoinBeanUtil` 的错误写法。

### 3.2 API DTO 补齐
- 新增 `YhtBatchTaskPageReqDTO`
- 新增 `YhtBatchDetailPageReqDTO`
- DTO 按项目现有风格使用 `pageNum` / `pageSize`，未再引入不匹配的分页基类。

### 3.3 Service 分层下沉
- 在 `YhtService` 增加：
  - `queryTaskPage`
  - `queryDetailPage`
- 在 `YhtServiceImpl` 中实现分页查询逻辑：
  - 任务分页：按 `batchNo`、`corpNo`、`bizType`、`batchStatus` 条件查询 `YhtBatchTaskDO`
  - 明细分页：先按 `taskId` 查询批次任务，再按 `batchNo` 和 `reqId` 查询 `YhtBatchDetailDO`
- 批量明细响应对象中的 `detailStatus`、`resFlag`、`procCode`、`procMsg` 由服务层手工映射，避免直接拷贝导致字段名错位。
