# 一户通记账通知失败不回滚主事务修复记录

## 1. 问题背景

- 模块路径：`prod/IdeaProjects/capinfo-gjj-busi-jshs/capinfo-gjj-busi-zjjs-ywgl/capinfo-gjj-busi-zjjs-ywgl-basic-svc-busi`
- 触发场景：一户通 `caps.205` 单笔付款交易结果回调后，业务结果已更新，但后续通知业务记账时因为 `JzglFeignClient#fkjg` 调用失败，导致异常继续向上抛出。
- 现象：`UnknownHostException: capinfo-gjj-busi-gjtq-jzgl-basic-svc` 最终沿着 `DefaultRegionStrategy.tzYwjz -> DefaultRegionStrategy.fkywJssbCl -> YwglServiceImpl.fkywJfJgCl` 返回，触发 `fkywJfJgCl` 事务回滚。

## 2. 根因分析

- `YwglServiceImpl.fkywJfJgCl` 使用 `REQUIRES_NEW` 事务处理付款结果。
- 失败分支会进入 `YwglServiceImpl.fkywJssbCl`，再委托 `DefaultRegionStrategy.fkywJssbCl`。
- `DefaultRegionStrategy.fkywJssbCl` 在更新交易结果后，直接通过 `this.tzYwjz(...)` 通知业务记账。
- `DefaultRegionStrategy.tzYwjz` 捕获异常后重新抛出 `BizException`，导致通知异常重新回到主事务调用链。
- 结论：问题不是交易结果处理本身失败，而是“后置通知动作”和“主业务事务”耦合在一起，通知失败错误地影响了已完成的业务结果落库。

## 3. 修复方案

- 将 `DefaultRegionStrategy.tzYwjz` 调整为“只记录日志、不再抛异常”。
- 在 `DefaultRegionStrategy.fkywJssbCl` 和 `DefaultRegionStrategy.skywJssbCl` 中统一通过安全包装方法执行记账通知。
- 明确约束：业务记账通知属于后置动作，失败时不能回滚已完成的主业务状态。

## 4. 对比留痕

| 对比项 | 修复前 | 修复后 |
| --- | --- | --- |
| `DefaultRegionStrategy.tzYwjz` 异常处理 | 记录日志后 `throw new BizException(...)` | 仅记录错误日志，不再向上抛出 |
| 失败结果处理中的记账通知 | 直接调用 `this.tzYwjz(...)` | 调用 `safeNotifyBusinessAccounting(...)`，显式隔离后置通知失败 |
| 事务影响 | 通知失败会带回 `fkywJfJgCl` 事务 | 通知失败只留日志，不影响前置业务结果 |

## 5. 验证情况

- 已补充聚焦测试：`DefaultRegionStrategyTest#tzYwjzShouldNotThrowWhenBusinessAccountingNotificationFails`
- 已通过 IDE 语法诊断确认本次改动文件无新增语法错误。

  - `ZbkhProviderController` 缺少 `JdkhtbYxDTO`
  - `YhtController` / `YhtService` / `YhtServiceImpl` 缺少若干 `YhtBatch*` DTO
- 结论：本次修复已完成代码落地与局部校验，但受模块现有基线编译问题影响，暂未完成测试执行闭环。

## 6. 后续建议

- 若需要完成自动化测试闭环，先补齐当前模块缺失的 `JdkhtbYxDTO`、`YhtBatchDetailPageReqDTO`、`YhtBatchTaskPageReqDTO`、`YhtBatchDetailRespDTO`、`YhtBatchTaskRespDTO` 等基线依赖。
- 其他策略类若也存在“后置通知直接抛异常”的写法，建议统一按本次方式收敛，避免同类事务回滚问题再次出现。
