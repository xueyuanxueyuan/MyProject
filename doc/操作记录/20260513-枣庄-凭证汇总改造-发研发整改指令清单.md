## 4. 建议本轮一并整改（P1）

### P1-1 修正“多 ywlx 摘要一致性校验”取数来源
- **问题**：
  - 当前 SQL 已先 `MIN(ywlx)`，导致 Java 层 `mapYwflName(xtlx, ywlxsInGroup, ywfl)` 实际拿不到真实的“组内多个 ywlx”列表。
  - 结果：金额、附件数、回写口径虽正确，但“摘要名称不一致 WARN”不会真实触发。
- **目标文件**：
  - `JzpzDOMapper.xml`
  - `JzpzDOMapper.java`
  - `CwhsServiceImpl.java`
- **修改要求**：
  - 二选一：
    - 方案 A：在汇总前按 `(yhzhhm, ywfl, jzrq, ztbh[, jzlxfl])` 反查 `distinct ywlx` 列表，传给 `mapYwflName`
    - 方案 B：SQL 层输出组内 `ywlx` 列表，再在 Java 层校验
  - 若采用方言相关函数（如 `LISTAGG/GROUP_CONCAT`），必须先评估达梦/MySQL 双方言兼容性。
- **验收标准**：
  - 构造“不同 `ywlx`、相同 `ywfl`、字典名不一致”的样例时，WARN 能真实触发。
  - 不影响现有金额、附件数、回写结果。

### P1-2 统一空串与 NULL 的归并口径
- **问题**：
  - 生成链路把空白视为无效值，但汇总分组和 SQL 查询当前只对 `NULL` 兜底，不处理空串/空白字符。
  - 历史脏数据若存在 `''` 或空白字符，可能被拆出额外分组。
- **目标文件**：
  - `JzpzDOMapper.xml`
  - `CwhsServiceImpl.java`
- **修改要求**：
  - Java 侧：所有维度默认值处理改为“空白值兜底”，不要只处理 `null`
  - SQL 侧：若方言允许，使用 `TRIM + NULLIF + COALESCE` 或等价方案，把空串统一归并到“其他账号/其他分类”
- **验收标准**：
  - 构造 `yhzhhm=''` / `ywfl='   '` 的历史数据时，应归并到“其他账号/其他分类”
  - 不再出现“空字符串组”和“其他账号组”并存
