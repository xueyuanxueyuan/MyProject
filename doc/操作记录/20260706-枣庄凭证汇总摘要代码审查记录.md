## 3. 审查结论

### 3.1 高风险：业务分类侧并未与“改为空串”的目标保持一致
当前仅银行名称兜底从 `"其他银行"` 改成了 `""`，但业务分类一侧仍保留多处旧回退：

1. `mapYwfl()` 在映射缺失时仍可能把 `ywfl` 落为 `"其他分类"`：

```java
if (mappingFallbackEnable) {
    return StrUtil.isNotBlank(ywlx) ? ywlx : "其他分类";
}
return "其他分类";
```

2. `mapYwflName()` / `mapStoredYwflDisplayName()` 在摘要展示阶段又会回退到 `"凭证汇总摘要"` 或存储值本身：

```java
return StrUtil.blankToDefault(ywlx, "凭证汇总摘要");
```

```java
if (StrUtil.isBlank(ywfl)) {
    return "凭证汇总摘要";
}
return ywfl;
```

这意味着：
- 即使你把“其他银行”去掉了，
- 只要 `ywfl` 缺失、字典未命中、历史数据仍存 `"其他分类"`，
- 最终摘要依然可能显示 `"其他分类"` 或 `"凭证汇总摘要"`，并没有完全实现“默认其他分类改为空串”的目标。

### 3.2 中风险：单元测试仍然固化老行为，和当前实现相矛盾
`VoucherSummaryDisplaySupportTest` 仍断言：

```java
assertEquals("其他银行归集业务", summary);
```

而当前实现已改为：

```java
String branchDisplay = StrUtil.blankToDefault(branchName, StrUtil.blankToDefault(yhdm, ""));
```

这会带来两个问题：
1. 逻辑改了，但测试没改，后续有人运行该测试时应当失败。
2. 即使测试因为环境/依赖未跑起来，测试文件本身也在误导后续维护者，容易让人误以为“其他银行”仍是目标行为。

### 3.3 低风险：注释/DTO说明仍保留旧口径，容易造成误判
以下位置的注释或字段说明仍保留旧文案：

1. `JzpzhzRespDTO` 中注释写着“业务分类缺失时为其他分类”。
2. `CwhsServiceImpl` 中 `pzhzJzbjXg()` 注释仍提到 `"其他银行"/"其他分类"` 维度归并。
3. `application-city-zaozhuang.yml` 中配置注释仍强调 fallback 为 `"其他分类"`。

这些虽然不一定直接引发运行时错误，但会导致后续排查时出现“代码已经改空串，为什么注释还说会回退到其他分类”的认知混乱。
