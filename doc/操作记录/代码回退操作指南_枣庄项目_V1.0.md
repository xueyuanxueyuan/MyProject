# 代码回退操作指南_枣庄项目_V1.0

## 1. 文档目的
- 适用范围：`zaozhuang/dev-凭证汇总修改` 分支上的“凭证汇总改造”4 笔原子提交。
- 目标：在不影响其他开发者无关提交的前提下，支持按提交粒度精确回退。
- 适用仓库：`zaozhuang/IdeaProjects/capinfo-gjj-busi-jshs`
- 关联分支：`zaozhuang/dev-凭证汇总修改`

## 2. 回退原则
- 优先使用 `git revert <commit>` 生成反向提交，避免重写共享分支历史。
- 仅在“本地未推送且明确允许覆盖历史”场景下，才考虑 `git reset --hard`。
- 回退前必须先创建临时备份分支，确保可一键恢复。
- 回退后必须执行最小验证，禁止只回代码不验结果。
- 若需回退到“某一功能模块之前”的状态，按提交逆序逐笔 `revert`，不要跨越无关提交整体回滚。

## 6. 仅限本地未推送场景：`git reset`

### 6.1 场景约束
- 仅允许在本地分支未推送、且明确确认无人基于该分支继续开发时使用。
- 已推送共享分支禁止使用 `git reset --hard` 覆盖远端历史。

### 6.2 命令示例
```bash
git checkout zaozhuang/dev-凭证汇总修改
git reset --hard 019c9646d
```

### 6.3 风险说明
- 会直接改写当前分支历史。
- 若误操作，会影响后续对账、审计和同事协作。
- 本项目默认不推荐此方式。

## 10. 常见风险与注意事项
- 不要把原始脏仓中的其他环境配置改动一起提交到回退分支。
- 回退第 2、3 笔前必须先评估业务是否已有新数据依赖 `yhzhhm/ywfl`。
- 若只想停用新口径，优先回退第 4 笔或调整区域配置，不要直接删表结构。
- 若 `revert` 冲突，先用 `git status` 定位冲突文件，解决后再 `git revert --continue`。
- 回退操作日志必须记录操作人、操作时间、触发原因、审批人。
