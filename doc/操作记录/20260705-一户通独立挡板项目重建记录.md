# 20260705-一户通独立挡板项目重建记录

## 1. 任务背景

用户要求基于当前一户通业务代码与接口规范 `上海集中代收付系统报文交换规范V1.2.7.7.md`，实现一个**全新的独立项目**形式的一户通挡板，要求：

- 不能直接写入现有业务工程
- 挡板需同时具备前端与后端
- 能记录接口对接记录
- 能同时模拟银行 / CAPS 与加密机厂商

## 2. 本次落地方案

新建独立工程：

- 项目路径：`d:\Probject\Gjj\yht-mock-server`
- 技术形态：Spring Boot 单体项目
- 端口：`9999`
- 前端形态：工程内静态页面

核心入口：

- 银行 / CAPS 模拟网关：`POST /yht-mock/api/gateway`
- 加密机模拟接口：
  - `POST /yht-mock/api/hsm/sign`
  - `POST /yht-mock/api/hsm/verify`
  - `POST /yht-mock/api/hsm/encrypt`
  - `POST /yht-mock/api/hsm/decrypt`
- 前端页面：`/yht-mock/index.html`

## 3. 已实现能力

### 3.1 银行 / CAPS 挡板

已支持以下主要报文的同步受理或查询模拟：

- `caps.101 / 103 / 105`
- `caps.201 / 203`
- `caps.301 / 303 / 305 / 307`
- `caps.601`
- `caps.999`

并支持异步回调模拟：

- `caps.107`
- `caps.205`
- `caps.306`
- `caps.308`
- 手工触发 `caps.600 / caps.916`

### 3.2 加密机厂商模拟

提供独立 HTTP 接口模拟签名、验签、加密、解密，并将调用记录写入挡板记录流，便于联调时同时观察银行链路与加密机链路。

### 3.3 接口对接记录

采用独立工程内文件持久化，不依赖现有业务系统数据库：

- 持久化文件：`d:\Probject\Gjj\yht-mock-server\data\mock-state.json`

记录范围包括：

- 网关请求/响应
- 手工或自动回调推送
- 加密机模拟调用

### 3.4 前端页面

已提供静态操作页，支持：

- 发送原始 CAPS 报文
- 调用 HSM 模拟接口
- 修改回调配置
- 手工触发回调
- 查看接口对接记录详情
