# 入口样例目录化与接入说明收口记录

## 1. 目标
- 在 `doc` 根目录下建立一个可提交到 Git 的入口文件样例目录。
- 保留当前 4 个运行入口文件的样例副本，便于跨项目、跨工具迁移时直接参考。
- 将通用接入说明收口为“唯一标准源 + 样例目录”的结构，删除被覆盖的旧说明文档。

## 2. 新增内容
- 新目录：`doc/入口文件样例/`
- 样例文件：
  - `doc/入口文件样例/CLAUDE.md`
  - `doc/入口文件样例/.trae/rules/edict-workflow.md`
  - `doc/入口文件样例/.trae/rules/anti-laziness-anti-hallucination.md`
  - `doc/入口文件样例/.trae/rules/workspace-common.md`
  - `doc/入口文件样例/README.md`

## 3. 调整内容
- `doc/项目规范/统一主规则-通用工具链接入说明.md`
  - 调整为当前仓库面向其他 AI 工具的唯一通用接入说明。
  - 明确要求：先读取标准源，再参考样例目录生成本工具入口文件。
  - 将“防遗漏检查清单”和“可直接交给其他工具的生成指令”并入该文档。

## 4. 删除内容
- `doc/项目规范/CLAUDE主源-跨工具入口同步模板.md`
- `doc/项目规范/统一主规则-多工具入口生成说明.md`

## 5. 当前推荐结构
- 唯一标准源：`doc/项目规范/统一主规则-通用工具链接入说明.md`
- 样例目录：`doc/入口文件样例/`
- 运行时入口：仓库根目录与 `.trae/rules/` 下的实际入口文件

## 6. 这样做的原因
- 其他工具在迁移时，不仅能读到标准源，还能直接看到一套已验证可用的入口文件样例。
- 相比只给规则说明，不给样例，这种结构更容易稳定生成入口文件，也更不容易漏规则。
- 相比保留多份接入说明，当前结构更简洁，职责更清楚。
- 将样例目录放在 `doc` 根下，也能减少 `doc/项目规范` 目录中的非规范内容，降低规范检索噪音。
