# 增值收益分配情况组原型改造对比

## 1. 改造前

- `zzsyfp` 仅存在左侧菜单、页面标题和通用单表标题映射。
- 页面主体仍落入旧的通用 `template v-else` 分支。
- 没有总表/附表双页签。
- 没有专属数据结构、公式、来源同步、草稿保存和审核锁定逻辑。
- 分中心无法按本机构录入分配事实值。

## 2. 改造后计划

- 新增 `isZzsyfpMenu` 和 `activeZzsyfpTab`，将 `zzsyfp` 拆成专属双页签页面。
- 总表页签按 10 行展示 `上年实绩数 / 本年实绩数 / 同比增长`。
- 附表页签按 10 行展示 `实绩数`，并横向透视 `全市 + 各机构`。
- 分中心仅允许编辑 5 个原始事实字段：
  - 贷款风险准备金当年分配
  - 贷款风险准备金当年支出
  - 管理费用当年分配
  - 城市廉租住房补充资金当年分配
  - 城市廉租住房补充资金当年上缴
- 自动来源字段、公式字段和全市列全部保持只读。
- 新增同步来源、保存草稿、提交确认、审核通过、退回、锁定、导出链路。

## 3. 数据结构变化

- 新增 `ZZSYFP_MAIN_META`
- 新增 `ZZSYFP_FB_ROW_CONFIG`
- 新增 `ZZSYFP_ZB_DETAIL_TEMPLATE`
- 新增 `ZZSYFP_ZB_LAST_YEAR`
- 新增 `ZZSYFP_SOURCE_MAP`
- 新增 `ZZSYFP_FB_DETAILS`
- 新增 `createInitialZzsyfpZbData()` / `createInitialZzsyfpFbData()`

## 4. 关键交互变化

- 市中心默认进入总表页签，只读查看全市汇总结果。
- 分中心默认进入附表页签，只能看到本机构列。
- “同步来源”只刷新待分配增值收益与两个年初余额，不覆盖已录入原始事实值。
- “保存草稿”保留当前录入状态。
- “提交确认”前执行“分配合计不能大于待分配增值收益”校验。
- “审核通过 / 退回 / 锁定”驱动主表与附表状态联动。

## 5. 本次实际落地结果

- 已在 `index.html` 中补齐 `zzsyfp` 专属 data、computed、methods、mounted 初始化逻辑。
- 已将菜单切换、角色切换与 `zzsyfp` 页面联动接通，支持市中心默认总表、分中心默认附表。
- 已补齐附表公式重算：
  - `贷款风险准备金年末余额 = 年初余额 + 当年分配 - 当年支出`
  - `城市廉租住房补充资金年末余额 = 年初余额 + 当年分配 - 当年上缴`
  - `分配合计 = 贷款风险准备金当年分配 + 管理费用当年分配 + 城市廉租住房补充资金当年分配`
- 已补齐总表汇总逻辑：总表 10 行由附表全市汇总值与上年锁定值自动生成 `上年实绩数 / 本年实绩数 / 同比增长`。
- 已补齐分中心交互链路：
  - 同步来源
  - 保存草稿
  - 提交确认
- 已补齐市中心交互链路：
  - 审核通过
  - 退回
  - 锁定
  - 导出完整报表

## 6. 验证结果

- 静态诊断：`GetDiagnostics` 对 `index.html` 检查结果为 0 条错误。
- 浏览器验收：
  - 市中心进入 `zzsyfp` 后默认展示总表，显示审核按钮与全市汇总结果。
  - 切换到“市本级(填报)”后默认进入附表，仅渲染本机构列，并暴露 5 个可编辑输入框。
  - 分中心提交前，当输入导致 `分配合计 > 待分配增值收益` 时，页面正确提示“分配合计不能大于待分配增值收益”。
  - 调整为合法值后，页面可正常完成“保存草稿”与“提交确认”。
  - 切回市中心后，可查看总表汇总结果，并可执行“审核通过”，状态联动正常。
