# 20260706-枣庄项目打包报错 JCImport 排查记录

## 1. 问题现象

枣庄项目打包时出现如下编译失败：

```text
[ERROR] Failed to execute goal org.apache.maven.plugins:maven-compiler-plugin:3.13.0:compile
[ERROR] java.lang.NoSuchFieldError: Class com.sun.tools.javac.tree.JCTree$JCImport does not have member field 'com.sun.tools.javac.tree.JCTree qualid'
[ERROR]     at lombok.javac.JavacImportList.getFullyQualifiedNameForSimpleNameNoAliasing(JavacImportList.java:53)
```

## 2. 结论

本次报错的直接根因是：

- 当前打包实际使用的是 `JDK 21.0.2`
- 枣庄工程按项目规范与 POM 约束应使用 `JDK 17`
- 业务模块中显式依赖的 `lombok` 版本为 `1.18.22`

`lombok 1.18.22` 与 `JDK 21` 的 `javac` 内部 API 不兼容，因此在注解处理阶段访问 `JCImport.qualid` 字段时触发 `NoSuchFieldError`。

## 3. 核查证据

### 3.1 当前打包环境

在目录 `zaozhuang/IdeaProject/capinfo-gjj-busi-jshs` 执行：

```bash
mvn -v
```

实测结果显示：

- Maven：`3.9.16`
- Java：`21.0.2`

### 3.2 工程 POM 约束

根 POM `zaozhuang/IdeaProject/capinfo-gjj-busi-jshs/pom.xml` 中声明：

```xml
<maven.compiler.source>17</maven.compiler.source>
<maven.compiler.target>17</maven.compiler.target>
```

### 3.3 项目规范

`doc/项目规范/打包编译发布规范.md` 明确要求：

```bash
java -version  # 应输出 17.0.2
mvn -v         # 应输出 3.9.14
```

### 3.4 触发模块的 lombok 版本

报错模块：

- `zaozhuang/IdeaProject/capinfo-gjj-busi-jshs/capinfo-gjj-busi-cwhs-jzgl/capinfo-gjj-busi-cwhs-jzgl-basic-svc-busi/pom.xml`

其中显式声明：

```xml
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <version>1.18.22</version>
</dependency>
```

## 4. 处理建议

优先方案：切回 `JDK 17` 重新打包，不先动源码依赖。

参考步骤：

```bash
$env:JAVA_HOME="C:\Users\Sour\.vfox\cache\java\v-17.0.2+8\java-17.0.2+8"
$env:Path="$env:JAVA_HOME\bin;C:\Users\Sour\.vfox\sdks\maven;$env:Path"
java -version
mvn -v
mvn clean package -DskipTests -s settings-tsp.xml
```

若后续必须长期使用 `JDK 21` 打包，则需要统一升级工程中的 `lombok` 版本，并联动验证所有模块的编译与注解处理行为；该方案属于兼容性升级，风险高于“切回 JDK 17”。

## 5. 建议结论

- 短期恢复打包：`JDK 17 + 现有工程`
- 长期升级路线：统一评估 `lombok`、父依赖 BOM、编译插件与 CI 环境后，再考虑迁移到 `JDK 21`
