# 20260615-一户通日志查询抽屉展示改造记录

## 1. 需求背景

- 一户通日志查询页面当前将原始报文与解密后 XML 固定展示在页面底部。
- 现需调整为使用抽屉方式展示，并改为双击日志列表行时打开。

## 2. 受影响文件

- `jiaxing/WebstormProjects/capinfo-gjj-frontend-jshs-gm/src/components/yht/yht-log.vue`
- `prod/WebstormProjects/capinfo-gjj-frontend-jshs-gm/src/components/yht/yht-log.vue`
- 对比留痕：`.doc-archive/20260601-doc-cleanup/操作记录/202606/20260615-一户通日志查询抽屉展示改造对比留痕.md`

## 3. 实现思路

1. 保留现有详情接口 `getYhtLogDetail(mesgId)` 与原始报文、解密后 XML 的格式化逻辑，不改后端契约。
2. 将底部常驻详情区替换为 `el-drawer`，减少页面纵向占用。
3. 将列表触发事件从 `row-click` 调整为 `row-dblclick`，避免单击即打断列表浏览。
4. 抽屉内继续保留四块内容：
   - 发送报文
   - 返回报文
   - 解密后发送报文(XML)
   - 解密后返回报文(XML)
5. 新增抽屉加载态、关闭重置和异常提示，避免抽屉残留旧数据。

## 4. 实际改动

### 4.1 交互调整

- 页面顶部提示文案增加“双击列表行可在抽屉中查看报文详情”。
- `x-table` 事件从 `@row-click="getYhtLog"` 改为 `@row-dblclick="handleRowDblclick"`。

### 4.2 抽屉详情

- 新增：
  - `drawerVisible`
  - `detailLoading`
  - `drawerTitle`
- 新增 `el-drawer` 作为详情容器。
- 将原有四块报文展示区整体迁移到抽屉中。
- 保留复制能力，继续复用原有 `copy()` 方法。

### 4.3 详情加载

- 新增 `handleRowDblclick()`：
  - 双击后打开抽屉
  - 清空旧数据
  - 调用详情接口加载最新报文
  - 加载失败时提示并关闭抽屉
- 新增 `handleDrawerClosed()`：
  - 关闭后重置标题、加载态和详情表单
