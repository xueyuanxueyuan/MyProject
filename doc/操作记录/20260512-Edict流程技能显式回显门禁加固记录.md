# Edict 流程技能显式回显门禁加固记录

## 1. 背景
- 当前工作区已启用 `Edict（三省六部）` 默认工作流。
- 现状问题不是流程技能未被调用，而是调用后未必会把技能规定的 Markdown 规范块显式回显给用户。
- 这会导致“实际走了流程，但用户看不到合规输出”的错觉，也会削弱三省六部作为统一交互门面的约束力。

## 2. 本次目标
- 将“调用三省流程技能后必须显式回显规范块，否则视为未按规范执行”上升为硬规则。
- 同步更新全局主规则、通用工具链接入说明、入口样例、实际 Edict 入口规则，以及 `edict-triage`、`edict-planning`、`edict-review` 技能主源与入口。
- 让后续其他 AI 工具接入时，也能继承这条显式回显门禁。

## 3. 处理思路
- 在 `CLAUDE.md` 中增加总控门禁，明确“仅调用技能不算完成环节”。
- 在 `doc/项目规范/统一主规则-通用工具链接入说明.md` 中同步增加同等约束，并把该项纳入防遗漏检查清单和其他工具生成指令。
- 在 `.trae/rules/edict-workflow.md` 与 `doc/入口文件样例/.trae/rules/edict-workflow.md` 中，分别对 `triage`、`planning`、`review` 三个环节增加显式回显要求。
- 在 `doc/技能库/edict-*` 与 `.trae/skills/edict-*` 中补充“强制回显规范块”与“仅调用技能不代表完成环节”的说明。

## 4. 影响文件
- `CLAUDE.md`
- `doc/项目规范/统一主规则-通用工具链接入说明.md`
- `doc/入口文件样例/CLAUDE.md`
- `.trae/rules/edict-workflow.md`
- `doc/入口文件样例/.trae/rules/edict-workflow.md`
- `doc/技能库/edict-triage/SKILL.md`
- `doc/技能库/edict-planning/SKILL.md`
- `doc/技能库/edict-review/SKILL.md`
- `.trae/skills/edict-triage/SKILL.md`
- `.trae/skills/edict-planning/SKILL.md`
- `.trae/skills/edict-review/SKILL.md`

## 5. 预期效果
- 调用 `edict-triage` 后，必须显式回显 `### 👑 太子批复 (Triage)` 规范块。
- 调用 `edict-planning` 后，必须显式回显 `### 📜 中书省草拟计划 (Planning)` 规范块。
- 调用 `edict-review` 后，必须显式回显 `### 🛡️ 门下省审议 (Review)` 规范块。
- 若仅调用技能工具而未回显对应规范块，统一视为未按 Edict 规范执行。
