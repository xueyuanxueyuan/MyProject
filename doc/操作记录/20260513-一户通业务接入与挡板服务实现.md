# 一户通 (yht) 业务接入与挡板服务说明

## 1. 业务接入改造说明
为实现一户通通道能够正常被业务链路调用，我们进行了以下改造：

### 1.1 增加业务接入层 `YhtYwService`
- **路径**：`cn.capinfo.gjj.busi.zjjs.ywgl.busi.yht.service.YhtYwService`
- **职责**：封装了一户通底层的 `YhtService`，提供对外的 `corpWalletSign` (签约) 和 `corpWalletCancel` (解约) 接口。
- **DTO 转换**：将外部传入的 `CorpWalletSignReqDTO` 和 `CorpWalletCancelReqDTO` 转换为内部的 `YhtSignReqDTO` 与 `YhtCancelReqDTO`，并将返回结果封装成统一的 `DbqyRespDTO`。

### 1.2 改造旧签约/解约入口路由 (`WbjkServiceImpl`)
- 在 `WbjkServiceImpl` 中，注入了 `YhtYwService`。
- 通过读取系统参数配置表中的路由开关（`XtlxEnum.XTLX_ZJJS.getValue()`, `JYCS`, `SFQYYHT`）决定通道走向。
- 若开关开启（`SF_Y`），则走一户通通道完成数字人民币对公钱包的签约/解约。

### 1.3 `YwglServiceImpl` 增加通道分流
- 在 `YwglServiceImpl` 处理付款业务时（如 `addFkywPlfk` 链路），增加了 `Jsqd.YHT` 通道的分流处理。
- 在 `khzhyxxCx` (账户有效性查询) 与 `yhzhHqyeCx` (余额查询) 增加了 `Jsqd.YHT` 通道分流，并根据一户通当前能力，对不支持的操作给予了明确的提示响应。

## 2. 独立挡板服务 (Mock) 接入说明
为支持脱离实际 CAPS 平台的本地化测试和联调，并且不污染现有主业务工程，我们新建了**完全独立的一户通挡板服务**，包含完整的前端页面与后端处理。

### 2.1 独立挡板服务结构（带状态的沙盘模式）
- **工程目录**：`/home/source/Jetbrains/Probject/Gjj/yht-mock-server`
- **技术栈**：Spring Boot 3.1.5 + Vue 3 (CDN) + Element Plus + ConcurrentHashMap 本地缓存
- **前端页面**：`http://localhost:8899/yht-mock/index.html`，提供可视化的网关请求接收记录查看与手动触发异步回调的表单界面。
- **后端机制**：
  - **模拟真实协议流转**：收到 `caps.305` 签约请求后，挡板不仅返回 `caps.900`，还会在本地缓存中生成一条“协议记录”，赋予其平台分配的模拟协议号和协议状态（如 `CS00`）。
  - **模拟真实交易流转**：收到 `caps.201` 支付请求后，挡板会生成一个以 `MOCK-SYS-` 开头的平台流水号，并记入本地交易库。
  - **支持规范化状态查询**：当业务系统发起 `caps.303` (协议查询) 或 `caps.203` (交易查询) 时，挡板不再盲目返回受理成功，而是从本地缓存中查出刚才的协议或交易，组装成规范的 `caps.304` (带 Base64 文件流) 或 `caps.204` 报文返回。
  - **智能回调组装**：通过前端点击发送异步回调时，挡板可关联原有的缓存数据进行辅助填写。

### 2.2 启动与使用方式

**1. 启动独立挡板服务**：
在 `yht-mock-server` 目录下，执行 Maven 启动命令：
```bash
cd yht-mock-server
mvn spring-boot:run
```
服务将在 `8899` 端口启动，上下文路径为 `/yht-mock`。

**2. 访问控制台**：
浏览器打开：[http://localhost:8899/yht-mock/index.html](http://localhost:8899/yht-mock/index.html)
在这里可以看到所有主业务发往挡板的请求，并可以点击“回调”按钮主动触发异步通知。

**3. 配置主业务指向挡板**：
在主业务工程的本地开发或测试环境 (`application-local.yml` 或 `application-test.yml`) 中，配置一户通的请求 URL 指向该挡板服务的 gateway：

```yaml
gjj:
  yht:
    caps:
      baseUrl: http://localhost:8899/yht-mock/api/gateway
```
通过上述配置，系统内发出的所有一户通交易均会被独立挡板服务拦截，从而实现业务全链路的闭环测试，同时保持了主项目的干净与纯粹。
