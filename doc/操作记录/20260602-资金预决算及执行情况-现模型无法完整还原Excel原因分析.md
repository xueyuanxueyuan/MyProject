# 资金预决算及执行情况 - 现模型无法完整还原 Excel 原因分析

## 1. 结论

当前独立模型脚本中的 `主表 + 明细表` 设计，**能够承载一部分业务数值录入**，但**不能稳定、完整、可维护地还原 Excel 13 张表的全部表样与取数规则**。

问题不在于“字段少几个”，而在于当前模型只覆盖了：

- 报表头部少量属性
- 部分行次的数值事实
- 机构维度按 `HSJGBH` 行化存储

但没有完整覆盖：

- 表样模板
- 动态列头
- 行分组层级
- 公式与取数来源
- 跨表勾稽
- 单元格展示规则
- 导出快照

所以如果目标是“系统里录完数据后，能够 100% 稳定产出和 Excel 一样的表”，当前模型确实不够。

## 2. 现模型的几个核心硬伤

### 2.1 总表主表没有承载明细行事实

当前 `CWHS_ZJYJS_ZJSYYSZB`、`CWHS_ZJYJS_YWSZYSZB`、`CWHS_ZJYJS_GJSYJSZB`、`CWHS_ZJYJS_YWSZJSZB`、`CWHS_ZJYJS_ZZSYFPQKZB` 这些“总表”表结构中，只存了：

- 报表编号
- 编制单位
- 年度
- 状态
- 表尾签字人
- 15 个系统字段

并**没有存储总表自己的行数据**。

而 Excel 中的总表并不是纯表头，它本身有完整的：

- 行次
- 项目名称
- 上年预算数
- 上年实绩数
- 本年预算数
- 比率列

这意味着当前总表是否能导出，完全依赖：

- 从附表推导
- 从其他表拼装
- 在导出时临时计算

这会导致三个问题：

- 逻辑非常分散，难维护
- 一旦 Excel 列结构调整，导出 SQL/代码要连带大改
- 无法保留“当时导出的报表快照”

### 2.2 执行情况表被建成“多指标列”，但 Excel 实际更像“行驱动模板”

例如当前 `CWHS_ZJYJS_ZJSYYSZXQKFB` 使用了：

- `BNYSS`
- `BNSJS`
- `SNTQS`

这样的多指标列。

但 Excel《资金使用预算执行情况表》的真实结构是：

- 行上已经展开成“本年归集预算数”“本年归集实绩数”“归集完成预算数（%）”“上年归集同期数”“归集同比增长（%）”等不同指标
- 列上主要是“全市、市本级、嘉善县、平湖市、海盐县、海宁市、桐乡市”

也就是说，Excel 的这张表核心上是：

- **行 = 业务项 + 指标项**
- **列 = 机构**

而不是：

- **行 = 业务项**
- **列 = 预算/实绩/同期**

所以当前这类结构会导致：

- 行次语义被压缩错位
- 比率类、同比类、空值类单元格无法稳定表达
- 同一模板下不同类型行的取数方式无法统一配置

### 2.3 当前模型缺少“表样模板层”

Excel 原表里，每一行、每一列都不仅是数据，还有版式语义：

- 哪几行是一级分组，如“归集提取”“个人贷款”“国债投资”
- 哪几行是明细项
- 哪几行是合计项
- 哪些单元格显示 `-`
- 哪些单元格显示空
- 哪些行要缩进显示
- 哪些地方有多级表头

当前模型只保存了：

- `HANGXH`
- `XMMC`
- 少量业务数值

但没有保存：

- 行分组代码
- 父子层级
- 排序规则
- 缩进层级
- 是否标题行
- 是否可编辑
- 是否公式行
- 是否展示为百分比
- 是否展示为“—”

这会导致系统虽然可能“有数”，但未必能“按 Excel 版式输出”。

### 2.4 当前模型缺少“列模板定义”

从 Excel 结构解析可见，不同表的列形态差异非常大：

- 预算总表：上年预算数、上年实绩数、本年预算数、为上年实绩%
- 预算附表：全市 + 6 个机构列
- 执行情况表：全市 + 6 个机构列，但行里包含预算、实绩、完成率、同期、同比
- 决算总表：上年同期数、本年预算数、本年实绩数、预算完成率、比上年同期增长
- 扩面表：指标、单位、全市 + 6 个机构列

当前脚本没有独立的“列定义表”，因此列头目前是被写死在：

- SQL 命名里
- 代码逻辑里
- 导出逻辑里

这意味着如果后续 Excel 把“海宁市”改成“海宁分中心”，或者新增一列“完成差额”，数据库本身没有地方承载这类模板变化。

### 2.5 当前模型缺少“公式与取数规则层”

Excel 解析文本里已经明确存在多种来源：

- 手工填
- 取上一年同表
- 取上一年决算表
- 取执行情况表
- 取会计科目
- 行内公式
- 行间汇总
- 比率公式
- 1 月 2 月为空，3 月起有值
- 初始化一年

当前模型只存结果值，没有存“为什么是这个值、怎么来的”。

这会带来两个直接问题：

- 系统无法自动判断哪些单元格可编辑、哪些应锁定
- 无法稳定自动重算或追溯公式来源

如果未来要支持：

- 自动取数
- 月度重算
- 审核校验
- 导出前校验勾稽

就必须有一层规则配置。

### 2.6 当前模型无法准确保留“单元格状态”

Excel 中很多格子不是简单的数字，而是有状态差异：

- `-`
- `——`
- 空值
- 0
- 手工填
- 自动取数
- 锁定
- 只读公式

这些状态在报表里是有业务意义的。

当前表结构里所有值几乎都被压成了 `DECIMAL` 或普通文本，这样会丢失：

- 是否本来就不适用
- 是否尚未生成
- 是否规则禁止填写
- 是否由系统自动生成

这会让导出结果看起来“像一张报表”，但细节上跟 Excel 原始语义不一致。

### 2.7 当前模型缺少“跨表勾稽与来源追踪”

根据需求分析，报表之间有明显勾稽关系：

- 附表“全市”汇总到总表
- 上年预算数来自上年本年预算数
- 年初余额来自上年决算年末余额
- 执行情况表 12 月值流入决算表
- 某些实绩数来自会计科目

当前模型没有专门的：

- 来源规则表
- 勾稽规则表
- 科目映射表
- 结果快照表

所以后续一旦用户问：

- “这个数从哪来的？”
- “为什么这里和那张表不一致？”
- “重新按 10 月底口径出一版”

系统很难准确解释和复原。

## 3. 具体到当前脚本的几个典型问题

### 3.1 `CWHS_ZJYJS_ZJSYYSZB` 只能存头部，不能直接存总表行数据

当前表能存：

- `BBBH`
- `BZDW`
- `ND`
- `DWFZR`
- `KJZG`
- `ZBR`

但不能直接存：

- 行次 1-15
- 上年预算数
- 上年实绩数
- 本年预算数
- 为上年实绩%

这说明它还不是完整意义上的“总表数据表”，更像“总表头表”。

### 3.2 `CWHS_ZJYJS_ZJSYYFB` 混合了承担附表和总表取数的职责

当前它有：

- `SNYSS`
- `SNSJS`
- `BNYSS`
- `BNSJS`

但从 Excel 原表看，资金使用预算附表本质上重点承载的是：

- 各机构的本年预算数
- 部分行的公式结果
- 全市汇总列

如果把上年预算、上年实绩、本年实绩都塞进“附表表”里，后续会出现：

- 数据语义混杂
- 不知道哪些值属于附表，哪些只是为了总表服务
- 导出逻辑越来越依赖代码约定而不是表结构语义

### 3.3 执行情况表和决算表没有承载“公式行/比例行/状态行”的元数据

例如：

- 完成率
- 同比增长
- 余额类不算比例
- 1、2 月为空
- 3 月起填报

这些都不是单纯的事实值，而是模板控制规则。

目前脚本中没有任何地方显式表示这些规则。

## 4. 结论性判断

如果目标只是：

- 保存部分业务数值
- 页面上做个近似展示
- 导出一份“长得像”的报表

那当前模型可以继续凑合推进。

但如果目标是你前面一直强调的：

- Excel 原表每一行每一列都不能漏
- 可稳定导出
- 能指导开发
- 后续还能维护

那当前模型**确实还不够**。

## 5. 推荐改造方向

我更推荐改成 **“业务事实表 + 模板配置表 + 规则表 + 快照表” 的混合模型**，而不是只保留现在这套“主表 + 明细表”。

### 方案 A：继续补字段硬扛

做法：

- 继续在现有 16 张表里加字段
- 用代码硬写每张表的导出规则

优点：

- 改动最小

缺点：

- 后续极易失控
- 每新增一张表或调整一列都要改 SQL、后端、前端、导出
- 不适合长期维护

**不推荐。**

### 方案 B：保留业务主子表，再增加模板与规则层

做法：

- 保留当前各业务独立主表
- 明细表只存“事实值”
- 新增模板行定义、模板列定义、公式规则、取数规则、导出快照等表

优点：

- 既保留业务模块清晰性
- 又能承载 Excel 表样
- 更利于前后端与报表导出

缺点：

- 比当前方案多几张配置表
- 设计复杂度会上升一点

**推荐。**

### 方案 C：完全转成通用单元格模型

做法：

- 一切都按“报表-行-列-单元格”存储

优点：

- 还原 Excel 能力最强

缺点：

- 接口不好写
- 业务 SQL 不直观
- 开发人员理解成本高

**不推荐作为主方案。**

## 6. 我建议的下一步

下一步不要直接在现在脚本上继续加字段，而是先把模型补成下面 4 层：

1. **业务单据层**
   - 各业务主表
   - 各业务事实明细表

2. **模板定义层**
   - 报表模板表
   - 模板行定义表
   - 模板列定义表

3. **规则引擎层**
   - 公式规则表
   - 取数来源规则表
   - 勾稽校验规则表
   - 科目映射表

4. **结果留痕层**
   - 导出快照表
   - 审核流转表
   - 锁表记录表

只有这样，才能把“可填数据”“自动计算”“Excel 版式”“导出快照”分开。

## 7. 直接判断

你的判断是对的：

> 现在这套建表，确实还不能让我放心地说，它一定能完整产出 Excel 中的 13 张表。

它距离“能存数据”已经不远了，但距离“能完整还原并稳定导出 Excel 原表”还差一层关键的模板与规则建模。
