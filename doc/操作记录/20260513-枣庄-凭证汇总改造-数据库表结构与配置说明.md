# 20260513-枣庄-凭证汇总改造-数据库表结构与配置说明

## 1. 说明

本文用于回答“凭证汇总改造到底涉及哪些表、怎么改、达梦脚本怎么执行、配置文件怎么配”四个问题，口径以当前设计文档、实施记录和枣庄代码现状为准。

## 2. 涉及的数据库对象

### 2.1 需要改表结构的表

| 表名 | 用途 | 本次是否改表 | 改动内容 |
| --- | --- | --- | --- |
| `cwhs_pz` | 凭证主表 | 是 | 新增 `yhzhhm`、`ywfl` 两个字段；新增按 `jzrq + yhzhhm + ywfl` 的复合索引 |
| `cwhs_hzpz` | 汇总凭证主表 | 是 | 新增 `yhzhhm`、`ywfl` 两个字段；新增按 `jzrq + yhzhhm + ywfl` 的复合索引 |

### 2.2 参与逻辑但不改表结构的表

| 表名 | 作用 | 本次是否改表 |
| --- | --- | --- |
| `ywlszb` | 业务流水主表；凭证生成时从这里取中心账号 `yhzhhm` | 否 |
| `cwhs_jzpz` | 记账凭证明细表；汇总 SQL 通过它汇总借贷方金额 | 否 |

说明：
- `yhzhhm` 的来源是业务流水主表 `ywlszb`，属于“取数来源表”，不是本次 DDL 改造对象。
- `ywfl` 通过 `ParamUtil.getCode(...)` 按 `ywlx -> codeZl1` 做映射，当前实现体现为代码调用，不涉及本模块内新增字典表 DDL。

## 3. 表结构怎么改

### 3.1 `cwhs_pz`

新增字段：

| 字段 | 类型 | 含义 | 口径 |
| --- | --- | --- | --- |
| `yhzhhm` | `VARCHAR(64)` | 中心账号 | 从 `ywlszb` 回源获取；空值归并为“其他账号” |
| `ywfl` | `VARCHAR(32)` | 业务分类 | `ywlx` 映射 `codeZl1`；缺失时按配置回退 |

新增索引：

| 索引名 | 字段 |
| --- | --- |
| `idx_cwhs_pz_jzrq_yhzhhm_ywfl` | `jzrq, yhzhhm, ywfl` |

### 3.2 `cwhs_hzpz`

新增字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `yhzhhm` | `VARCHAR(64)` | 汇总凭证对应的中心账号维度 |
| `ywfl` | `VARCHAR(32)` | 汇总凭证对应的业务分类维度 |

新增索引：

| 索引名 | 字段 |
| --- | --- |
| `idx_cwhs_hzpz_jzrq_yhzhhm_ywfl` | `jzrq, yhzhhm, ywfl` |

## 4. 代码里是怎么用这两个字段的

### 4.1 凭证生成阶段

1. 在 `ywjzPz` 链路生成凭证时，先根据业务关联键回查 `ywlszb`，取 `yhzhhm`。
2. 再用 `ywlx` 调 `ParamUtil.getCode(Constants.HSDWDM, xtlx, "ywlx", ywlx)`，取返回结果中的 `codeZl1` 作为 `ywfl`。
3. 如果 `codeZl1` 为空：
   - `voucher.mapping.strictMode=true`：直接抛错；
   - `voucher.mapping.strictMode=false` 且 `voucher.mapping.fallback.enable=true`：回退为 `ywlx`；
   - 否则回退为“其他分类”。
4. 最终把 `yhzhhm`、`ywfl` 一起落到 `cwhs_pz`，后续汇总后再落到 `cwhs_hzpz`。

### 4.2 凭证汇总阶段

1. 汇总查询不再按原来的 `ywlx` 分组，而是改为按 `yhzhhm + ywfl` 聚合。
2. SQL 中对空值、空串、空白统一做归并：
   - `yhzhhm` 归并到“其他账号”
   - `ywfl` 归并到“其他分类”
3. 汇总后的附件数统计、汇总凭证回写，也改为按 `yhzhhm + ywfl` 维度处理。

## 5. 达梦执行脚本

已单独落库脚本：
- `doc/数据库脚本/20260513-枣庄-凭证汇总改造-达梦执行脚本.sql`

脚本内容如下：

```sql
ALTER TABLE cwhs_pz ADD yhzhhm VARCHAR(64);
ALTER TABLE cwhs_pz ADD ywfl VARCHAR(32);

COMMENT ON COLUMN cwhs_pz.yhzhhm IS '中心账号';
COMMENT ON COLUMN cwhs_pz.ywfl IS '业务分类(由ywlx映射codeZl1)';

ALTER TABLE cwhs_hzpz ADD yhzhhm VARCHAR(64);
ALTER TABLE cwhs_hzpz ADD ywfl VARCHAR(32);

COMMENT ON COLUMN cwhs_hzpz.yhzhhm IS '中心账号';
COMMENT ON COLUMN cwhs_hzpz.ywfl IS '业务分类(由ywlx映射codeZl1)';

CREATE INDEX idx_cwhs_pz_jzrq_yhzhhm_ywfl ON cwhs_pz (jzrq, yhzhhm, ywfl);
CREATE INDEX idx_cwhs_hzpz_jzrq_yhzhhm_ywfl ON cwhs_hzpz (jzrq, yhzhhm, ywfl);
```

回滚脚本：

```sql
DROP INDEX idx_cwhs_pz_jzrq_yhzhhm_ywfl;
DROP INDEX idx_cwhs_hzpz_jzrq_yhzhhm_ywfl;

ALTER TABLE cwhs_pz DROP COLUMN yhzhhm;
ALTER TABLE cwhs_pz DROP COLUMN ywfl;
ALTER TABLE cwhs_hzpz DROP COLUMN yhzhhm;
ALTER TABLE cwhs_hzpz DROP COLUMN ywfl;
```

执行建议：
1. 先执行 DDL，再发布代码和配置。
2. 先在测试环境验证汇总、回写、附件数统计都正常，再进生产。
3. 如果现场库里已经手工建过字段或索引，执行前先核对，避免重复执行报错。

## 6. 配置文件怎么改

### 6.1 推荐改动位置

当前枣庄项目推荐把本功能配置写在区域配置文件：
- `capinfo-gjj-busi-cwhs-jzgl-basic-svc-app/src/main/resources/application-city-zaozhuang.yml`

公共 `application.yml` 保留原有通用配置和 profile 激活即可，不建议把枣庄专项灰度配置混在公共默认配置里。

### 6.2 建议增加的配置

```yaml
voucher:
  summary:
    byYwfl: true
  mapping:
    strictMode: false
    fallback:
      enable: true
```

### 6.3 配置含义

| 配置项 | 建议值 | 作用 |
| --- | --- | --- |
| `voucher.summary.byYwfl` | `true` | 开启新汇总口径，按 `yhzhhm + ywfl` 聚合；若为 `false` 则回退旧版按 `ywlx` 汇总 |
| `voucher.mapping.strictMode` | `false` | 字典映射缺失时不直接报错，允许走回退逻辑 |
| `voucher.mapping.fallback.enable` | `true` | 当 `codeZl1` 取不到时，允许 `ywfl` 回退为 `ywlx` |

### 6.4 当前代码默认值

代码里通过 `@Value` 注入的默认值如下：

```java
@Value("${voucher.summary.byYwfl:true}")
@Value("${voucher.mapping.strictMode:false}")
@Value("${voucher.mapping.fallback.enable:true}")
```

因此即使区域配置遗漏，默认行为也是：
- 开启新汇总口径
- 关闭严格模式
- 开启 `ywfl=ywlx` 回退

但为了上线可控，仍建议把配置显式写入 `application-city-zaozhuang.yml`。

## 7. 实施顺序建议

1. 执行达梦 DDL 脚本。
2. 核对 `application-city-zaozhuang.yml` 已写入 `voucher.*` 配置。
3. 发布 `capinfo-gjj-busi-cwhs-jzgl` 代码。
4. 在测试环境验证以下场景：
   - 同一 `ywlx`、不同 `yhzhhm` 会拆成多张汇总凭证；
   - 不同 `ywlx`、同一 `ywfl` 会合并汇总；
   - 历史 `NULL` / 空串数据会归并到“其他账号/其他分类”；
   - 附件数统计、回写更新口径与汇总维度一致。

## 8. 结论

本次凭证汇总改造真正涉及的表结构变更只有 2 张表：
- `cwhs_pz`
- `cwhs_hzpz`

`ywlszb` 和 `cwhs_jzpz` 只是参与取数/汇总，不需要改表结构。上线时重点是三件事：
- 先执行 DDL；
- 显式补齐 `voucher.*` 配置；
- 按 `yhzhhm + ywfl` 维度做一轮汇总回归验证。
