# 20260707-长十六进制字符串解析为 PDF 记录

## 1. 背景
- 输入内容：一段超长十六进制字符串，起始为 `789C8515F957...`。
- 目标：判断其数据类型，确认是普通文本、压缩流、加密密文还是某种二进制文件。

## 2. 分析过程
- 先按十六进制数据处理，确认其由合法的十六进制字符组成。
- 观察前缀 `78 9C`，该特征与 `zlib` 压缩头高度一致。
- 使用本机 `node` 的 `zlib.inflateSync` 对原始字节流进行解压验证。
- 解压后得到以 `%PDF-1.7` 开头的内容，确认解压结果为 PDF 文件。
- 继续校验 PDF 结构，确认存在 `xref`、`trailer`、`startxref`、`%%EOF` 等完整尾部标记。

## 3. 结论
- 原始字符串不是随机密文，也不是普通编码文本。
- 该字符串本质上是：

```text
十六进制字符串
-> 还原为二进制字节流
-> zlib 压缩数据
-> 解压后得到完整 PDF 文件
```

- 关键识别结果如下：
  - 原始字节长度：`1661` 字节
  - 解压后长度：`2359` 字节
  - 解压后文件头：`%PDF-1.7`
  - PDF 对象数：`8`
  - 页面对象数：`1`
  - PDF 结构完整性：存在 `xref`、`trailer`、`%%EOF`
  - 生成器特征：`iText 5.5.13.3`

## 4. 关键证据
- 解压后头部十六进制预览：

```text
255044462D312E370A25E5BF8FE5AB8C0A322030206F626A0A3C3C2F4C656E677468203735312F46696C7465722F466C6174654465636F64653E3E7374726561
```

- 对应可读文本预览：

```text

```

- 尾部预览：

```text

startxref

%%EOF
```

## 5. 复现方式
- 可使用如下 Node.js 命令复现：

```bash
node -e "const zlib=require('zlib'); const hex='原始十六进制字符串'; const pdf=zlib.inflateSync(Buffer.from(hex,'hex')); console.log(pdf.slice(0,16).toString());"
```

- 若需落盘为 PDF，可将解压后的 `Buffer` 写入文件。

## 6. 空白页原因补充
- 继续对解压后的 PDF 做对象级检查，确认其结构层面是完整的：
  - 存在 `Catalog`、`Pages`、`Page`、`Font`、`xref`、`trailer`、`%%EOF`
  - 页对象 `4 0 obj` 指向内容流对象 `2 0 obj`
- 但进一步检查发现，页面内容流对象 `2 0 obj` 虽声明了 `Filter/FlateDecode`，其 `stream` 原始字节无法再次被正常 `inflate`。
- 同时，在整个 PDF 可打印结构中，未检出常见的文本绘制指令或页面绘制指令，例如：
  - `BT`
  - `ET`
  - `Tj`
  - `TJ`
  - `Tm`
  - `Td`
  - `Do`
- 这说明该文件更像是：

```text
PDF 外壳完整
-> 页面对象存在
-> 但页面内容流损坏、不可正常解码，或本身未写入有效绘制指令
-> 最终查看时表现为空白页
```

- 因此，“处理完后是空白文件”并不一定是处理步骤错误，更可能是源数据本身对应的 PDF 就是空白页或损坏页内容。

## 7. 内容恢复尝试结论
- 继续针对页面内容流做了恢复性验证，尝试方向包括：
  - 直接对页内容流做 `inflate` / `inflateRaw`
  - 按 UTF-8 解码后再转回单字节序列
  - 移除疑似替换字符后重试解压
  - 对内容流做前 64 字节范围内的偏移扫描并尝试局部解压
- 上述方式均未恢复出可解析的 PDF 页面指令，也未提取出正文文本。
- 当前能够稳定提取的信息仍只有 PDF 元信息与结构信息：
  - `PDF 1.7`
  - 生成器：`iText 5.5.13.3`
  - 创建时间：`20260706154125+08'00'`
  - 单页结构存在，但页面正文不可恢复
- 结论：以当前这段十六进制数据为唯一输入，暂时**无法可靠解析出 PDF 正文内容**；更大概率是源 PDF 页面流本身已损坏，或在生成/转存时发生了不可逆损坏。
