# 修复 Agent 门下省审议后中断执行问题

## 1. 问题背景
用户反馈：在提交任务给 Agent 后，Agent 在执行完分析（输出三省规范块）后，本应按计划自动向下执行后续步骤，但目前往往会在回复完诸如“陛下，我已经阅读了最新的设计文档内容...”之类的话后，直接结束回合，等待用户再次输入指令（例如用户需要手动回复“立刻开始评审”才能继续）。

## 2. 问题排查
根据 Edict (三省六部) 工作流规范进行排查：
- **太子 (Triage)**：意图识别与初步分拣正常。
- **中书省 (Planning)**：任务规划与拆解正常，通过 `TodoWrite` 生成了步骤。
- **门下省 (Review)**：合规性审查与风险评估正常，输出了门下省的规范块。
- **原因定位**：在相关的规则和技能文件中，虽然定义了在“合规且低风险”的情况下将计划转呈“尚书省”进行执行分发，但并未**明确强制要求在同一回合内立即调用工具向下执行**。导致大模型在输出完前置的分析和规范块后，将其视作一个完整的回答逻辑闭环，从而中断并等待用户的下一步确认。

## 3. 修复方案
针对该行为进行了规则和文档层面的强制约束，确保 Agent 知道在低风险情况下的连贯执行要求。

### 3.1 修改文件清单
1. `doc/技能库/edict-review/SKILL.md` 与 `.trae/skills/edict-review/SKILL.md`
   - 在“强制门禁” / “本地补充”中增加：**严禁中断**：若风险评估为【低风险】，在回显完规范块后，必须在**同一回合**内立即调用 `edict-dispatch` 或相关工具向下执行，**绝不允许**在此处中断回复并等待用户输入指令。
2. `AGENTS.md` (本仓库 · 最高优先级指令)
   - 修改执行顺序要求：“若低风险则**必须同一回合内**继续 TodoWrite... 再调用 edict-dispatch 或 Read/Write/Shell 等工具**自动向下执行，严禁中断等待**”。
3. `.trae/rules/edict-workflow.md`
   - 在门下省章节追加“严禁中断”的要求。
4. `CLAUDE.md`
   - 补充说明：“低风险情况下，审议通过后**必须在同一回合内立即向下调度**，严禁中断等待”。

### 3.2 提取核心记忆
调用 `manage_core_memory` 将该“三省审议低风险必须自动向下执行规则”写入项目级核心记忆中，确保其长效固化。

## 4. 结论
规则更新后，当用户下达正式任务时，若门下省审议结果为低风险，Agent 将会在同一轮回复中输出规范块并**直接开始执行后续工具/任务**，不再出现“干到一半就停下来”的情况。
