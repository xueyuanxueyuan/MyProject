# 20260705-一户通独立挡板项目场景规则增强记录

## 1. 本轮目标

在既有独立挡板项目 `d:\Probject\Gjj\yht-mock-server` 基础上继续完善，使其不再只依赖固定成功模板，而是具备可配置的联调场景能力。

## 2. 本轮改动

### 2.1 后端新增场景规则仓

新增模型：

- `MockScenarioRule`
- `MockScenarioContext`

并扩展 `MockStateSnapshot` 与 `MockStoreService`，实现：

- 场景规则持久化
- 场景规则列表查询
- 场景规则保存/删除
- 按报文类型、账号、协议号、批次号、流水号匹配最优规则

### 2.2 网关模拟从“固定模板”升级为“按规则返回”

增强 `MockGatewayService`，使以下请求可受场景规则影响：

- `caps.101`
- `caps.201`
- `caps.301`
- `caps.305`
- `caps.307`
- `caps.601`
- `caps.999`

规则命中后可改变：

- `ResFlag`
- 业务状态
- 返回码
- 返回信息
- 是否自动回调
- 回调报文类型

### 2.3 协议头 / XML 切分兼容修复

修复 `CapsCodecService` 的两个兼容问题：

1. 不再只按固定头长度切分，而是优先定位 `<?xml` / `<Message` 起点
2. 解析头部前会去除换行并补齐长度，避免 `MesgType`、`ReqId`、账号等字段读空

该修复直接解决了“网关能受理，但场景规则匹配不上”的问题。

### 2.4 前端页面增强

增强页面 `src/main/resources/static/yht-mock/index.html`，新增：

- 挡板概览卡片
- 示例报文快速填充
- 场景规则管理表单
- 协议 / 交易 / 批次状态观察区
- 回调开关细项配置

## 3. 新增接口

- `GET /yht-mock/api/scenarios`
- `POST /yht-mock/api/scenarios`
- `DELETE /yht-mock/api/scenarios/{id}`

## 4. 验证结果

已完成最小验证：

1. `mvn -q -DskipTests compile` 通过
2. `GET /yht-mock/api/stats` 可返回 `scenarioCount`
3. `GET /yht-mock/index.html` 可访问增强后的前端页面
4. 新增场景规则后，`caps.201` 请求可按账号尾号命中失败规则
5. 命中规则后的交易状态可在 `/yht-mock/api/trades` 中看到：
   - `status=FAIL`
   - `resFlag=FAIL`
   - 指定 `retCode`
   - `callbackEnabled=false`
