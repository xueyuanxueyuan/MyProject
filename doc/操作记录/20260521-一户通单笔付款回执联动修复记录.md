# 一户通单笔付款回执联动修复记录

## 1. 问题现象

测试通过结算系统发起一户通单笔付款业务后，挡板向结算服务推送 `caps.205.001.01` 实时交易回执。

现象表现为：

1. 结算侧能够接收到挡板推送；
2. 接口能够返回 `caps.900` 确认；
3. 但付款业务主数据和业务结果没有继续处理。

## 2. 根因定位

### 2.1 单笔付款交易码是 `20601`

根据现有测试文档与一户通业务接入代码：

1. 单笔付款走 `caps.201 -> TranCode=20601`；
2. 单笔收款走 `caps.201 -> TranCode=20602`。

### 2.2 `caps.205` 回调处理器只补了 `20602`

在 `YhtRealtimeCallbackProcessor` 中：

1. `caps.205` 回调能够正常解析；
2. 能按 `corpNo + tranCode + serialNum + sysSeqNo` 匹配一户通任务；
3. 能更新一户通任务状态；
4. 之前只对 `20602` 调用了 `skywJfJgCl(...)`；
5. 对 `20601` 没有任何付款业务联动处理。

这就导致：

- 单笔付款回执到达后，只是“一户通任务表状态收敛”；
- 付款业务主表 / 业务结果 / 记账通知链路没有往下走。

## 3. 本次修复

### 3.1 回调处理器新增 `20601` 联动

在 `YhtRealtimeCallbackProcessor` 中新增：

1. `triggerSinglePaymentBusiness(...)`
2. 仅对 `TranCode=20601` 生效；
3. 当业务状态进入最终态时触发付款业务处理；
4. 同时覆盖成功和失败回执。

新增日志：

1. `caps.205单笔付款业务处理开始`
2. `caps.205单笔付款业务处理完成`
3. `caps.205单笔付款回执已收敛, 暂不触发业务处理`

### 3.2 结算业务层新增付款结果联动方法

在 `YwglService` / `YwglServiceImpl` 中新增：

- `fkywJfJgCl(ZjjsSFkywJgAddReqDTO ywJg, String yhdm)`

处理逻辑：

1. 通过 `jslsh` 查询付款业务；
2. 成功回执时更新 `YwJg` 为交易成功；
3. 更新银行存款日记账；
4. 调用 `tzYwjz(...)` 继续通知业务侧；
5. 失败回执时转入既有 `fkywJssbCl(...)` 失败处理链。

## 5. 当前结论

本次已从代码层补齐“一户通单笔付款 `20601` 回执 -> 付款业务结果处理”的缺口。

也就是说，现在挡板推送 `caps.205` 后，不再只是更新一户通任务状态，而会继续推进结算付款业务处理链。

1. 在测试环境重新发起一笔一户通单笔付款；
