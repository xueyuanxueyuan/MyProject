# BDC108批量付款失败原因未更新到fkyw_plmx排查记录

## 1. 排查目标

核查批量付款交易 BDC108 的处理结果，解释住建部返回失败原因为什么没有更新到 `fkyw_plmx`。

## 2. 关键链路

### 2.1 控制器入口

`YwglController.plywjgDown(BDC108ReqDTO)` 对应接口 `/plywjgDown`，方法内直接调用 `wbjkService.plywjgcx(bdc108ReqDTO)`。

### 2.2 BDC108实现

`WbjkServiceImpl.plywjgcx(BDC108ReqDTO)` 的处理逻辑：

1. 组装 BDC108 请求报文；
2. 调用住建部 BDC108 接口；
3. 解析返回报文中的批量结果文件；
4. 按 `|` 拆分文件行，封装为 `PlywJgHzRespDTO` 列表；
5. 将 `ret[24]` 映射为 `jsxym`，将 `ret[25]` 映射为 `jsxyxx`；
6. 直接 `return R.success(plywjgList)`。

该方法没有调用 `fkywPlmxDmService.editFkywPlmx(...)`，也没有更新 `zjjs_fkyw_plmx` 或 `zjjs_zj_plfkmx`。

## 3. 与真正落库链路的差异

`YwglServiceImpl.sysPlywJgCl(SysPlywJgRespDTO, ZjPlywzb)` 才包含批量业务结果落库逻辑。

批量付款 `plywlx = "01"` 时，该方法会：

1. 按 `zjPlywzb.jslsh + plywjg.xuhao` 查询 `ZjPlfkmx`；
2. 根据明细状态设置 `jszt`；
3. 更新 `ZjPlfkmx.fhzt/fhxx/hoststatus/jyrq/caphostseqno/yhje`；
4. 再按 `zxbh + jslsh + mxlsh` 查询 `FkywPlmx`；
5. 将 `zjPlfkmx.fhzt` 写入 `FkywPlmx.jsxym`；
6. 将 `zjPlfkmx.fhxx` 写入 `FkywPlmx.jsxyxx`；
7. 调用 `fkywPlmxDmService.editFkywPlmx(plmx)` 更新业务明细。

## 4. 根因结论

BDC108 返回的失败原因没有更新到 `fkyw_plmx`，直接原因是当前 `WbjkServiceImpl.plywjgcx(BDC108ReqDTO)` 只把结果文件解析成 `PlywJgHzRespDTO` 返回给调用方，未执行任何落库或业务结果分发。

换句话说，BDC108 方法里虽然解析出了：

- `jsxym = ret[24]`
- `jsxyxx = ret[25]`

但这些字段只存在于返回 DTO 中，没有进入 `YwglServiceImpl.sysPlywJgCl(...)`，因此不会触发 `fkyw_plmx.jsxym/jsxyxx` 更新。

## 5. 可能的修复方向

如需让 BDC108 下载结果后同步更新 `fkyw_plmx`，建议在 BDC108 解析结果后增加统一分发处理，复用或抽取 `sysPlywJgCl` 中的批量付款明细更新逻辑，避免重复实现。

重点要保证字段映射为：

- BDC108 明细 `ret[24]` 或明细失败码 -> `fkyw_plmx.jsxym`
- BDC108 明细 `ret[25]` 或明细失败原因 -> `fkyw_plmx.jsxyxx`
- BDC108 明细序号 `ret[14]` -> `mxlsh` 匹配键
- BDC108 批量编号 `ret[2]` -> `plbh` / 批次定位键

本次仅排查定位，未修改业务代码。
