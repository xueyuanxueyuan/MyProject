# 20260707-回归测试缺口补强

## 背景与范围

本次针对 `yht-mock-server` 模块近期生产代码变更进行回归测试缺口审查与补强，重点聚焦：

- 解析与数据校验链路的新增/修改逻辑路径
- Bug 修复（生产代码变更）但测试未同步覆盖的风险点
- 共享基础能力（XML 解析、状态持久化）的稳定性与回归风险

涉及生产代码（变更点摘要）：

- `CapsCodecService.parseXml`：改为安全 XML 解析配置（禁用 DOCTYPE / 外部实体 / 外部 DTD 等）
- `MockGatewayService.dispatch`：XML 解析失败时显式失败返回，避免后续处理与副作用
- `MockStoreService`：引入 `.bak` 备份文件与 `.tmp` 临时写入，提升持久化的原子性与可恢复性

## 识别的覆盖缺口与风险

### 1) XML 安全解析：防 XXE / DOCTYPE 注入

风险行为：

- 允许 DOCTYPE 与外部实体时可能触发 XXE 读取本地文件或造成拒绝服务
- 解析失败时若继续业务处理，可能写入错误状态或产生不可预期响应

补强策略：

- 对 `CapsCodecService.parseXml` 做“允许正常 XML / 拒绝 DOCTYPE”双路径验证
- 对 `MockGatewayService.dispatch` 的解析失败路径做覆盖（拒绝 DOCTYPE 与畸形 XML），并验证不会调用 `saveTrade` 产生写入副作用

### 2) 状态持久化：备份恢复与临时文件清理

风险行为：

- 主状态文件损坏或缺失时导致状态丢失，影响对账/签约/批次/交易的模拟回放能力
- 写入过程中异常导致半写文件，重启后无法恢复

补强策略：

- 覆盖“主文件损坏 -> 从 `.bak` 恢复”的路径
- 覆盖“主文件缺失但 `.bak` 存在 -> 从 `.bak` 恢复并重建主文件”的路径
- 覆盖“更新后不残留 `.tmp` 临时文件”的路径，降低长期运行磁盘污染与读写异常风险

  - 覆盖安全解析配置不影响正常报文解析；同时验证 `text(...)` 在命名空间报文下可取值

  - 覆盖 DOCTYPE 拒绝路径，降低 XXE/外部实体风险
- `MockGatewayServiceTest#dispatchRejectsXmlWithDoctypeInsteadOfProcessingTrade`
  - 覆盖 DOCTYPE 注入报文在网关层被拒绝；并验证不会写入交易状态

- `MockStoreServiceTest#initRestoresStateFromBackupWhenPrimaryFileIsMissing`
  - 覆盖主文件缺失但备份存在时的恢复路径，并验证主文件被重建
- `MockStoreServiceTest#updateSettingsWritesBackupAndLeavesNoTempFile`
  - 覆盖写入后 `.bak` 生成与 `.tmp` 不残留，降低持久化异常与磁盘污染风险
