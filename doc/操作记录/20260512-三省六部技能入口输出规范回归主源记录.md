# 三省六部技能入口输出规范回归主源记录

## 1. 背景
- 用户指出当前三省六部技能在实际调用时的输出，不符合 `doc/技能库/edict-*` 中定义的输出规范。
- 经核对发现：`doc/技能库/edict-*` 保留了完整的角色化交互与输出规范，而 `.trae/skills/edict-*` 已被轻量化，导致实际命中入口时容易偏离主源格式。

## 2. 核查结论
- `doc/技能库/edict-triage/SKILL.md`
- `doc/技能库/edict-planning/SKILL.md`
- `doc/技能库/edict-review/SKILL.md`
- `doc/技能库/edict-dispatch/SKILL.md`

以上 4 个文件中，均明确保留了：
- 职责定位
- 执行逻辑
- 输出规范
- “陛下”称谓与“转呈/审议/调度”语义

而 `.trae/skills/edict-*` 在此前压缩中改成了“适用场景 + 核心要求 + 主源位置 + 使用提示”的薄入口格式。

## 3. 本次处理
- 将 `.trae/skills/edict-triage/SKILL.md` 调整为“主源输出规范 + 本地补充”结构。
- 将 `.trae/skills/edict-planning/SKILL.md` 调整为“主源输出规范 + 本地补充”结构。
- 将 `.trae/skills/edict-review/SKILL.md` 调整为“主源输出规范 + 本地补充”结构。
- 将 `.trae/skills/edict-dispatch/SKILL.md` 调整为“主源输出规范 + 本地补充”结构。

## 4. 调整原则
- 输出规范、角色称谓和交互语义，以 `doc/技能库/edict-*` 主源为准。
- 本地工作区特有的总控要求（如流程技能优先、Todo 落地、验证闭环）通过“本地补充”段保留。
- 避免再次只保留轻量入口而丢失主源交互格式。

## 5. 结果
- 三省六部技能的入口层重新具备角色化交互格式。
- 后续即使直接命中 `.trae/skills/edict-*`，也能更稳定地按主源输出规范回奏。
- 主源与入口层的职责关系更清晰：主源负责完整规范，入口负责发现加载，同时保留必要的本地补充。
