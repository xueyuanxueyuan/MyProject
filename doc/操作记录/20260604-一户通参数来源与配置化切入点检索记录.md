# 20260604-一户通参数来源与配置化切入点检索记录

## 1. 检索范围
- corpNo
- feeNoList
- dsjgbm 映射
- yht 配置项
- 静态映射实现

## 2. 结论摘要
- `corpNo` 当前来源于 `yht.caps.corp-no` 配置项，经 `YhtCapsProperties.corpNo` 注入后在 `YhtServiceImpl`、`YhtProtocolRequestOrchestrator` 等处使用。
- `feeNoList` 当前主要来源于 `YhtFeeMappingServiceImpl` 的静态 `Map<String, List<String>>`，由 `dsjgbm` 映射得到。
- `dsjgbm` 目前仍在签约/解约外部 DTO 与内部签约链路中存在；收付款外层 DTO 已按文档说明开始收口。
- `yht` 配置项当前已落在 `application.yml` 的 `yht.caps.*` 下，至少包含 `base-url`、`corp-no`、`user-name`、`password`、`receiver-id`、`switch-config`、`retry`、`sign`、`encrypt`。
- 可配置化最直接切入点有三处：`YhtFeeMappingServiceImpl` 静态映射、`YhtSceneParamResolver` 硬编码默认值、`YhtCapsProperties` 单企业号模型。

## 4. 配置化建议
- 第一阶段：把 `YhtFeeMappingServiceImpl` 静态 `Map` 外提到配置文件或 Nacos。
- 第二阶段：把 `YhtSceneParamResolver` 中 `DEFAULT_FEE_NO`、`DEFAULT_SIGN_DSJGBM`、实时/批量固定码改为配置驱动。
- 第三阶段：新增统一场景解析层配置表，维护 `scene/jsqd/jbjgbh/biz_sub_type -> corpNo/tranCode/bizType/feeNo/feeNoList/dsjgbm`。
- 第四阶段：收口外部 DTO，不再要求业务侧传 `dsjgbm`、`feeNo`、`feeNoList` 等通道参数。
