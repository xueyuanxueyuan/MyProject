# 嘉兴浙商、交通、邮储交易测试发起记录

## 任务背景

- 原始测试数据文件：
  - `gjj-automation-test/test_data/jx/嘉兴公积金银行测试数据收集表（浙商银行）.xlsx`
  - `gjj-automation-test/test_data/jx/银行测试数据收集表_交通银行.xlsx`
  - `gjj-automation-test/test_data/jx/银行测试数据收集表_邮储.xlsx`
- 银行代码：
  - 浙商银行：`313041`
  - 交通银行：`301000`
  - 邮储银行：`313009`
- 测试环境：`http://k8s.jxgjj:31129`
- 测试范围：`test_main.py::TestTransaction`

## 初始问题

- 原始 Excel 虽然已经是新模板结构，但 `test_data_reader.py` 对嘉兴这 3 家银行存在两个兼容缺口：
  - 无法稳定从 Excel 内容中解析出正确 `yhdm`
  - 无法为单笔收款、单笔付款场景补齐 `fkyhmc/skyhmc`
- 首轮直接发起交易测试时，三家银行都出现同类问题：
  - 单笔收款返回 `付款银行名称编号不能为空`
  - 单笔付款虽然 HTTP 200，但业务返回 `证件类型长度不能超过2`

## 处理过程

1. 新增回归测试 `gjj-automation-test/test_data_reader_bank_name_support.py`
   - 验证原始嘉兴三家银行 Excel 可以直接推断银行代码
   - 验证可补齐默认银行名称
   - 验证对私证件类型可归一为两位编码
2. 修复 `gjj-automation-test/test_data_reader.py`
   - 增加银行名称/银行代码双向映射
   - 增加按文件名兜底识别银行代码能力
   - 修复空白中心专户行覆盖 `yhdm` 的问题
   - 为 `fkyhmc_*` 自动补齐银行名称
   - 将对私证件类型从 `身份证` 等文本归一为接口编码，如 `01`
3. 复跑嘉兴三家银行真实交易测试
   - 使用原始 Excel 文件，不再依赖临时副本
   - 分别对浙商、交通、邮储执行 `python3 -m pytest test_main.py::TestTransaction -v --tb=short -s`
