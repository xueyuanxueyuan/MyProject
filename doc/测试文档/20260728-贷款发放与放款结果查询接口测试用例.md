# 贷款发放与放款结果查询接口测试用例

> 依据当前代码整理：`YwglController` 的 BDC302、BDC303 接口，以及对应请求 DTO、校验注解和业务实现。
>
> 适用控制器前缀：`/api/v1/ywgl`

## 一、接口信息

| 接口 | HTTP 方法 | 完整路径 | 请求 DTO | 业务含义 |
|---|---|---|---|---|
| 贷款发放 | POST | `/api/v1/ywgl/zjbjyDkff` | `BDC302ReqDTO` | 校验批量明细后调用住建部 BDC302 |
| 放款结果查询 | POST | `/api/v1/ywgl/zjbjyFkjgCx` | `BDC303ReqDTO` | 按借款合同和借款人信息查询住建部 BDC303 |

请求头：

```http
Content-Type: application/json
```

> 如系统启用了登录鉴权，请按实际环境补充 `Authorization` 或其他鉴权请求头。

## 二、测试前置条件

1. 结算系统已启动，且能访问 `/api/v1/ywgl`。
2. 住建部接口通道或对应挡板已配置并可访问。
3. `zjbInterfaceHeaderReqDTO.receivenode` 使用已在银行配置中登记的 6 位中心/银行代码。下面示例使用 `105000`，仅作为测试占位值。
4. BDC302 的 `list` 不能为 `null` 或空数组；`batchtotalnum` 必须等于明细条数，`batchtotalamt` 必须等于明细 `dkje` 之和。
5. JSON 字段名应使用 Java DTO 的字段名（例如 `acctno`、`loanagrno`），不要直接使用住建部 XML 报文字段名（例如 `AcctNo`、`LoanAgrNo`）。

### 3.2 正常场景预期结果

- HTTP 请求能够正常进入接口，返回项目统一响应包装 `R`。
- 住建部成功返回时：
  - `data.zjbInterfaceHeaderRespDTO` 不为空；
  - `data.bdc302RespBodyDTO` 不为空；
  - `data.bdc302RespBodyDTO.batchNo` 不为空，表示住建部返回的贷款放款批次号。
- 服务端会根据 `receivenode`、交易代码 `BDC302` 组装住建部报文。
- 服务端会重新生成 `fileName`，因此请求中的 `fileName` 仅作为示例值，实际发送文件名以服务端生成值为准。

### 3.3 BDC302 测试用例

| 用例编号 | 场景 | 操作/数据 | 预期结果 |
|---|---|---|---|
| BDC302-001 | 单笔正常贷款发放 | 使用 3.1 完整请求；`batchtotalnum=1`，`batchtotalamt=120000.00` | 请求成功；返回 `batchNo`；数据库新增一条批量明细记录；住建部收到 BDC302 请求 |
| BDC302-002 | 多笔正常贷款发放 | `list` 增加第二条明细，例如第二条 `dkje=80000.00`；同步改为 `batchtotalnum=2`、`batchtotalamt=200000.00`，并保证两个 `mxlsh` 不重复 | 请求成功；两条明细均被处理；总笔数和总金额校验通过 |
| BDC302-003 | 缺少中心/银行代码 | 删除 `zjbInterfaceHeaderReqDTO.receivenode` 或传空字符串 | 参数校验失败，不应调用住建部接口 |
| BDC302-004 | 缺少 BDC302 请求体必填字段 | 删除 `acctno`、`bkrefloancapno`、`txdate`、`hostseqno`、`batchtotalnum`、`batchtotalamt` 中任意一个 | 参数校验失败，不应进入正常发放逻辑 |
| BDC302-005 | 缺少批量明细 | `list: []` 或不传 `list` | 业务失败，提示“批量明细不能为空” |
| BDC302-006 | 明细笔数不一致 | `list` 只有 1 条，但 `batchtotalnum=2` | 业务失败，提示“明细笔数与总笔数不符，请核实！” |
| BDC302-007 | 明细金额不一致 | 明细 `dkje=120000.00`，但 `batchtotalamt=120001.00` | 业务失败，提示“明细金额与总金额不符，请核实！” |
| BDC302-008 | 明细流水号重复 | 两条明细使用相同的 `mxlsh` | 业务失败，提示“存在重复明细流水号，请核实！” |
| BDC302-009 | 明细必填字段缺失 | 删除 `mxlsh`、`jkhtbh`、`dkdblx`、`ydfkrq`、`hkfs`、`dkje`、`jkhtll`、`llfdbl`、`jkrxm`、`jkrzjlx`、`jkrzjh`、`sfrmc`、`sfrzhhm`、`sfrzhmc`、`sfrkhhdm`、`sfrkhyhmc`、`zhlx` 中任意一个 | 参数校验失败 |
| BDC302-010 | 住建部返回业务失败 | 挡板返回 `txStatus` 非 `0` 或 `rtnCode` 非 `00000` | 当前实现会保留住建部响应头/体，并以统一响应返回业务提示；需核对 `rtnCode`、`rtnMessage` |
| BDC302-011 | 住建部连接故障 | 模拟 `invokeFront` 返回以 `-` 开头的故障串或通道不可用 | 业务失败，提示“住建部查询交易故障或住建部环境未开通” |
| BDC302-012 | 住建部响应格式错误 | 模拟成功响应但不返回有效响应体 | 业务失败，提示“查询住建部错误”或“查询住建部报文格式错误”，以全局异常处理实际包装为准 |

## 四、BDC303 放款结果查询

### 4.1 正常请求 JSON 示例

请求：`POST /api/v1/ywgl/zjbjyFkjgCx`

```json
{
  "zjbInterfaceHeaderReqDTO": {
    "txcode": "BDC303",
    "receivenode": "105000"
  },
  "bdc303ReqBodyDTO": {
    "loanagrno": "JKHT202607280001",
    "fullname": "张三",
    "doctype": "01",
    "idnum": "370402199001010011"
  }
}
```

### 4.2 正常场景预期结果

住建部成功返回且有响应体时，重点检查：

- `data.zjbInterfaceHeaderRespDTO` 不为空；
- `data.bdc303RespBodyDTO` 不为空；
- `data.bdc303RespBodyDTO.loanAcct`：贷款账号；
- `data.bdc303RespBodyDTO.issueDate`：贷款发放日期；
- `data.bdc303RespBodyDTO.loadAmt`：贷款金额；
- `data.bdc303RespBodyDTO.loanRate`：贷款利率；
- `data.bdc303RespBodyDTO.hostSeqNo`：主机流水号；
- `data.bdc303RespBodyDTO.payStatus`：贷款发放状态；
- `data.bdc303RespBodyDTO.crAcctNo`、`crAcctName`：收款账户及户名；
- `data.bdc303RespBodyDTO.payFailReason`：放款失败原因，成功时通常为空。

当 `payStatus=1` 时，当前业务实现会尝试将放款失败信息写入放款失败处理表；测试时应同时核对该表是否产生对应记录。

### 4.3 BDC303 测试用例

| 用例编号 | 场景 | 操作/数据 | 预期结果 |
|---|---|---|---|
| BDC303-001 | 查询已成功放款记录 | 使用 4.1 请求；挡板返回 `txStatus=0`、`rtnCode=00000`，并返回完整放款结果 | 请求成功；返回贷款账号、发放日期、金额、状态等字段 |
| BDC303-002 | 查询放款失败记录 | 挡板返回成功报文，设置 `payStatus=1`，并填写 `payFailReason`、`hostSeqNo`、`loadAmt` 等字段 | 接口返回放款失败结果；当前实现尝试新增放款失败处理记录 |
| BDC303-003 | 缺少中心/银行代码 | 删除 `zjbInterfaceHeaderReqDTO.receivenode` 或传空字符串 | 参数校验失败，不应调用住建部接口 |
| BDC303-004 | 缺少借款合同编号 | 删除 `loanagrno` 或传空字符串 | 参数校验失败 |
| BDC303-005 | 缺少借款人姓名 | 删除 `fullname` 或传空字符串 | 参数校验失败 |
| BDC303-006 | 缺少证件信息 | 删除 `doctype` 或 `idnum`，或传空字符串 | 参数校验失败 |
| BDC303-007 | 合同编号、姓名、证件号长度超限 | 分别超过 30、60、2、60 个字符 | 参数校验失败 |
| BDC303-008 | 住建部返回无结果/空响应体 | 模拟 `txStatus=0`、`rtnCode=00000`，但不返回业务体 | 当前实现按响应格式错误处理；核对统一异常响应 |
| BDC303-009 | 住建部返回业务失败 | 模拟 `txStatus` 非 `0` 或 `rtnCode` 非 `00000` | 当前实现抛出业务异常；由于实现层统一捕获异常，需核对最终错误提示和错误码 |
| BDC303-010 | 住建部连接故障 | 模拟 `invokeFront` 返回以 `-` 开头的故障串或通道不可用 | 业务失败，提示“住建部查询交易故障或住建部环境未开通” |

```json
  }

```


## 六、执行检查清单

- [ ] 使用实际环境可用的 `receivenode`，不要直接照搬示例值。
- [ ] BDC302 的 `batchtotalnum` 与 `list.length` 一致。
- [ ] BDC302 的 `batchtotalamt` 与所有明细 `dkje` 之和一致，精确到两位小数。
- [ ] BDC302 的每条明细 `mxlsh` 唯一。
- [ ] BDC302、BDC303 的日期字段按 `yyyyMMdd`、最多 8 位传值。
- [ ] BDC303 的 `doctype=01` 表示身份证时，`idnum` 使用与测试档案匹配的证件号码。
- [ ] 正常场景核对住建部请求是否实际发出，不只检查 HTTP 返回码。
- [ ] 失败场景同时核对接口响应、应用日志和数据库副作用。
- [ ] BDC303 `payStatus=1` 场景核对放款失败处理表是否产生记录。
