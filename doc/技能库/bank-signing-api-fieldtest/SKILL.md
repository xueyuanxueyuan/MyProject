# 银行接口实测取证纪律

用于往住建部嘉兴环境逐户/逐笔发起银行接口实测，并对外输出「通 / 不通 / 卡在谁」结论的场景。
本技能解决的核心痛点：**假失败（自己发错字段）** 与 **假确定性（把瞬时故障当缺陷）**。

## 何时使用

- 用户下达「发一笔 X 银行 Y 业务」「把 X 银行测试数据全部跑一遍」。
- 需要输出银行 × 接口连通性矩阵、单笔/批量签约报告。
- 已有报告要复验、要订正、要追加新账户。

## 三条铁律

1. **源数据为准，发报前断言**：账号、户名、证件号、手机号一律以源 `xlsx` 逐字为准，禁止凭记忆或复用旧脚本常量。发报前断言 `zh` 与源数据**逐字相等**，并断言 `hm` 与 xlsx 户名一致。
   > ⚠ **账号长度按行取值，绝不可全局硬编码**。实测口径差异极大：建行对公 20 位 / 对私 19 位，**嘉兴银行对私仅 16 位**；更坑的是**同一张 sheet 内不同行长度也可能不同**（嘉兴银行对公 sheet 同时存在 **13 位与 18 位**）。断言应写成「与源数据逐字比对」，而非写死某个数字——写死数字必然误报或漏报。
2. **一次失败不下结论**：单次失败只能记为「疑似」，定性为「确定性缺陷」至少需要**间隔数分钟**的第二次复测同串。误把瞬时故障写成确定性缺陷，比漏报更坑——它会把排查方向带偏到银行侧。
3. **报喜前回源复验全量**：补测漏掉的账户后，**必须把全量账户重打一遍**再交付。只补打漏测项会让新旧结论混在一份报告里自相矛盾。

## 标准流程

### 第 0 步：读源 xlsx 的全部 sheet

```python
import openpyxl
wb = openpyxl.load_workbook(路径, data_only=True)
for sn in wb.sheetnames:
    ws = wb[sn]
    print("===", sn, ws.dimensions, ws.max_row, ws.max_column)
    for r in ws.iter_rows(min_row=1, max_row=ws.max_row, values_only=True):
        print(" | ".join("" if c is None else str(c) for c in r))
```

- **必须打印 `ws.dimensions` 与全部行**，不要用「读到空行为止」的循环——测试数据表存在**跳号插入**（如嘉兴建行对私 `A1:N13`，序号 1-5 连续、6-10 空、11-12 有数据）。
- 核对「填写说明」sheet 末行备注，常写明后续补充行（如 `2026-09-14 JPG 截图补充 | 对私+2`），可解释跳号来源。
- 同一目录存在 `.bak`、`_修正`、`_复测` 等同名变体时，确认要用的是哪一个再读。

### 第 0.5 步：新数据并入 canonical + 建临时副本（要用非首户时）

用户新给一批账户（常见形式：微信截图，**只有「账号 + 户名」**）时的标准动作：

1. **先备份、再追加合并**（铁律：先读原文件 → 备份 → 追加合并，**禁新建覆盖**）：
   ```python
   import shutil; shutil.copy2(SRC, SRC + ".bak-YYYYMMDD-HHMM")   # 另起名字，别覆盖已有 .bak
   ```
   openpyxl 读原文件 → `ws.append([...])` 追加到对应 sheet 末行 → `wb.save(SRC)`；追加后**回读逐行复核对齐**。
2. ⚠ **截图只有账号+户名 ⇒ 证件号缺失**：对私须 `zjlx=01` + `zjh`，自行**模拟**一个 **GB11643 校验位合法**的 18 位号，并在 `备注` 注明「证件号系统模拟（银行未提供）」，交付时**显式告知用户**。若银行后端强校验「账号+户名+证件号」一致性，须回头索取真实证件号（否则可能造出「客户账户记录不存在」类假失败）。
3. **驱动单笔只取 `accts[0]`**：要用非首户（如刚并入的新户）就**建临时副本把目标户提到该 sheet 首行**，**不要改 canonical 的行序**。
   ```python
   # ✅ 唯一稳妥做法：新建 Workbook 逐 sheet 重建
   src = load_workbook(SRC, data_only=True)
   wbo = Workbook(); wbo.remove(wbo.active)
   for name in src.sheetnames:
       rows = [list(r) for r in src[name].iter_rows(values_only=True)]
       if name == "对私账户信息":
           h, d = rows[0], rows[1:]
           first = [r for r in d if r[6] in 目标户名]
           rest  = [r for r in d if r[6] not in 目标户名]
           rows = [h] + first + rest
       nws = wbo.create_sheet(name)
       for r in rows: nws.append(r)
   wbo.save(TMP)
   ```
   > ⚠ **禁用 openpyxl 原位改值重排**：`ws.cell(row, col, value=None)` **不清旧值**——改非空值生效、改 None 失效，会把「客户号/备注」串到相邻行（实测**无合并单元格**也会发生）。重排后**逐格打印**（序号/账号/证件号/姓名/备注）复核对齐，并复核 canonical **未被污染**。

### 第 1 步：发报前断言（脚本化，不靠眼睛）

```python
row = 源表按序号索引[序号]        # ← 按【序号】取行，账号/户名一律从源表读，绝不手打
zh, hm = str(row[2]), row[6]
assert len(zh) == len(str(row[2])), f"{hm} 账号长度异常 {len(zh)}: {zh}"
assert zh in 源表账号集合, f"{hm} 账号不在源表：{zh}"
```

> ⚠ **手打账号 = 定时炸弹**。测试侧错一位会造出**稳定的假失败**（如「非本行账号」「借记卡卡号不存在」），排查时会把方向带偏到银行侧。已实际踩过两次：① 建行公司五二少录 3 位 → 假「非本行账号」；② 嘉兴银行对公序号 7 把 `102101201100001750` 敲成 `102101201200001750` → 直接被断言拦下。**用序号/户名做键，账号只读不写。**

- 已实测账号长度参考（**仅供交叉验证，不作为断言常量**）：建行对公 20 / 对私 19；嘉兴银行对私 16、对公 13 与 18 并存。
- **读源数据时先打印长度分布快速体检**：`print(sorted(set(len(str(r[2])) for r in rows[1:] if r[2])))` —— 一眼看出该 sheet 有几套长度口径，避免按第一行印象套用。
- 对公无身份路径：`zhlx=2 / zjlx="" / zjh="" / tyshxydm=""`（嘉兴建行实测：对公**不需要**统一社会信用代码）。
- 对私：`zhlx=1 / zjlx=01 / zjh=证件号`。手机号列可能为空，需补真实号或占位，并在报告中标注哪些是占位。
- 个别银行有前置字段要求：嘉兴银行 / 中行 / 浙江农信单笔签约**必须带 `beizhu`**（缺失直接 `code:-9 [备注]不能为空`）；浙江农信签到/签约需 `plxmbh=C33040871BDC204`。
- `--city jiaxing` 必须显式传（默认可能是 zaozhuang），否则会打到错误环境并报权限错。

### 第 2 步：三层判读响应

| 层 | 字段 | 含义 |
|---|---|---|
| HTTP 层 | HTTP status | 非 200 = 网关/网络问题，**不进入业务层**，不要拿它当业务结论 |
| 框架层 | 外层 `code` / `msg` | `code:0` + `msg:ok` 仅代表请求被受理；`code:10000` = 后端抛异常（含网关路由、解析失败） |
| 业务层 | `data.resultValue` / `data.resultMessage` | `00000` = 业务成功；`99999` + message = 业务失败，**看 message 定性** |

状态查询补充判据：`resultQyzt`（`00`=已签约 / `03`=未签约）+ `resultHm`。**`resultHm` 是否回显正确户名**是「后端确实命中了该账户记录」的强证据；失败户通常为 `resultQyzt=03` 且 `resultHm=null`。

### 第 3 步：失败分类

| 现象 | 定性 | 归属 |
|---|---|---|
| `99999` + 「借记卡卡号不存在」「客户账户记录不存在」「非本行账号」 | 账户数据问题 | 银行侧（先自查账号是否录错！） |
| `99999` + 「该客户已经签约,不能重复签约」 | 幂等保护命中 = **已签约态** | 非失败，计入成功/已签 |
| `code:10000` + 「依据业务报文未寻址到可用服务 交易码@@xxx@@」 | 网关未找到该交易码的服务 | **首先怀疑瞬时服务未就绪**，复测 |
| `code:10000` + `For input string: "D00BHS..."` / `B1447` | 住建部后端 `NumberFormatException` | 后端缺陷，报文不可解；**但 `D00BHS` 类已实测可自愈（某行 5/5「确定性」后于另一日自行消失）→ 必须跨日复测，不得直接对外结论「永久不可用」** |
| `code:10000` + 「文件数据不能为空」 | 后端签约服务未就绪 | 后端/运维；**若同行 query 正常而 sign 不通 → 缺口在签约服务，非整条结算通道** |

### 第 4 步：瞬时 vs 确定性复测

- 同一账户**同一报文**间隔数分钟重发。
- 若同批其他账户当时正常、只有它失败且**换了时间点就通** → 瞬时故障（如后端服务注册窗口、重启窗口）。
- 若复测仍同串、或多账户稳定复现同一错误码 → 确定性缺陷。
- 判为瞬时故障时，顺手把当时**同批全部账户**再跑一遍，确认是否整批受影响。
- **长期卡点必须跨日复测**：同串连续多日只证明「**当前未恢复**」，**不证明「永久缺陷」**。后端服务恢复往往无任何通知（实测：某行 sign 连续 3 个测试日逐字同错，第 4 天直接成功）。因此输出「X 服务不可用」时必须附**观测窗口**（如「9/14–9/17 sign 不可用」），禁止写成不带日期、看来像永久结论的表述——那会误导后续排期和对外口径。
- **恢复判定必须等口径**：沿用上次**同一账户同一报文**，并同时看状态查询是否回显户名 / 承办银行。只凭 sign 返回 `00000` 单点不足以排除偶发；换账户则连「接口是否恢复」都无法判定。

### 第 4.5 步：批量签约专项（签完不算完，必须下明细核对回写）

批量（`plQyJysq`）**受理成功 ≠ 每户处理成功**。完整链路是三步：

1. `plQyJysq`（BDC130）→ 看 `data.fhzt`（`00000`=受理）+ `data.plbh`
2. `plQyJyZtcx`（BDC131）→ 看 `data.pczt`（`1`=处理完成）
3. `plQyJyMxXz`（BDC132）→ 取 `data.gjjZipData`，**去空白 → hex 解码 → `zlib.decompress` → JSON**，逐条看 `yhclzt`（`00`=成功）/ `yhsbyy`（如「交易成功」）/ `plbh`

```python
h = "".join(zip_hex.split())                  # 密文含换行，必须先剥
details = json.loads(zlib.decompress(binascii.unhexlify(h)).decode("utf-8"))
```

- ⚠ **受理成功但明细缺字段 = 回写遗漏，不是成功**。实测：某批量 2 条中 1 条**整段缺 `yhclzt/yhsbyy/plbh`**。
- ⚠ **判定「回写遗漏」前必须排除异步滞后**：隔 60s 以上**再次下载**比对；若字段仍缺**且 `updatedTime` 未变** → 方可判漏写（若 `updatedTime` 变了则可能是异步未完成）。
- 🔎 **已知相关变量**：已被单笔签约过的账户、以及位置在首条的明细，都出现过缺回写；用同批/同日另一笔做对照可缩小范围（实测同批位置 1 的**未签约**明细正常回写 → 排除「首条位置」解释，倾向「已签约明细走幂等分支不回写」）。
- ⚠ **明细条数要断言**：批量去重要求各明细**账户互不相同**；若明细数少于账户数，或同一账户回绕重复，后端可能直接 `code:10000`。构建后先 `len(details)` 与预期比对。

### 第 5 步：落盘与勘误

- 报告写清：数据源路径、逐户结果矩阵、成功/失败计数、失败分类与归属、待办责任人。
- **订正旧结论时先归档旧版**：`cp 报告.md 报告.md.YYYYMMDD-HHMM.bak`，再写新版，并在新版顶部放「勘误声明」表（上一版结论 / 复验事实 / 性质）。
- 同步刷新 `MEMORY.md` 对应银行 bullet 与当日 `YYYY-MM-DD.md`；旧版结论必须显式标注「已被 X 时点复验推翻」，不要留在记忆里当事实。
- 脚本里被证伪的常量（错账号等）就地改掉，别留给下一个人接着踩。

## 常见坑

- ❌ 只读「前 N 行有效数据」→ 漏掉跳号行的账户（建行对私漏 2 户的真实案例）。
- ❌ 账号手敲少几位 → 稳定的假失败「非本行账号」，白查一轮银行侧。
- ❌ 用**账号**当字典键或做去重 → sheet 内**存在重复账号行**（实测对公序号 1 与 11 同号不同户名；对私序号 8/16、10/15 同号），会**静默丢行**。改**按序号**建索引。
- ❌ 以为**序号列是数字** → 实测为**字符串**（`"1"` 而非 `1`），用 int 索引会 `KeyError`。
- ❌ 把网关层的「未寻址到可用服务」当业务缺陷 → 排查方向直接带偏。
- ❌ 补测后只更新补测段、不重打全量 → 报告自相矛盾。
- ❌ Bash 工具 PATH 可能损坏（`dirname: command not found` / `ls: command not found`），改用 Read/Glob/Grep 工具或 Python 一行式；venv python 用绝对路径 `C:/Users/Sour/.workbuddy/binaries/python/envs/default/Scripts/python.exe`。
- ❌ 复测时**换账户** → 无法判定「接口层是否恢复」。验证服务恢复必须**沿用上次同一账户同一报文**做等口径比对；换账户只能验证新账户，不能验证接口。
- ❌ 把「整通道不可用」与「部分恢复」混为一谈：query 通了但 sign 没通，是**结构性信息**（缺口在签约服务），不要笼统写「该行签约类仍不可用」就收工。
- ❌ 原位 `ws.cell(row, col, value=None)` 重排首户 → 旧值不清、列串行（客户号/备注串到相邻行）；**必须新建 Workbook 重建**（2026-09-22 交行踩坑）。
- ❌ 为让新户当首户而直接改 canonical 行序 → canonical 只做「备份 + 追加」，重排一律落临时副本。
- ❌ 新数据只照抄「账号+户名」→ 对私缺 `zjh` 会报「证件号码必须非空」；须模拟**校验位合法**的证件号并在备注/交付中标注来源。
- ⚠️ 逐笔单指令节奏：用户倾向明确「银行 + 业务类型 + 金额」的单独指令，日志要干净、不随意触碰其他银行。

## 输出规范

回显以下块：

```
【银行接口实测】
- 银行/环境：
- 数据源：
- 发报前断言：通过 / 不通过（明细）
- 结果矩阵：已签约 x / 失败 y（共 n 户）
- 失败分类：账户数据 a 户｜网关瞬时 b 户｜后端缺陷 c 户
- 定性依据：单次 / 复测 m 次同串（须注明是否同账户同报文）
- 观测窗口：YYYY-MM-DD ~ YYYY-MM-DD（结论仅在此窗口内成立）
- 待办归属：
- 产物：
```

拿到复测证据前，结论栏只能写「疑似 / 待复测」，不得写「确定性」。
写「某服务不可用」必须带观测窗口；跨日未复测前不得升级为不带日期的持久结论。
