# 润乾报表端到端制作技能使用说明

## 交给 AI 安装

将整个 ZIP 文件交给可以访问本机文件和终端的 AI，并发送：

> 请安装这个 `runqian-report-making` 技能。先阅读包内 `使用说明.md` 和 `SKILL.md`，自行检查本机 Codex 技能目录、Java JDK、润乾设计器、类库和许可证位置；根据本机实际路径生成 `config/local.json`，完成技能校验。不要照抄示例路径，不要复制或修改许可证内容，缺失或存在多个候选时明确告诉我。

AI 应完成以下操作：

1. 解压并确认顶层技能目录名为 `runqian-report-making`。
2. 确定技能目录：优先使用环境变量 `CODEX_HOME` 下的 `skills`；未设置时使用当前用户目录下的 `.codex/skills`。
3. 将整个技能目录复制到 `<Codex技能目录>/runqian-report-making`。若已存在同名技能，先比较文件并征得用户同意后再覆盖。
4. 首次安装时在 Windows 上运行 `scripts/detect-local-environment.ps1`。后续新对话直接复用 `config/local.json` 并运行 `scripts/validate-local-environment.ps1` 快速校验；配置缺失时重新探测，路径确认失效时才显式传 `-Force` 重建。其他系统由 AI 按 `config/local.example.json` 的字段自行探测并生成 `config/local.json`。
5. 检查 Java JDK、润乾安装根目录、设计器、许可证和每个 classpath 目录均真实存在。存在多个安装或许可证候选时停止并请用户选择。
6. 运行 `skill-creator/scripts/quick_validate.py`；如果本机没有该校验脚本，至少检查 `SKILL.md` 前置 YAML、`agents/openai.yaml` 和所有相对引用。
7. 告知用户安装路径、探测到的运行环境、校验结果和尚未解决的问题。重新打开 Codex 会话，使新技能被发现。

`config/local.json` 是本机文件，不应再次分享。它只应记录路径，不应嵌入许可证内容、账号、密码、令牌或数据库连接信息。

润乾官方对象模型检查和常规修改统一通过 `scripts/invoke-rpx-tool.ps1` 执行。固定 Java 源码保存在技能目录，编译缓存保存在本机 LocalAppData；不要在业务项目的 `.codex` 或报表目录中为每次任务创建临时 `.java`、`.class`、补丁 JSON 或检查脚本。

## 本机前置条件

- 可使用终端和本地文件的 Codex 或其他编码 AI。
- 完整 Java JDK，`java` 和 `javac` 均可用。
- 已安装润乾报表设计器及其 Java 类库。
- 本机合法可用的润乾许可证 XML。
- 修改目标 RPX、需求原型及相关代码的访问权限。

缺少上述条件时，技能仍可用于阅读需求、分析结构和编写实施说明，但不能声称已经完成 RPX 对象模型读写或真实预览。

## 最新版关键能力

本版本已经覆盖实际润乾报表从零制作和反复验收中确认的关键问题：

- 使用润乾官方对象模型读取和原位修改 RPX，逻辑行列数不依赖二进制头计数。
- 持久复用本机 `config/local.json` 和对象模型工具，新对话不重复探测已确认环境，也不重复生成临时 Java 检查程序。
- 写入前正常关闭设计器，写入后回读并重新打开同一模板，避免缓存覆盖。
- 纵向明细使用 `ds_rows.select(...)` 主格，同行字段通过左主格同步向下扩展；只显示第一条数据时优先检查 `leftHead`、`topHead` 和主格表达式。
- 快照值已经是 `19.42` 这类百分点时，使用 `0.00'%'` 显示为 `19.42%`，避免 `0.00%` 再次乘 100。
- 百分比列名保留“（%）”；金额存在全表统一单位时，不在每个金额列名中重复单位。
- 表头允许自动换行；金额、比例和同比数据默认单行显示，固定列宽不足时使用缩小适应。
- 前端固定列和主体表格使用同一行高，避免数据行越多错位越明显。
- 润乾列对象的“可视”与单元格的“隐藏列”是独立设置；必须同时检查 `getColVisible()` 和 `getColHidden()`，并覆盖合并区域从属单元格及空白单元格。

AI 修改 RPX 后至少应回读确认：逻辑行列数、参数和数据集、合并关系、主格关系、字段表达式、隐藏列状态、数值格式、换行与适应方式、字体和打印设置。

## 使用方式

安装完成后，可以直接对 AI 说：

> 使用 `$runqian-report-making`，原地修改 `D:\项目\report\example.rpx`，新增“期末余额”字段。先核对需求原型和现有数据契约，不要新建模板，不要覆盖无关改动；写入后做静态回读校验，真实预览由我验收。

也可以要求完整制作：

> 使用 `$runqian-report-making`，根据指定原型和现有前后端数据契约，从零完成目标 RPX、打印布局和预览接入。

建议每次明确提供：

- 唯一目标 RPX 的绝对路径。
- 原型、截图、需求文档或现有页面位置。
- 需要新增或调整的字段、表头、格式和布局。
- 是否允许修改后端 DTO、快照、SQL 或前端打印入口。
- 是否要求真实数据快照和打印预览验证。

## 工作边界

- 外观以用户指定的原型为准，数据以已确认的数据契约为准。
- 修改已有报表时默认原地修改唯一目标，不创建替代业务模板。
- 写入前正常关闭润乾设计器，写入后使用官方对象模型回读并重新打开同一 RPX。
- 不把示例安装路径当成其他电脑的默认路径。
- 不携带、复制、上传或修改许可证内容。
- 涉及业务 SQL、Java 或前端代码时，还必须遵守目标项目自己的规范和权限边界。

## 常见问题

### 找不到润乾安装目录

先设置 `RAQSOFT_HOME` 或 `RUNQIAN_HOME` 为包含 `bin/report.exe` 的 `report` 目录，再运行探测脚本。不要通过搜索整个网络盘来猜测安装位置。

### 找到多个许可证

不要自动选择。由用户确认与当前润乾版本和授权范围匹配的许可证，再把路径写入 `config/local.json`。

### 技能已经安装但 AI 没有触发

重新打开 Codex 会话，并明确说“使用 `$runqian-report-making`”。检查技能目录中是否直接包含 `SKILL.md`，避免多嵌套一层目录。

### 可以只修改 RPX 吗

可以。若新增字段已存在于数据集、DTO 或快照中，可仅修改 RPX；若字段尚未进入数据契约，AI 必须先说明需要修改的后端或数据集范围，不能猜字段或静默回退。

### 报表为什么只显示第一条数据

检查明细主格是否使用 `ds_rows.select(...)` 产生纵向序列，并检查同行其他数据单元格是否设置了正确的左主格。只有 `ds_rows.FIELD` 而没有扩展主格时，通常只会渲染当前第一条记录。

### 百分比为什么变成 1942.00% 或拆成两行

当源值为 `19.42` 时，应使用字面量格式 `0.00'%'`，不能使用会缩放的 `0.00%`。比例数据单元格应关闭换行并使用单行缩小适应；表头仍可自动换行。
