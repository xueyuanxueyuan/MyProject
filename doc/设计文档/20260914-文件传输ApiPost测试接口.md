# 文件传输 ApiPost 测试接口

## 范围与边界

供嘉兴查询统计服务测试独立文件传输 JAR，保留原静态方法及 Demo 旧处理样例。Demo 移入 capinfo-gjj-file-transfer/src/test/java，不再启动或依赖 CxtjApplication；现有往返测试调用迁移后的示例入口验证加解密效果。

Controller 负责 HTTP 适配，独立测试应用服务负责临时文件管理，实际协议、密钥及流水逻辑全部调用 FileTransferUtil。公共 JAR 不增加 Web Controller。

## 接口约定

- POST /api/v1/cxtj/file-transfer-test/upload：multipart/form-data，字段 txCode、yhdm、file；返回 R<UploadResult>，data 内含 fileId、digest。
- POST /api/v1/cxtj/file-transfer-test/download：JSON 字段 txCode、yhdm、fileId、digest；返回 application/octet-stream 附件，包含还原后的原文件名和原始字节。本测试接口对应单文件上传，不支持返回多文件目录。
- 空参数、空文件及含路径的文件名返回 400；不允许调用方传入服务器目录或远程地址。
- 临时目录按请求隔离，上传成功/失败及下载返回/失败后清理。下载先完成解密和摘要校验，再写入 HTTP 响应；不将文件整体读入内存。

## 启用与安全

以 gjj.zjb.file.test-api-enabled=true 显式开启；缺省关闭。提供 application-file-transfer-test.yml，需将 file-transfer-test 追加到现有 profiles，而非替换原数据库、银行环境。专用 profile 设置 multipart 单文件20MB、总请求21MB上限。沿用现有服务/网关鉴权，不新增匿名白名单，勿在生产启用。

保留用户当前地址和成功状态配置。测试接口不自动上传，不自动重试；运行调用将访问当前环境的 Redis、流水服务及住建部文件服务。

## 验证计划

独立模块往返测试验证迁移后的 Demo；MockMvc 覆盖 HTTP 上传和下载契约；应用服务测试覆盖参数、文件名、临时文件清理；条件注册测试覆盖默认关闭。最后编译 cxtj app，不调用真实住建部。

- Java17.0.2、Maven3.9.16：独立模块 clean install 成功，10项测试全部通过，Demo 入口已纳入真实加解密的模拟往返测试。
