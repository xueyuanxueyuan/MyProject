# 嘉兴与 prod 一户通无参自动恢复跑批

## 当前需求

任务参数留空，自动按业务及协议任务状态扫描所有可恢复交易。不能要求操作者提供机构、银行、方向、时间或流水列表。本设计替代上一版仅 prod、显式流水清单的调度方式。嘉兴与 prod 同步实现，保留地区已有差异。

## 状态规则

仅自动经办（jblx=a）、一户通渠道（jsqd=0103）、未逻辑删除且机构、银行、流水非空的收付款主业务。结果表缺失或状态为10/20时，若无一户通实时/批次任务则可补齐；状态50不能无依据新建交易。已有完整任务仅筛选自动处理标记N、重试次数未满3次且到达下次允许时间，同时满足 UNKNOWN/UNKNOWN + SEND_NOT_STARTED 或 FAIL/FAIL + E054/E419。任务有效性和原报文拒绝证据仍由原恢复服务再次验证。

未知发送超时、已受理、处理中、成功、取消、已记账、人工接管不作为可重发交易。未知发送继续原补查流程，不通过扩大失败状态的口径盲目扣款。

## 实施与验收

1. 补齐嘉兴上一版恢复链路，逐文件对比，保留地区差异及本地修改。
2. 新增扫描DAO与扫描服务：按主键游标分页，每页100条；本轮固定主键上界，持续处理全部页。分页大小不是业务筛选参数，也不是每轮100条上限。新增数据下一轮继续覆盖；坏数据不阻塞更大主键，单笔失败隔离。
3. 原任务处理器 yhtTradeRecoveryJobHandler 改为无参实际执行；另提供无参预检查处理器 yhtTradeRecoveryPreviewJobHandler。使用已有逐笔补齐/重发服务及原始业务键，组织/银行/方向从数据库记录读取。
4. 不自动部署、不创建或启用真实调度实例，不调用真实平台。验证两套代码编译、任务无需参数、跨页不漏数、状态过滤、失败隔离、系统暂停、重复执行防重、SQL参数绑定及既有恢复回归。

## 调度配置

| 用途 | BEAN处理器 | 任务参数 |
| --- | --- | --- |
| 正式自动跑批 | yhtTradeRecoveryJobHandler | 留空 |
| 全范围预检查，不写库不外发 | yhtTradeRecoveryPreviewJobHandler | 留空 |

配置需要的执行周期即可，不要求机构、银行、日期、收付款方向或结算流水参数。两类业务自动扫描，组织和银行从原业务行读取。旧版 JSON 参数不再解析；尤其旧 dryRun=true 不能保护正式任务不发送，升级前应停用旧调度，改用预检查处理器核对，再启用正式任务。

分页每次100条，一轮持续扫描所有页到本轮主键上界；不是只处理100笔。为避开刚接收尚在正常推进的业务，取本轮开始前60秒作为扫描时间点。新进入可恢复状态或后续新增的业务由下一轮覆盖。空创建时间的历史业务允许扫描，具体发送仍校验业务和任务。

每笔回报结算流水和结果类型，不输出原报文和账号。scanned按主业务计数，failed表示至少一个子任务失败的主业务数量；paused=true表示暂停或中断，任务报未完成，不能误判整轮完成。某笔失败继续处理后续主键；进程重启从头按最新状态扫描，已受理/成功的任务不再重发。建议使用单机串行/丢弃后续调度，避免主动设置过短任务超时导致每轮反复处理前段；不要部署多个不同调度名重复驱动同一功能。

## 状态判定说明

| 数据状态 | 本任务行为 |
| --- | --- |
| 结果表缺失，或 jszt=10/20，且没有关联一户通任务 | 校验原业务及批量原始明细，补建结果与后续一户通任务并申请发送 |
| 结果 jszt=50 且没有原一户通任务 | 不自动新建，无法仅凭失败状态证明未曾扣款 |
| 原任务 UNKNOWN/UNKNOWN 且 SEND_NOT_STARTED | 检查原任务完整性、业务有效性及重试预算后，复用原任务发送 |
| 原任务 FAIL/FAIL 且 E054/E419 | 仅当原报文和 CAPS900 拒绝证据关联校验通过时，允许有界原报文重发 |
| SEND_FAIL、其他 UNKNOWN、INIT、SENT、ACCEPTED、PROCESSING、SUCCESS | 不当作可重发数据；不明结果交由既有补查处理 |
| 主业务取消、已记账、待确认、已删除、人工经办，或协议人工接管 | 跳过 |
| 批量原始明细不完整、金额笔数不一致、局部子批次或孤立任务 | 拦截，不补造业务明细，不更换流水重发 |

SEND_NOT_STARTED只由发送边界记录确定尚未写出请求体的证据。历史SEND_FAIL不自动转换为此标记。无需新增表/字段或手工初始化状态，不应为了入选跑批直接改库状态。新建恢复走提交后异步发送，DISPATCH_REQUESTED只是本地已安排，不代表银行最终成功。

## 风险边界

运行窗口避免对同一业务进行人工取消、删除或改账；真实数据库行锁、Redis和平台集成尚需测试环境验证。任务默认无参正式执行，因此已有调度部署升级前应先停用，先使用预检查处理器核对候选范围。

## 异步发送安全复核

恢复入口给内部交易DTO设置不参与JSON传输的recovery标志，普通交易保持原行为。恢复新任务在异步工作开始和网关发送前，均复核系统暂停状态、原业务唯一性和有效状态；读取失败也停止发送。若任务已建而尚未外发，将确定未发送的结果记录为SEND_NOT_STARTED；若已进入HTTP写出阶段，则不能据异常推定未发送。依赖暂停服务采用延迟注入，避免形成服务循环依赖。

复核缩小了排队期间被取消、删除或暂停后仍发送的风险，但不代表数据库状态检查与远端受理构成原子事务；仍应避免同一业务并发人工操作。任务暂停或线程中断会返回未完成，不报告整轮成功。

方法参数注释已逐项说明，常见名称含义如下：

- jslsh / serial：原主业务结算流水，不是明细流水；明细流水另取mxlsh / serialNum，具体以所在方法为准。
- reqId：一户通请求号；existing重发复用原号，不重新编号。
- jbjgbh / org / organization：经办机构编号；yhdm / bank：主业务银行代码；corp / corpNo：配置中的一户通企业编号。
- dryRun：true仅预检查，false正式恢复。由处理器在内部固定选择，用户无需传参，旧JSON参数不参与判断。
- recovery：内部DTO标志，true启用恢复新任务发送前复核，false保留普通业务路径；不发给平台。
- collect / collection：true收款，false付款；direction以sk/fk表示，批量bizType以COLLECT/PAY表示。
- cutoff：本轮开始前60秒的固定筛选时间；afterId是已处理游标，maxId是本轮扫描上界，limit是每页读取量，不是整轮总量限制。
- requestBodyNotStarted：true是“确定尚未开始写出HTTP请求体”的证据；false只是缺少这项证据，不代表一定发送成功或失败。
- realtimeKey / batchKey / batchDetailKeys：已占用的实时、批次和明细幂等键，用来防重复提交，不是银行账号。
