# 资金风控私有模型与大模型双模式并存：成对留存、对比与报告分析补充设计

日期：2026-10-13。状态：**用户已确认“两套结果都留存可对比、任一时刻只指定一套正式生效”的业务方向；本文为待业务、模型、风控、安全、DBA、前后端联合评审的接口/数据设计，未实施、未投产批准。**

本稿补充 `20261013-资金风控私有模型保留与大模型能力承接双轨改造方案.md`；此前 `doc/评审记录/20261013-资金风控私有模型保留与大模型双轨方案专项评审.md` 只审查旧范围，**不覆盖本稿新增的双选择、成对比较及报告分析功能**。原方案的旧模型保留、出域、回测、事实校验、双签和回滚门禁继续有效。如原方案用词“切换路由”与本稿“用户可任选方式生成非正式比较结果”冲突，以本稿区分“生成/留存”和“正式生效”；正式生效仍以服务端唯一批准路由为准。此 `v2` 是新接口契约版本号，不是“只能使用新模型”，也不是将旧 API 替换或停用的开关。

## 1. 业务体验与互斥规则

前端在**模型训练、模型比较、基础/派生预测、报告生成**分别提供方式选择：`PRIVATE`（现有私有模型）、`AI_FORECAST`（获准的数值预测候选）、`BOTH`（两者一起运行并对比）；报告另有 `TEMPLATE`（原报告）和 `AI_NARRATIVE`（带事实校验的大模型报告）。方式选择属于一次任务的输入，**不能改写全局正式路由**；无 AI 候选能力/权限时 `AI_FORECAST/BOTH` 不可选，说明原因并保持 `PRIVATE` 可用。

同一业务比较组允许保留两套预测和两份报告，即使某一路失败也保留已成功一路、失败原因及不可比较标记。默认旧正式路由不变；双模式运行的两套结果均先为 `COMPARISON_ONLY`。只有符合审批门槛、具有服务端 `runId` 的单一结果可经审批正式生效，任一时刻同一机构、指标、预测期、口径/步长范围**最多一个有效正式结果版本**。`COMPARISON_ONLY` 不参与预警、调拨、正式报表取数或自动决策；比对、报告分析也不改变正式路由。已存在旧历史正式结果保留原样，迁移前不伪造其运行 ID。

## 2. 四类可用操作的产品契约

| 操作与界面 | 私有方式 | AI 方式 | BOTH/对比呈现 |
| --- | --- | --- | --- |
| 训练页 `mxxl.vue` | 沿用 `startTraining` 和现有 GRU/LSTM/ARIMA/SVR/MLP 任务、记录 | 数值候选有真实适配训练能力时执行独立训练作业；`ZERO_SHOT` 只登记基础权重/推理基线，第三方文本 LLM 没训练接口则显示“不支持训练”，不得模拟进度 | 各自任务列表、数据快照、制品版本与来源；新旧训练分数只作历史显示，不代替统一回测 |
| 模型比较页 `mxdb.vue` | 旧模型之间沿用原比较/确认最佳 | 新候选在统一评估域比较，不复用旧 `modelIds` | 新旧同数据可得时点、机构、指标、预测步长、测试折次；表格与图形显示逐期数值、误差、覆盖和风险漏报；缺可比条件禁排名，LLM 解释只作辅助 |
| 预测页 `jcyc.vue` 等 | 旧预测调用仍可访问；展示 `PRIVATE` 标签与制品 | 调新适配器产出独立 `AI_FORECAST` 运行，数字只来自受控预测模型 | 一键“同时预测”；并排曲线/表格、差额/差异率、区间、实际值（成熟后）、版本与输入摘要；选择正式生效要单独审批 |
| 报告模板页 `bgmbgl.vue` | 按原模板渲染，历史继续可下载 | 从服务端可追溯的相应预测运行/事实快照生成 `AI_NARRATIVE` 草稿，事实核验与双人审阅后渲染 | 选择“两份报告”，并排查看逐指标事实、段落引用与差异说明；若绑定比较专用预测，则两份报告都标记“试验对比、非正式”，不进入正式报告列表；报告无法映射到同一口径则只做内容层面并读并标注 `NOT_COMPARABLE` |

## 3. 关联键、状态与存储模型

由服务端创建不可变 `comparisonGroupId`，绑定 `institutionId + indicatorCode + asOfDate + horizon + timeGrain + currency + unit + dataAvailableAt + datasetSnapshotId + snapshotDigest + metricPolicyVersion`；请求 `BOTH` 时只取**一次**冻结输入，派发私有、AI 两条独立 `runId`，请求里不能让两边各自重查实时数。比较组不决定正式状态，支持重试失败一侧而不覆盖已留存一侧。若时点数据不一致，或出域脱敏/字段限制致使两侧关键预测输入不等价，则标记 `NOT_COMPARABLE` 并记录各侧实际输入摘要，不凭相同月份或共同组 ID 硬配对、排名。

`FORECAST_RUN` 新增或新建对应逻辑域字段：`runId, comparisonGroupId, sourceType=PRIVATE|AI_FORECAST, modelFamily, artifactId, artifactDigest, datasetSnapshotId, snapshotDigest, period, amount(Decimal), unit, mode=COMPARISON_ONLY|SHADOW|APPROVED_FORMAL, parentRunId(重试/修订), status, createdBy, createdAt`。一组多期点用运行主表+逐期明细；原正式预测表与新候选表分离，推荐只追加制品、运行和报告修订版本，禁止直接覆写比较历史。旧训练 ID、模型 ID、报告 ID 原样保持；历史迁移只建立授权的 `legacyReference` 映射，不伪造缺失快照摘要。

`PAIR_COMPARISON`：`comparisonId, comparisonGroupId, privateRunId, aiRunId, evaluationPolicyVersion, comparabilityStatus=PAIR_READY|PARTIAL|NOT_COMPARABLE, reasonCode, diffDigest, createdAt`；同一组若因重试或换模型有多个运行，比较关系明确指定**两个版本 ID**，不能用“最新一次”隐式配对。差异率分母为零显示“不可计算”并展示绝对差；收入/支出、净现金流与比率由各自基础指标按同一确定性公式生成，标记不平衡或基础数据缺失。历史实际值和风险标签成熟前，仅报告“预测分歧”，不写“误报/漏报”。

`REPORT_RUN`：`reportRunId, comparisonGroupId, forecastRunId, sourceType=PRIVATE_TEMPLATE|AI_NARRATIVE, purpose=COMPARISON_ONLY|FORMAL, baseDatasetSnapshotId/digest, reportSnapshotId/digest, templateId/version/digest, promptVersion, llmModelVersion, contentVersion/digest, fileRef/digest, status`；两份报告共用基础数据快照但分别冻结各自的预测金额及报告事实快照，各自绑定预测来源且可独立生成/下载/授权查询，旧模板本身不被修改。比较模式的 `PRIVATE_TEMPLATE` 必须由服务端受控快照填充模板；不能直接把旧 `generateReport` 的 `globalParams/runtimeItemValues` 作为权威事实（旧接口继续保留给未迁移场景）。绑定 `COMPARISON_ONLY` 预测的报告也必须是 `COMPARISON_ONLY`，不得被正式报表取数或对外发布引用；正式报告须重新核验选定正式预测的当前版本、审批及报告快照。模板不引用预测值的报告须记录为 `FACT_ONLY` 并说明其与预测差异分析不适用。报告比较 `REPORT_COMPARISON` 保存明确的两个 `reportRunId`、同口径事实交集、差异列表及 `COMPARABLE/PARTIAL/NOT_COMPARABLE`，没有双方同口径数据时仅允许显示“文本描述差异”，不宣称金额矛盾。

正式选择由 `FORMAL_DECISION` 引用**一个**已冻结且可正式使用的 `runId` 及路由代际/审批记录；同互斥域内生效事件必须与旧保存、定时保存、优化、回滚共用达梦事务锁及唯一约束。比较结果留存不依赖于正式选择；正式生效、撤销、回滚只追加决策事件，不删也不改另一条结果。针对旧“正式表按机构/指标/期间更新”的语义，必须先由 DBA/业务确认唯一域及修订策略：建议正式表作为批准快照的**当前投影**，历史值留在不可变运行/决策明细；旧表仍由兼容读路径提供，灰度前验证所有写者，不得静默双写出两个当前值。

## 4. 新增接口草案（共同编排，不替换旧接口）

统一在 `/api/v1/zjfk/forecast/v2` 下定义比较型 API；前端模式选择不是路由批准：

| API（草案） | 服务端行为 / 核心返回 |
| --- | --- |
| `GET /capabilities?institutionId&indicatorCode` | 返回可用模式、训练能力 `TRAIN|ZERO_SHOT|INFERENCE_ONLY|UNAVAILABLE`、授权范围、不可用原因；由服务端校验，页面状态不替代权限检查 |
| `POST /training-jobs` | `sourceType` 与冻结数据快照，私有方式在迁移期可沿用旧接口；新模式返回各自任务 ID、模型版本、训练能力和状态，不把文本 LLM 推理当训练 |
| `POST /comparison-groups` | `mode=PRIVATE|AI_FORECAST|BOTH`、机构/指标/时点/步长及 `Idempotency-Key`；服务端先取一个快照/发组 ID，再派发运行；返回 `groupId` 和两侧 `runId/status`，单边失败不撤销成功边 |
| `GET /comparison-groups/{groupId}`、`GET /comparison-groups/{groupId}/differences` | 严格按机构权限查询成对运行、逐期点、状态/错误、差异及可比性；未成熟真实标签不做准确率裁判 |
| `POST /comparison-groups/{groupId}/reports`、`GET /comparison-groups/{groupId}/reports` | `reportMode=TEMPLATE|AI_NARRATIVE|BOTH` 并指定各自 `forecastRunId`；冻结报告事实后两份独立作业，分别返回草稿/审批/渲染状态与不可比较原因 |
| `POST /report-comparisons`、`GET /report-comparisons/{id}` | 必须指定两个 `reportRunId` 和事实快照版本；确定性程序先计算事实差异，LLM 可解释但不可改数或给出无证据的因果判断 |
| `POST /document/analysis-jobs`、`GET /document/analysis-jobs/{analysisId}` | `sourceReportType=LEGACY|PRIVATE_TEMPLATE|AI_NARRATIVE, sourceReportId, analysisType=SUMMARY|RISK_REVIEW|FACT_CHECK|COMPARE, expectedDigest, Idempotency-Key`；返回独立任务、证据引用、状态与需人工核查项；`COMPARE` 还需第二报告 ID |
| `POST /formal-decisions`、`GET /formal-decisions/{id}` | 仅接受批准的 `runId`、版本、评估与审批凭证；核对当前范围唯一正式生效后短事务落库，不能由 `BOTH` 请求或报告分析自动触发 |

所有新变更接口需稳定的幂等键与请求摘要；对端未知态转对账，不能重试导致多次计费/训练。DTO、实际 URL、错误码、权限和 ID 所有权由 API/Vue/Python/DBA/风控在阶段 0 冻结；表仅为设计草案。旧 `model-comparison/confirm-best` 是旧模型比较选择，**不是**批准新 `FORMAL_DECISION`。

## 5. 对已生成报告做 AI 分析

入口为“报告历史”列表逐份操作：可选“摘要分析、风险线索、事实核验、与另一份报告比较”。前端仅传服务端 `reportId`、期望文件摘要与分析方式；后端校验报告所有权、机构、可读授权和版本，按白名单从文件服务或已冻结正文取内容，**不接受客户端上传同名伪造文件或任意 URL**。支持何种历史 DOCX/PDF 格式须先由报告负责人实际核查；解析失败、加密文件、图片扫描无法验真等返回 `UNSUPPORTED/REVIEW_REQUIRED`，不编造内容。

分析分为两层：规则层从批准的事实快照抽取机构、日期、金额、比例、预测来源和风险阈值，验证同口径及证据；文本层将最小化、经授权的报告片段送经批准的 LLM 提取摘要、矛盾候选、风险线索与建议核查项。输出每条 `findingId, evidenceRef(报告页码/段落或事实项), statement, severity, factStatus=VERIFIED|CONFLICT|UNVERIFIABLE, limitation`。历史旧报告若缺冻结快照/预测来源，则只能做文本摘要与“待核查”提示，**不得伪称完成财务事实核验**。分析结果绑定源文件/正文哈希、快照与模型/提示词版本、生成时间，独立留存和权限控制；修改报告后旧分析标 `STALE`，不得回写原报告或自动触发预警/调拨。

对比分析应先展示确定性差额和可比性，再把已授权的结构化差异交给 LLM 生成解释性文本；事实引用缺失、越权或有提示词注入时拒绝高可信叙述。真实报告出域须执行既有完整报文/用途授权与发送前撤权版本核验；模型或文件服务故障只保留可验证的规则层结论，明确标注“不含 AI 解读”。

## 6. 前端交互与状态

训练页保留现有训练按钮和历史数据，增加模式卡片、能力限制、任务来源/制品；新旧比较页在旧“模型比较”基础上新增“跨来源同口径评估”标签，不复用旧 `modelId`。预测页增加 `PRIVATE|AI_FORECAST|BOTH` 切换、共用快照确认、双列/双线对比、单边失败重试和正式生效状态徽标；报告页增加 `TEMPLATE|AI_NARRATIVE|BOTH`、报告配对视图与分析入口，草稿/核验/待审/渲染分别展示进度。默认保持原私有方式；禁止从“已生成”自动显示为“正式”，候选无资格时按钮置灰并提示原因。旧页面在灰度范围需迁移到可信运行 ID，否则按现有评审拒绝其无凭证的正式保存；灰度前必须测全调用方。

测试断言：选 `PRIVATE` 不发 AI 请求；选 `AI_FORECAST` 不覆盖旧制品；选 `BOTH` 两结果含同一快照摘要、不同运行 ID，成功一路可保留且不可比较原因可见；保存比较结果不会出现在正式预警；正式选择在并发/回滚/旧入口竞争下只能有一套生效；两份报告各绑对的预测来源；旧报告没有可信快照时标记不可事实核验；分析只读不改变原报告字节或文件摘要。前端拒绝越权模式与后端二次权限验证都需覆盖。
