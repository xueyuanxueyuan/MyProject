# 一户通挡板动账对手账户兜底开关

日期：2026-09-21

## 需求

动账通知新增「对手账户兜底」开关。开启后，所有动账通知的对手账户一律使用动账配置中的默认兜底账户生成，不再根据中心账户所属银行判断是否配置了对手账户；关闭时保持原有「按中心银行标识精确匹配 YHT_MOCK_BANK_ACCOUNT，未配置或停用即记录失败」的行为。

## 已确认口径

- 兜底账户即动账配置中已有的对手账号/户名/行号字段（默认 99993304000000000001 / 一户通模拟对账专户 / 999999999999），不新增第二组账户字段。
- 兜底开关开启时优先级高于银行配置：即使该中心银行已配置对手账户，也使用兜底账户。
- 兜底开关开启时不再要求中心银行标识非空，因此批量交易缺少中心银行标识也能生成通知。
- 兜底开关关闭时行为、报错文案与升级前完全一致，历史失败记录不受影响。
- 开关持久化在 YHT_MOCK_MOVEMENT_CFG 新列 C_FALLBACK_ENABLED，默认 0（关闭），清历史数据保留配置。

## 实现边界

- 模型：MovementSettings 增加 fallbackEnabled；validateNotificationFields 在开关开启时校验兜底账号、户名、行号非空且长度合法，保存阶段即拦截非法配置。
- 通知生成：MovementNotificationService.counterparty(centerBankId, settings) 在开关开启时直接构造兜底账户（bankId=FALLBACK，bankName=默认兜底账户）并复用 BankCounterparty.validate；关闭时走原查询分支。
- 前端：动账配置区新增「对手账户兜底」下拉（关闭=按中心银行匹配 / 开启=全部用兜底账户），随回调配置一起读取与保存。
- 页面保留原自动动账开关与手动推送流程；生成的通知快照、去重键、金额方向均不变。

## 数据库升级

Schema 版本由 3 升为 4。空库用 doc/数据库脚本/一户通挡板达梦/01-schema.sql；已有版本 3 用同目录 05-upgrade-v3-to-v4.sql（校验版本→加列默认 0→更新版本为 4）。停止所有旧实例、备份并演练后才可执行，不得对已有库重跑建库脚本，也不得只改版本号。详细步骤、回退与 WHENEVER 行在达梦客户端的兼容说明见该目录 README.md。
