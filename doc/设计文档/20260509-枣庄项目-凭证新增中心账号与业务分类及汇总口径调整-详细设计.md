# 20260509-枣庄项目-凭证新增中心账号与业务分类及汇总口径调整-详细设计

## 1. 文档信息
- 文档类型：设计文档（SDD）
- 适用范围：枣庄项目（资金结算财务核算相关链路）
- 版本：V1.0
- 编写日期：2026-05-09
- 目标系统：业务凭证生成与凭证汇总模块

## 2. 背景与目标
当前凭证生成链路未在凭证表中固化中心账号（`yhzhhm`）和业务分类（`ywfl`），且凭证汇总口径仍按业务类型（`ywlx`）统计，已不满足现行核算分析需求。

本次改造目标：
1. 在业务凭证生成时，向凭证表新增并落库：`yhzhhm`、`ywfl`。
2. `yhzhhm` 取值：由业务传递关联键从 `ywlszb` 获取权威值。
3. `ywfl` 取值：由 `ywlx` 在参数字典中映射 `codeZl1` 得到。
4. 汇总口径调整：新增按中心账号汇总，并将原按 `ywlx` 汇总改为按 `ywfl` 汇总，最终核心分组维度为 `yhzhhm + ywfl`。

## 3. 现状分析
### 3.1 现状能力
1. 凭证主流程具备完整的主表/明细落库与汇总查询能力。
2. `ywlx` 在业务链路中可获取，可作为 `ywfl` 映射输入。
3. 现有汇总逻辑可通过 SQL 分组维度调整扩展。

### 3.2 主要问题
1. 无 `yhzhhm` 字段，无法按中心账号维度核算。
2. 汇总口径按 `ywlx`，不符合按业务分类统计要求。
3. 字典映射质量（缺失、重复）与历史数据兼容需明确策略。

## 4. 术语与口径定义
1. `ywlx`：业务类型编码（现有业务字段）。
2. `ywfl`：业务分类编码，本次定义为参数字典中 `ywlx -> codeZl1` 映射结果。
3. `yhzhhm`：中心账号，来源于 `ywlszb` 的权威字段。
4. `ywlszb`：业务流水主表（权威业务快照来源）。

统一口径：
1. 生成口径：凭证生成时固化 `yhzhhm`、`ywfl`。
2. 汇总口径：按 `yhzhhm + ywfl` 聚合。
3. 展示口径：业务分类展示 `ywfl`，不再以 `ywlx` 作为汇总维度。

## 5. 总体方案设计
### 5.1 设计原则
1. 权威优先：关键维度以后端权威数据源计算，不信任前端直传核心账务维度。
2. 生成前置：在生成凭证时即完成分类映射并落库，避免汇总时重复衍生计算。
3. 兼容可回切：引入口径开关，支持灰度与快速回切。
4. 可追溯：新增字段在日志、监控、导出链路全量可见。

### 5.2 改造范围
1. 数据库：凭证主表（及必要汇总中间表）字段与索引。
2. 应用服务：凭证组装与落库逻辑。
3. 数据访问：DO/DTO/Mapper/XML。
4. 汇总查询：分组口径与导出模板。
5. 运维配置：开关、监控、告警。

## 6. 数据库设计
> 以下表名以“凭证主表”举例，实际以生产库真实表名替换。

### 6.1 DDL 变更（示例）
```sql
ALTER TABLE cwjz_ywlszb ADD yhzhhm VARCHAR(64);
ALTER TABLE cwjz_ywlszb ADD ywfl   VARCHAR(32);

COMMENT ON COLUMN cwjz_ywlszb.yhzhhm IS '中心账号';
COMMENT ON COLUMN cwjz_ywlszb.ywfl   IS '业务分类(由ywlx映射codeZl1)';
```

### 6.2 索引建议
```sql
CREATE INDEX idx_cwjz_jzrq_yhzhhm_ywfl
ON cwjz_ywlszb (jzrq, yhzhhm, ywfl);
```

若常按机构过滤：
```sql
CREATE INDEX idx_cwjz_jbjg_jzrq_yhzhhm_ywfl
ON cwjz_ywlszb (jbjgbh, jzrq, yhzhhm, ywfl);
```

### 6.3 回滚脚本（示例）
```sql
DROP INDEX idx_cwjz_jzrq_yhzhhm_ywfl;
DROP INDEX idx_cwjz_jbjg_jzrq_yhzhhm_ywfl;
ALTER TABLE cwjz_ywlszb DROP COLUMN yhzhhm;
ALTER TABLE cwjz_ywlszb DROP COLUMN ywfl;
```

## 7. 凭证生成链路详细设计
### 7.1 输入输出
1. 输入：业务关联键（如 `ywlsh/jslsh/sqbid`，按实际链路唯一键确定）、`ywlx`。
2. 输出：凭证主表记录新增字段 `yhzhhm`、`ywfl`。

### 7.2 处理流程
1. 读取业务上下文中的关联键 `sourceBizKey`。
2. 通过 `sourceBizKey` 查询 `ywlszb`，获取 `yhzhhm`。
3. 通过 `ywlx` 查询参数字典，映射得到 `ywfl = codeZl1`。
4. 组装凭证主表 DTO/DO 时写入 `yhzhhm`、`ywfl`。
5. 落库并记录审计日志。

### 7.3 伪代码
```java
String yhzhhm = ywlszbService.queryYhzhhmByBizKey(sourceBizKey);
String ywfl = dictService.getCodeZl1ByYwlx(ywlx);

cwjzYwlsDTO.setYhzhhm(yhzhhm);
cwjzYwlsDTO.setYwfl(ywfl);

receiveCwjzxx(cwjzYwlsDTO, ...);
```

### 7.4 异常处理策略
1. `yhzhhm` 为空：
- 严格模式：抛 `BizException`，阻断生成。
- 兼容模式：写 `UNKNOWN`，打告警并计数。
2. `ywfl` 映射失败：
- 严格模式：抛 `BizException`。
- 兼容模式：写 `UNMAPPED`，打告警并计数。
3. 映射歧义（一个 `ywlx` 多个 `codeZl1`）：直接视为配置错误，阻断并告警。

> 建议默认：测试/灰度期用兼容模式，稳定后切换严格模式。

## 8. 参数字典映射设计
### 8.1 服务接口
1. `String getYwflByYwlx(String ywlx)`

### 8.2 缓存策略
1. 本地缓存 `TTL=5~10分钟`。
2. 支持字典更新后主动失效。

### 8.3 数据治理
1. 上线前核对全量 `ywlx` 是否可映射。
2. 校验 `ywlx -> codeZl1` 唯一性。
3. 对停用/空值字典项提前清理。

## 9. 汇总逻辑改造设计
### 9.1 口径变更
1. 旧口径：`GROUP BY ywlx`
2. 新口径：`GROUP BY yhzhhm, ywfl`

### 9.2 SQL 示例
旧：
```sql
SELECT ywlx, SUM(ywfse) AS total_ywfse
FROM cwjz_ywlszb
WHERE jzrq = :jzrq
GROUP BY ywlx;
```

新：
```sql
SELECT yhzhhm, ywfl, SUM(ywfse) AS total_ywfse
FROM cwjz_ywlszb
WHERE jzrq = :jzrq
GROUP BY yhzhhm, ywfl;
```

### 9.3 查询与导出改造
1. 列表新增：`yhzhhm`。
2. 原“业务类型”列替换为“业务分类（`ywfl`）”。
3. 导出模板字段、表头、排序逻辑同步调整。

### 9.4 历史数据兼容
1. 历史记录 `yhzhhm/ywfl` 为空时归并为：
- `yhzhhm = 未识别账号`
- `ywfl = 未分类`
2. 报表可增加筛选项：是否隐藏“未分类”数据。

## 10. 配置与开关设计
1. `voucher.summary.byYwfl`：是否启用新汇总口径。
2. `voucher.generate.strictMode`：凭证生成是否严格校验 `yhzhhm/ywfl`。
3. `voucher.dict.cache.ttlSeconds`：字典缓存过期时间。

默认建议：
1. 新口径开关默认关闭，上线后灰度开启。
2. 严格模式默认关闭，灰度稳定后开启。

## 12. 风险评估与应对
1. 字典配置风险：
- 风险：`ywlx` 未配置或重复配置。
- 应对：上线前执行映射体检脚本并阻断发布。
2. 关联键风险：
- 风险：无法稳定定位 `ywlszb` 记录。
- 应对：需求冻结阶段确认唯一关联键，必要时多键兜底。
3. 口径变更风险：
- 风险：新旧报表数据不可直接同比。
- 应对：发布说明明确口径变更并提供对照期。
4. 性能风险：
- 风险：分组维度变更导致查询变慢。
- 应对：索引先行、灰度压测、慢 SQL 观测。

## 14. 测试设计
### 14.1 功能用例
1. 正常：`yhzhhm` 可查、`ywfl` 可映射，落库正确。
2. `yhzhhm` 缺失：验证严格/兼容策略。
3. `ywfl` 缺失：验证严格/兼容策略。
4. 同 `yhzhhm` 同 `ywfl` 多笔汇总正确。
5. 同 `yhzhhm` 不同 `ywfl` 分组拆分正确。
6. 不同 `yhzhhm` 同 `ywfl` 分组拆分正确。
7. 历史空值数据归并正确。

### 14.2 性能用例
1. 日常数据量：对比改造前后汇总接口 P95。
2. 高峰数据量：压测分组查询与导出稳定性。
3. 索引命中：检查执行计划与慢 SQL。

### 14.3 回归范围
1. 凭证生成主流程。
2. 凭证查询、汇总查询、导出。
3. 财务对账相关页面。

## 15. 发布与回滚
### 15.1 发布步骤
1. 发布应用（默认关闭新口径）。
2. 执行 DDL 与索引。
3. 开启灰度：小范围启用 `voucher.summary.byYwfl`。
4. 观察1~2个结算周期。
5. 全量开启新口径。

### 15.2 回滚策略
1. 应用回切：关闭新口径开关，恢复旧查询逻辑。
2. 严格模式回切：`strictMode=false`。
3. 数据库回滚：优先不删字段，仅逻辑回切；确需回滚再执行 DDL 回退。

## 16. 验收标准
1. 新增字段落库准确率 100%（按策略定义排除兼容兜底数据）。
2. 新汇总口径与抽样手工核算一致。
3. 开关可控且可回切，不影响主流程可用性。
4. 性能指标满足基线要求。
5. 财务与业务验收通过并留档。

## 17. 变更影响清单
1. 数据库：凭证主表结构、索引。
2. 后端：凭证生成服务、字典服务、汇总服务、导出服务。
3. 配置：新增2~3个开关配置项。
4. 运维：新增监控与告警规则。
5. 业务侧：报表口径说明与培训。

## 18. 附录
### 18.1 待确认项
1. `ywlszb` 关联键最终采用哪一个字段（`ywlsh/jslsh/sqbid`）。
2. 生产首期是否默认开启兼容模式。
3. 历史数据是否需要一次性回填 `ywfl`。

### 18.2 建议
1. 若历史数据量可控，建议离线回填 `ywfl` 以减少“未分类”占比。
2. 在上线前一天执行一次全量映射扫描，提前暴露字典脏数据。
