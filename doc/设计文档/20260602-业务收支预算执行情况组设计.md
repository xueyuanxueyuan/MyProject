# 资金预决算及执行情况 - 业务收支预算执行情况组设计

## 1. 设计范围

本组仅覆盖以下 1 张表：

- 住房公积金业务收支预算执行情况表

本组属于月度执行类报表，采用单表模式，不拆总表/附表。

## 2. 最终功能设计结论

本组最终功能设计结论如下：

1. 本表按月编制，次月填报上月数据。
2. 本表的责任主体仍是分中心，市中心负责汇总审核。
3. 本表业务值以自动取数和自动计算为主，不再设置大量手工录入项。
4. 分中心负责触发本机构取数、查看结果、确认提交；市中心负责查看全口径结果、审核、退回、锁定和导出。
5. 本表采用 `主表 + 机构执行明细表 + 前端行配置渲染` 模式。
6. 数据库存储继续按 `HSJGBH` 存机构行，不做“一个机构一列”的物理设计。
7. 前端展示还原 Excel 列样式：`全市 + 各分中心`。

## 3. Excel 原表结构拆解

## 3.1 表头结构

表头标题：

- `嘉兴市住房公积金业务收支预算执行情况表`

表头关键信息：

- 年月：如 `2025年10月`
- 编制单位：嘉兴市住房公积金管理服务中心（全市）
- 单位：万元以下两位

列头结构：

- 项目
- 全市
- 市本级
- 嘉善县
- 平湖市
- 海盐县
- 海宁市
- 桐乡市

## 3.2 行结构

本表业务行共 15 行，分为 3 个区块：

### 3.2.1 收入区

1. 本年预算数
2. 本年实绩数
3. 为本年预算数%
4. 上年同期数
5. 同比增长%

### 3.2.2 支出区

6. 本年预算数
7. 本年实绩数
8. 为本年预算数%
9. 上年同期数
10. 同比增长%

### 3.2.3 增值收益区

11. 本年预算数
12. 本年实绩数
13. 为本年预算数%
14. 上年同期数
15. 同比增长%

## 3.3 Excel 明确给出的规则语义

### 收入

- 本年预算数：`1--2月空值，3月起取预算数`
- 本年实绩数：`401收入`
- 为本年预算数%：`实绩 / 预算`
- 上年同期数：`同口径上年同期实际数`
- 同比增长%：`本年实绩 / 上年同期 - 1`

### 支出

- 本年预算数：`1--2月空值，3月起取预算数`
- 本年实绩数：`411支出`
- 为本年预算数%：`实绩 / 预算`
- 上年同期数：`同口径上年同期实际数`
- 同比增长%：`本年实绩 / 上年同期 - 1`

### 增值收益

- 本年预算数：`收入预算数 - 支出预算数`
- 本年实绩数：`收入实绩数 - 支出实绩数`
- 为本年预算数%：`实绩 / 预算`
- 上年同期数：`同表实际数`
- 同比增长%：`本年实绩 / 上年同期 - 1`

### 全市列

- 全市金额值 = 各分中心值汇总
- 全市比率值 = 汇总后的分子 / 汇总后的分母

## 4. 填报与审核权限设计

## 4.1 分中心填报人

职责：

- 仅查看 `全市 + 本机构` 两类列
- 触发本机构自动取数
- 查看本机构自动生成结果
- 确认并提交本机构执行数据
- 在退回后重新取数并再次提交

限制：

- 不能查看其他分中心原始结果
- 不能修改自动取数值
- 不能修改自动计算值
- 不能修改全市汇总值
- 不能锁定报表

## 4.2 市中心审核人

职责：

- 查看全市及全部分中心数据
- 查看系统汇总后的全市口径
- 审核、退回、锁定、导出

限制：

- 不直接改分中心原始结果
- 只能通过退回让责任分中心重新确认
- 不允许人工覆盖全市自动汇总结果

## 4.3 单元格权限规则

按照“单元格类型 + 数据归属 + 状态”控制：

1. 自动取数格
   - 全程只读
2. 自动计算格
   - 全程只读
3. 汇总展示格
   - 全程只读
4. 责任确认类元数据
   - 仅本机构、草稿/退回状态下允许编辑，例如制表人签名

## 5. 页面功能设计

## 5.1 页面定位

本表原型定位为：

- 分中心单表确认提报页
- 市中心单表汇总审核页
- Excel 结果预览页

## 5.2 页面结构

页面采用单页结构：

1. 顶部信息区
2. 工具栏区
3. 业务收支执行情况主表
4. 底部签字区

## 5.3 分中心视角

展示规则：

- 展示 `全市` 列
- 展示 `当前登录分中心` 列
- 不展示其他分中心列

按钮规则：

- 自动取数
- 保存草稿
- 提交审核

交互规则：

- 表格业务值只读
- 若取数失败，显示异常标记和失败原因
- 允许录入或确认本机构制表人信息

## 5.4 市中心视角

展示规则：

- 展示 `全市 + 全部机构` 列
- 所有业务值只读

按钮规则：

- 审核通过
- 退回
- 锁定
- 导出完整报表

## 6. 推荐数据模型

## 6.1 主表

表名：`CWHS_ZJYJS_YWSZYSZXQKB`

职责：

- 存储月报主单
- 存储年月、状态、签字、审核、锁定、取数控制信息
- 作为全部机构执行明细的父单据

## 6.2 机构执行明细表

表名：`CWHS_ZJYJS_YWSZYSZXQKFB`

职责：

- 一张月报中一个机构一行
- 存储该机构在本表中的收入、支出、增值收益执行指标
- 作为全市汇总和前端展示的唯一来源

## 7. 核心业务规则

## 7.1 预算空值规则

- 1 月、2 月：`本年预算数` 允许为空
- 3 月起：收入、支出预算值从年度预算表带入
- 增值收益预算值由收入预算减支出预算自动计算

## 7.2 自动取数值

包括但不限于：

- 收入本年实绩数：`401收入`
- 支出本年实绩数：`411支出`
- 收入上年同期数：上年同月实际值
- 支出上年同期数：上年同月实际值

规则：

- 系统自动获取
- 分中心、市中心都不可手工改写
- 取数失败允许保存草稿，不允许提交

## 7.3 自动计算值

包括但不限于：

- 收入为本年预算数%
- 收入同比增长%
- 支出为本年预算数%
- 支出同比增长%
- 增值收益预算数
- 增值收益实绩数
- 增值收益为本年预算数%
- 增值收益上年同期数
- 增值收益同比增长%
- 全市列

规则：

- 系统自动计算
- 全程只读
- 比率类全市值必须按汇总后的分子分母重算

## 8. 最终功能设计结果

业务收支预算执行情况组最终功能设计结果如下：

1. 本组是月度单表，不拆总表/附表。
2. 本组由分中心负责本机构自动取数确认与提报。
3. 市中心查看全口径数据并执行审核、退回、锁定。
4. 本组采用 `主表 + 机构执行明细表 + 行配置渲染` 模型。
5. 全市列由系统汇总生成，不允许人工调整。
6. 预算值 1-2 月允许为空，3 月起按预算表带入。
7. 前端原型应表现为“分中心确认提报、市中心只读汇总审核”。
