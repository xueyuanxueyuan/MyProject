# 资金预决算及执行情况 - 资金使用预算执行情况组设计

## 1. 设计范围

本组仅覆盖以下 1 张表：

- 住房公积金资金使用预算执行情况表

本组属于月度执行类报表，采用单表模式，不拆总表/附表。

## 2. 最终功能设计结论

本组最终功能设计结论如下：

1. 本表按月编制，次月填报上月数据。
2. 本表的填报主体是分中心，不是市中心。
3. 分中心只填报本机构允许填写的原始值，不能修改公式值、自动取数值和全市汇总值。
4. 市中心查看全市及各分中心数据，负责汇总校验、审核、退回、锁定和导出。
5. 本表采用 `主表 + 机构执行明细表 + 前端行配置渲染` 的模式。
6. 数据库存储继续按 `HSJGBH` 存机构行，不做“一个机构一列”的物理设计。
7. 前端展示继续还原 Excel 列样式：`全市 + 各分中心`。

## 3. Excel 原表结构拆解

## 3.1 表头结构

表头标题：

- `嘉兴市住房公积金归集使用预算执行情况表`

表头关键信息：

- 编制单位：嘉兴市住房公积金管理服务中心（全市）
- 年月：如 `2025年10月`
- 单位：万元以下两位

列头结构：

- 项目
- 全市
- 市本级
- 嘉善县
- 平湖市
- 海盐县
- 海宁市
- 桐乡市

## 3.3 Excel 明确给出的取数和公式语义

### 归集提取区

- 上年末余额：`取决算年末余额`
- 本年归集预算数：`取本年预算数`
- 本年归集实绩数：`201贷方科目`
- 归集完成预算数（%）：`实绩数 / 预算数`
- 上年归集同期数：`上年同期对应实绩数`
- 归集同比增长（%）：`本年 / 上年 - 1`
- 本年提取预算数：`取本年预算数`
- 本年提取实绩数：`201借方科目`
- 当年统筹调剂资金：`手工填`
- 期末余额：`上年末 + 归集 - 提取 + 统筹`

### 个人贷款区

- 上年末余额：`取决算年末余额`
- 本年发放实绩数：`121科目`
- 本年收回实绩数：`121贷 + 122贷 - 122借 - 公转商转出`
- 当年“公转商”贷款转出：`手工填，+/-`
- 期末余额：`上年末 + 发放 - 回收 - 公转商转出`
- 逾期贷款：`3-5逾期本金，大于等于6期为余额`
- 逾期贷款率：`逾期 / 期末余额`

### 全市列

大多数金额行在 Excel 中标注为：

- `水平之和`

即：

- 全市值 = 各分中心值之和

## 4. 填报与审核权限设计

## 4.1 分中心填报人

职责：

- 仅查看 `全市 + 本机构` 两类列
- 仅填报本机构允许编辑的原始值
- 可保存草稿、提交审核
- 可在退回后继续修改本机构数据

限制：

- 不能查看其他分中心原始录入列
- 不能修改自动取数值
- 不能修改自动计算值
- 不能修改全市汇总值
- 不能锁定报表

## 4.2 市中心审核人

职责：

- 查看全市及全部分中心数据
- 查看系统汇总后的全市口径
- 审核、退回、锁定、导出

限制：

- 不直接改分中心原始录入值
- 只能通过退回让责任分中心修正
- 不允许人工覆盖全市自动汇总结果

## 4.3 单元格权限规则

按照“单元格类型 + 数据归属 + 状态”控制：

1. 原始录入格
   - 仅本机构、草稿/退回状态下允许分中心编辑
2. 自动取数格
   - 全程只读
3. 自动计算格
   - 全程只读
4. 全市汇总格
   - 全程只读

## 5. 页面功能设计

## 5.1 页面定位

本表原型定位为：

- 分中心单表填报页
- 市中心单表汇总审核页
- Excel 结果预览页

## 5.2 页面结构

页面采用单页结构：

1. 顶部信息区
2. 工具栏区
3. 执行情况主表
4. 底部签字区

## 5.3 分中心视角

展示规则：

- 展示 `全市` 列
- 展示 `当前登录分中心` 列
- 不展示其他分中心列

按钮规则：

- 自动取数
- 保存草稿
- 提交审核

编辑规则：

- 仅本机构原始录入行允许输入
- 本机构公式行、自动取数行只读
- 全市列始终只读

## 5.4 市中心视角

展示规则：

- 展示 `全市 + 全部机构` 列
- 所有业务值只读

按钮规则：

- 审核通过
- 退回
- 锁定
- 导出完整报表

## 6. 推荐数据模型

## 6.1 主表

表名：`CWHS_ZJYJS_ZJSYYSZXQKB`

职责：

- 存储月报主单
- 存储年月、状态、签字、审核、锁定、取数控制信息
- 作为所有机构执行明细的父单据

## 6.2 机构执行明细表

表名：`CWHS_ZJYJS_ZJSYYSZXQKFB`

职责：

- 一张月报中一个机构一行
- 存储该机构在本表中的全部原始值、自动取数值、自动计算值
- 作为全市汇总和前端展示的唯一来源

## 6.3 为什么不采用“市中心统一填报”

因为这与已确认的共性规则冲突：

1. 只有“本机构 + 原始录入格 + 草稿/退回”允许填报人编辑。
2. 全市值必须由分中心明细自动汇总生成。
3. 市中心负责汇总查看和审核，不直接替代分中心录入原始事实值。

## 7. 核心业务规则

## 7.1 可编辑原始值

本表当前明确允许分中心填写的原始值包括：

- `当年统筹调剂资金`
- `当年“公转商”贷款转出`

如后续确认还有其他非自动来源字段，可继续扩充，但仍必须满足“原始录入格”原则。

## 7.2 自动取数值

包括但不限于：

- 上年末余额
- 本年归集实绩数
- 本年提取实绩数
- 本年发放实绩数
- 本年收回实绩数
- 逾期贷款

规则：

- 系统自动获取
- 分中心、市中心都不可手工改写
- 取数失败允许保存草稿，不允许提交

## 7.3 自动计算值

包括但不限于：

- 完成预算数（%）
- 同比增长（%）
- 期末余额
- 逾期贷款率
- 个人贷款余额占归集余额比
- 全市列

规则：

- 系统自动计算
- 全程只读
- 比率类全市值必须按汇总后的分子分母重算

## 7.4 月份空值规则

依据共性规则：

- 1 月、2 月照常生成单据
- 特定字段允许为空
- 空值不等于 0
- 导出时保留空语义

## 8. 最终功能设计结果

资金使用预算执行情况组最终功能设计结果如下：

1. 本组是月度单表，不拆总表/附表。
2. 本组由分中心填报本机构原始值。
3. 市中心查看全口径数据并执行审核、退回、锁定。
4. 本组采用 `主表 + 机构执行明细表 + 行配置渲染` 模型。
5. 全市列由系统汇总生成，不允许人工调整。
6. 自动取数失败不允许人工补录兜底。
7. 前端原型应表现为“分中心可填、市中心只读汇总审核”。
