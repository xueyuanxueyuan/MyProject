# 资金风控文件存储开关

## 已确认需求
MinIO 开启时保留现有逻辑；关闭时使用结算电子回单中的 Capinfo 统一附件服务，不接入 WZ 网智。默认开启，不修改生产配置，不迁移或删除历史文件，保留报告列表创建人姓名查询兜底。

## 方案及实施步骤
1. 在现有 MinioService 接口后采用条件装配：minio.enabled 缺省或为 true 时使用原实现，为 false 时使用 Capinfo 实现，并禁止初始化 MinioClient。
2. 复用 FileUploadServiceClient 上传、下载、查询、删除和访问链接契约，新增文件 API 依赖，不引入对结算业务模块的依赖。
3. 新存储引用使用 capinfo/附件ID/文件名，沿用 templatePath 和 reportPath 字段及现有文件名提取逻辑，不改数据库表。关闭 MinIO 后遇到旧对象路径明确提示重新上传或迁移，不能把旧路径直接当附件 ID。
4. 先测试默认、开启、关闭三种装配，再覆盖文件读写、空响应、失败响应、删除及历史路径拒绝。下载输入流关闭时必须释放远端 HTTP 响应。
5. 执行相关测试及模块编译，检查差异、记录实际结果与联调边界。

## 切换边界
开关在启动时生效，不作为运行时热切换使用。旧 MinIO 文件不会出现在 Capinfo 服务中；启用 Capinfo 前应重新上传模板。新附件回切 MinIO 后同样不能当作原桶对象使用。不自动降级到另一存储，以免隐藏配置错误或读错数据。

## 部署配置
保留 MinIO：minio.enabled=true（未配置也为 true）。使用 Capinfo：在当前环境生效配置中设置 minio.enabled=false，然后重启应用。源码 application.yml 明确保留 true，不修改已有 endpoint、账号、密钥或环境地址。

Capinfo 客户端使用结算同款 FileUploadServiceClient。通过服务发现访问 capinfo-gjj-public-file-pub-svc；如需指定直连地址，使用该公共客户端既有配置键 gjj.capinfo.gjj.public-file-pub-svc，不新造另一套地址参数。直连地址必须配置为对应环境真实文件服务地址，不是浏览器预览地址。

```yaml
minio:
  enabled: false
```

关闭的是资金风控直接使用 MinIO 的逻辑；统一文件服务本身使用哪种底层存储由文件服务决定。统一文件服务还需具备独立可用的存储和认证配置。

## 接口映射及验收
- 上传：POST /attachment/api/v2/upload，业务类型 ZJFK，子类型 document，校验成功响应与附件 ID。
- 内容下载：GET /attachment/api/v1/download，仅传一个附件 ID，按文件服务源码应返回原始文件字节，不是多文件压缩包；关闭输入流时释放 HTTP 响应。
- 存在检查：GET /attachment/api/v1/query/id/{id}，只有成功且无数据才视为不存在；网络或业务失败不能伪装成文件不存在。
- 删除：POST /attachment/api/v1/delete，校验响应数据为 true；不存在时 deleteIfExists 可直接成功。
- 链接：GET /attachment/api/v1/previewUrl/{id}，沿用统一文件服务的文件访问链接；浏览器可达性、认证和有效期需按目标环境验证。
- 旧对象路径明确提示重新上传或迁移，不对旧路径发起附件删除或查询。新引用沿用末段文件名，保持两个现有报告下载入口的文件名处理逻辑。

联调需验证：重新上传月度模板、生成报告、按记录下载、按编码路径下载、获取链接和删除。未执行生产配置变更、迁移或发布。
