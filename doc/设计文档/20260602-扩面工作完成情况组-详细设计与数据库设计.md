# 资金预决算及执行情况 - 扩面工作完成情况组详细设计与数据库设计

## 1. 设计目标

本文档用于把“扩面工作完成情况组”推进到可直接指导后端开发、前端联调和达梦建表的详细设计层级。

## 2. 本轮定版结论

本轮按最新确认口径，将本组结构定为：

1. 本表是月度单表，不拆总表/附表。
2. 分中心是唯一责任填报主体，市中心只做汇总审核。
3. 主表采用一月一单模式。
4. 明细表采用“一张报表 + 一个机构一行”的固定字段模式。
5. 主表和明细表统一使用 15 个系统字段。
6. 明细表中的 `HSJGBH` 保存具体责任机构。
7. 前端通过固定行配置把明细固定字段还原为 Excel 6 行结构。

## 3. 业务对象设计

## 3.1 主表对象

表名：`CWHS_ZJYJS_KMGZWCQKB`

定位：

- 一张月度扩面工作完成情况表一行
- 存表头、截止日期、状态、签字、审核、锁定、取数控制信息
- 不直接存 6 行业务展示值

职责：

- 作为月报主单
- 作为机构完成情况明细的父记录
- 作为状态流转、审核和锁定控制主体

## 3.2 机构完成情况明细对象

表名：`CWHS_ZJYJS_KMGZWCQKFB`

定位：

- 一张扩面完成情况表按机构拆成多行
- 一行代表一个核算机构在一个月报单中的全部扩面指标
- 是分中心提报与全市汇总的唯一来源

职责：

- 存储机构自动取数值
- 存储机构手工填报的 `目标任务`
- 存储机构自动计算值
- 存储机构确认状态与异常信息

## 4. 状态流转设计

## 4.1 主表状态

建议口径：

- `0`：草稿
- `1`：已提交
- `2`：审核退回
- `3`：审核通过
- `4`：已锁定

## 4.2 明细表状态

明细表也保留 `BBZT`：

- `0`：草稿
- `1`：已提交
- `2`：退回
- `3`：审核通过
- `4`：已锁定

作用：

- 标识具体机构当前提报状态
- 支撑“只退回责任机构”的处理模式

## 4.3 流转规则

1. 市中心创建月报主单并设置截止日期。
2. 系统初始化全部分中心明细行。
3. 系统自动取数并写入各机构 `本年实缴`、`上年实缴`。
4. 系统自动计算 `本年净增`、`净增长率`。
5. 分中心在 3 月起维护本机构 `目标任务`。
6. 系统根据 `目标任务` 计算 `完成率`。
7. 分中心保存草稿或提交本机构数据。
8. 市中心查看全市和各机构完成情况，执行审核或退回。
9. 审核通过后市中心锁定，主表与明细表全部只读。

## 5. 系统字段口径

两张表统一保留以下 15 个系统字段：

- `ID BIGINT NOT NULL`
- `ZXBH NVARCHAR(15) NOT NULL`
- `REVISION INT NOT NULL`
- `CREATOR NVARCHAR(100)`
- `CREATED_TIME TIMESTAMP(0) NOT NULL DEFAULT CURRENT_TIMESTAMP()`
- `UPDATOR NVARCHAR(100)`
- `UPDATED_TIME TIMESTAMP(0)`
- `JBJGBH NVARCHAR(30) NOT NULL`
- `JBJGMC NVARCHAR(90) NOT NULL`
- `WDBH NVARCHAR(30)`
- `WDMC NVARCHAR(90)`
- `QDLX NVARCHAR(10)`
- `QDBM NVARCHAR(16)`
- `DEL_FLAG NVARCHAR(1) NOT NULL DEFAULT '0'`
- `HSJGBH NVARCHAR(10) NOT NULL DEFAULT '01'`

说明：

- 主表中的 `HSJGBH` 保存全市口径，如 `01`
- 明细表中的 `HSJGBH` 保存实际责任机构

## 6. 字段类型规则

人数/任务字段统一使用：

- `DECIMAL(20,4)`

- `DECIMAL(20,6)`

编号、状态、标识类字段统一使用：

- `VARCHAR2`

## 8. 可编辑字段范围

本组分中心只允许：

- 触发自动取数
- 保存确认状态
- 提交本机构结果
- 在 3 月起维护本机构 `目标任务`
- 维护制表人等元数据

其余字段规则：

- 自动取数值：只读
- 自动计算值：只读
- 全市汇总值：只读，不落明细表

## 9. 自动取数与计算设计

## 9.1 自动取数映射

- `BN_SJ <- 截止日期时点本年实缴人数`
- `SN_SJ <- 上年同截止日期本年实缴人数`

规则：

- 系统自动获取
- 若取数失败允许保存草稿，不允许提交
- 取数口径必须挂在截止日期上，确保月报快照可追溯

## 9.2 手工填报映射

- `MB_RW <- 1月、2月为空；3月起由分中心填报并沿用全年`

规则：

- 1 月、2 月显示为空值
- 3 月起仅本机构、草稿/退回状态可编辑
- 若 4 月后未改值，则沿用已生效的年度任务值

## 9.3 自动计算规则

- `BN_JZ = BN_SJ - SN_SJ`
- `JZZL = BN_JZ / SN_SJ`
- `WC_L = BN_SJ / MB_RW`

说明：

- `SN_SJ` 为空或 0 时，`JZZL` 返回空
- `MB_RW` 为空或 0 时，`WC_L` 返回空
- `1 月、2 月` 的 `WC_L` 默认返回空

## 9.4 全市列

- 金额行：全市值 = 全部分中心值求和
- 比率行：全市值 = 汇总分子 / 汇总分母

对应关系：

- 全市 `本年净增 = 全市本年实缴 - 全市上年实缴`
- 全市 `净增长率 = 全市本年净增 / 全市上年实缴`
- 全市 `完成率 = 全市本年实缴 / 全市目标任务`

## 10. 接口设计

## 10.1 查询页面

`GET /api/zjyjs/kmgzwcqk/{mainId}`

返回内容：

- 主表信息
- 当前角色可见列范围
- 全机构完成情况明细数组
- 行配置数组
- 当前机构取数状态

## 10.2 自动取数

`POST /api/zjyjs/kmgzwcqk/fetchBranch`

作用：

- 按主表年月、截止日期和当前机构重新自动取数
- 更新本机构自动取数项
- 重算本机构和全市公式项

## 10.3 保存本机构草稿

`POST /api/zjyjs/kmgzwcqk/saveBranch`

作用：

- 保存本机构 `目标任务` 和制表人等元数据

## 10.4 分中心提交

`POST /api/zjyjs/kmgzwcqk/submitBranch`

作用：

- 仅提交本机构行
- 行状态改为已提交
- 触发主表汇总状态刷新

## 10.5 市中心审核

- `POST /api/zjyjs/kmgzwcqk/review`
- `POST /api/zjyjs/kmgzwcqk/reject`
- `POST /api/zjyjs/kmgzwcqk/lock`

## 11. 业务流程

## 11.1 建单与初始化

1. 市中心创建月报主表并设置截止日期。
2. 系统初始化全部分中心明细行。
3. 系统根据年月和截止日期批量取数。
4. 系统重算本年净增、净增长率。
5. 若月份大于等于 3，则带入已生效的年度目标任务。

## 11.2 分中心填报流程

1. 分中心进入页面。
2. 系统仅返回全市列和本机构列。
3. 分中心点击自动取数，查看本机构结果。
4. 若月份大于等于 3，分中心可维护 `目标任务`。
5. 系统实时计算 `完成率`。
6. 分中心保存草稿并提交本机构数据。

## 11.3 市中心审核流程

1. 市中心打开扩面完成情况表。
2. 查看全市列及全部分中心列。
3. 核对异常机构和结果勾稽。
4. 审核通过或退回责任机构。
5. 审核通过后执行锁定。

## 12. 数据流与关联

## 12.1 数据流

1. 扩面业务统计口径和上年同期数据进入自动取数服务。
2. 自动取数服务写入机构完成情况明细表。
3. 分中心录入或确认 `目标任务`。
4. 公式计算服务计算净增、净增长率、完成率。
5. 汇总服务生成全市展示值。
6. 前端按行配置渲染 6 行 Excel 结构。

## 12.2 数据关联

- 主表和明细表使用 `MAIN_ID + BBBH` 双关联。
- 明细表使用 `HSJGBH` 区分责任机构。
- 全市列不落库，由明细汇总生成。
