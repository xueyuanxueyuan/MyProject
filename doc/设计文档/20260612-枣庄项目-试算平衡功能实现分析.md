# 枣庄项目试算平衡功能实现分析

## 1. 需求结论

- 来源文档：`doc/需求文档/1.1.1.1. 试算平衡.md`
- 功能目标：财务会计岗选择账套、截至日期后，统计资产、负债、净资产、收入、支出余额，并按 `资产 = 负债 + 净资产 + 收入 - 支出` 校验是否平衡。
- 输入项：
  - 财务账套
  - 截至日期
- 输出项：
  - 资产
  - 资产合计
  - 负债
  - 净资产
  - 收入
  - 支出
  - 负债合计

## 3. 现状与需求差异

### 3.1 输入口径差异

- 需求要求：账套 + 截至日期
- 现有总账余额表：账套 + 年度 + 月度
- 影响：
  - 现有实现只能按整月月末口径统计
  - 需求要求支持任意截至日期

### 3.2 输出口径差异

- 需求要求展示五类金额：
  - 资产
  - 负债
  - 净资产
  - 收入
  - 支出
- 现有总账余额表只按余额方向分组：
  - 借方组
  - 贷方组
- 影响：
  - 无法直接区分“净资产”“收入”“支出”
  - 不能直接输出“负债合计 = 负债 + 净资产 + 收入 - 支出”

### 3.3 业务校验差异

- 需求公式：`资产 = 负债 + 净资产 + 收入 - 支出`
- 现有页面校验：`资产合计 = 负债及所有者权益合计`
- 影响：
  - 当前页面逻辑与试算平衡需求不完全一致
  - 需要新增专门的试算平衡汇总逻辑

## 4. 推荐实现方案

## 4.1 总体方案

推荐在 **账簿管理模块基础上新增“试算平衡”专用接口和页面**，不要直接复用现有 `newzzyeb.vue` 页面逻辑。

原因：

1. 现有 `listZzyebZbgl` 的查询口径是“年度 + 月度”，与“截至日期”不一致。
2. 现有返回结果是“一级科目列表”，而需求更适合返回“分类汇总结果”。
3. 现有前端按借贷方向分组，不能满足五类科目拆分。
4. 试算平衡应作为独立功能，后续更容易扩展导出、月结准入校验和异常提示。

## 4.2 后端设计

### 4.2.1 新增接口位置

建议放在：

- Controller：`CwhsZbglController`
- Service：`CwhsZbglService`
- Impl：`CwhsZbglServiceImpl`

建议新增接口：

- `POST /api/v1/cwhs/querySsphZbgl`

命名说明：

- `Ssph` 可表示“试算平衡”
- 保持与账簿管理模块接口命名风格一致

### 4.2.2 新增 DTO

建议新增请求 DTO：

- `SsphReqDTO`
  - `zxbh`
  - `jbjgbh`
  - `ztbh`
  - `jzrq`

建议新增响应 DTO：

- `SsphRespDTO`
  - `zcbalance` 资产
  - `zchj` 资产合计
  - `fzbalance` 负债
  - `jzcbalance` 净资产
  - `srbalance` 收入
  - `zcbalanceExpense` 支出
  - `fzhj` 负债合计
  - `phjg` 平衡结果
  - `phxx` 平衡说明
  - `jzrq` 截至日期
  - `ztbh`

如果前端需要明细穿透，可补充：

- `List<SsphDetailRespDTO> details`

### 4.2.3 SQL 设计建议

推荐新增 Mapper：

- `SsphZbglMapper`
- `SsphZbglMapper.xml`

核心思路：

1. 从 `cwhs_kmxx` 取一级科目。
2. 按科目前缀做分类汇总：
   - `1%` -> 资产
   - `2%` -> 负债
   - `3%` -> 净资产
   - `4%` -> 收入/支出
3. 余额取数统一使用：
   - `f_cwhs_getKmye(ztbh, kmbh, #{jzrq})`
4. 收入和支出的拆分不要只看借贷方向，建议结合科目编码或科目属性精确区分。

### 4.2.4 收入与支出的识别建议

这是实现时最关键的一点。

现有系统里：

- 一级科目 `4` 是“收入和支出类”
- 但需求需要拆成“收入”和“支出”两个栏目

建议优先按以下顺序确认口径：

1. **优先看科目编码规则**
   - 若 `4` 下已经按二级或三级编码区分收入和支出，应通过科目编码前缀拆分
2. **其次看科目余额方向**
   - 收入通常贷方余额
   - 支出通常借方余额
3. **必要时补充配置表**
   - 新增“试算平衡科目分类配置”
   - 避免硬编码导致后续账套口径差异

如果当前枣庄账套编码规则稳定，建议优先用“科目编码前缀 + 余额方向”双重判断。

### 4.2.5 公式实现

后端建议统一返回：

- `资产 = sum(资产类科目余额)`
- `负债 = sum(负债类科目余额)`
- `净资产 = sum(净资产类科目余额)`
- `收入 = sum(收入类科目余额)`
- `支出 = sum(支出类科目余额)`
- `资产合计 = 资产`
- `负债合计 = 负债 + 净资产 + 收入 - 支出`

再计算：

- `isBalanced = 资产合计.compareTo(负债合计) == 0`

### 4.2.6 可复用现有能力

可以复用的现有点：

1. `CwhsZbglController` 的登录用户注入方式
2. `CwhsZbglServiceImpl` 的账簿查询组织方式
3. `f_cwhs_getKmye()` 余额取数函数
4. `CwhsServiceImpl` 中已有的平衡检查异常提示风格

不建议直接复用的点：

1. `listZzyebZbgl` 的“年度 + 月度”入参模型
2. `newzzyeb.vue` 的借贷分组页面逻辑
3. `phjc` 聚合检查接口，因为它偏检查任务，不是试算平衡汇总报表

## 6. 风险点

### 6.1 最大风险：收入/支出口径

如果枣庄账套没有统一的收入、支出编码规则，则不能只靠一级科目 `4` 直接拆分，必须与业务方确认：

- 收入类科目范围
- 支出类科目范围
- 是否允许按余额方向划分

### 6.2 截至日期口径

现有总账余额表是整月口径，而试算平衡要求截至日期口径，实现时必须确认：

- 是否允许查询任意自然日
- 还是仅允许查询月末日期

若月结准入使用，通常更推荐：

- 仅允许选择会计期间末日

### 6.3 月结准入联动

需求说明里提到“月末的平衡结果可作为月结准入检查依据”，因此建议后续扩展：

- 在月结前调用试算平衡接口
- 若不平衡则禁止月结

## 7. 最终建议

建议采用 **“新增试算平衡独立接口 + 新增独立页面 + 复用现有余额函数”** 的方案落地。

该方案优点：

- 改动范围清晰
- 与现有账簿管理模块结构一致
- 能准确适配“截至日期 + 五类汇总 + 平衡公式”
- 后续容易接入月结准入校验

不建议仅修改现有 `newzzyeb.vue`，因为它当前是“总账余额表”，不是“试算平衡”，两者在输入、分组、公式上都不完全一致。

## 8. 已确认的最终取值口径

根据最新确认，试算平衡各项全部按 **一级科目余额** 取值，分类规则固定如下：

- 资产：`kmbh like '1%' and kmjb = 1`
- 负债：`kmbh like '2%' and kmjb = 1`
- 净资产：`kmbh like '3%' and kmjb = 1`
- 收入：`kmbh like '401%' and kmjb = 1`
- 支出：`kmbh like '411%' and kmjb = 1`

余额统一通过以下函数按截至日期取值：

- `f_cwhs_getKmye(ztbh, kmbh, jzrq)`

汇总公式固定为：

- 资产合计 = 资产
- 负债合计 = 负债 + 净资产 + 收入 - 支出
- 平衡结果 = 资产合计 是否等于 负债合计
