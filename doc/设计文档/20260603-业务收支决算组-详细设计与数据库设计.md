# 资金预决算及执行情况 - 业务收支决算组详细设计与数据库设计

## 1. 设计目标

本文档用于把“业务收支决算组”推进到可直接指导后端开发、前端联调和达梦建表的详细设计层级。

本组范围仅包含：

- 住房公积金业务收支决算总表
- 住房公积金业务收支决算附表

本组关联文档：

- [业务收支决算组设计.md](file:///home/source/Jetbrains/Probject/Gjj/doc/设计文档/20260603-业务收支决算组设计.md)

## 2. 本轮定版结论

本轮按已确认口径，将业务收支决算组结构定为：

1. 附表承接机构决算来源结果，是总表的唯一实绩来源。
2. 总表采用“主表 + 总表明细行”模式。
3. 附表继续采用“一张报表 + 一个机构一行”的固定字段模式。
4. 总表、总表明细、附表明细统一使用 15 个系统字段。
5. 总表与附表统一使用 `MAIN_ID + BBBH` 双关联。
6. 本组不开放常规金额手工录入，只允许同步来源和确认流转。
7. 总表接口返回 12 行 `details` 数组，附表接口返回机构明细数组。

## 3. 业务对象设计

## 3.1 总表主表对象

表名：`CWHS_ZJYJS_YWSZJSZB`

定位：

- 一张年度业务收支决算总表一行
- 存表头、状态、同步时间、审核、锁定等控制信息
- 不直接存 12 行业务值

职责：

- 作为业务收支决算主单
- 作为总表明细和附表明细的父记录
- 作为状态流转、审核和锁定控制主体

## 3.2 总表明细对象

表名：`CWHS_ZJYJS_YWSZJSZMX`

定位：

- 一张总表的 12 行业务项逐行存储
- 一行代表 Excel 总表中的一个项目
- 存该行的 `SNTQS`、`BNYSS`、`BNSJS`、`YSWCL`、`BSTQZZ`

职责：

- 直接承载总表展示数据
- 直接支撑总表前端与 Excel 导出
- 避免总表主表字段膨胀

## 3.3 附表明细对象

表名：`CWHS_ZJYJS_YWSZJSFB`

定位：

- 一张附表按机构拆成多行
- 一行代表一个核算机构在一个决算单中的全部固定字段
- 是机构来源展示、总表实绩汇总和流转确认的基础

职责：

- 存储机构来源结果
- 存储机构公式计算结果
- 存储机构同步状态与流转状态
- 为总表明细提供全市实绩来源

## 4. 状态流转设计

统一状态建议：

- `0`：草稿
- `1`：已提交
- `2`：审核退回
- `3`：审核通过
- `4`：已锁定

流转规则：

1. 市中心创建业务收支决算主单。
2. 系统初始化总表 12 行明细和附表机构行。
3. 系统执行来源同步，抓取上年决算、本年预算和 12 月执行结果。
4. 分中心查看本机构附表结果并提交确认。
5. 市中心审核通过或退回。
6. 审核通过后，市中心执行锁定。
7. 锁定后总表主表、总表明细、附表明细全部只读。

## 5. 系统字段口径

三张表统一保留以下 15 个系统字段：

- `ID BIGINT NOT NULL`
- `ZXBH NVARCHAR(15) NOT NULL`
- `REVISION INT NOT NULL`
- `CREATOR NVARCHAR(100)`
- `CREATED_TIME TIMESTAMP(0) NOT NULL DEFAULT CURRENT_TIMESTAMP()`
- `UPDATOR NVARCHAR(100)`
- `UPDATED_TIME TIMESTAMP(0)`
- `JBJGBH NVARCHAR(30) NOT NULL`
- `JBJGMC NVARCHAR(90) NOT NULL`
- `WDBH NVARCHAR(30)`
- `WDMC NVARCHAR(90)`
- `QDLX NVARCHAR(10)`
- `QDBM NVARCHAR(16)`
- `DEL_FLAG NVARCHAR(1) NOT NULL DEFAULT '0'`
- `HSJGBH NVARCHAR(10) NOT NULL DEFAULT '01'`

说明：

- 主表中的 `HSJGBH` 保存全市口径，如 `01`
- 总表明细中的 `HSJGBH` 与主表保持一致
- 附表明细中的 `HSJGBH` 保存具体确认机构

void recalcDetail(DecisionFbDetail detail) {
    detail.setYwsrHj(nvl(detail.getYwsrZfgjjlxs())
        + nvl(detail.getYwsrZzsylxs())
        + nvl(detail.getYwsrWtdklxs())
        + nvl(detail.getYwsrGdtzsr())
        + nvl(detail.getYwsrQtsr()));

    detail.setYwszHj(nvl(detail.getYwszZfgjjlxzc())
        + nvl(detail.getYwszGjsxfzc())
        + nvl(detail.getYwszWtdksxfzc())
        + nvl(detail.getYwszQtzc()));

    detail.setZzsy(nvl(detail.getYwsrHj()) - nvl(detail.getYwszHj()));
}

## 10.2 总表生成

```java
void syncTotalDetails(Long mainId) {
    Map<String, BigDecimal> actualMap = sumFbFields(mainId);
    Map<String, BigDecimal> budgetMap = loadBudgetValues(mainId);
    Map<String, BigDecimal> lastYearMap = loadLastYearDecisionValues(mainId);

    for (DecisionZbDetail row : listZbDetails(mainId)) {
        row.setSntqs(lastYearMap.get(row.getXmbm()));
        row.setBnyss(budgetMap.get(row.getXmbm()));
        row.setBnsjs(actualMap.get(row.getXmbm()));

        if (isRatioApplicable(row.getXmbm())) {
            row.setYswcl(calcRatio(row.getBnsjs(), row.getBnyss()));
            row.setBstqzz(calcGrowth(row.getBnsjs(), row.getSntqs()));
        } else {
            row.setYswcl(null);
            row.setBstqzz(null);
        }

        updateZbDetail(row);
    }
}
```

## 10.3 同步来源流程

```java
DecisionMain syncAll(String nd, String operator) {
    DecisionMain main = getOrCreateMain(nd, operator);

    List<DecisionFbDetail> details = buildOrLoadFbDetails(main);
    Map<String, ExecutionSnapshot> execMap = loadDecemberExecution(nd);
    Map<String, BudgetSnapshot> budgetMap = loadBudgetSnapshot(nd);
    Map<String, LastYearDecisionSnapshot> lastYearMap = loadLastYearDecision(nd);

    for (DecisionFbDetail detail : details) {
        fillFromExecution(detail, execMap.get(detail.getHsjgbh()));
        fillFromBudget(detail, budgetMap.get(detail.getHsjgbh()));
        fillFromLastYear(detail, lastYearMap.get(detail.getHsjgbh()));
        recalcDetail(detail);
        detail.setQszt("1");
        updateFbDetail(detail, operator);
    }

    syncTotalDetails(main.getId());
    main.setQssj(now());
    updateMain(main, operator);
    return main;
}
```

## 11. 数据流转设计

1. 市中心创建业务收支决算主单。
2. 系统初始化总表 12 行和附表机构行。
3. 系统同步来源：预算、执行、上年决算。
4. 分中心查看本机构附表结果并提交确认。
5. 市中心审核通过或退回。
6. 锁定后生成正式快照与导出文件。

## 14. 本轮结论

本轮详细设计的核心结论如下：

1. 业务收支决算组采用 3 张业务表：主表、总表明细表、附表明细表。
2. 总表明细承接 12 行决算指标，附表明细承接 12 行机构结果。
3. 本组数据全部来源于预算、执行和上年决算，不允许在本表中人工改写业务值。
4. 分中心承担结果确认职责，市中心承担审核、锁定和导出职责。
