### 1.3 关键风险与缺口（来自对齐清单 + 评审稿 P0–P3）
- **数据出域前置条件未满足**：平台协议第 4.1 条限制提交国家秘密/商业秘密，第 8.1 条将金融输出定位为参考；真实账户/交易/策略数据出域前须法务/安全/业务/采购确认。当前任何公网调用都不应发送真实数据。
- **两套 DDL 未执行**：连接表与候选五表均"待执行"，代码已硬引用表名/列，未建表会启动或首调报"表/列不存在"。
- **A4 已实现（2026-10-15 已落代码并编译通过）**：候选审核发布全流程（状态机 + 审批人隔离 + 模拟结果禁推 TESTED + 事件审计）。详见下文 §3 Phase 2。
- **A5 未实现**：规则执行/回测/机构隔离仍是设计约束，未落地。
- **评审稿 P0 三阻断问题仍是设计约束**：① 模型–训练–路由强绑定（artifactDigest / datasetSnapshotId / metricContractVersion 等不可变绑定未落地）；② 回测未来数据泄漏（feature_available_at / event_time / as_of / purge / embargo 未定义）；③ 影子–正式差异审计（amountDelta / riskLevelDelta / alertTriggerDelta 未持久化）。
- **`snapshot_hash` 此前恒 NULL（P0 已修为元数据指纹）**：属元数据指纹而非全量内容哈希，严谨度有限，留作后续增强。

## 2. 实施方案改进建议

- **改进 1（优先级重排）**：把"先做报告生成"细化为"先闭环候选 A3–A5 + 用合成数据做报告草稿 PoC"。理由：候选模块已八成且 DDL 已就绪，是最高 ROI 的下一步；报告草稿 `aiDraft` 依赖已审批指标快照，应紧随其后用**合成样本**验证网关与事实校验，全程零真实数据。
- **改进 2（双轨制边界落代码门禁）**：私有模型（旧）与大模型候选（新）通过独立 UUID / 版本 / 任务 / 产物隔离；未来对比功能用独立关联记录引用两侧结果，**禁止修改旧算法 ID 或旧结果表**。此条须作为代码评审门禁硬卡。
- **改进 3（数据闸门前移）**：在 `llm-config` 与 `aiDraft` 调用前，固化 `IndicatorSnapshot` 最小字段白名单（指标编码/周期/数值/单位/来源 ID/版本/截至/质量/数据等级）+ 服务端 `allowedPurpose` / 数据等级校验；明确"去掉姓名 ≠ 完成匿名化/商业秘密审查"，出域范围须法务/安全/业务共同确认。
- **改进 4（把评审稿 P0 三阻断转为可执行约束清单）**：路由绑定 `artifactDigest + datasetSnapshotId + metricContractVersion + institutionId + indicatorCode + forecastHorizon + riskThresholdVersion`；回测每折记录 `featureMaxAvailableAt / labelAvailableAt / purgeWindow / embargoWindow` 并加"注入未来异常值重跑历史折结果不变"的自动化测试；影子预测持久化 `amountDelta / riskLevelDelta / alertTriggerDelta`，且影子**只产生审计事件、不写正式处置、不派发正式任务、不改正式阈值**。
- **改进 5（密钥/SSRF 已做，补集成测试）**：`LlmConnectionSecurity` 已实现 AES-GCM + SSRF + 公网解析拦截、连接测试仅固定合成文本；需补集成测试覆盖这些路径，确保"密钥只经服务端机密管理，不入库/前端/日志"在测试层可证。
- **改进 6（测试矩阵按缺陷驱动补齐）**：后端单元覆盖数据白名单/权限/SSRF/密钥脱敏/幂等/并发/重试/429/超时/空JSON/错误引用/跨机构/提示词注入/金额零负空/月季模板/审批人隔离/版本过期/孤儿文件补偿；当前仅 20 项覆盖草稿基础行为，须按矩阵补齐；Python 契约与回测时间窗、达梦唯一键/并发、前端权限/构建另行联测。

## 3. 后续开发规划（分阶段 + 验收门禁）

| 阶段 | 内容 | 验收门禁 |
|---|---|---|
| **Phase 1 · A3 收尾（后端侧基本完成）** | DBA 执行大写整改 DDL + 回滚演练；补 `rule_artifact` 控制器端点（save/get）与读路径；补 A4 状态机 + 审批人隔离 + 产物落库单元测试（22 项全绿）；前端"查看"页需在独立前端仓库补 | 后端端点/读路径已编译+单测通过；首调需待 DBA 大写整改建表后联测 |
| **Phase 2 · A4 审核发布** ✅ 代码已完成并编译通过 | `review` / `publish-candidate` / `rollback` 接口 + 状态机（TEST_PENDING→TESTED→REVIEWED→CANDIDATE）+ 审批人隔离 + 事件审计 | 门禁逻辑已落：双人审批 + 预期版本校验 + 模拟结果禁推 TESTED + DISABLED/回滚可恢复；仅前端按钮与端到端联调待补 |
| **Phase 3 · A5 规则执行/回测/机构隔离** | 规则执行器（提示词/规则优化，**非权重训练**）、同快照滚动回测（无未来泄漏）、机构隔离与跨机构权限；`rule_task` 状态机 DRAFT→WAITING_NETWORK→RUNNING→SUCCEEDED/FAILED/UNKNOWN（UNKNOWN 先对账不盲重试）；`rule_artifact` 落库 | 零真实资金数据；TRAIN/ADAPT 须真实制品证据否则 INFERENCE_ONLY/UNAVAILABLE；跨机构权限用例通过 |
| **Phase 4 · 报告草稿 aiDraft（设计稿首选）** | `IndicatorSnapshot` 冻结 → 受控网关返回结构化 JSON（title/summary/findings/limitations）→ 事实校验（金额/日期/单位一致率 100%）→ 草稿持久化 → 人工复核/渲染（poi-tl 专用占位符） | 零真实数据出域；AI 故障回退旧模板且明确标识；敏感零外传；草稿/快照/版本失效规则生效 |
| **Phase 5 · 预测评估与路由（设计稿 Phase 2）** | `forecast/evaluations` 同快照回测（MAE/RMSE/WAPE/召回/误报）+ `forecast/routes` 审批路由（并发唯一性）+ 影子预测差异审计 | 比较同口径；训练/测试无未来数据泄漏；阈值/召回/误报未签署不批准生产路由；影子不触发正式处置 |
| **Phase 6 · 灰度上线（设计稿 Phase 4）** | 审批路由、预算告警、故障演练、回滚、监控（P50/P95/错误率/tokens/空响应/退稿/一致率/漂移） | 业务/安全/法务/采购/运维签署；阈值/SLA 确认后限量放行 |

> 顺序原则：Phase 1–3 把"候选/规则"这条已搭骨架的线闭环并验证合成数据可行；Phase 4 用合成数据证明"受控叙述生成"可信；Phase 5–6 才碰数值预测与灰度，且须阈值/合同/出域全部就绪。

## 4. 总体门禁（贯穿所有阶段）
- 默认关闭公网；真实数据出域在**安全/法务/业务/采购**确认前不开。
- 大模型只做受控叙述/报告草稿，**不替代数值预测**；实验性 LLM 数值预测默认禁止。
- 所有新 API 状态变更需身份审计 + `Idempotency-Key`；DTO **不返明文密钥/原始提示词/客户报文**。
- 第三方调用不处长事务；短事务登记 `PENDING` + 快照 + 幂等；异步领任务持租约；DOCX 已传而落库失败记孤儿文件、可恢复，不报成功。
- 上线前出**经 DBA 评审**的达梦 DDL/索引/回滚与权限清单。
