## 1. 阶段目标

1. 延续第七阶段建议，为 `FkywBatchModel` 与 `SkywBatchModel` 补充批次不变量校验。
2. 使用 TDD 先新增失败测试，验证空批次流水号、空明细集合必须抛出 `BizException`。
3. 保持既有批次统计语义不变：明细数、总金额、成功数、失败数、待处理数仍按原规则计算。
4. 不改变 REST 路径、请求/响应 DTO、数据库结构、批量收付款应用服务编排方式。

---

## 2. 改动前现状

| 模型 | 改动前行为 | 风险 |
| --- | --- | --- |
| `FkywBatchModel.create` | 直接构造批次模型，仅 `List.copyOf(items)` 间接处理 `null` 明细集合 | 空批次号可进入领域模型；空明细集合可生成总金额 0、明细数 0 的无意义批次 |
| `SkywBatchModel.create` | 与付款批次相同，缺少显式业务参数校验 | 批量收款可能产生无业务明细的批次模型 |
| 异常语义 | 空集合不抛业务异常；`null` 集合可能触发 NPE | 不符合项目统一 `BizException` 业务异常规范 |

## 6. 风险与说明

1. 本阶段仅增强领域模型构造时的不变量校验，不改变外部接口字段和路径。
2. 空批次号、空明细集合现在会更早以 `BizException(PARAM_ERROR)` 暴露；这符合项目业务异常规范，但调用方如果曾依赖空批次模型，需要同步修正调用方输入。
3. 本阶段未改变批量收付款事务边界、部分失败语义、批次持久化策略。
4. `FkywBatchModel` 与 `SkywBatchModel` 仍存在结构重复；后续可评估抽象共享批次统计组件，但本轮未扩大重构范围。

---

## 7. 下一阶段建议

3. 设计批次持久化模型，将批次流水号、批次统计、明细关联关系落入明确仓储边界。
4. 继续治理转账模块异常语义，消除剩余非 `BizException` 的业务参数异常。
