# 资金预决算及执行情况 - 资金使用预算组详细设计与数据库设计

## 1. 设计目标

本文档用于把“资金使用预算组”从原则设计推进到可落库、可开发、可联调的详细设计层级。

本组范围仅包含：

- 住房公积金资金使用预算总表
- 住房公积金资金使用预算附表

本组关联文档：

- [资金使用预算组设计.md](file:///home/source/Jetbrains/Probject/Gjj/doc/设计文档/20260602-资金使用预算组设计.md)
- [资金使用预算组-前端原型设计.md](file:///home/source/Jetbrains/Probject/Gjj/doc/设计文档/20260602-资金使用预算组-前端原型设计.md)

## 2. 本轮定版结论

本轮按已确认口径，将预算组结构定为：

1. 附表是唯一填报来源。
2. 总表不再把所有展示项全部展开成物理字段。
3. 总表改为“主表 + 总表明细行”模式。
4. 附表继续采用“一张报表 + 一个机构一行”的固定字段模式。
5. 总表、总表明细、附表明细统一使用 15 个系统字段。
6. 总表与子表关联采用 `MAIN_ID + BBBH` 双关联。
7. 前端原型继续维持当前 Excel 化展示效果，但接口结构按新模型输出。

## 3. 业务对象设计

## 3.1 总表主表对象

表名：`CWHS_ZJYJS_ZJSYYSZB`

定位：

- 一张年度预算总表一行
- 存表头、状态、签字、锁定等控制信息
- 不直接存 15 行业务项的金额值

职责：

- 作为预算组主单
- 作为总表明细和附表明细的父记录
- 作为流程流转和锁定的控制主体

## 3.2 总表明细对象

表名：`CWHS_ZJYJS_ZJSYYSZMX`

定位：

- 一张总表的 15 行业务项逐行存储
- 一行代表 Excel 总表中的一个项目
- 存该行的 `SNYSS`、`SNSJS`、`BNYSS`、`WSNSJBL`

职责：

- 直接承载总表展示数据
- 直接支撑总表前端和 Excel 导出
- 减少总表主表字段爆炸

## 3.3 附表明细对象

表名：`CWHS_ZJYJS_ZJSYYFB`

定位：

- 一张附表按机构拆成多行
- 一行代表一个核算机构在一个预算单中的全部固定字段
- 是分中心填报与总表汇总的唯一来源

职责：

- 存储机构原始输入值
- 存储机构自动带入值与自动计算值
- 为总表明细提供汇总来源

## 4. 状态流转设计

统一状态建议：

- `0`：草稿
- `1`：已提交
- `2`：审核退回
- `3`：审核通过
- `4`：已锁定

流转规则：

1. 市中心创建预算主单。
2. 系统初始化总表 15 行明细和附表机构行。
3. 分中心填报附表本机构数据。
4. 分中心提交后，市中心审核。
5. 市中心退回或审核通过。
6. 审核通过后，市中心执行锁定。
7. 锁定后总表主表、总表明细、附表明细全部只读。

## 5. 系统字段口径

三张表统一保留以下 15 个系统字段：

- `ID BIGINT NOT NULL`
- `ZXBH NVARCHAR(15) NOT NULL`
- `REVISION INT NOT NULL`
- `CREATOR NVARCHAR(100)`
- `CREATED_TIME TIMESTAMP(0) NOT NULL DEFAULT CURRENT_TIMESTAMP()`
- `UPDATOR NVARCHAR(100)`
- `UPDATED_TIME TIMESTAMP(0)`
- `JBJGBH NVARCHAR(30) NOT NULL`
- `JBJGMC NVARCHAR(90) NOT NULL`
- `WDBH NVARCHAR(30)`
- `WDMC NVARCHAR(90)`
- `QDLX NVARCHAR(10)`
- `QDBM NVARCHAR(16)`
- `DEL_FLAG NVARCHAR(1) NOT NULL DEFAULT '0'`
- `HSJGBH NVARCHAR(10) NOT NULL DEFAULT '01'`

说明：

- 主表中的 `HSJGBH` 默认保存全市口径，如 `01`
- 总表明细中的 `HSJGBH` 与主表保持一致
- 附表明细中的 `HSJGBH` 保存具体填报机构

## 6. 字段类型规则

金额字段统一使用：

- `DECIMAL(20,4)`

比例字段统一使用：

- `DECIMAL(20,6)`

编号类字段统一使用：

- `VARCHAR2` 或 `NVARCHAR`

## 8. 总表 15 行定义

总表明细固定初始化以下 15 行：

1. `GJTQ_NCYE` 归集提取-年初余额
2. `GJTQ_DNGJS` 归集提取-当年归集数
3. `GJTQ_DNTQS` 归集提取-当年提取数
4. `GJTQ_NMYE` 归集提取-年末余额
5. `GRDK_NCYE` 个人贷款-年初余额
6. `GRDK_DNFFS` 个人贷款-当年发放数
7. `GRDK_DNSHS` 个人贷款-当年收回数
8. `GRDK_DNGZSDKZC` 个人贷款-当年公转商贷款转出
9. `GRDK_NMYE` 个人贷款-年末余额
10. `GRDK_DKYEZBGJYE` 个人贷款余额占归集余额比%
11. `GDTZ_NCYE` 国债投资-年初余额
12. `GDTZ_DNZJS` 国债投资-当年增加数
13. `GDTZ_DNHSS` 国债投资-当年回收数
14. `GDTZ_NMYE` 国债投资-年末余额
15. `GDTZ_YEZBGJYE` 国债投资余额占归集余额比%

## 9. 字段编辑控制

## 9.1 附表可编辑字段

仅以下字段允许分中心录入：

- `GJTQ_DNGJS`
- `GJTQ_DNTQS`
- `GJTQ_DNTCDJZJ`
- `GRDK_DNFFS`
- `GRDK_DNSHS`
- `GRDK_DNGZSDKZC`

## 9.2 附表自动带入字段

- `GJTQ_NCYE`
- `GRDK_NCYE`

## 9.3 附表自动计算字段

- `GJTQ_NMYE = GJTQ_NCYE + GJTQ_DNGJS - GJTQ_DNTQS + GJTQ_DNTCDJZJ`
- `GRDK_NMYE = GRDK_NCYE + GRDK_DNFFS - GRDK_DNSHS - GRDK_DNGZSDKZC`
- `GRDK_DKYEZBGJYE = GRDK_NMYE / GJTQ_NMYE`
- `GDTZ_NMYE = GDTZ_NCYE + GDTZ_DNZJS - GDTZ_DNHSS`
- `GDTZ_YEZBGJYE = GDTZ_NMYE / GJTQ_NMYE`

## 10. 数据关联设计

## 10.1 主表与总表明细关联

- 技术关联：`MAIN_ID = CWHS_ZJYJS_ZJSYYSZB.ID`
- 业务关联：`BBBH = CWHS_ZJYJS_ZJSYYSZB.BBBH`

## 10.2 主表与附表明细关联

- 技术关联：`MAIN_ID = CWHS_ZJYJS_ZJSYYSZB.ID`
- 业务关联：`BBBH = CWHS_ZJYJS_ZJSYYSZB.BBBH`

## 10.3 为什么采用双关联

采用 `MAIN_ID + BBBH` 双关联的原因：

1. `MAIN_ID` 适合数据库内部更新、删除、联表查询。
2. `BBBH` 适合导出、日志、接口追踪和人工识别。
3. 避免只靠业务编号带来的版本化和复制单据风险。

## 11. 数据流转设计

## 11.1 制单阶段

1. 市中心创建预算主表。
2. 系统生成主表编号 `BBBH`。
3. 系统初始化总表 15 行明细。
4. 系统初始化附表机构行。
5. 系统带入上年预算、上年决算年初值。

## 11.2 填报阶段

1. 分中心查询附表。
2. 系统仅下发本机构数据。
3. 分中心录入可编辑字段。
4. 后端重算附表公式字段。
5. 后端同步重算总表 15 行。

## 11.3 审核阶段

1. 分中心提交预算。
2. 市中心查看总表和附表。
3. 市中心核对总表汇总值与附表来源值。
4. 市中心退回或审核通过。

## 11.4 锁定阶段

1. 市中心执行锁定。
2. 系统校验所有机构是否完成。
3. 系统将主表、总表明细、附表明细状态更新为锁定。
4. 导出时统一以锁定状态数据为准。

## 12. 详细业务逻辑流程

## 12.1 创建预算主单流程

```text
开始
  -> 市中心点击“新建预算”
  -> 系统生成 BBBH
  -> 写入总表主表
  -> 初始化总表 15 行明细
  -> 按机构初始化附表明细
  -> 从上年预算带入总表 SNYSS
  -> 从上年决算带入附表年初余额与总表 SNSJS
  -> 返回预算主单详情
结束
```

## 12.2 分中心保存附表流程

```text
开始
  -> 分中心打开附表页面
  -> 系统按 HSJGBH 只返回本机构明细
  -> 用户录入可编辑字段
  -> 前端提交本机构可编辑字段
  -> 后端校验状态是否允许编辑
  -> 后端更新附表固定字段
  -> 后端重算附表公式字段
  -> 后端汇总所有机构附表
  -> 后端重算总表 15 行明细
  -> 返回最新主表/总表/附表状态
结束
```

## 12.3 市中心审核流程

```text
开始
  -> 市中心打开总表
  -> 系统返回总表主表 + 总表明细 + 附表明细摘要
  -> 市中心核对异常项
  -> 若不通过：写审核意见并退回
  -> 若通过：更新状态为审核通过
  -> 等待锁定
结束
```

## 13.3 汇总总表明细伪代码

```java
void refreshZbmxFromFb(Long mainId, String bbbh, String operator) {
    List<BudgetFb> fbList = listFbByMainId(mainId);
    Map<String, BudgetZbmx> zbmxMap = listZbmxByMainId(mainId)
        .stream()
        .collect(Collectors.toMap(BudgetZbmx::getXmbm, item -> item));

    updateLine(zbmxMap.get("GJTQ_NCYE"), lastYearBudget("GJTQ_NCYE"), lastYearActual("GJTQ_NCYE"), sum(fbList, BudgetFb::getGjtqNcye));
    updateLine(zbmxMap.get("GJTQ_DNGJS"), lastYearBudget("GJTQ_DNGJS"), lastYearActual("GJTQ_DNGJS"), sum(fbList, BudgetFb::getGjtqDngjs));
    updateLine(zbmxMap.get("GJTQ_DNTQS"), lastYearBudget("GJTQ_DNTQS"), lastYearActual("GJTQ_DNTQS"), sum(fbList, BudgetFb::getGjtqDntqs));
    updateLine(zbmxMap.get("GJTQ_NMYE"), lastYearBudget("GJTQ_NMYE"), lastYearActual("GJTQ_NMYE"), sum(fbList, BudgetFb::getGjtqNmye));
    updateLine(zbmxMap.get("GRDK_DKYEZBGJYE"), lastYearBudgetRatio("GRDK_DKYEZBGJYE"), lastYearActualRatio("GRDK_DKYEZBGJYE"), calcRatio(sum(fbList, BudgetFb::getGrdkNmye), sum(fbList, BudgetFb::getGjtqNmye)));

    recalcRate(zbmxMap.values());
    updateAllZbmx(zbmxMap.values(), operator);
}
```

## 15. 前端原型实现说明

## 15.1 总表原型

总表前端不再需要把 `GJTQ_NCYE_SNYSS` 这类字段映射成列。

改为：

1. 后端直接返回总表明细数组 `details`
2. 前端按 `hangxh` 排序
3. 直接渲染 15 行
4. `sfgs = 1` 的行使用公式样式

这样更贴近当前原型需要的表格效果。

## 15.2 附表原型

附表前端继续保持：

- 一行一个业务项
- 一列一个机构
- 全市列自动汇总

实现方式仍然是：

1. 后端返回机构明细行 `details`
2. 前端用行配置 `budgetFbRowConfig`
3. 把机构行 Pivot 成横向区县列

## 16. 为什么总表要行化而不是继续固定字段化

1. 总表一年只制作一次，行结构稳定。
2. Excel 总表天然是按行表达的。
3. 总表改行后，接口和前端更贴近报表本身。
4. 避免总表主表字段膨胀。
5. 便于以后调整行次或新增少量项目。
