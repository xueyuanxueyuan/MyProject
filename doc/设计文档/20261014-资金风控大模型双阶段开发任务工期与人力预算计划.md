# 资金风控大模型双阶段开发任务、工期与人力预算计划

编制日期：2026-10-14。状态：**估算与项目排期基线，待业务、技术、安全、采购和项目经理核定**；不是第三方合同、接口能力证明、真实数据出域或生产投产批准。依据 `20261014-资金风控双模式并存最终落地方案-专家复审建议稿.md`，按用户明确的“先接入与测试，后能力应用”拆分；私有模型继续可用，两套预测与报告均可留存比较，但同一范围最多一套正式生效。

## 1. 估算边界与技术选型

现有 Java `ModelController`、`AlgorithmTypeController`、`ModelTrainingController`、`ModelComparisonController` 分别已有模型、算法类型、训练、对比接口；前端 `mxxl.vue`、`mxdb.vue` 及对应 `src/api/mxgl` 调用旧路径。`mxsf.vue` 当前实际是**算法类型管理页面**，不能仅据文件名认定已有“模型发布审批”功能。旧预测 `PredictionResultController` 和报告 `DocumentController` 保持原接口；旧 `confirm-best` 不是新模型正式投产批准。阶段一按“能力配置/候选发布/合成测试”定义，不开放真实资金计算或正式表写入；阶段二才做独立预测、报告和比较。

选择**独立供应商连接配置＋能力注册表＋候选版本/发布事件**，前端沿用模型管理导航增加能力标签与测试台，不把第三方 `provider/model` 直接伪装成 GRU 算法 ID；原算法和模型记录保持兼容。候选模型运行由统一网关调用，不在前端持密钥。相较直接扩展旧算法类型表并替换旧训练路径，此方案需新增表和 API，但能区分“文本叙述、零样本数值推理、真正适配训练”并保留旧历史。大模型支持的训练能力、许可及安全处理逐供应商实测/审查；若通用文本 API 不提供训练接口，页面明确“不支持训练”，不能用提示词编辑冒充训练。

**测算口径**：1 人日＝8 小时；按每周 5 个工作日；研发与评审可并行；起始日**假设**为 2026-10-19，若合同/环境/数据批准晚于该日，里程碑顺延。仅统计开发、联调、测试、验收支持的人力；不计第三方 API 用量、采购合同、GPU、网关/存储、税费、汇率、差旅和生产值守。金额是示例性全成本内部核算单价，不是本公司工资或供应商报价。

## 6. 计划冻结前需确认的五项

1. 模型候选：第三方通用 LLM 与数值时序候选各由谁提供、许可、适配训练能力、出域边界；不能默认所有“训练”按钮都会产生权重。
2. 合规环境：测试是否只用合成数据；真实资金序列、报告段落、双报告联合发送的字段组合与用途分别由谁授权。
3. 范围选择：阶段二 B7 正式治理是否纳入本轮审批；如不纳入，只交付比较/报告试验模式，不修改旧正式写入。
4. 费率与编制：项目经理、人事/采购确认实际人日单价、共享人员可用比例、全年假日与合同/基础设施报价。
5. 验收口径：业务/风控事前签预测/重大漏报阈值、报告事实来源；达梦 DBA/运维对旧写者、数据库唯一域和回滚签字。

本文件是**可核算的计划假设**，不是已发生人日或已确认预算；上述五项变化后应按任务人日、费率和关键路径重算。编制过程仅只读核查代码/文档，没有训练、构建、真实供应商调用、环境验证或费用实测。
