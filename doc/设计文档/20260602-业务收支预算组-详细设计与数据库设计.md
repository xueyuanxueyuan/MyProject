# 资金预决算及执行情况 - 业务收支预算组详细设计与数据库设计

## 1. 设计目标

本文档用于把“业务收支预算组”从首版功能设计推进到可直接指导后端开发、前端联调和达梦建表的详细设计层级。

本组范围仅包含：

- 住房公积金业务收支预算总表
- 住房公积金业务收支预算附表

本组关联文档：

- [业务收支预算组设计.md](file:///home/source/Jetbrains/Probject/Gjj/doc/设计文档/20260602-业务收支预算组设计.md)
- [业务收支预算组-前端原型设计.md](file:///home/source/Jetbrains/Probject/Gjj/doc/设计文档/20260602-业务收支预算组-前端原型设计.md)

## 2. 本轮定版结论

本轮按已确认口径，将业务收支预算组结构定为：

1. 附表是唯一填报来源。
2. 总表采用“主表 + 总表明细行”模式。
3. 附表继续采用“一张报表 + 一个机构一行”的固定字段模式。
4. 总表、总表明细、附表明细统一使用 15 个系统字段。
5. 总表与附表统一使用 `MAIN_ID + BBBH` 双关联。
6. 第 5 行 `国债投资收入` 保持不适用口径，数据库存空值，页面与导出显示 `-`。
7. 总表接口直接返回 12 行 `details` 数组，附表接口返回机构明细数组。

## 3. 业务对象设计

## 3.1 总表主表对象

表名：`CWHS_ZJYJS_YWSZYSZB`

定位：

- 一张年度业务收支预算总表一行
- 存表头、状态、签字、审核、锁定等控制信息
- 不直接存 12 行业务值

职责：

- 作为业务收支预算主单
- 作为总表明细和附表明细的父记录
- 作为状态流转和锁定控制主体

## 3.2 总表明细对象

表名：`CWHS_ZJYJS_YWSZYSZMX`

定位：

- 一张总表的 12 行业务项逐行存储
- 一行代表 Excel 总表中的一个项目
- 存该行的 `SNYSS`、`SNSJS`、`BNYSS`、`WSNSJBL`

职责：

- 直接承载总表展示数据
- 直接支撑总表前端与 Excel 导出
- 避免总表主表字段膨胀

## 3.3 附表明细对象

表名：`CWHS_ZJYJS_YWSZYSFB`

定位：

- 一张附表按机构拆成多行
- 一行代表一个核算机构在一个预算单中的全部固定字段
- 是分中心填报与总表汇总的唯一来源

职责：

- 存储机构原始输入值
- 存储机构自动计算值
- 为总表明细提供汇总来源

## 4. 状态流转设计

统一状态建议：

- `0`：草稿
- `1`：已提交
- `2`：审核退回
- `3`：审核通过
- `4`：已锁定

流转规则：

1. 市中心创建业务收支预算主单。
2. 系统初始化总表 12 行明细和附表机构行。
3. 分中心填报附表本机构数据。
4. 分中心提交后，市中心审核。
5. 市中心退回或审核通过。
6. 审核通过后，市中心执行锁定。
7. 锁定后总表主表、总表明细、附表明细全部只读。

## 5. 系统字段口径

三张表统一保留以下 15 个系统字段：

- `ID BIGINT NOT NULL`
- `ZXBH NVARCHAR(15) NOT NULL`
- `REVISION INT NOT NULL`
- `CREATOR NVARCHAR(100)`
- `CREATED_TIME TIMESTAMP(0) NOT NULL DEFAULT CURRENT_TIMESTAMP()`
- `UPDATOR NVARCHAR(100)`
- `UPDATED_TIME TIMESTAMP(0)`
- `JBJGBH NVARCHAR(30) NOT NULL`
- `JBJGMC NVARCHAR(90) NOT NULL`
- `WDBH NVARCHAR(30)`
- `WDMC NVARCHAR(90)`
- `QDLX NVARCHAR(10)`
- `QDBM NVARCHAR(16)`
- `DEL_FLAG NVARCHAR(1) NOT NULL DEFAULT '0'`
- `HSJGBH NVARCHAR(10) NOT NULL DEFAULT '01'`

说明：

- 主表中的 `HSJGBH` 保存全市口径，如 `01`
- 总表明细中的 `HSJGBH` 与主表保持一致
- 附表明细中的 `HSJGBH` 保存具体填报机构

## 6. 字段类型规则

金额字段统一使用：

- `DECIMAL(20,4)`

比例字段统一使用：

- `DECIMAL(20,6)`

编号类字段统一使用：

- `VARCHAR2` 或 `NVARCHAR`

## 8. 总表 12 行定义

总表明细固定初始化以下 12 行：

1. `YWSR_HJ` 业务收入
2. `YWSR_ZFGJJLXS` 住房公积金利息收入
3. `YWSR_ZZSYLXS` 增值收益利息收入
4. `YWSR_WTDKLXS` 委托贷款利息收入
5. `YWSR_GDTZSR` 国债投资收入
6. `YWSR_QTSR` 其他收入
7. `YWSZ_HJ` 业务支出
8. `YWSZ_ZFGJJLXZC` 住房公积金利息支出
9. `YWSZ_GJSXFZC` 住房公积金归集手续费支出
10. `YWSZ_WTDKSXFZC` 委托贷款手续费支出
11. `YWSZ_QTZC` 其他支出
12. `ZZSY` 增值收益

其中：

- 行 `1、7、12` 为公式行
- 行 `5` 为不适用行
- 其余行为明细输入汇总行

## 9. 字段编辑控制

## 9.1 附表可编辑字段

仅以下字段允许分中心录入：

- `YWSR_ZFGJJLXS`
- `YWSR_ZZSYLXS`
- `YWSR_WTDKLXS`
- `YWSR_QTSR`
- `YWSZ_ZFGJJLXZC`
- `YWSZ_GJSXFZC`
- `YWSZ_WTDKSXFZC`
- `YWSZ_QTZC`

## 9.2 附表自动计算字段

- `YWSR_HJ = YWSR_ZFGJJLXS + YWSR_ZZSYLXS + YWSR_WTDKLXS + YWSR_GDTZSR + YWSR_QTSR`
- `YWSZ_HJ = YWSZ_ZFGJJLXZC + YWSZ_GJSXFZC + YWSZ_WTDKSXFZC + YWSZ_QTZC`
- `ZZSY = YWSR_HJ - YWSZ_HJ`

## 9.3 不适用字段控制

- `YWSR_GDTZSR` 默认空值
- 页面展示为 `-`
- 不允许分中心编辑
- 总表第 5 行同步显示为 `-`

## 10. 数据关联设计

## 10.1 主表与总表明细关联

- 技术关联：`MAIN_ID = CWHS_ZJYJS_YWSZYSZB.ID`
- 业务关联：`BBBH = CWHS_ZJYJS_YWSZYSZB.BBBH`

## 10.2 主表与附表明细关联

- 技术关联：`MAIN_ID = CWHS_ZJYJS_YWSZYSZB.ID`
- 业务关联：`BBBH = CWHS_ZJYJS_YWSZYSZB.BBBH`

## 10.3 为什么采用双关联

采用 `MAIN_ID + BBBH` 双关联的原因：

1. `MAIN_ID` 适合数据库内部联表、更新和删除。
2. `BBBH` 适合接口追踪、导出标识和人工识别。
3. 同时保留技术主键与业务编号，更利于历史版本和日志追溯。

## 11. 数据流转设计

## 11.1 制单阶段

1. 市中心创建业务收支预算主表。
2. 系统生成主表编号 `BBBH`。
3. 系统初始化总表 12 行明细。
4. 系统按机构初始化附表行。
5. 系统从上年预算表带入 `SNYSS`。
6. 系统从上年业务收支决算表带入 `SNSJS`。

## 11.2 填报阶段

1. 分中心查询附表。
2. 系统仅下发本机构数据。
3. 分中心录入可编辑字段。
4. 后端重算附表公式字段。
5. 后端汇总所有机构附表。
6. 后端同步重算总表 12 行。

## 11.3 审核阶段

1. 分中心提交预算。
2. 市中心查看总表和附表。
3. 市中心核对总表汇总值与附表来源值。
4. 市中心退回或审核通过。

## 11.4 锁定阶段

1. 市中心执行锁定。
2. 系统校验所有机构数据和勾稽规则。
3. 系统将主表、总表明细、附表明细状态更新为锁定。
4. 导出时统一以锁定状态数据为准。

## 12. 详细业务逻辑流程

## 12.1 创建业务收支预算主单流程

```text
开始
  -> 市中心点击“新建业务收支预算”
  -> 系统生成 BBBH
  -> 写入总表主表
  -> 初始化总表 12 行明细
  -> 按机构初始化附表明细
  -> 从上年预算带入总表 SNYSS
  -> 从上年决算带入总表 SNSJS
  -> 返回业务收支预算主单详情
结束
```

## 12.2 分中心保存附表流程

```text
开始
  -> 分中心打开附表页面
  -> 系统按 HSJGBH 只返回本机构明细
  -> 用户录入 8 个可编辑字段
  -> 前端提交本机构输入值
  -> 后端校验状态是否允许编辑
  -> 后端更新附表固定字段
  -> 后端重算附表合计与增值收益
  -> 后端汇总所有机构附表
  -> 后端重算总表 12 行明细
  -> 返回最新主表/总表/附表状态
结束
```

## 12.3 市中心审核流程

```text
开始
  -> 市中心打开总表
  -> 系统返回总表主表 + 总表明细 + 附表明细摘要
  -> 市中心核对异常项
  -> 若不通过：写审核意见并退回
  -> 若通过：更新状态为审核通过
  -> 等待锁定
结束
```

void refreshZbmxFromFb(Long mainId, String bbbh, String operator) {
    List<YwszysFb> fbList = listFbByMainId(mainId);
    Map<String, YwszysZbmx> zbmxMap = listZbmxByMainId(mainId)
        .stream()
        .collect(Collectors.toMap(YwszysZbmx::getXmbm, item -> item));

    updateLine(zbmxMap.get("YWSR_ZFGJJLXS"), sum(fbList, YwszysFb::getYwsrZfgjjlxs));
    updateLine(zbmxMap.get("YWSR_ZZSYLXS"), sum(fbList, YwszysFb::getYwsrZzsylxs));
    updateLine(zbmxMap.get("YWSR_WTDKLXS"), sum(fbList, YwszysFb::getYwsrWtdklxs));
    updateLine(zbmxMap.get("YWSR_GDTZSR"), null);
    updateLine(zbmxMap.get("YWSR_QTSR"), sum(fbList, YwszysFb::getYwsrQtsr));
    updateLine(zbmxMap.get("YWSZ_ZFGJJLXZC"), sum(fbList, YwszysFb::getYwszZfgjjlxzc));
    updateLine(zbmxMap.get("YWSZ_GJSXFZC"), sum(fbList, YwszysFb::getYwszGjsxfzc));
    updateLine(zbmxMap.get("YWSZ_WTDKSXFZC"), sum(fbList, YwszysFb::getYwszWtdksxfzc));
    updateLine(zbmxMap.get("YWSZ_QTZC"), sum(fbList, YwszysFb::getYwszQtzc));

    recalcIncomeTotal(zbmxMap);
    recalcExpenseTotal(zbmxMap);
    recalcZzsy(zbmxMap);
    recalcRate(zbmxMap);
    updateAllZbmx(zbmxMap.values(), operator);

## 15. 前端原型实现说明

## 15.1 总表原型

总表前端不需要把 `YWSR_HJ_SNYSS` 这类字段展开成对象字段。

改为：

1. 后端直接返回总表明细数组 `details`
2. 前端按 `hangxh` 排序
3. 直接渲染 12 行
4. `sfgs = 1` 的行使用公式样式
5. `sfbsy = 1` 的行显示 `-`

## 15.2 附表原型

附表前端继续保持：

- 一行一个业务项
- 一列一个机构
- 全市列自动汇总

实现方式仍然是：

1. 后端返回机构明细行 `details`
2. 前端用固定行配置 `fbRowConfig`
3. 把机构行 Pivot 成横向机构列

## 16. 为什么总表采用行化而不是固定字段化

1. 业务收支预算总表一年只制作一次，行结构稳定。
2. Excel 总表天然是按行表达的。
3. 总表行化后更便于导出和前端渲染。
4. 可以避免主表字段膨胀。
5. 与资金使用预算组的总表模型保持一致，降低整体系统复杂度。
