# 临沂项目科目总账与科目明细账生成和查询逻辑梳理

## 1. 结论概览

- 临沂项目“科目总账”“科目明细账”都不是直接实时查询凭证明细后即时渲染，而是先由前端点击“制作”触发后端生成账表快照，再由报表模板按参数读取已生成的数据。
- 当前现行主实现统一落在表 `cwhs_zb`，通过 `bbbh` 区分账表类型：
  - `bbbh='zz'`：科目总账
  - `bbbh='mxz'`：科目明细账
- 旧版 `Zz/Mxz` 实体、Mapper 与历史存储过程仍保留，但从现有 Java 主流程看，当前主链路已经收敛到统一账表表 `cwhs_zb`。
- 总账支持一次输入多个科目编号批量制作；明细账当前按单科目制作。

## 2. 主流程总览

### 2.1 科目总账

1. 前端进入“科目总账”页面，选择账套、起止日期、科目编号。
2. 点击“制作”后，请求 `/api/v1/cwhs/makeZbZz`。
3. 聚合层 `gm-agg` 仅做转发，经 Feign 调用 `cwhs-jzgl` 记账服务。
4. `cwhs-jzgl` 中 `makeZbZz()` 按科目循环生成账表数据。
5. 生成前先删除当前“账套 + 科目 + 截止日期 + 操作员 + 报表类型”的旧快照。
6. 后端汇总年初至查询起始日前一日的累计借贷发生额、余额，写入“上年结转/上次结转”。
7. 再按日期循环生成每日汇总行，并在月末补“本月合计”，最终补“本年合计”。
8. 数据写入 `cwhs_zb` 后，前端弹出“制作成功”，随后通过报表组件加载 `jshs-zz` 模板预览。

### 2.2 科目明细账

1. 前端进入“科目明细账”页面，选择账套、起止日期、科目编号、凭证类型。
2. 点击“制作”后，请求 `/api/v1/cwhs/makeZbMxz`。
3. 聚合层同样只做转发，经 Feign 进入 `cwhs-jzgl`。
4. `makeZbMxz()` 先删除旧快照，再计算“上年结转/上次结转”。
5. 随后按凭证列表逐笔生成明细行，并在跨月处插入“本月合计”。
6. 循环结束后再补最后一个“本月合计”和“本年合计”。
7. 数据写入 `cwhs_zb` 后，前端通过 `jshs-mxz` 模板查询并展示。

## 3. 前端入口与参数组织

### 3.1 页面入口

- 科目总账页面：`linyi/WebStromProject/capinfo-gjj-frontend-jshs-gm/src/components/cwhs/report/zz.vue`
- 科目明细账页面：`linyi/WebStromProject/capinfo-gjj-frontend-jshs-gm/src/components/cwhs/report/mxz.vue`

### 3.2 前端共同处理

- 页面初始化默认把日期设置为“当前月第一天到最后一天”。
- 页面都会校验：
  - 账套不能为空
  - 起止日期不能为空
  - 科目编号不能为空
  - 起始日期必须大于等于账套建账日期
  - 起始日期不能大于截止日期
- 点击“制作”时，会把日期区间拆成：
  - `ksrq = jzrq_start`
  - `jzrq = jzrq_end`
- `czy` 来自当前登录用户 `userInfo.name`。

### 3.3 接口定义

前端 API 在 `linyi/WebStromProject/capinfo-gjj-frontend-jshs-gm/src/api/cwhs/zb.js`：

- `/api/v1/cwhs/makeZbZz`
- `/api/v1/cwhs/makeZbMxz`

### 3.4 总账与明细账前端差异

- 科目总账：
  - 使用 `reportName='jshs-zz'`
  - `kmbh` 允许逗号分隔多个科目，后端按科目循环制作
- 科目明细账：
  - 使用 `reportName='jshs-mxz'`
  - 增加 `pzlx` 和 `bj` 参数
  - `pzlx='hz'` 时，前端把 `bj` 改成 `2`；否则为 `1`

## 5. 科目总账生成逻辑

主方法：`CwhsServiceImpl.makeZbZz()`

### 5.1 输入与预处理

- 固定 `bbbh='zz'`
- 把请求转成 `Zb` 实体作为删除条件与保存基础
- 把 `kmbh` 按逗号拆分，支持多科目循环生成

### 5.2 删除旧快照

删除条件来自 `ZbDOMapper.xml#deleteByZb`：

- `ztbh`
- `bbbh`
- `kmbh`
- `tjny`
- `czy`

这里的 `tjny` 实际写的是本次请求的截止日期 `jzrq`，所以同一操作员在相同截止日期下重做，会覆盖同口径旧结果。

### 5.3 计算期初信息

- 读取科目基础信息 `Kmxx`，得到：
  - 科目名称 `kmmc`
  - 科目余额方向 `kmyefx`
- 统计区间改为“本年 1 月 1 日到查询起始日前一天”，汇总借贷发生额。
- 再调用 `getKmye()` 取查询起始日前一天的余额。
- 若起始日为 `01-01`，写“上年结转”；否则写“上次结转”。

### 5.4 生成期间数据

现行调用：

- `saveZbLoop(..., "d")`

说明：

- 当前总账主流程走的是按日循环分支，不是按月循环分支。
- 每日会汇总当天凭证借贷发生额，生成一条“汇总记字自 X 号到 Y 号凭证”记录。
- 若跨月或到月末，会补一条“本月合计”。
- 每写一行都调用 `saveZb()`，落到统一表 `cwhs_zb`。

### 5.5 生成年累计

- 循环结束后，再统计“本年 1 月 1 日到截止日期”的借贷累计。
- 写入最后一条“本年合计”。

## 6. 科目明细账生成逻辑

主方法：`CwhsServiceImpl.makeZbMxz()`

### 6.1 输入与预处理

- 固定 `bbbh='mxz'`
- 先删除旧快照
- 读取科目基础信息 `Kmxx`

### 6.2 计算期初

- 统计“本年 1 月 1 日到查询起始日前一天”的累计借贷发生额。
- 调用 `getKmye()` 获取查询起始日前一天余额。
- 写入“上年结转”或“上次结转”。

### 6.3 逐笔生成明细

- 通过 `jzpzDmService.getJzpzxxList()` 获取凭证列表。
- 逐条凭证循环处理：
  - 若月份切换，先补上一月的“本月合计”
  - 根据科目余额方向更新余额
  - 写入当前凭证的明细行，包含：
    - `jzpzh`
    - `xspzh`
    - `zhaiyao`
    - `jffse`
    - `dffse`
    - `jzrq`
    - `yue`

### 6.4 尾部补齐

- 循环结束后补最后一个“本月合计”
- 再补“本年合计”

## 7. 账表落库模型

### 7.1 统一账表实体

位置：

- `.../domain/entity/Zb.java`

核心字段：

- `ztbh`：账套

- `kmmc`：科目名称
- `jzpzh`：记账凭证号
- `xspzh`：显示凭证号
- `zy`：摘要
- `jffse` / `dffse`
- `kmyefx`
- `yue`
- `czy`
- `jzrq`
- `bbbh`
- `tjny`
- `xuhao`
- `tjsj`

### 7.2 持久化服务

位置：

- `.../domain/service/impl/ZbDmServiceImpl.java`
- `.../domain/dao/mapper/ZbDOMapper.xml`

作用：

- `saveZb`：插入 `cwhs_zb`
- `deleteByZb`：按账套、报表类型、科目、统计日期、操作员删除旧快照
- `getByZb`：按同口径查询结果，按 `xuhao` 排序返回

## 8. 查询与展示逻辑

### 8.1 页面展示方式

前端统一使用组件：

- `linyi/WebStromProject/capinfo-gjj-frontend-jshs-gm/src/components/common/report-browser-embed.vue`

逻辑：

- 组件把报表地址拼成 iframe URL
- 默认走 `report-jshs/raqsoft`
- 地址格式：
  - `/{reportType}/{busiType}/api/vl/{reportName}?参数`

因此总账/明细账并不是前端自己查列表渲染，而是把查询参数传给润乾报表模板，由报表引擎执行模板中的 SQL。

### 8.2 总账报表查询

报表模板：

- `linyi/IdeaProject/capinfo-gjj-busi-jshs/report/raqsoft/jshs-zz.rpx`

从模板中可提取出核心 SQL：

```sql
select * from cwhs_zb
where ztbh = ?
  and bbbh = 'zz'
  and concat(?, ',') like concat('%', kmbh, ',%')
  and tjny = ?
  and czy = ?
order by kmbh, xuhao
```

说明：

- 总账查询读的是制作完成后的 `cwhs_zb`
- 通过 `bbbh='zz'` 识别总账
- 通过 `tjny = jzrq_end` 精确命中本次制作批次
- 通过 `czy` 区分不同操作员生成的快照
- 通过 `concat(?, ',') like concat('%', kmbh, ',%')` 支持传入多个科目编号并联合展示

### 8.3 明细账报表查询

报表模板：

- `linyi/IdeaProject/capinfo-gjj-busi-jshs/report/raqsoft/jshs-mxz.rpx`

模板内核心 SQL：

```sql
select * from cwhs_zb
where ztbh = ?
  and bbbh = 'mxz'
  and kmbh = ?
  and tjny = ?
  and czy = ?
order by xuhao
```

说明：

- 明细账同样查询 `cwhs_zb`
- 通过 `bbbh='mxz'` 识别明细账
- 当前是单科目查询

### 8.4 查询链路的本质

查询链路不是：

- 前端 -> 后端接口 -> 实时聚合凭证 -> 返回 JSON 列表

而是：

- 前端“制作” -> 后端生成账表快照入库
- 前端 iframe 加载报表模板
- 报表模板带参数直接查 `cwhs_zb`
- 报表引擎渲染页面

## 9. 历史实现痕迹

初始化 SQL 中仍保留历史存储过程：

- `p_cwhs_mxz`
- `p_cwhs_zz`

它们同样体现了统一账表思路：

- 先删旧结果
- 再写 `cwhs_zb`
- 用 `bbbh='mxz'/'zz'` 区分类型

说明当前 Java 服务实现并不是完全推翻旧逻辑，而是把原先存储过程的思路迁移/收敛到 Java 服务层。

## 10. 关键注意事项

### 10.1 先制作再查看

- 若用户只打开报表、不先点击“制作”，看到的是旧快照，甚至可能没有数据。
- 因此“制作”本质上是一次预计算和快照刷新。

### 10.2 截止日期决定快照版本

- `tjny` 实际使用请求截止日期 `jzrq_end`。
- 同一个截止日期、同一操作员、同一账套和科目重做，会覆盖前次结果。

### 10.3 操作员维度参与查询

- 删除与查询都带 `czy`。
- 这意味着两个操作员即便查询同一账套同一科目同一日期，快照也是彼此隔离的。

### 10.4 总账与明细账都是快照表，不是源数据表

- 源数据仍来自凭证、科目、余额等业务表与服务。
- `cwhs_zb` 更像“报表结果缓存表/账表快照表”。

## 11. 建议的理解口径

可以把临沂项目这两个功能概括为：

- 科目总账：按科目把期间内发生额和余额整理成账页快照，再由报表模板读取展示。
- 科目明细账：按凭证逐笔展开科目发生情况并动态滚动余额，最后形成账页快照，再交给报表模板展示。
