# 资金预决算及执行情况 - 资金使用预算执行情况组详细设计与数据库设计

## 1. 设计目标

本文档用于把“资金使用预算执行情况组”推进到可直接指导后端开发、前端联调和达梦建表的详细设计层级。

本组仅覆盖：

- 住房公积金资金使用预算执行情况表

## 2. 本轮定版结论

本轮按最新确认口径，将本组结构定为：

1. 本表是月度单表，不拆总表/附表。
2. 分中心是唯一填报主体，市中心只做汇总审核。
3. 主表采用一月一单模式。
4. 明细表采用“一张报表 + 一个机构一行”的固定字段模式。
5. 主表和明细表统一使用 15 个系统字段。
6. 明细表中的 `HSJGBH` 保存具体填报机构。
7. 前端通过固定行配置把明细固定字段还原为 Excel 29 行结构。

## 3. 业务对象设计

## 3.1 主表对象

表名：`CWHS_ZJYJS_ZJSYYSZXQKB`

定位：

- 一张月度资金使用预算执行情况表一行
- 存表头、状态、签字、审核、锁定、取数控制信息
- 不直接存 29 行业务值

职责：

- 作为月报主单
- 作为机构执行明细的父记录
- 作为状态流转、审核和锁定控制主体

## 3.2 机构执行明细对象

表名：`CWHS_ZJYJS_ZJSYYSZXQKFB`

定位：

- 一张执行情况表按机构拆成多行
- 一行代表一个核算机构在一个月报单中的全部执行指标
- 是分中心填报与全市汇总的唯一来源

职责：

- 存储机构原始输入值
- 存储机构自动取数值
- 存储机构自动计算值
- 为全市汇总和导出提供来源

## 4. 状态流转设计

## 4.1 主表状态

建议口径：

- `0`：草稿
- `1`：已提交
- `2`：审核退回
- `3`：审核通过
- `4`：已锁定

说明：

- 主表状态体现整张月报的总体状态
- 市中心审核后统一改变主表状态

## 4.2 明细表状态

明细表也保留 `BBZT`：

- `0`：草稿
- `1`：已提交
- `2`：退回
- `3`：审核通过
- `4`：已锁定

作用：

- 标识具体机构当前填报状态
- 支撑“只退回责任机构”的处理模式

## 4.3 流转规则

1. 市中心创建月报主单。
2. 系统初始化全部分中心明细行。
3. 系统自动取数并写入各机构自动取数项。
4. 分中心打开本机构视图，只能编辑本机构允许填报字段。
5. 分中心保存草稿或提交本机构数据。
6. 市中心查看全市和各机构执行情况，执行审核或退回。
7. 审核通过后市中心锁定，主表与明细表全部只读。

## 5. 系统字段口径

两张表统一保留以下 15 个系统字段：

- `ID BIGINT NOT NULL`
- `ZXBH NVARCHAR(15) NOT NULL`
- `REVISION INT NOT NULL`
- `CREATOR NVARCHAR(100)`
- `CREATED_TIME TIMESTAMP(0) NOT NULL DEFAULT CURRENT_TIMESTAMP()`
- `UPDATOR NVARCHAR(100)`
- `UPDATED_TIME TIMESTAMP(0)`
- `JBJGBH NVARCHAR(30) NOT NULL`
- `JBJGMC NVARCHAR(90) NOT NULL`
- `WDBH NVARCHAR(30)`
- `WDMC NVARCHAR(90)`
- `QDLX NVARCHAR(10)`
- `QDBM NVARCHAR(16)`
- `DEL_FLAG NVARCHAR(1) NOT NULL DEFAULT '0'`
- `HSJGBH NVARCHAR(10) NOT NULL DEFAULT '01'`

说明：

- 主表中的 `HSJGBH` 保存全市口径，如 `01`
- 明细表中的 `HSJGBH` 保存实际填报机构

## 6. 字段类型规则

金额字段统一使用：

- `DECIMAL(20,4)`

比例字段统一使用：

- `DECIMAL(20,6)`

编号、状态、标识类字段统一使用：

- `VARCHAR2`
- `NVARCHAR`
- `CHAR(1)`

## 9. 自动取数与计算设计

## 9.1 自动取数映射

### 归集提取

- `GJTQ_SYMYE <- 上年归集使用决算表年末余额`
- `GJTQ_BNGJYS <- 本年资金使用预算表归集预算值`
- `GJTQ_BNGJSJ <- 科目201贷方`
- `GJTQ_SNGJTQS <- 上年同月执行表归集实绩数`
- `GJTQ_BNTQYS <- 本年资金使用预算表提取预算值`
- `GJTQ_BNTQSJ <- 科目201借方`

### 个人贷款

- `GRDK_SYMYE <- 上年归集使用决算表年末余额`
- `GRDK_BNFFYS <- 本年资金使用预算表发放预算值`
- `GRDK_BNFFSJ <- 科目121相关发生额`
- `GRDK_SNFFTQS <- 上年同月执行表发放实绩数`
- `GRDK_BNSHYS <- 本年资金使用预算表收回预算值`
- `GRDK_BNSHSJ <- 121贷 + 122贷 - 122借 - 公转商转出`
- `GRDK_SNSHTQS <- 上年同月执行表收回实绩数`
- `GRDK_YQDK <- 逾期贷款统计结果`

## 9.2 自动计算规则

### 归集提取

- `GJTQ_GJWCL = GJTQ_BNGJSJ / GJTQ_BNGJYS`
- `GJTQ_GJTBZZ = GJTQ_BNGJSJ / GJTQ_SNGJTQS - 1`
- `GJTQ_TQWCL = GJTQ_BNTQSJ / GJTQ_BNTQYS`
- `GJTQ_TQTBZZ = GJTQ_BNTQSJ / GJTQ_SNTQTQS - 1`
- `GJTQ_QMYE = GJTQ_SYMYE + GJTQ_BNGJSJ - GJTQ_BNTQSJ + GJTQ_DNTCTJZJ`

### 个人贷款

- `GRDK_FFWCL = GRDK_BNFFSJ / GRDK_BNFFYS`
- `GRDK_FFTBZZ = GRDK_BNFFSJ / GRDK_SNFFTQS - 1`
- `GRDK_SHWCL = GRDK_BNSHSJ / GRDK_BNSHYS`
- `GRDK_SHTBZZ = GRDK_BNSHSJ / GRDK_SNSHTQS - 1`
- `GRDK_QMYE = GRDK_SYMYE + GRDK_BNFFSJ - GRDK_BNSHSJ - GRDK_DNGZSDKZC`
- `GRDK_YQDKL = GRDK_YQDK / GRDK_QMYE`

### 跨区块

- `DKYEZBGJYE = GRDK_QMYE / GJTQ_QMYE`

### 全市列

- 金额行：全市值 = 全部分中心值求和
- 比率行：全市值 = 汇总分子 / 汇总分母

## 11. 业务流程

## 11.1 建单与初始化

1. 市中心创建月报主表。
2. 系统初始化全部分中心明细行。
3. 系统批量取数。
4. 系统重算公式项。

## 11.2 分中心保存流程

1. 分中心进入页面。
2. 系统仅返回全市列和本机构列。
3. 分中心编辑本机构允许填写字段。
4. 后端校验 `当前机构 + 草稿/退回` 权限。
5. 更新本机构明细。
6. 重算本机构公式。
7. 汇总重算全市列。

## 11.3 分中心提交流程

1. 分中心点击提交审核。
2. 后端校验本机构自动取数状态。
3. 后端将本机构行状态改为已提交。
4. 若全部机构都已提交，则主表进入待审核状态。

## 11.4 市中心审核流程

1. 市中心打开执行情况表。
2. 查看全市列及全部分中心列。
3. 核对异常机构和公式结果。
4. 审核通过或退回责任机构。
5. 审核通过后执行锁定。

## 12. 数据流与关联

## 12.1 数据流

1. 上年决算表、本年预算表、会计科目、逾期统计结果进入自动取数服务。
2. 自动取数服务写入机构执行明细表。
3. 分中心补录原始手工字段。
4. 公式计算服务重算机构值。
5. 汇总服务生成全市展示值。
6. 前端按行配置渲染 29 行 Excel 结构。

## 12.2 数据关联

- 主表和明细表使用 `MAIN_ID + BBBH` 双关联。
- 明细表使用 `HSJGBH` 区分填报机构。
- 全市列不落库，由明细汇总生成。
