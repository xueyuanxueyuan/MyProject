## 4. 风险与说明

1. 本阶段仍未引入 Spring MVC 集成测试，当前 Controller 测试聚焦方法级 DTO 映射和领域服务调用，避免因环境配置扩大改动面。
2. 收款模型不变量当前覆盖最小业务要素；核算单位、银行代码、渠道等更严格校验建议在编号/命令对象抽取阶段统一处理。
3. 收付款批量业务仍缺少批次聚合对象，本阶段仅用测试保护既有 Controller 批量响应行为，未改变事务语义。
4. `TransferDomainService` 仍存在 `IllegalArgumentException`，本阶段范围只覆盖收付款链路；转账模块建议作为后续独立阶段处理。
5. 本阶段没有发布、远程部署、数据库变更或生产配置修改。

## 5. 下一阶段建议

1. 抽取收付款请求 DTO 到领域模型的转换逻辑，减少 Controller 构造聚合根的职责。
2. 统一业务流水号生成组件，将单笔/批量/收款/付款编号规则从 Controller 下沉到 common 或 domain service。
3. 为批量付款/批量收款建立批次模型，明确批次号、明细号、总金额、成功/失败数量与部分失败语义。
4. 扩展转账模块异常与测试保护，消除剩余 `IllegalArgumentException`。
