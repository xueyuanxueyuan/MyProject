# 资金风控第三方大模型详细设计：专家修订增补稿

日期：2026-10-13。依据：`20261012-资金风控第三方大模型详细设计-评审稿.md` 及专家组评审意见。本文件为原稿的修订增补，不改变现有业务接口、数据或生产配置；以下能力和测试均尚未实现或验证。原稿保持不变，新功能默认关闭。未取得出域、模型阈值和合同证据前，仅允许合成数据 PoC；禁止公网真实数据调用、`CANARY` 与 `ACTIVE`。

## 1. 架构与标识：增补原稿第 2、4、5 节

`trainingRecordId=zjfk_model_training.id`，`modelId=zjfk_model.id`；`candidateId`、`evaluationId`、`artifactId`、`routeId`、`datasetSnapshotId`、`predictionSnapshotId`、`reportSnapshotId` 和 `draftId` 各自独立。旧比较接口的 `modelIds` 实际为训练记录 ID，旧接口语义不变，不得用于新路由审批。候选不可变绑定 `trainingRecordId + artifactDigest + algorithmVersion + datasetSnapshotId`；评估绑定 `candidateId + artifactDigest + snapshotDigest + metricContractVersion + institutionId + indicatorCode + horizon + evaluationWindow`；正式路由绑定获批的 `evaluationId + evaluationDigest + artifactDigest + routeVersion + riskThresholdVersion`。摘要或口径变化必须重评重审，不能原地更换模型制品。

训练新增数据库持久化任务，字段包括 `taskId, businessType, businessId, actorId, idempotencyKey, requestHash, snapshotId, status, version, attemptCount, leaseOwner, leaseToken, leaseUntil, externalSubmissionStatus, externalRequestId, failureCode`。worker 领取、续租和完成须按 `version + leaseToken` 条件更新，失租者禁止回写。内部状态 `PENDING -> RUNNING -> SUCCEEDED`，异常进 `RETRY_WAIT / RECONCILE_REQUIRED / FAILED`。外部 Python 提交状态独立为 `NOT_SUBMITTED -> SUBMITTING -> CONFIRMED`；超时无法确认进 `UNKNOWN`，先用外部幂等键/任务 ID 查询，证实未提交方可重试，无法查询则人工对账。进程内异步或 Redis 防重不能替代恢复机制。

## 2. 第 3 节：供应商审批与字段出域

供应商配置状态 `DRAFT -> SECURITY_APPROVED -> CONTRACT_APPROVED -> ENABLED`；申请与审批身份分离，变更生成新版本，必要审批被撤销后立即停止新的真实数据调用。配置绑定固定网关、模型版本、用途、允许数据等级、密钥引用、预算和合同证据。留存、训练使用、地域、删除/退出、子处理者、故障通知和价格变更由安全、法务、采购确认。健康检查只允许固定合成文本，不视为真实数据授权。

新增专用出域 DTO，仅由获批快照映射指标编码、期间、数值、单位、来源版本、截至时间、质量状态。服务端依次校验：身份和机构 -> 用途和期间 -> 数据等级与合同 -> 字段白名单 -> 敏感值 -> 快照摘要 -> 出域审计；任一失败立即阻断。禁止复用 Python 训练 CSV/Base64、完整报告数据模型、客户与银行账号、SQL、连接信息或内部风险策略。审计记录 `traceId`、快照摘要、字段编码、规则及配置版本、审批单号、拒绝原因，不保存敏感值。真实字段分类矩阵未获业务、安全、法务和采购签署时，不允许公网出域。

## 3. 第 4—6 节：时序回测、公平比较和预测路由

样本记录 `eventTime`、`availableAt`、`asOf`、标签可用时间及数据修订版本；历史折只能读取 `availableAt <= asOf` 的值。每折独立拟合填补、标准化和特征选择；按预测起点滚动切分，明确 purge/embargo 长度及特征观察窗、标签形成期和多步预测依据。仅用训练/验证折调参；锁定测试窗只作最终选型验收，若改阈值或重新调参须登记新评估，不将原测试窗继续视为独立。

朴素基线、已有 Python 模型和新候选共享 `datasetSnapshotId + snapshotDigest + institutionSet + indicatorCode + unit + foldDefinition + horizon + validSampleMask`；缺折、失败折和异常剔除统一计入覆盖率。低于业务签署的最低折数/覆盖率时标记 `INELIGIBLE`，不得审批。统一计算 MAE、RMSE、WAPE、偏差、召回与误报；WAPE 分母为零标记不可计算。指标权重、误差容忍及阈值未经业务/风控签署时只能展示描述性结果，不能作上线排名结论。

候选状态 `EVALUATING -> REVIEW_PENDING -> SHADOW -> CANARY -> ACTIVE`；`REJECTED / ROLLED_BACK` 不可直接激活。正式预测唯一入口 `ForecastRouteResolver` 按机构、指标、预测起点、步长、生效时点与路由版本解析已批准制品；双人审批时重核评估、制品摘要、阈值、时段和身份。Python 输入必须从不可变 `predictionSnapshotId` 产生，派生指标和落库绑定同一摘要。影子预测进入独立记录，绝不写正式预测或处置；同一阈值快照下记录金额差、风险等级差、预警触发差和漏报/误报。阈值改变须重新评估审批。GRU 仅能作为已批准、同口径、制品有效的显式回退路由，记录原因与审计；否则拒绝本次正式预测，旧审核结果只能标记过期展示，LLM 不猜数。

## 4. 第 7、10 节：报告快照、审批与文件补偿

先冻结模板参数、模板版本、SQL/公式结果、来源和 `reportSnapshotId + snapshotDigest`；取数失败停止，不调用 LLM。预览、草稿、事实校验、人工修订、审批、渲染必须使用同一快照；新快照渲染入口不得调用旧 `generateReport` 重新查询 SQL，不接受任意 `runtimeItemValues` 或未批准额外参数。状态 `DATA_READY -> DRAFTING -> VALIDATING -> REVIEW_PENDING -> APPROVED -> RENDERING -> RENDERED`，另有 `FAILED / REJECTED / EXPIRED`；快照、模板、提示词或正文摘要变更即过期。

校验分结构、证据、数值和敏感信息四层；每项叙述有有效 `evidenceId`，金额、比例、日期及单位须与快照 `BigDecimal` 和经签署的换算/舍入口径一致，区别零、负数、空值与 `NULL`；事实不符或无出处不得审批。保存草稿原文/修订后哈希、差异、操作者、角色、时间和审批意见；修订人不得审批本人修订。审批条件更新须比对 `expectedVersion`、快照与正文哈希；发布文件不得覆盖，更正生成新版本。

渲染短事务登记任务并冻结批准版本，事务外渲染及按确定性文件键上传，短事务条件更新关联 `reportId + fileDigest`。状态 `PENDING -> RENDERING -> STORED -> LINKED`，异常进 `RETRY_WAIT / RECONCILE_REQUIRED / FAILED`。上传成功但落库失败先按文件键对账恢复关联，无法恢复再登记孤儿文件审计清理，不得报告成功。只有 AI 叙述失败且原数据完整时可显式降级无 AI 模板，原 SQL 失败必须整份停止。

## 5. 第 8、9、11 节：API、逻辑表和前端

新评估请求明确 `candidateIds, datasetSnapshotId, snapshotDigest, institutionId, indicatorCode, horizon, evaluationWindow`；新路由审批明确 `candidateId, evaluationId, artifactDigest, scope, effectiveFrom/To, riskThresholdVersion, expectedVersion`；新报告创建、审阅、渲染按动作传 `draftId, reportSnapshotId, snapshotDigest, templateVersion, promptVersion, expectedVersion`。服务端重核全部权限和摘要，不信任客户端。配置审批、评估启动、路由批准/回滚、草稿创建/审阅/渲染均带 `Idempotency-Key`；同授权主体、接口、键、指纹返回原任务，指纹不同或版本失配拒绝。所有读写逐次校验机构权限，前端按钮隐藏不算鉴权。

逻辑表新增候选及制品、不可变快照、评估主明细、正式路由及审批事件、影子结果、供应商审批、AI 任务、报告草稿、渲染任务和审计事件。评估明细按“评估+候选+折次+预测期”唯一，幂等按“主体+接口+键”唯一；达梦事务须锁定检查同机构、指标、步长和有效时段的正式路由不得重叠，普通唯一键不能防区间交叠。物理 DDL、并发策略、回滚脚本另经目标达梦评审，本次未执行。前端新建独立 `create -> get/status -> review -> render` 状态流，展示快照、事实校验、修订差异、版本冲突、过期和降级；旧非 AI 模板仍用旧接口与 DTO。预测页区分正式/影子/过期结果，评估页展示折次、覆盖率和不可比原因。
