# 资金风控第三方大模型可落地分阶段改造方案（技术复审稿）

日期：2026-10-13。状态：专家技术审议未通过后的修订建议；**未获业务、安全、DBA、技术负责人签署，不是投产审批**。继承 `20261013-资金风控第三方大模型详细设计-合并复审稿.md` 的业务边界：LLM 仅用于报告叙述，不做资金金额预测；新链路默认关闭。旧协议不静默改变字段含义，灰度范围内旧正式写入可以按服务端门禁拒绝；灰度前须完成调用方升级与回归。此稿不修改旧设计及源码。

## 1. 审议决定与拆分方式

技术专家对“立刻全面编码上线链路”结论为 **FAIL**：预测运行凭证的跨端传递、优化修改旁路、异步接口与 ID 所有权、达梦物理模型、Python 不确定提交对账以及报告模板映射尚未封闭。外部供应商合同不是合成数据模块开发的前置条件，但始终是真实数据第三方调用的前置条件。

按“调查/合成能力 → 数据契约 → 独立安全与报告模块 → 预测治理 → 受控联调”拆批。前一批完成验收，不等于自动放行下一批；任何批次不得以真实资金数据填充未获授权的新链路。方案核准后，第一批仅在隔离开发/测试环境实施；是否进入源代码修改另由项目负责人与设计责任方确认。

## 2. 首批实施前必须冻结的契约

| 决策项 | 推荐可实施契约 | 谁确认 / 证据及停止条件 |
| --- | --- | --- |
| 旧预测保存与运行凭证 | 新增独立 v2 `/forecast/runs` 创建与 `/forecast/runs/{predictionRunId}/save` 保存 API；服务端以 `predictionRunId` 关联不可变输入快照、批准的制品/路由/路由版本、结果摘要及机构/指标/步长，保存请求**不接受客户端重新传资金数值作为事实来源**。旧 API 请求响应字段保持原义；启用范围的旧 `savePredictionResults` 无可信运行 ID 时明确拒绝，不以线程本地、缓存最近一次生成或客户端指定金额推断来源 | API、预测后端、前端、定时任务负责人共同审定时序图、错误码及迁移清单；旧页面与定时任务未升级前不得打开启用范围 |
| 正式表全部写者 | 明确列旧手动保存、`YcjgJob` 两处保存、`applyOptimization` 及仓库内其他直接 mapper/SQL 写者。灰度范围内优化操作先禁止直接改正式预测值；若业务需要，单独设计带审批、快照、修订版本和审计的优化流程。统一在同一持锁短事务核对路由代际/回滚/运行 ID；未启用范围保持旧行为 | 后端负责人提交基于当前源码和 SQL 的全写者清单；负例确保无运行 ID、旧客户端、重复保存、优化更新及回滚后在途保存均不能绕行 |
| Python 外部提交 | 新内部任务 ID 与 Python `taskId` 分开存储；当前对端任务 ID 由 Python 创建，不预设客户端幂等。`SUBMITTING` 超时进入 `RECONCILE_REQUIRED`，不自动重发。对端自动清理和人工清理均须评估：现有自动任务清理默认为 72 小时、人工清理接口默认 24 小时，查不到任务不能证明未接收。冻结两条清理路径的权限、未知态豁免、最大对账窗口与权威证据；若未接收证明不可得，则维持未知态 | Python 负责人核实任务跨实例可见性和保留/清理配置；未核实不得上线自动恢复机制 |
| 达梦存储与互斥 | 先出新表字段、金额精度/索引/序列、唯一约束、路由范围互斥键及迁移前检查、回滚和数据保全脚本；正式生效、正式保存、回滚共用事务级互斥键；不能用逻辑表或其他数据库的 `auto_increment` 直接上线 | DBA 和后端签目标达梦版本的物理设计；双连接并发测试与回滚演练不过，不接入正式路由写入 |
| 报告快照与模板槽位 | 建不可变 `reportSnapshotId + snapshotDigest`，预览、验证、签核、渲染只读同一快照。逐模板清点 poi-tl 确定性数据项及可写的**文字槽位白名单**；AI 仅写叙述槽，不能覆盖金额、公式、编号、日期、机构；无映射模板禁用 AI 渲染 | 报告服务、业务模板负责人签模板版本/槽位清单；快照与最终文件数字和哈希回归通过后再扩模板 |
| 文件服务回执 | 上传前持久化渲染任务及文件摘要；只收到附件 ID 且不能按客户端键定位时，回执不明进入 `RECONCILE_REQUIRED`，不得宣称渲染成功或盲传第二次。文件服务明确可查询标识或经授权人工定位/孤儿清理流程 | 文件服务、运维确认契约；丢回执与关联失败故障注入未通过前不开放真实数据 AI 渲染 |

## 3. 最小接口、责任层与状态契约（提案，编码前联审）

| 业务动作 / 建议路径 | API DTO / 主标识 | BUSI、APP/worker 与前端职责 | 响应与失败要求 |
| --- | --- | --- | --- |
| `POST /api/v1/zjfk/forecast/runs`、`GET /forecast/runs/{predictionRunId}` | 机构、指标、步长、起点与幂等键；**不接收客户端金额**；服务端生成 `predictionRunId` | BUSI 校验授权并冻结预测快照/批准路由；APP 调用获准 Python 制品；Vue 或定时任务取运行状态 | 返回运行 ID、路由版本与 `PENDING/RUNNING/SUCCEEDED/FAILED/RECONCILE_REQUIRED`；结果只来自服务端 |
| `POST /api/v1/zjfk/forecast/runs/{predictionRunId}/save` | 运行 ID、期望版本、幂等键；不提交独立金额 | BUSI 同范围锁校验用户、机构、路由/回滚栅栏、结果摘要，一次性标记已保存；定时任务走内部等价方法 | 相同键同指纹返回原结果；重放不同内容或失效运行拒绝并审计；旧保存仅在未启用范围保持旧语义 |
| `POST /api/v1/zjfk/training/tasks`、`GET /training/tasks/{taskId}`、`POST /training/tasks/{taskId}/reconcile` | `taskId` 属内部持久任务；`trainingRecordId` 为旧训练记录；`modelId` 为旧模型记录；`candidateId/artifactId` 均为新记录 | BUSI 持久化幂等任务并授权查询；APP/worker 领租/提交及查询；对账动作限授权运维并附证据，不提供“找不到就重发”操作 | 返回任务状态及可脱敏错误码；`UNKNOWN/RECONCILE_REQUIRED` 不自动转成功/重试 |
| `POST /api/v1/zjfk/document/aiDraft/create`、`GET /document/aiDraft/{draftId}`、`POST /document/aiDraft/{draftId}/edit`、`/validate`、`/review` | 草稿 ID、快照 ID/摘要、正文版本与期望版本；编辑只提交允许的叙述段落 | BUSI 冻结取数与槽位白名单、事实校验并双人复核；APP 网关合成/获批字段出域；Vue 展示不可编辑的确定性数值 | 编辑使旧校验过期；不满足当前正文哈希/快照校验则拒绝签核；SQL 错误不调用 LLM |
| `POST /api/v1/zjfk/document/aiDraft/{draftId}/render`、`GET /document/renderTasks/{renderTaskId}` | 渲染任务 ID 仅服务端生成；引用已批准的快照、正文和模板版本 | BUSI 冻结审批证据；worker 事务外渲染上传，事务内关联附件；Vue 轮询 | `RENDERED` 才返回文件；`RECONCILE_REQUIRED/FAILED` 不返回成功 |

D 批还有原详细设计列出的候选评估、双签批准、路由回滚及影子预测路径；本稿不将其误作已冻结 DTO。A 批须将原稿的 `evaluationId/candidateId/artifactId/routeApprovalId/routeId/experimentId` 分别指定服务端生成者、归属表、可读范围，形成评估启动/查询、提交/两签/回滚、影子启动/查询的逐接口字段和状态迁移表，并由 API、BUSI、前端及风控联合签署；在表未签署前 D 批不得编码依赖这些契约的旧正式写入切换。

新接口状态变更统一 `Idempotency-Key` 与请求摘要，冲突返回稳定业务错误；乐观版本错误、越权、凭证不存在/已消费、路由失效、数据取数失败、对账待处理分别定义可区分的业务错误类别，并由 API 与前端联审映射为可恢复提示。任何新路径不得把旧 `modelIds` 改解释为 `candidateId`。此表是接口范围/状态提案，不代表 DTO 字段、响应码或现有认证上下文已签署。

## 4. 按批改造计划与明确门禁

| 批次 | 技术负责人及可交付物 | 准入 → 验收证据 | 不满足则 |
| --- | --- | --- | --- |
| A 现状基线 | 技术负责人组织 Java、Vue、Python、DBA：列完整正式写者、报告模板槽位、Python 任务/清理能力、达梦版本及环境调用链；拟出 SQL/DTO/迁移设计 | 在授权环境只读核实并由各责任人签代码位置与契约清单 → 可提交实施规格供正式评审 | 不修改旧写入路径，不推定外部能力 |
| B 合成安全组件 | 网关与安全负责人：独立配置草稿、密钥引用、拒绝式出域映射、合成数据适配器、限流和审计 | 设计与合成样本测试授权 → 字段组合、越权、撤权/发送竞态、DNS/重定向及空报文负例 | 禁真实数据调用；不改正式预测表 |
| C 报告基础 | 报告负责人：快照只读、模板白名单、事实校验、双人审阅与回执对账任务；先用固定合成模板 | 业务签槽位 → 预览/编辑/校验/渲染同摘要、SQL 失败停机、丢回执不报成功 | 限合成模板与内部测试；不扩任意真实模板 |
| D 任务与预测治理 | 预测、Python、DBA：达梦迁移、持久任务/对账、候选和回测、路由及独立 v2 预测保存；前端和定时任务升级 | 物理模型及接口契约签署 → 并发互斥、旧入口旁路、优化更新拦截、回滚失效、任务未知态回归 | 新预测路由开关保持关闭 |
| E 真实数据与受控灰度 | 业务/风控、安全/法务/采购、运维与变更审批方组织历史回测、影子、报告与灰度 | 数据授权/合同/阈值签署 → 锁定测试窗、目标环境联调、安全测试、回滚灾备及阶段 0—4 准入签署 | 不批准真实数据新链路或 CANARY/ACTIVE |

每批均要最小单元测试、与旧 API 回归、错误场景和回滚材料；先验收当前批再决定下批。B、C 的合成模块在契约签署后可独立开发，不必等 E 的合同；C 中与文件服务强耦合部分按回执能力单独冻结。D 中所有改旧写入的工作必须在 A 的完整写者清单与 DBA/API 契约通过后启动，不能依据本稿直接替换现有生产路径。

## 5. 请求评审专家团裁决的问题

1. `applyOptimization` 在灰度范围是先禁止正式修改，还是另行设计经审批的版本化优化？未签前采用**禁止修改灰度正式结果**作为安全默认值。
2. 旧页面和定时任务的升级次序：全部新调用方具备服务端运行 ID 时才允许打开任何对应灰度范围；旧保存接口在该范围无可信运行凭证一律拒绝。责任方是否认可该显式兼容边界？
3. Python 任务清理与不可查询、达梦互斥方案、报告模板槽位及文件回执能力是否有已确认的责任方和环境版本？没有证据的项保持待核实，绝不填充假定值。

待专家团对本稿闭环复评，并由业务/安全/风控/技术负责人确认边界之后，才拆出具体代码任务；投产仍需单独审批。
