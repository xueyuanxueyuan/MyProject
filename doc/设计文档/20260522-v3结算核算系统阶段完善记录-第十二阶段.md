## 1. 阶段目标

1. 延续第十一阶段后的第十二阶段安排，优先治理账户模块。
2. 移除 `AccountController` 对 `AccountRepository` 的直接依赖，避免 HTTP 适配层绕过应用层/领域服务查询账户。
3. 新增账户应用用例服务，收口账户注册与账户列表查询用例。
4. 新增账户响应 DTO 与 app Assembler，避免 Controller 对外直接暴露 `AccountModel`。
5. 为账户查询补齐领域服务语义：核算单位代码为空时抛 `BizException(PARAM_ERROR)`。
6. 保持既有 REST 路径和请求形态不变：
   - `POST /api/account/register`
   - `GET /api/account/query`
   - 注册请求仍沿用 `Map<String,Object>` 字段：`zhbh`、`zhmc`、`zh`、`khyh`、`hsdwdm`、`qybz`。

## 2. 改动前现状

| 位置 | 改动前行为 | 分层/语义风险 |
| --- | --- | --- |
| `AccountController#registerAccount` | Controller 内直接从 `Map<String,Object>` 取字段并构造 `AccountModel`，调用 `AccountDomainService#registerAccount` | HTTP 适配层承担用例组装与领域模型构造，Controller 偏厚 |
| `AccountController#queryAccounts` | Controller 直接注入 `AccountRepository` 并调用 `findByHsdwdm` | Controller 直连 Domain Repository，绕过应用层和领域服务查询语义 |
| `AccountController` 返回类型 | `R<AccountModel>` / `R<List<AccountModel>>` | 对外暴露领域模型，不符合 DTO 化规范 |
| `AccountDomainService` | 仅包含账户注册，缺少账户查询用例 | 账户查询规则散落在 Controller，无法统一参数校验 |
| 账户测试 | 缺少账户领域服务、应用服务、Controller 单元测试 | 账户路径缺少分层改造保护与回归证据 |

## 6. 风险与说明

1. 本阶段不改变接口路径、HTTP 方法、请求字段、数据库结构和基础设施 Mapper/Entity。
2. `AccountApplicationService` 当前沿用既有 `Map<String,Object>` 请求形态，未引入账户注册请求 DTO；后续如需强化接口契约，可单独设计账户请求 DTO/Assembler 切片。
3. `AccountController` 已移除 `AccountRepository` 和 `AccountDomainService` 字段依赖，但源码中原有 `@ConditionalOnBean(...)` 注释仍只是注释文本，不参与编译。
4. 账户注册的不变量校验仍较薄，本阶段仅新增账户列表查询的核算单位参数校验。
5. 基础设施编译过程中存在既有 deprecation warning：`RedisConfig` 中 `Jackson2JsonRedisSerializer#setObjectMapper` 标记为过时；本阶段未处理该既有警告。
6. 仓库中存在大量本轮之前的未跟踪/已修改文件；本阶段未处理这些既有工作区状态，仅对第十二阶段相关文件做局部验证。
