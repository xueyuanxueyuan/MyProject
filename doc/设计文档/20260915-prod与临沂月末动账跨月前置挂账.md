# prod 与临沂月末动账跨月前置挂账

## 已确认口径

- 资金日期只取账户变动通知 `ZjZhbdtz.jyrq`，格式 `yyyyMMdd`，不取事件日期或通知创建时间。
- 比较日期为结算参数 `RQCS/RQRQ` 加一天，不取机器当天。
- 仅处理 `jyrq` 是自然月最后一天、比较日期已进入后续月份、通知尚未处理（`dzzt=0`）的情况。
- 支持大小月、闰年及跨年；未来月末不提前挂账。例：`20260831` 与 `2026-08-31 + 1 天` 触发；与 `2026-08-30 + 1 天` 不触发。

## 当前自动认领范围（2026-09-15 最新确认）

- 只对明确单笔业务（sfpl=0）自动匹配认领，批量、空值或未知标志均只挂账。
- 暂收款调用 YwglService.skywZskZdCl；暂付款调用 YwglService.fkywZfkZdCl。月末应用服务不再直接调用 zskRl。
- 月末服务只定位唯一单笔业务并构造事件；实际暂收暂付查询、匹配和领用复用上述既有方法。
- 原事件业务流水优先；缺失时按银行流水限定中心、成功状态、账户和金额定位单笔候选。转移接续仍按既有区域规则在挂账提交后通知，不同时普通认领。

## 实现方案

### 2026-09-15 命名与架构整改设计

- 按项目规范 2.3 使用业务拼音缩写：月末跨月动账=ymkydz，交易日期=jyrq，业务日期=ywrq，暂收暂付=zszf，挂账后=gzh，自动领用=zdly，原业务结算流水=ywJslsh。
- 原 ZjdzclServiceImpl 只保留通知入口、暂收暂付生成及区域转移接续路由；公共签名不变。
- 应用层新增 YmkydzService / YmkydzServiceImpl，编排参数读取、既有 DmService 查询、Feign 挂账与领用、提交后同步处理。不新增对外接口，故不修改 api/app 装配模块。
- 领域层新增 YmkydzGz，封装无外部依赖的月末、跨月及匹配日期窗口规则。不把参数客户端、Feign 或数据库访问放入领域规则。
- 复用项目已有 JoinBeanUtil、Java 17 日期 API、Spring 事务同步；不新增框架、数据库对象或异步消息，不改变原事务时机及唯一匹配保护。
- 新增类和方法补齐中文职责、参数、返回值与异常说明；关键分支说明原业务流水保留、整批金额保护、提交后调用原因及转移接续互斥关系。
- 验收：现有两地各 69 项回归在重构后保持通过；规范扫描不得新增高风险命中；检查注释、命名、UTF-8 与改动范围。
- 方案审议：采用“应用编排 + 纯领域规则”的切片拆分；不选只替换名字（大类仍难读），也不引入异步事件或框架升级（会改变本次同步处理约定）。

目标为 prod、linyi 的 `capinfo-gjj-busi-zjjs-ywgl-basic-svc-busi` 模块内 `ZjdzclServiceImpl`。

1. 在业务匹配前严格解析原通知 `jyrq` 并判断月末跨月。
2. 正金额复用暂收生成，负金额复用暂付生成；零金额拒绝。
3. 在内部挂账模式下，使用生成结果 ID 调用 `zskZfkGzcl(id, zskjz/zfkjz)`，保留公共方法签名。
4. 生成或挂账失败抛业务异常，空响应及显式失败同样阻断匹配。
5. 挂账成功后，在本地事务提交后的同步回调中继续匹配：使用原事件业务流水号（生成暂收暂付之前保留），缺失时使用银行流水号，限定中心、成功状态、账户、金额与日期；仅对 sfpl=0 的唯一候选构造对账事件，按收付款方向调用 `skywZskZdCl` / `fkywZfkZdCl`，由既有方法查询暂收暂付并自动认领，不等待下一次任务。退出的是原动账直接对账路径，不能重复走原入账路径。
6. 对符合转移接续规则的暂收款，在挂账成功且本地提交后继续通知业务认领；该分支与普通自动领用互斥，保留 prod 策略及临沂摘要/备注正则差异。
7. 同月、非月末和已处理通知不重复触发新增生成/挂账。保留两地超时阈值。无唯一候选时保留挂账状态，不随意认领；既有入口返回 false/null 表示未完成匹配，保留挂账；底层领用接口失败、空响应或显式 false 抛异常。

在公共入口委托银企直联前，同样覆盖 BJC404 通知与 BJC102 付款结果，复用原查询条件和金额方向；不改银企直联独立实现。不改月初批量任务、财务凭证模板和全局认领管控，不执行真实资金操作或发布。

## 事务与验证边界

原入口使用本地 Spring 事务，日记账、暂收暂付和凭证通过 Feign 调用。本地回滚不能撤销远端已提交数据；本次复用既有事务架构，不引入分布式事务。远端成功而后续失败的恢复与重试须联调验证，不能仅凭本地单测宣称端到端入账一致性通过。

自动领用会通过业务回调更新原通知，因此不能在原事务持有通知行锁时同步调用远端领用。新增 afterCommit 同步处理：本地提交释放行锁后执行领用或转移通知，仍在事务入口返回之前执行，不使用异步线程或后续定时任务。回滚时不执行；没有本地事务时直接执行。若外层存在更大事务，则在该事务提交时执行。afterCommit 失败不能回滚已提交的挂账，需保留并核查异常。

自动匹配的日期窗口按自然日计算：通知交易日期减业务结果日期在 [-1, 2] 天内，跨月跨年不使用整数日期直接相减。转移通知沿用既有异常记录逻辑；通知失败的补偿不在本次新增范围内。

批量边界：现有 zskRl 请求没有明细选择参数，业务回调 zskLyUpdateYwxx 按中心、业务流水和成功状态处理整批成功明细，并更新父结果金额及状态。因此不能按单个银行流水组直接领用整批。当前仅允许明确单笔 sfpl=0，且保留业务总金额、银行结果金额与通知绝对金额一致及唯一匹配保护；所有批量业务均先挂账，不自动领用，不宣称已覆盖此类自动认领。若要支持此类资金，需另行补齐明细级核验及领用接口能力。
