## 1. 阶段目标

1. 承接第十三阶段凭证模块治理后的下一阶段建议，优先治理对账模块。
2. 将 `ReconController#createRecon` 中的请求 Map 解析、`BigDecimal` 转换与 `ReconModel` 构造移入应用服务。
3. 新增 `ReconApplicationService` 收口对账创建用例。

5. 在 `ReconDomainService#createRecon` 中补齐对账创建不变量校验：对账信息、对账编号、核算单位、对账日期、系统余额、银行余额、对账结果非空，并校验对账结果与系统余额/银行余额是否一致。
6. 保持既有 REST 路径和请求形态不变：`POST /api/recon/create`，请求仍沿用 `Map<String,Object>` 字段：`dzbh`、`hsdwdm`、`dzrq`、`xtye`、`yhye`、`dzjg`。

## 2. 改动前现状

| 位置 | 改动前行为 | 分层/语义风险 |
| --- | --- | --- |
| `ReconController#createRecon` | Controller 直接从 `Map<String,Object>` 取字段、转换金额并构造 `ReconModel` | HTTP 适配层承担用例组装与领域模型构造，Controller 偏厚 |
| `ReconController` 字段依赖 | 注入 `ReconDomainService` 和未使用的 `ReconRepository` | Controller 存在领域仓储依赖痕迹，分层边界不清晰 |
| `ReconController` 返回类型 | `R<ReconModel>` | 对外暴露领域模型，不符合 DTO 化规范 |
| `ReconDomainService#createRecon` | 仅调用 `model.initialize()` 和 `reconRepository.save(model)` | 缺少对账编号、核算单位、日期、余额、结果语义等不变量校验 |
| 对账测试 | 缺少领域服务、应用服务、Controller 单元测试 | 对账路径缺少分层改造保护与回归证据 |

## 6. 风险与说明

1. 本阶段不改变接口路径、HTTP 方法、请求字段、数据库结构和基础设施 Mapper/Entity。
2. `ReconApplicationService` 当前沿用既有 `Map<String,Object>` 请求形态，未引入对账创建请求 DTO；后续如需强化接口契约，可单独设计请求 DTO/Assembler 切片。
3. `ReconController` 已移除 `ReconRepository` 和 `ReconDomainService` 字段依赖。
4. 对账结果语义当前以 `dzjg=MATCH` 表示系统余额与银行余额应一致；非 `MATCH` 表示应存在差异。若后续有正式枚举或字典，应将该字符串语义收敛到枚举。
5. 基础设施编译过程中存在既有 deprecation warning：`RedisConfig` 中 `Jackson2JsonRedisSerializer#setObjectMapper` 标记为过时；本阶段未处理该既有警告。
6. 仓库中存在大量本轮之前的未跟踪/已修改文件；本阶段未处理这些既有工作区状态。
