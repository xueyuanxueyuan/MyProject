# 临沂项目科目总账明细账仅用 jzrq、弃用 tjny 条件实现建议

## 1. 前提约束

本次口径以用户最新要求为准：

- 不新增字段
- 沿用现有字段和参数
- `tjny` 不再作为删除和查询条件
- 仅使用现有 `jzrq` 字段完成报表结果的生成重制与查询

## 2. 可行性结论

该方案**可以做**，但有一个前提必须同时成立：

- 当前所有账表行，包括“上年结转 / 上次结转 / 本月合计 / 本年合计”这类汇总行，也必须写入一个有效的 `jzrq`

如果不做这一步，仅把 `tjny` 从条件中删除，会出现：

- 旧汇总行删不掉
- 报表按 `jzrq` 范围查询时查不出汇总行
- 同一科目不同期间重制后结果混杂

## 3. 当前问题点

现有实现里，以下行保存时 `jzrq = null`：

- 总账：
  - 上年结转 / 上次结转
  - 本月合计
  - 本年合计
- 明细账：
  - 上年结转 / 上次结转
  - 本月合计
  - 本年合计

而当前删除与查询仍依赖：

- `ztbh`
- `bbbh`
- `kmbh`
- `tjny`
- `czy`

因此一旦去掉 `tjny`，就必须让 `jzrq` 真正承担“这一批结果的期间定位”能力。

## 4. 推荐实现口径

## 4.1 总原则

只保留现有字段时，建议把 `jzrq` 分成两类使用方式：

- 明细/发生行：`jzrq` 仍保存真实记账日期
- 汇总/结转/合计行：`jzrq` 统一写成一个位于查询期间内、且可稳定命中的日期

这样删除和查询都可以统一按 `jzrq` 范围处理。

## 4.2 建议的 jzrq 赋值规则

### 总账

- 上年结转 / 上次结转：
  - `jzrq = ksrq`
- 每日汇总发生行：
  - `jzrq = 实际发生日期`
- 本月合计：
  - `jzrq = 当月最后一个已统计日期`
  - 如果当月已到月末，则就是月末日
  - 如果查询截止在月中，则取本次统计到的最后一天
- 本年合计：
  - `jzrq = jzrq_end`

### 明细账

- 上年结转 / 上次结转：
  - `jzrq = ksrq`
- 凭证明细行：
  - `jzrq = 实际凭证记账日期`
- 本月合计：
  - `jzrq = 该月最后一个已统计日期`
- 本年合计：
  - `jzrq = jzrq_end`

## 4.3 这样做的原因

这样处理后：

- 所有行都落在 `[ksrq, jzrq_end]` 期间内
- 同一期间重制时，能通过 `jzrq` 范围整批删干净
- 报表查询时，能把汇总行一并查出来
- 月结自动制作时，可以直接按月度开始/截止日期制作和查询

## 5. 删除条件建议

当前 `deleteByZb` 按 `tjny` 删除，应调整为按 `jzrq` 区间删除。

### 总账/明细账统一建议

删除条件保留：

- `ztbh`
- `bbbh`
- `kmbh`
- `czy`

删除区间改为：

- `jzrq >= ksrq`
- `jzrq <= jzrq_end`

即：

```sql
delete from cwhs_zb
where ztbh = ?
  and bbbh = ?
  and kmbh = ?
  and czy = ?
  and jzrq >= ?
  and jzrq <= ?
```

注意：

- 前提是所有汇总行的 `jzrq` 必须已改成非空且落入期间内

## 6. 查询条件建议

报表模板里当前按 `tjny = jzrq_end` 查询，应改成按 `jzrq` 范围查询。

### 总账

当前模板 `jshs-zz.rpx` 逻辑建议改成：

```sql
select *
from cwhs_zb
where ztbh = ?
  and bbbh = 'zz'
  and concat(?, ',') like concat('%', kmbh, ',%')
  and czy = ?
  and jzrq >= ?
  and jzrq <= ?
order by kmbh, xuhao
```

### 明细账

当前模板 `jshs-mxz.rpx` 逻辑建议改成：

```sql
select *
from cwhs_zb
where ztbh = ?
  and bbbh = 'mxz'
  and kmbh = ?
  and czy = ?
  and jzrq >= ?
  and jzrq <= ?
order by xuhao
```

## 7. 生成逻辑最小改动点

## 7.1 saveZb 不再依赖 tjny 作为判定

当前 `saveZb()` 中：

- `tjny = zb.getJzrq()`
- 仍会继续落库到 `tjny`

在本次方案里：

- 可以保留 `tjny` 字段继续写值，不必删字段
- 但业务上不再把它当删除与查询条件

也就是说：

- **字段保留**
- **条件移除**

## 7.2 总账需要补齐汇总行 jzrq

需要改动这些调用点：

- 上年结转 / 上次结转：把 `null` 改成 `ksrq`
- 本月合计：把 `null` 改成“该月最后统计日期”
- 本年合计：把 `null` 改成 `jzrq_end`

## 7.3 明细账需要补齐汇总行 jzrq

需要改动这些调用点：

- 上年结转 / 上次结转：把 `null` 改成 `ksrq`
- 月切换时插入的本月合计：把 `null` 改成 `jzrq_last2`
- 尾部本月合计：把 `null` 改成 `jzrq_end`
- 本年合计：把 `null` 改成 `jzrq_end`

## 8. 是否保留 czy

在“不加字段”的前提下，我建议**暂时保留 `czy`**。

原因：

- 去掉 `tjny` 后，如果连 `czy` 也去掉，那么同账套、同科目、同期间的数据很容易被不同用户互相覆盖
- 先保留 `czy`，至少还能维持现有隔离方式

如果后续月结自动制作希望全员共查同一份结果，可以再统一约定：

- 自动任务固定写 `czy = SYSTEM`

然后报表查询也统一按 `SYSTEM` 查询。

这样仍然不需要新增字段。

## 9. 月结自动制作适配建议

按本方案，月结自动制作可以这样做：

1. 传入月初 `ksrq`
2. 传入月末 `jzrq_end`
3. 自动调用总账制作接口
4. 自动调用明细账制作接口
5. 查询报表时同样按该 `jzrq` 范围取数

这样月结和人工查询口径就统一了。

## 10. 结论

在“**不新增字段，只用现有 `jzrq`，并且 `tjny` 不再作为条件**”这个约束下，正确做法不是简单删掉 `tjny` 条件，而是：

1. 保留现有表结构和参数
2. 让所有汇总行的 `jzrq` 也赋成有效日期
3. 删除按 `jzrq` 范围删
4. 查询按 `jzrq` 范围查
5. 暂时保留 `czy` 作为结果隔离条件

这样可以在不新增字段的情况下，满足：

- 按期间重制总账和明细账
- 按期间直接查询报表
- 支持月结自动制作

同时避免：

- 汇总行丢失
- 新旧结果混杂
- 不同期间重制互相污染
