# 资金预决算及执行情况 - 资金使用预算组设计

## 1. 设计范围

本组仅覆盖以下两张表：

- 住房公积金资金使用预算总表
- 住房公积金资金使用预算附表

本组对应的前端原型设计单独见：

- [资金使用预算组-前端原型设计.md](file:///home/source/Jetbrains/Probject/Gjj/doc/设计文档/20260602-资金使用预算组-前端原型设计.md)

本组对应的详细设计与数据库设计单独见：

- [资金使用预算组-详细设计与数据库设计.md](file:///home/source/Jetbrains/Probject/Gjj/doc/设计文档/20260602-资金使用预算组-详细设计与数据库设计.md)

本组设计必须严格继承已确认的共性规则，包括：

- 全市值不允许人工调整
- 每张业务表独立建模，优先采用固定字段
- 模板只做辅助配置，不过度模板化
- 预算表在每年 3 月编制，审议通过后锁定
- 自动取数失败不允许人工补录兜底

## 2.3 结构结论

本组最核心的结构结论有 4 个：

1. 附表是分中心填报来源表，总表是全市汇总展示表。
2. 总表和附表不是同构关系，不能设计成一套字段直接复用。
3. 总表中的“本年预算数”并非全部手工填写，很多值来自附表汇总、上一年度预算或上一年度决算。
4. 附表中的“全市”列是系统汇总列，不是人工录入列。

## 3. 业务规则清单

## 3.1 时间规则

- 每年 3 月生成当年预算单据。
- 预算表编制完成后进入审核。
- 审议通过后锁定，不允许继续修改。

## 3.2 填报主体规则

- 分中心填报人只填附表本机构数据。
- 市中心查看全市及各机构数据，负责审核和锁定。
- 总表业务值不由分中心直接填写。

## 3.3 汇总规则

- 附表“全市” = 各分中心数据自动汇总。
- 总表“本年预算数”来源于附表“全市”或上年决算/预算结果。
- 不允许人工直接修改全市汇总结果。

## 3.4 上年结转规则

- 总表“上年预算数”取上一年度同表“本年预算数”。
- 总表“上年实绩数”取上一年度决算表对应值。
- 附表“年初余额”按上一年度决算年末余额自动带出。

## 3.5 表内公式规则

### 归集提取

- 附表年末余额 = 年初余额 + 当年归集数 - 当年提取数 + 当年统筹调剂资金
- 总表年末余额 = 年初余额 + 当年归集数 - 当年提取数

说明：

- 总表虽然不展示“当年统筹调剂资金”独立行，但总表口径仍需承接附表的最终归集提取结果。
- 系统实现时应以附表汇总结果作为总表来源，而不是在总表中重新让用户填一次。

### 个人贷款

- 年末余额 = 年初余额 + 当年发放数 - 当年收回数 - 当年“公转商”贷款转出
- 个人贷款余额占归集余额比% = 个人贷款年末余额 / 归集提取年末余额

### 国债投资

- 年末余额 = 年初余额 + 当年增加数 - 当年回收数
- 国债投资余额占归集余额比% = 国债投资年末余额 / 归集提取年末余额

## 3.6 不可填规则

以下内容不得手工填报：

- 全市列
- 总表公式项
- 总表上年预算数
- 总表上年实绩数
- 附表年末余额
- 附表各类占比行

## 3.7 当前阶段可填规则

附表中原则上允许手工填写的仅包括：

- 归集提取-当年归集数
- 归集提取-当年提取数
- 归集提取-当年统筹调剂资金
- 个人贷款-当年发放数
- 个人贷款-当年收回数
- 个人贷款-当年“公转商”贷款转出

国债投资部分当前按 Excel 原表口径处理：

- 默认值为 0
- 不作为本期可编辑重点

后续若业务确认某年度存在国债投资预算值，再开放对应字段。

## 4. 页面交互设计

## 4.1 页面布局

本组建议采用“一组两页签”结构：

1. 总表页签
2. 附表页签

页面顶部统一展示：

- 年度
- 报表编号
- 编制单位
- 状态
- 操作按钮

## 4.2 附表页面

附表页面作为主要填报页。

展示方式：

- 行方向固定 16 行业务项
- 列方向展示 6 个分中心
- 全市列固定在最前，只读展示

交互规则：

- 分中心登录后，仅本机构列可编辑
- 其他机构列只读
- 全市列只读
- 自动计算行实时联动刷新

### 附表重点交互

- 输入框仅出现在可填业务行
- 公式行显示结果，不显示输入框
- 比例行显示百分比格式
- 默认值为 0 的国债投资行显示只读 0

## 4.3 总表页面

总表页面作为汇总展示页。

展示方式：

- 按 15 行业务结构展示
- 展示 4 个值列和 1 个比例列

交互规则：

- 业务值全部只读
- 由系统根据附表汇总和历史数据自动生成
- 仅签字信息、备注信息等辅助项允许市中心在审核阶段录入

## 4.4 操作按钮

分中心可见：

- 保存草稿
- 提交审核

市中心可见：

- 退回
- 审核通过
- 锁定
- 导出 Excel

## 5. 权限与填报控制

## 5.1 分中心填报人

可操作范围：

- 查看总表
- 查看附表中的全市及本机构列
- 编辑附表本机构可填字段

不可操作范围：

- 编辑全市列
- 编辑其他机构列
- 编辑总表业务值
- 修改系统自动计算结果

## 5.2 市中心审核人

可操作范围：

- 查看全市及所有机构明细
- 审核总表与附表勾稽关系
- 退回或通过

不可操作范围：

- 直接改写分中心原始录入值
- 直接改写全市汇总值

## 5.3 锁定后

- 总表、附表全部只读
- 导出内容取锁定快照

## 6. 数据库设计

## 6.1 设计原则

本组数据库遵循：

- 固定字段优先
- 总表与附表独立建模
- 附表按机构一行存储
- 不为本组再引入通用单元格模型

## 6.2 总表设计

建议表名：

- `CWHS_ZJYJS_ZJSYYSZB`

表定位：

- 一张年度预算总表一行
- 存储总表表头信息、状态信息、锁定信息以及总表可见业务值快照

### 核心表头字段

- `BBBH` 报表编号
- `ND` 年度
- `BZDW` 编制单位
- `BBZT` 报表状态
- `DWFZR` 单位负责人
- `KJZG` 会计主管
- `ZBR` 制表人
- `SPSJ` 审批时间
- `SFSD` 是否锁定

### 总表业务字段设计

总表业务字段按“行 + 指标”固定展开。

建议命名结构：

- `{业务段}_{指标项}_{值类型}`

值类型固定为：

- `SNYSS` 上年预算数
- `SNSJS` 上年实绩数
- `BNYSS` 本年预算数
- `WSNSJBL` 为上年实绩比率

### 示例字段

- `GJTQ_NCYE_SNYSS`
- `GJTQ_NCYE_SNSJS`
- `GJTQ_NCYE_BNYSS`
- `GJTQ_DNGJS_BNYSS`
- `GJTQ_NMYE_BNYSS`
- `GRDK_NCYE_SNSJS`
- `GRDK_DNFFS_BNYSS`
- `GRDK_NMYE_BNYSS`
- `GRDK_DKYEZBGJYE_BNYSS`
- `GDTZ_NCYE_BNYSS`
- `GDTZ_NMYE_BNYSS`
- `GDTZ_YEZBGJYE_BNYSS`

说明：

- 比例类字段仍采用数值字段存储，前端按百分比显示。
- 不适用值可为空，不强行写 0。

## 6.3 附表设计

建议表名：

- `CWHS_ZJYJS_ZJSYYFB`

表定位：

- 一张年度预算附表按机构拆成多行
- 一行代表一个机构当年的附表预算数据

主键维度建议：

- `ND`
- `BBBH`
- `HSJGBH`

### 机构字段

- `HSJGBH`
- `JBJGBH`
- `JBJGMC`

### 附表业务字段设计

附表仅承载“本年预算数”口径，因此每个项目只保留一个固定字段。

建议字段：

- `GJTQ_NCYE`
- `GJTQ_DNGJS`
- `GJTQ_DNTQS`
- `GJTQ_DNTCDJZJ`
- `GJTQ_NMYE`
- `GRDK_NCYE`
- `GRDK_DNFFS`
- `GRDK_DNSHS`
- `GRDK_DNGZSDKZC`
- `GRDK_NMYE`
- `GRDK_DKYEZBGJYE`
- `GDTZ_NCYE`
- `GDTZ_DNZJS`
- `GDTZ_DNHSS`
- `GDTZ_NMYE`
- `GDTZ_YEZBGJYE`

说明：

- 公式类字段如 `GJTQ_NMYE`、`GRDK_NMYE`、`GRDK_DKYEZBGJYE`、`GDTZ_NMYE`、`GDTZ_YEZBGJYE` 物理上保留字段，但不允许人工编辑。
- 这样做是为了在锁定时保留导出口径快照，避免每次导出都依赖实时重算。

## 6.4 为什么总表和附表不能共表

原因如下：

1. 总表列结构是 4 类指标 + 比率，附表只有本年预算数。
2. 附表多出“当年统筹调剂资金”行，总表没有对应展示行。
3. 总表强调跨年对比，附表强调机构分解。
4. 总表是展示结果，附表是填报来源。

因此本组不建议把总表和附表硬做成一张通用表。

## 7. 自动计算与取数规则

## 7.1 自动取上一年度预算

总表 `SNYSS` 字段统一取上一年度总表 `BNYSS` 对应字段。

示例：

- `2025.GJTQ_DNGJS_SNYSS = 2024.GJTQ_DNGJS_BNYSS`

## 7.2 自动取上一年度决算

总表 `SNSJS` 字段统一取上一年度决算表对应字段。

附表年初余额也取上一年度决算附表的年末余额。

示例：

- `2025.GJTQ_NCYE_BNYSS = 2024 决算表 GJTQ_NMYE_SNSJS`
- `2025 附表.GJTQ_NCYE = 2024 决算附表.GJTQ_NMYE`

## 7.3 自动汇总附表

全市值不入库为独立人工行，统一按机构行实时汇总。

汇总逻辑：

- 全市 = 市本级 + 嘉善 + 平湖 + 海盐 + 海宁 + 桐乡

## 7.4 总表本年预算数生成规则

总表 `BNYSS` 主要分三类来源：

1. 直接取附表全市汇总值
2. 由总表公式计算
3. 由上一年度决算值带出

具体规则如下：

- `GJTQ_NCYE_BNYSS` = 上一年度决算对应年末余额
- `GJTQ_DNGJS_BNYSS` = 附表全市 `GJTQ_DNGJS`
- `GJTQ_DNTQS_BNYSS` = 附表全市 `GJTQ_DNTQS`
- `GJTQ_NMYE_BNYSS` = 附表全市 `GJTQ_NMYE`
- `GRDK_NCYE_BNYSS` = 上一年度决算对应年末余额
- `GRDK_DNFFS_BNYSS` = 附表全市 `GRDK_DNFFS`
- `GRDK_DNSHS_BNYSS` = 附表全市 `GRDK_DNSHS`
- `GRDK_DNGZSDKZC_BNYSS` = 附表全市 `GRDK_DNGZSDKZC`
- `GRDK_NMYE_BNYSS` = 附表全市 `GRDK_NMYE`
- `GRDK_DKYEZBGJYE_BNYSS` = 附表全市 `GRDK_DKYEZBGJYE`
- `GDTZ_*` 默认按 0 或空值口径生成

## 7.5 比率字段计算规则

- `WSNSJBL = BNYSS / SNSJS`
- 比率类字段分母为 0 或空时，结果为空，不强行置 0

## 8. 接口设计

## 8.1 查询预算组首页

`GET /api/zjyjs/zjsyy/list`

返回：

- 年度
- 报表编号
- 状态
- 锁定状态
- 创建时间

## 8.2 查询预算总表

`GET /api/zjyjs/zjsyy/zb/{id}`

返回：

- 表头信息
- 总表全部固定字段
- 只读标识

## 8.3 查询预算附表

`GET /api/zjyjs/zjsyy/fb/{id}`

返回：

- 表头信息
- 全市汇总视图
- 各机构固定字段行
- 当前用户可编辑字段范围

## 8.4 保存附表

`POST /api/zjyjs/zjsyy/fb/save`

保存内容：

- 当前机构允许编辑的固定字段

## 8.5 提交审核

`POST /api/zjyjs/zjsyy/submit`

提交前校验：

- 必填字段是否填写
- 公式字段是否成功生成
- 全市汇总是否成功
- 上年取数是否成功

## 8.6 审核与锁定

- `POST /api/zjyjs/zjsyy/review`
- `POST /api/zjyjs/zjsyy/reject`
- `POST /api/zjyjs/zjsyy/lock`

## 8.7 导出

`GET /api/zjyjs/zjsyy/export/{id}`

导出规则：

- 优先取锁定快照
- 未锁定时导出当前预览值并标识“草稿”

## 9. 导出与快照设计

## 9.1 快照时点

以下时点生成快照：

- 审核通过前预览快照
- 锁定时正式快照

## 9.2 快照内容

快照应包含：

- 总表全部展示字段
- 附表全部机构明细字段
- 表头
- 签字信息
- 导出时间
- 导出版本号

## 9.3 为什么必须保留快照

因为本组存在大量自动带值和自动汇总：

- 上年预算带入
- 上年决算带入
- 附表汇总总表
- 表内公式实时计算

如果不保留锁定快照，后续历史重查时结果可能受源数据变化影响。

## 10. 本组待你确认的问题点

以下 4 个关键口径已确认：

1. 附表作为唯一填报来源，总表全部业务值由系统生成，不允许在总表直接补录业务数据。
2. 附表“全市”列不落人工行，只做查询汇总视图。
3. 国债投资本期默认按只读 0/空值处理，不纳入分中心手工填报重点。
4. 总表锁定时保留总表快照字段，附表锁定时保留机构明细快照。

## 14. 达梦建表字段级设计

## 14.1 设计口径

本节用于把本组设计进一步细化到可直接转 DDL 的层级。

字段类型遵循当前仓库达梦脚本风格：

- 主键：`BIGINT`
- 编码类：`NVARCHAR` 或 `VARCHAR2`
- 状态类：`VARCHAR2(2)` 或 `NVARCHAR(1)`
- 时间类：`TIMESTAMP(0)`
- 金额/比率类：`DECIMAL(20,4)`

说明：

- 金额和比率统一先按 `DECIMAL(20,4)` 设计，前端决定显示为金额或百分比。
- 比率字段存储小数值，例如 `0.4869`，页面再格式化为 `48.69%`。
- “不适用”字段允许为空，不强制写 0。
