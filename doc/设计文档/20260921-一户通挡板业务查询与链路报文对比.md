# 一户通挡板业务查询与交易链路报文对比

日期：2026-09-21

## 需求

挡板管理页新增「业务查询」：分别展示单笔交易、批量交易、签约类交易三类数据列表与当前状态并实时刷新；每行可关联到链路追踪查看该笔业务各节点的加密与解密后报文；批量业务支持下钻查看逐笔明细的数据列表，含每笔明细的状态与失败原因。

## 已确认口径

- 三类数据来源：单笔交易 YHT_MOCK_TRADE、批量交易 YHT_MOCK_BATCH、签约类交易 YHT_MOCK_PROTOCOL，与「业务状态仓」同源，不新增业务表。
- 批量状态口径（2026-09-22 二次修订）：挡板作为银行侧，**推送 107 即代表该批次交易处理完毕**，状态必须是终态。
  - 受理阶段（caps.101）即按同一次生成的结果文件推导默认终态：全部明细结果码 00 → `SUCC`，存在非 00 → `FAIL` 并带首个失败明细的结果码与描述；场景规则显式 `forceStatus` 时以规则为准。
  - 推送 107 前再兜底一次（幂等）：若批次仍停留在非终态（PROC/PEND/INIT 等），按结果文件落终态并保存，确保 107 报文与页面状态一致；已有终态不覆盖，规则显式强制状态时不覆盖（并记日志说明）；结果文件无法解析时保持原状态、不猜测。
  - **105/106 只读**：caps.105 是企业查询批次结果的请求，106 只如实回显批次状态，**不再修改状态、不再写库**（此前 `buildCaps106` 里存在「PROC → SUCC」并保存的副作用，已删除）。
- 历史数据修复：升级前产生的、已推送 107 但仍为 PROC 的批次，通过 `POST /yht-mock/api/batches/repair-processing`（页面「修复处理中批次」按钮）按各批次自身结果文件一次性落终态；缺少或无法解析结果文件的批次不修改，单独列出供人工核对。修复为 SUCC 的批次可再用资金流水页「同步已有成功交易」补生成按包动账流水。该操作幂等，可重复执行。
- 批量动账口径（2026-09-22 修订）：**按包生成**，一个批次只登记并推送一条动账流水，金额取该批次成功明细金额合计（付款方向取负，失败明细不计入），去重键使用批次维度（企业号|业务日期|交易码|批次标识），同一批次重复触发不重复生成。此前按明细逐笔生成，1073 条明细会刷出 1073 条流水。
- 页面形态：**同页三标签**（单笔交易 / 批量交易 / 签约类交易），一次只显示一个标签的全宽表格，避免三列并排导致列被挤压截断；标签切换不刷新页面，各标签独立记忆当前页码与每页条数。
- 批量明细：**模态弹窗**展示（不再是页面底部内联卡片，避免必须滚动到底才能看），弹窗内逐笔列出明细自身状态与失败原因，并在汇总行展示包级流水状态、金额与失败原因。
- 分页：**服务端分页**，接口按 page/size 查询并返回 total/totalPages；每页条数可选 10 / 20（默认） / 50 / 100，页码与总条数在面板底部展示，首尾页时禁用对应翻页按钮。列表只返回摘要字段，不返回批次结果文件等大字段。
- 实时刷新为页面轮询（默认开启、每 5 秒），只轮询当前标签且保持当前页码，页面不可见或处于链路追踪页时不轮询；可手动关闭。
- 「链路」按钮复用既有链路追踪：把该行的链路关键词（单笔取 ReqId 优先、批量取批次号、签约取协议号）写入关键词并跳转，由既有链路时间线按共享标识串联。
- 报文对比：请求/响应走 CAPS 信封加密时保存解密后明文；未加密节点两列相同，解密列显示「未加密」提示，避免误判为丢数据。
- 批量明细：解析批次结果文件逐笔明细（序号/银行标识/账号/户名/金额/结果码/结果描述/主机流水），并关联该批次的资金流水状态与失败原因。

## 实现边界

- 模型：MockRecord 增加 decryptedRequestBody / decryptedResponseBody，对应 YHT_MOCK_RECORD 新增的 C_DECRYPTED_REQUEST_BODY / C_DECRYPTED_RESPONSE_BODY（CLOB）；原始加密报文列不变。
- 网关：仅当请求实际发生信封解密时写入两列明文（请求明文 + 响应明文），未加密时保持为空。
- 新增接口：`GET /yht-mock/api/business/{type}?page=1&size=20`（type=trade|batch|protocol；返回 type/page/size/total/totalPages/count/items，items 含当前状态、金额或笔数、更新时间、链路关键词；page 1~10000，size 1~100）；`GET /yht-mock/api/batches/{batchNo}/details`（明细列表 + 资金流水状态与失败原因 + 每状态计数）。
- 明细与流水的关联规则（2026-09-22 起）：动账按包生成，明细不再逐笔挂流水；接口返回 `packageFlow`（包级流水的状态、金额、方向、失败原因、推送次数）与 `flowStatusCount`，页面明细行只展示明细自身状态与失败原因，包级流水在汇总处展示。
- **升级注意**：按包生成改变了批量动账去重键（由明细维度改为批次维度），升级前已按明细生成过流水的历史批次若再次触发同步/重发，会产生一条新的包级流水（与历史明细级流水并存），需要人工识别。建议不要在历史批次上重新触发动账。
- 前端：新增 business.js 与「业务查询」区块（三标签全宽列表 + 服务端分页控件 + 明细面板 + 实时刷新开关）；链路追踪的调用详情改为原始请求/解密后请求/原始响应/解密后响应四块报文分区展示。
- 不修改结算端接口、不改动链路串联算法、不影响资金流水的生成与推送判定。
