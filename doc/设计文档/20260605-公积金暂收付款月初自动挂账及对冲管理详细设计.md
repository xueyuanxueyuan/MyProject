## 1. 背景与目标

### 1.1 业务背景

当前公积金资金结算与财务核算链路中，银行流水、账户变动通知、暂收款、暂付款、银行存款日记账、凭证和月结之间存在强关联。月末或月初存在部分资金流水未及时挂账时，会带来以下问题：

1. 暂收、暂付款未按资金实际发生月份挂账，存在跨期风险。
2. 跨月未挂账资金仍可能被匹配、认领或查询出来继续处理，影响财务月结口径。
3. 月结任务当前具备前置检查能力，但缺少在月结之前对上月未挂账资金自动补挂账的独立处理任务。
4. 正负资金流水清理依赖人工多环节处理，需要支持暂收与暂付之间的手工对冲。

因此，本次设计将“月初自动挂账”和“月结检查”明确拆分为两个独立任务：

```text
每月 1 日 02:00
  ↓
任务一：月初自动挂账任务
  - 扫描上月未挂账资金
  - 自动生成暂收/暂付
  - 按资金发生日完成挂账
  - 写入处理日志
  ↓
任务二：月结任务前置检查
  - 检查是否仍存在未处理/未挂账数据
  - 检查未记账日记账、未记账业务流水
  - 检查通过后执行月结
```

### 1.2 设计目标

1. 新增独立的“月初自动挂账任务”，在自动月结任务之前执行。
2. 保留现有月结前置检查逻辑，将其作为自动挂账后的兜底校验。
3. 对跨月且未挂账的暂收/暂付款，在匹配、认领、查询等入口统一管控。
4. 支持正负资金流水手工对冲，并记录对冲单号、对冲状态和凭证信息。
5. 明确状态字段、任务边界、接口影响、数据库设计、异常处理和验收用例。

### 1.3 非目标

1. 本设计不直接替换现有月结任务。
2. 本设计不取消现有月结前置检查。
3. 本设计不直接执行数据库结构变更。
4. 本设计不直接修改现有生产数据。
5. 本设计不在当前阶段承诺所有暂收/暂付接口已经具备统一状态字典，实际开发前需复核各表字段含义。

### 2.5 挂账与认领的业务边界

本设计明确区分“挂账”和“认领”：

| 业务动作 | 含义 | 处理对象 | 是否可使用认领接口 |
| --- | --- | --- | --- |
| 挂账 | 将未挂账资金按发生日生成暂收/暂付，并形成财务入账记录 | 银行流水、账户变动通知、暂收/暂付、日记账、凭证 | 否 |
| 认领 | 将已存在的暂收/暂付款领用到具体收款、付款退款等业务 | 已挂账或已存在的暂收/暂付和业务单据 | 是，仅限认领场景 |
| 匹配 | 在暂收/暂付与业务之间建立匹配候选或确认关系 | 暂收/暂付、收款业务、付款退款业务 | 否，匹配不等同挂账 |

设计约束：

1. 月初自动挂账任务必须调用财务挂账、凭证、日记账或暂收/暂付生成相关能力，不得调用 `zskRl` 等暂收款认领接口替代挂账。
2. 认领接口只在“资金已经形成暂收/暂付后，将暂收/暂付领用到业务”的环节使用。
3. 跨月未挂账管控可以限制认领入口，但不代表自动挂账要走认领入口。
4. 文档和代码命名中应避免使用“匹配认领”描述挂账，自动任务统一称为“自动挂账”或“补挂账”。

## 3. 总体设计

### 3.1 任务拆分原则

本需求拆分为四个功能域：

| 功能域 | 职责 | 是否独立任务 |
| --- | --- | --- |
| 月初自动挂账 | 处理上月未挂账资金，生成暂收/暂付并挂账 | 是 |
| 月结前置检查 | 检查自动挂账后是否仍有遗漏，阻止异常月结 | 是，沿用现有月结任务 |
| 跨月权限管控 | 对跨月未挂账数据限制查询、匹配、认领 | 否，嵌入业务接口 |
| 正负流水对冲 | 手工选择正负资金流水并生成对冲凭证 | 否，新增业务能力 |

### 3.2 执行顺序

```text
每月 1 日 02:00
  ↓
月初自动挂账任务
  ↓
成功：写入成功日志，更新流水/暂收暂付/日记账状态
失败：写入失败日志，保留待处理状态
  ↓
每月 1 日 03:00 或 07:00
  ↓
月结任务 yjAddJobHandler
  ↓
执行 checkGlobalMonthEndPreconditions
  ↓
执行 checkAccountMonthEndPreconditions
  ↓
检查通过后执行 cwhsService.addYj
```

### 3.3 设计原则

1. 自动挂账任务只负责挂账，不直接推进财务月结。
2. 月结任务只负责检查与月结，不承担自动补挂账职责。
3. 查询过滤与操作校验必须同时存在，避免绕过前端或列表过滤直接提交。
4. 对冲必须具备可审计性，必须记录对冲单号、参与流水、参与暂收/暂付、凭证号和操作人。
5. 状态变更必须幂等，重复执行任务不得重复生成暂收/暂付或重复对冲。

## 4. 月初自动挂账详细设计

### 4.1 任务定义

建议新增 XXL Job：

```text
zszfMonthBeginAutoPostJobHandler
```

中文名称：

```text
暂收暂付月初自动挂账任务
```

建议执行时间：

```text
每月 1 日 02:00
```

如果业务要求 7 点执行，可配置为：

```text
每月 1 日 07:00
```

但必须保证该任务执行时间早于自动月结任务。

### 4.2 任务输入

| 参数 | 来源 | 说明 |
| --- | --- | --- |
| 当前日期 | 系统时间 | 用于计算上月区间 |
| 业务日期 | 系统参数 `RQRQ` | 用于确认是否已进入当月 1 日 |
| 上月年月 | 当前日期减一个月 | 格式 `YYYY-MM` |
| 上月月初 | 日期计算 | 上月第一天 |
| 上月月末 | 日期计算 | 上月最后一天 |

### 4.3 候选数据范围

候选数据优先来源：

```text
zjjs_zj_zhbdtz
```

候选条件：

1. 交易日期 `jyrq` 在上月月初至上月月末之间。
2. 动账处理状态 `dzzt = '0'`。
3. 未生成暂收/暂付或未完成挂账。
4. 未被标记为已对冲、已忽略或异常关闭。

说明：

- 当前代码已有 `countUnprocessedZhbdtz` 使用 `dzzt='0'` 统计未处理账户变动通知。
- 开发时需要补充查询明细方法，例如 `listUnprocessedZhbdtzForAutoPost`。

### 4.4 收款类与付款类识别

建议优先按现有字段判断资金方向，判断顺序如下：

1. 如果账户变动通知存在明确交易方向字段，优先使用交易方向。
2. 如果不存在交易方向字段，则按金额正负判断：
   - 金额大于 0：收款类流水，生成暂收款。
   - 金额小于 0：付款类流水，生成暂付款。
3. 如果借贷方向字段存在，则以借贷方向与金额正负做一致性校验。

异常规则：

| 场景 | 处理方式 |
| --- | --- |
| 金额为空 | 记失败日志，不生成暂收/暂付 |
| 金额为 0 | 记失败日志，不生成暂收/暂付 |
| 方向无法识别 | 记失败日志，保留待人工处理 |
| 金额方向与借贷方向冲突 | 记失败日志，保留待人工处理 |

### 4.5 挂账科目规则

| 资金来源 | 生成对象 | 挂账科目 | 辅助核算 |
| --- | --- | --- | --- |
| 收款类流水 | 暂收款 | `21904` 其他应付款-其他应付款 | 按机构辅助核算，默认会计科 |
| 付款类流水 | 暂付款 | `119` 其他应收款 | 按银行大类辅助核算 |

设计要求：

1. 科目不要硬编码在业务主流程中，应优先通过参数、科目配置或账套配置获取。
2. 如果暂时只能按需求固定科目实现，也应集中在常量或配置类中，避免散落在多个方法。
3. 科目缺失或辅助核算缺失时，当前流水失败，不影响其他流水处理。

### 4.6 自动挂账处理流程

自动挂账只处理“资金入财务暂收/暂付账”的动作，不处理“暂收/暂付被具体业务认领”的动作。该流程不得调用暂收款认领接口。

```text
开始
  ↓
校验业务日期是否已进入当月 1 日
  ↓
计算上月月初、月末
  ↓
查询上月 dzzt='0' 的账户变动通知
  ↓
逐条处理
  ↓
判断资金方向
  ├─ 收款类：生成暂收款挂账对象
  └─ 付款类：生成暂付款挂账对象
  ↓
生成银行存款日记账或关联既有日记账
  ↓
调用财务挂账/凭证生成能力，按资金发生日入账
  ↓
更新暂收/暂付入账状态
  ↓
更新账户变动通知 dzzt
  ↓
写入自动挂账日志
  ↓
结束
```

挂账接口选择原则：

1. 优先复用现有“生成暂收/暂付 + 生成凭证 + 更新日记账/入账状态”的财务核算能力。
2. 如现有能力分散，应封装独立的 `ZszfAutoPostService` 编排，不得在 Job 中直接拼接多张表更新。
3. 不允许用暂收款认领接口、匹配接口替代挂账接口。
4. 自动挂账完成后，资金只是形成暂收/暂付并完成财务入账，不自动绑定到具体业务。

### 4.7 幂等控制

自动挂账任务必须支持重复执行。

幂等键建议：

```text
zhbdtz_id + 资金方向 + 交易日期 + 金额
```

幂等校验规则：

| 已存在数据 | 处理方式 |
| --- | --- |
| 已存在暂收/暂付且已挂账 | 跳过，记跳过日志 |
| 已存在暂收/暂付但未挂账 | 继续执行挂账 |
| 已存在挂账日志且状态成功 | 跳过 |
| 已存在失败日志 | 可重试处理 |
| 已对冲 | 跳过 |

### 4.8 失败处理

单条失败不得中断整个任务。

任务级结果：

| 场景 | XXL Job 结果 |
| --- | --- |
| 全部成功 | `handleSuccess` |
| 部分成功、部分失败 | 建议 `handleFail`，消息包含失败数量和日志查询入口 |
| 全部失败 | `handleFail` |
| 无待处理数据 | `handleSuccess` |

### 4.9 自动挂账日志

建议新增自动挂账日志表，用于财务上班后查看系统确认补挂账结果。

建议表名：

```text
cwhs_zszf_auto_post_log
```

字段建议：

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| zxbh | varchar(20) | 中心编号 |
| ztbh | varchar(20) | 账套编号 |

| source_amount | decimal(18,2) | 原流水金额 |

## 5. 月结前置检查详细设计

### 5.1 与自动挂账任务的关系

月结检查不与自动挂账冲突，二者职责不同：

| 任务 | 执行顺序 | 职责 |
| --- | --- | --- |
| 月初自动挂账任务 | 先执行 | 主动处理上月未挂账资金 |
| 月结前置检查 | 后执行 | 兜底检查是否仍有未处理数据 |

### 5.2 保留现有校验

保留现有 `YjAddJobHandler` 中的以下校验：

1. 业务日期必须到当月 1 日。
2. 上月不能存在未入暂收暂付数据。
3. 指定账套不能存在未记账银行存款日记账。
4. 指定账套不能存在未记账业务流水。

### 5.3 建议增强点

1. `countUnprocessedZhbdtz` 建议新增明细查询能力，月结失败时可以返回失败明细数量和日志入口。
2. 月结检查的提示文案中增加“请先查看月初自动挂账日志”。
3. 月结检查不自动触发补挂账，避免月结任务职责膨胀。
4. 如果自动挂账任务未执行，月结检查仍应按当前逻辑阻止月结。

## 6. 跨月未挂账权限管控设计

### 6.1 判断规则

统一判断口径：

```text
允许操作 = 资金交易日期与当前业务日期同月 OR 入账状态 = 已入账
禁止操作 = 资金交易日期与当前业务日期不同月 AND 入账状态 = 未入账
```

### 6.2 日期来源

| 概念 | 推荐字段 | 说明 |
| --- | --- | --- |
| 资金交易日期 | `jyrq` 或 `jzrq` | 优先使用原始账户变动通知交易日期 |
| 当前业务日期 | 系统参数 `RQRQ` | 与现有业务日期口径保持一致 |
| 入账日期 | `rzrq` | 实际入账日期 |
| 月结年月 | 账套属性 `yjny` | 判断财务已结账月份 |

实际开发前必须确认字段来源，避免混用 `jyrq`、`jzrq`、`rzrq`。

### 6.3 受控功能

| 功能 | 控制方式 | 说明 |
| --- | --- | --- |
| 暂收款 → 收款业务匹配查询 | 查询过滤 | 不展示跨月未入账数据 |
| 暂收款 → 收款业务匹配提交 | 操作校验 | 提交时二次校验 |
| 暂付款 → 付款退款匹配查询 | 查询过滤 | 不展示跨月未入账数据 |
| 暂付款 → 付款退款匹配提交 | 操作校验 | 提交时二次校验 |
| 暂付款认领 | 操作校验 | 禁止认领 |
| 暂收/暂付相关查询 | 查询过滤 | 默认过滤不可操作数据 |

### 6.3.1 挂账、匹配、认领的管控边界

跨月管控同时影响挂账、匹配和认领，但三者处理方式不同：

| 链路 | 控制目标 | 设计要求 |
| --- | --- | --- |
| 自动挂账链路 | 对上月未挂账资金主动补挂账 | 只调用挂账能力，不调用认领能力 |
| 匹配链路 | 防止跨月未挂账资金被匹配到业务 | 查询过滤 + 匹配提交校验 |
| 认领链路 | 防止跨月未挂账暂收/暂付被业务领用 | 认领查询过滤 + 认领提交校验 |

认领链路的修改仅限于增加控制，不改变挂账实现：

1. `zskRl` 等认领接口只能在资金已经形成暂收/暂付后使用。
2. 自动挂账任务不得调用认领接口。
3. 认领接口需要增加跨月未挂账校验，防止未挂账资金被领用。
4. 匹配接口与认领接口应分别加校验，不应把匹配校验替代认领校验。

### 6.4 统一校验服务

建议新增统一校验服务：

```text
ZszfMonthControlService
```

核心方法建议：

| 方法 | 职责 |
| --- | --- |
| `boolean isSameMonth(Date fundTradeDate, Date businessDate)` | 判断交易日期与业务日期是否同月 |
| `boolean isPosted(String rzzt)` | 判断是否已入账 |
| `void checkAllowOperate(ZszfControlContext context)` | 操作前校验，不通过抛业务异常 |
| `QueryCondition buildVisibleCondition(ZszfQueryContext context)` | 查询层构造过滤条件 |

错误文案：

```text
该笔暂收/付款交易日期为 [YYYYMMDD]，已超过当前业务日期 [yyyy-mm-dd]，且未挂账，不允许进行[匹配/认领/查询]操作。请先完成入账或联系财务。
```

### 6.5 查询过滤与操作校验双保险

必须同时实现：

1. 查询接口过滤：减少用户看到不可操作数据。
2. 操作接口校验：防止用户绕过页面直接调用接口。

### 6.6 匹配与认领首批实施说明（2026-06-05）

本次实施范围仅覆盖“匹配部分”和“认领部分”的跨月未挂账管控，不实现月初自动挂账、月结前置检查和正负流水对冲。

| 链路 | 实施方式 | 说明 |
| --- | --- | --- |
| 暂收款可用列表 | 在暂收款查询条件中追加 `rzzt = '1' OR jyrq BETWEEN 当前业务月初 AND 当前业务月末` | 跨月未入账暂收款不进入认领/匹配选择范围 |
| 暂付款可用列表 | 在暂付款查询条件中追加同口径过滤 | 跨月未入账暂付款不进入认领选择范围 |
| 暂收款认领提交 | 根据暂收款 ID 查询原始记录后执行硬校验 | 避免绕过页面直接调用认领接口 |
| 暂付款认领提交 | 根据暂付款 ID 查询原始记录后执行硬校验 | 避免绕过页面直接调用认领接口 |
| 暂收款匹配提交 | 业务管理侧通过账户管理 Feign 校验暂收款 ID | 业务管理不直接依赖账户管理实现类 |

实施约束：

1. 挂账与认领继续保持边界隔离，本次没有使用认领接口替代挂账。
2. 匹配查询中的收款业务、付款业务候选分页属于业务侧数据，不直接持有暂收/暂付 `rzzt` 字段；因此首批实施以暂收/暂付可用列表过滤和匹配提交二次校验作为双保险。
3. 统一业务日期仍取资金结算系统参数 `RQCS/RQRQ`，判断规则为“同业务月或已入账允许，跨业务月且未入账禁止”。

## 7. 正负资金流水对冲详细设计

### 7.1 对冲场景

| 场景 | 收款资金 | 付款/退款资金 | 处理方式 |
| --- | --- | --- | --- |
| 双方都未挂账 | 未入账 | 未入账 | 勾选两条日记账流水，生成对冲凭证，自动标记已入账 |
| 双方都已挂账 | 已入账 | 已入账 | 选择暂付，再选择暂收，生成对冲凭证并冲销两笔挂账 |
| 单方挂账 | 已入账 | 未入账 | 先对未挂账一方执行挂账，再生成对冲凭证 |

### 7.2 对冲限制

| 限制 | 规则 |
| --- | --- |
| 金额相等 | 收方金额绝对值 = 付方金额绝对值 |
| 同一账户 | 两笔流水必须属于同一个银行账户 |
| 不可重复 | 已对冲流水不可再次对冲 |
| 跨月限制 | 双方均未挂账且不同月份时不可对冲 |
| 状态限制 | 已匹配、已认领、已核销的数据不可再次参与对冲 |


### 7.4 对冲状态字段

建议在参与对冲的业务对象上增加以下字段，或通过对冲单反查：

| 字段 | 说明 |
| --- | --- |
| hedge_status | 对冲状态：`0` 未对冲，`1` 已对冲 |
| hedge_no | 对冲单号 |
| hedge_time | 对冲时间 |

如果不能改原表，则在查询和操作时通过 `cwhs_zszf_hedge_order` 判断是否已对冲。

### 7.5 对冲凭证

凭证分录按需求：

```text
借：暂收款
贷：暂付款
```

或根据实际借贷方向反向生成。

设计要求：

1. 对冲凭证必须记录对冲单号。
2. 对冲成功后更新两端流水或暂收/暂付状态。
3. 对冲失败时不得更新业务状态。
4. 对冲凭证撤销时需回退对冲状态。

### 7.6 对冲处理流程

```text
用户选择正负两端数据
  ↓
校验金额是否相等
  ↓
校验是否同一银行账户
  ↓
校验是否已对冲
  ↓
校验跨月规则
  ↓
判断挂账状态
  ├─ 双方未挂账：生成对冲凭证并标记已入账
  ├─ 双方已挂账：生成对冲凭证并冲销两笔挂账
  └─ 单方挂账：先补挂账，再生成对冲凭证
  ↓
生成对冲单号
  ↓
写入对冲单
  ↓
更新两端状态为已对冲
  ↓
返回处理结果
```

## 15. 结论

本需求应按“先处理、后检查、再管控、补对冲”的思路落地：

1. **月初自动挂账任务**是新增独立任务，必须早于月结任务执行。
2. **月结前置检查**不是替代逻辑，必须保留作为兜底。
3. **跨月未挂账权限管控**必须同时覆盖查询过滤和操作校验。
4. **正负资金流水对冲**需要具备对冲单号、对冲状态、凭证号和防重复处理能力。
5. 开发前必须先确认 `dzzt`、`rzzt`、`cxzt` 等状态字典，避免不同表状态值混用。
