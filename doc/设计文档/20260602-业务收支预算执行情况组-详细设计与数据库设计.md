# 资金预决算及执行情况 - 业务收支预算执行情况组详细设计与数据库设计

## 1. 设计目标

本文档用于把“业务收支预算执行情况组”推进到可直接指导后端开发、前端联调和达梦建表的详细设计层级。

## 2. 本轮定版结论

本轮按最新确认口径，将本组结构定为：

1. 本表是月度单表，不拆总表/附表。
2. 分中心是唯一责任填报主体，市中心只做汇总审核。
3. 主表采用一月一单模式。
4. 明细表采用“一张报表 + 一个机构一行”的固定字段模式。
5. 主表和明细表统一使用 15 个系统字段。
6. 明细表中的 `HSJGBH` 保存具体责任机构。
7. 前端通过固定行配置把明细固定字段还原为 Excel 15 行结构。

## 3. 业务对象设计

## 3.1 主表对象

表名：`CWHS_ZJYJS_YWSZYSZXQKB`

定位：

- 一张月度业务收支预算执行情况表一行
- 存表头、状态、签字、审核、锁定、取数控制信息
- 不直接存 15 行业务值

职责：

- 作为月报主单
- 作为机构执行明细的父记录
- 作为状态流转、审核和锁定控制主体

## 3.2 机构执行明细对象

表名：`CWHS_ZJYJS_YWSZYSZXQKFB`

定位：

- 一张执行情况表按机构拆成多行
- 一行代表一个核算机构在一个月报单中的全部业务收支执行指标
- 是分中心确认提报与全市汇总的唯一来源

职责：

- 存储机构自动取数值
- 存储机构自动计算值
- 存储机构确认状态与异常信息
- 为全市汇总和导出提供来源

## 4. 状态流转设计

## 4.1 主表状态

建议口径：

- `0`：草稿
- `1`：已提交
- `2`：审核退回
- `3`：审核通过
- `4`：已锁定

## 4.2 明细表状态

明细表也保留 `BBZT`：

- `0`：草稿
- `1`：已提交
- `2`：退回
- `3`：审核通过
- `4`：已锁定

作用：

- 标识具体机构当前确认提报状态
- 支撑“只退回责任机构”的处理模式

## 4.3 流转规则

1. 市中心创建月报主单。
2. 系统初始化全部分中心明细行。
3. 系统自动取数并写入各机构自动取数项。
4. 分中心打开本机构视图，查看自动生成结果。
5. 分中心保存草稿或提交本机构数据。
6. 市中心查看全市和各机构执行情况，执行审核或退回。
7. 审核通过后市中心锁定，主表与明细表全部只读。

## 5. 系统字段口径

两张表统一保留以下 15 个系统字段：

- `ID BIGINT NOT NULL`
- `ZXBH NVARCHAR(15) NOT NULL`
- `REVISION INT NOT NULL`
- `CREATOR NVARCHAR(100)`
- `CREATED_TIME TIMESTAMP(0) NOT NULL DEFAULT CURRENT_TIMESTAMP()`
- `UPDATOR NVARCHAR(100)`
- `UPDATED_TIME TIMESTAMP(0)`
- `JBJGBH NVARCHAR(30) NOT NULL`
- `JBJGMC NVARCHAR(90) NOT NULL`
- `WDBH NVARCHAR(30)`
- `WDMC NVARCHAR(90)`
- `QDLX NVARCHAR(10)`
- `QDBM NVARCHAR(16)`
- `DEL_FLAG NVARCHAR(1) NOT NULL DEFAULT '0'`
- `HSJGBH NVARCHAR(10) NOT NULL DEFAULT '01'`

说明：

- 主表中的 `HSJGBH` 保存全市口径，如 `01`
- 明细表中的 `HSJGBH` 保存实际责任机构

## 6. 字段类型规则

金额字段统一使用：

- `DECIMAL(20,4)`

比例字段统一使用：

- `DECIMAL(20,6)`

编号、状态、标识类字段统一使用：

- `VARCHAR2`
- `NVARCHAR`
- `CHAR(1)`

## 8. 可编辑字段范围

本组不设置业务值人工编辑字段，分中心只允许：

- 触发自动取数
- 保存确认状态
- 提交本机构结果
- 维护制表人等元数据

其余字段规则：

- 自动取数值：只读
- 自动计算值：只读
- 全市汇总值：只读，不落明细表

## 9. 自动取数与计算设计

## 9.1 自动取数映射

### 收入

- `SR_BNYSS <- 1-2月为空，3月起取业务收支预算表收入预算值`
- `SR_BNSJS <- 科目401收入`
- `SR_SNTQS <- 上年同月执行表收入实绩数`

### 支出

- `ZC_BNYSS <- 1-2月为空，3月起取业务收支预算表支出预算值`
- `ZC_BNSJS <- 科目411支出`
- `ZC_SNTQS <- 上年同月执行表支出实绩数`

## 9.2 自动计算规则

### 收入

- `SR_WBNYSSBL = SR_BNSJS / SR_BNYSS`
- `SR_TBZZ = SR_BNSJS / SR_SNTQS - 1`

### 支出

- `ZC_WBNYSSBL = ZC_BNSJS / ZC_BNYSS`
- `ZC_TBZZ = ZC_BNSJS / ZC_SNTQS - 1`

### 增值收益

- `ZZSY_BNYSS = SR_BNYSS - ZC_BNYSS`
- `ZZSY_BNSJS = SR_BNSJS - ZC_BNSJS`
- `ZZSY_WBNYSSBL = ZZSY_BNSJS / ZZSY_BNYSS`
- `ZZSY_SNTQS = SR_SNTQS - ZC_SNTQS`
- `ZZSY_TBZZ = ZZSY_BNSJS / ZZSY_SNTQS - 1`

### 全市列

- 金额行：全市值 = 全部分中心值求和
- 比率行：全市值 = 汇总分子 / 汇总分母

## 10. 接口设计

## 10.1 查询页面

`GET /api/zjyjs/ywszyszxqk/{mainId}`

返回内容：

- 主表信息
- 当前角色可见列范围
- 全机构执行明细数组
- 行配置数组
- 当前机构取数状态

## 10.2 自动取数

`POST /api/zjyjs/ywszyszxqk/fetchBranch`

作用：

- 按主表年月和当前机构重新自动取数
- 更新本机构自动取数项
- 重算本机构和全市公式项

## 10.3 保存本机构草稿

`POST /api/zjyjs/ywszyszxqk/saveBranch`

作用：

- 保存本机构确认状态和制表人等元数据

## 10.4 分中心提交

`POST /api/zjyjs/ywszyszxqk/submitBranch`

作用：

- 仅提交本机构行
- 行状态改为已提交
- 触发主表汇总状态刷新

## 10.5 市中心审核

- `POST /api/zjyjs/ywszyszxqk/review`
- `POST /api/zjyjs/ywszyszxqk/reject`
- `POST /api/zjyjs/ywszyszxqk/lock`

## 11. 业务流程

## 11.1 建单与初始化

1. 市中心创建月报主表。
2. 系统初始化全部分中心明细行。
3. 系统根据年月和机构批量取数。
4. 系统重算收入、支出、增值收益相关公式项。

## 11.2 分中心确认流程

1. 分中心进入页面。
2. 系统仅返回全市列和本机构列。
3. 分中心点击自动取数，查看本机构结果。
4. 若取数成功，分中心保存草稿并提交本机构数据。
5. 若取数失败，系统展示失败原因，不允许提交。

## 11.3 市中心审核流程

1. 市中心打开执行情况表。
2. 查看全市列及全部分中心列。
3. 核对异常机构和结果勾稽。
4. 审核通过或退回责任机构。
5. 审核通过后执行锁定。

## 12. 数据流与关联

## 12.1 数据流

1. 年度业务收支预算表、上年同月执行表、会计科目进入自动取数服务。
2. 自动取数服务写入机构执行明细表。
3. 公式计算服务计算收入、支出、增值收益相关结果。
4. 汇总服务生成全市展示值。
5. 前端按行配置渲染 15 行 Excel 结构。

## 12.2 数据关联

- 主表和明细表使用 `MAIN_ID + BBBH` 双关联。
- 明细表使用 `HSJGBH` 区分责任机构。
- 全市列不落库，由明细汇总生成。
