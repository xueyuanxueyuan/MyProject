# 一户通挡板自动动账通知实施设计

## 目标与边界

交易模拟成功后，向结算系统 POST /api/v1/ywgl/saveZhbdzt 提交与模拟动账通知页面相同的数据。该接口保存后发布处理事件，不只是暂存。仅修改 yht-mock-server，不修改业务系统、数据库或环境配置，不提交、不发布。

## 数据与触发

- 单笔：20601 付款取 DbtrActId，金额为负；20602 收款取 CdtrActId，金额为正。必须同时满足 status/resFlag=SUCC、RetCode=000000。
- 批量：40501 付款、40502 收款，取 CorpAcctNo。批次 SUCC 且 ResFlag=SUCC、无 ErrorCode 时解析结果文件，只提交返回码 00 的成功明细。初始 PROC 不生成，提回结果转为 SUCC 后触发。
- 对手账号、户名、行号统一配置为测试虚拟信息；余额为固定模拟值，不冒充真实余额。
- 收付款动账代码由配置明确指定，不猜测地区交易字典。未知类型、缺失账号、非法金额不发送并记录原因。
- 单笔使用原银行流水；批量使用批次号和明细序号生成稳定唯一的模拟银行流水。

标准 caps.101 仅提供 FileName 而不提供 BatchNo，因此批量去重优先取原请求 FileName，再回退 BatchNo；已通过重复上传链路测试确认。自动通知不使用挡板缺失金额/明细时的演示默认值。

## 安全与去重

- 默认关闭，启用需填写通知地址、收付款动账代码。与 CAPS 自动回调开关分离，遵守场景禁用自动回调。
- 完整 HTTP/HTTPS 地址禁止用户信息及查询串；鉴权从指定服务器环境变量读取 Authorization，不持久化凭证、不返回前端、不写日志。
- 按企业号、日期、交易码、原业务流水或批次明细持久化去重。发送前落盘占位，落盘失败禁止发送；成功、失败和超时均不自动重发。
- 请求、响应与状态记入本地日志；清空普通日志不清空去重，清空所有历史会清空去重。
- 异步有界执行，失败不改变原交易结果；重启不自动重发在途请求。

## 修订（2026-09-22，用户反馈交易日期变了）

动账通知报文在原页面数据基础上新增 **jyrq（交易日期）** 字段，取值固定为原交易 `checkDate`（交易处理完成日），单笔与批量按包一致，随报文发送给结算端落 `zjZhbdtz.jyrq`；结算端不再按推送当日生成交易日期。原因：此前报文不含日期，结算端按接收日生成，导致补推/重推时交易日期随推送时间漂移。改动仅在 `MovementNotificationService.generateMovement` 增加 `jyrq` 字段（businessDate 非空时），并补充后端断言用例；未修改 CAPS 回调格式、未打包未部署。
