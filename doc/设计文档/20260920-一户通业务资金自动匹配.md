# 一户通业务资金自动匹配

## 确认范围

用户确认修改 prod 和嘉兴，命中特殊对手账号优先匹配一户通；找不到时继续其他类型匹配。不发布、不修改真实银行账号，不连接业务数据库。

## 实施设计

- gjj.yht.fund-match.counterparty-accounts 使用字符串账号列表；默认空，不改变原流程。2026-09-21 按用户确认移除银行分组，入口名单仅比较通知的 jydszh，不比较银行代码。
- 在账户变动通知进入普通收付款匹配前调用专用匹配器。prod 保留现有月末跨月挂账优先级。
- 当前一户通批量结果分发直接回写 zjjs_yw_jg 和收付款明细，不回写传统批量处理表；batch_task.success_amt 不能作为已维护成功金额使用。
- 以业务批次（结算流水号）为单位，中心账号取收付款主业务 yhzhhm，交易日期取业务结果 jyrq（由一户通结果分发器回写），成功金额取业务结果 yhje（成功明细汇总）；不使用申请总金额或创建日期。
- 限定中心、机构、银行、收付款方向、一户通批量任务及已分发终态。正数为收款，负数为付款，按金额绝对值比较。零金额、冲正及不完整关键字段不进入新流程。
- 零候选返回原流程；多候选保留未匹配并记日志，不任意选择。唯一候选更新成功明细和业务结果到 70，通知到 7；失败明细保持不变。
- 通知行锁及结果条件更新防重复竞争，检查更新笔数，异常回滚本地修改。收款复用 skywFsRjz，付款复用 updateYhckrjz，再调用现有业务记账通知。
- 已有 dzclJobHandler 重试 dzzt=0 通知，覆盖结果晚到。已经由其他流程认领或转暂收暂付的通知不被本功能夺回。
- 按主业务批次成功总额匹配，不擅自将一笔动账拆分到多个业务批次；银行对拆分子批次分别动账时，不使用金额组合试配。

## 对手账号列表配置

以下仅为格式示例，账号为测试值，不是实际银行账号：

```yaml
gjj:
  yht:
    fund-match:
      counterparty-accounts:
        - 001234
        - 009999
```

配置中的每个字符串都是 jydszh，不需要 yhdm 或 custNo；同一家银行的多个账号直接平铺填写。账号必须加引号以保留前导零。未启用时使用 counterparty-accounts: []。

升级时将原银行映射下的账号合并为同一列表，原 counterparty-accounts: {} 也需改为 []；不继续兼容旧映射结构。此变更仅简化优先匹配入口的账号名单，交易候选查询保留原有中心、机构、中心账号、银行、日期、金额等条件。
