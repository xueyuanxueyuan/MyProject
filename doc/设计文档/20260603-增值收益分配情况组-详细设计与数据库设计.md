# 资金预决算及执行情况 - 增值收益分配情况组详细设计与数据库设计

## 1. 设计目标

本文档用于把“增值收益分配情况组”推进到可直接指导后端开发、前端联调和达梦建表的详细设计层级。

本组范围仅包含：

- 住房公积金增值收益分配情况总表
- 住房公积金增值收益分配情况附表

本组关联文档：

- [增值收益分配情况组设计.md](file:///home/source/Jetbrains/Probject/Gjj/doc/设计文档/20260603-增值收益分配情况组设计.md)

## 2. 本轮定版结论

本轮按已确认口径，将增值收益分配情况组结构定为：

1. 总表采用“主表 + 总表明细行”模式。
2. 附表采用“一张报表 + 一个机构一行”的固定字段模式。
3. 总表、总表明细、附表明细统一使用 15 个系统字段。
4. 总表与附表统一使用 `MAIN_ID + BBBH` 双关联。
5. 自动来源字段与原始录入字段分离，分中心仅维护 5 个原始事实字段。
6. 总表接口返回 10 行 `details` 数组，附表接口返回机构明细数组。

## 3. 业务对象设计

## 3.1 总表主表对象

表名：`CWHS_ZJYJS_ZZSYFPQKZB`

定位：

- 一张年度增值收益分配总表一行
- 存表头、状态、同步时间、审核、锁定等控制信息
- 不直接存 10 行业务值

职责：

- 作为增值收益分配主单
- 作为总表明细和附表明细的父记录
- 作为状态流转、审核和锁定控制主体

## 3.2 总表明细对象

表名：`CWHS_ZJYJS_ZZSYFPQKZMX`

定位：

- 一张总表的 10 行业务项逐行存储
- 一行代表 Excel 总表中的一个项目 + 说明组合
- 存该行的 `SNSJS`、`BNSJS`、`TBZZ`

职责：

- 直接承载总表展示数据
- 直接支撑总表前端与 Excel 导出
- 保存行次、项目、说明、是否公式行等结构信息

## 3.3 附表明细对象

表名：`CWHS_ZJYJS_ZZSYFPQKFB`

定位：

- 一张附表按机构拆成多行
- 一行代表一个核算机构在一个分配单中的全部固定字段
- 是机构来源展示、汇总统计和流转确认的基础

职责：

- 存储机构自动来源字段
- 存储机构原始录入事实值
- 存储机构公式结果
- 存储机构同步状态与流转状态
- 为总表明细提供全市实绩来源

## 4. 状态流转设计

统一状态建议：

- `0`：草稿
- `1`：已提交
- `2`：审核退回
- `3`：审核通过
- `4`：已锁定

流转规则：

1. 市中心创建增值收益分配主单。
2. 系统初始化总表 10 行明细和附表机构行。
3. 系统执行来源同步，抓取业务收支决算增值收益和上一年度年末余额。
4. 分中心维护本机构允许编辑的分配事实值，可保存草稿。
5. 分中心提交确认。
6. 市中心审核通过或退回。
7. 审核通过后，市中心执行锁定。
8. 锁定后总表主表、总表明细、附表明细全部只读。

## 5. 系统字段口径

三张表统一保留以下 15 个系统字段：

- `ID BIGINT NOT NULL`
- `ZXBH NVARCHAR(15) NOT NULL`
- `REVISION INT NOT NULL`
- `CREATOR NVARCHAR(100)`
- `CREATED_TIME TIMESTAMP(0) NOT NULL DEFAULT CURRENT_TIMESTAMP()`
- `UPDATOR NVARCHAR(100)`
- `UPDATED_TIME TIMESTAMP(0)`
- `JBJGBH NVARCHAR(30) NOT NULL`
- `JBJGMC NVARCHAR(90) NOT NULL`
- `WDBH NVARCHAR(30)`
- `WDMC NVARCHAR(90)`
- `QDLX NVARCHAR(10)`
- `QDBM NVARCHAR(16)`
- `DEL_FLAG NVARCHAR(1) NOT NULL DEFAULT '0'`
- `HSJGBH NVARCHAR(10) NOT NULL DEFAULT '01'`

说明：

- 主表中的 `HSJGBH` 保存全市口径，如 `01`
- 总表明细中的 `HSJGBH` 与主表保持一致
- 附表明细中的 `HSJGBH` 保存具体确认机构

## 6. 字段类型规则

金额字段统一使用：

- `DECIMAL(20,4)`

比例字段统一使用：

- `DECIMAL(20,6)`

编号类字段统一使用：

- `VARCHAR2` 或 `NVARCHAR`

## 8. 总表 10 行定义

总表明细固定初始化以下 10 行：

1. `DFPZZSY` 待分配增值收益
2. `DKFXZBJ_NCYE` 贷款风险准备金 / 年初余额
3. `DKFXZBJ_DNFP` 贷款风险准备金 / 当年分配
4. `DKFXZBJ_DNZC` 贷款风险准备金 / 当年支出
5. `DKFXZBJ_NMYE` 贷款风险准备金 / 年末余额
6. `GLFY_DNFP` 管理费用 / 当年分配
7. `CSLZZFBQZJ_NCYE` 城市廉租住房补充资金 / 年初余额
8. `CSLZZFBQZJ_DNFP` 城市廉租住房补充资金 / 当年分配
9. `CSLZZFBQZJ_DNSJ` 城市廉租住房补充资金 / 当年上缴
10. `CSLZZFBQZJ_NMYE` 城市廉租住房补充资金 / 年末余额

其中：

- 行 `15、20` 对应的两行是公式行
- 其余行根据自动来源或机构汇总结果生成

## 10. 详细业务逻辑

## 10.1 初始化逻辑

1. 市中心创建年度主单。
2. 系统为总表初始化 10 行明细记录。
3. 系统按机构初始化附表行。
4. 附表默认状态为草稿。
5. 自动来源字段先置空，待执行来源同步。

## 10.2 来源同步逻辑

### 待分配增值收益

- 来自本年度业务收支决算附表 `ZZSY`
- 市中心视角汇总后形成总表第 11 行
- 分中心仅能同步本机构对应值

### 两个年初余额

- 来自上一年度锁定快照中的对应年末余额
- 若上一年度无数据，则保留空值

### 同步原则

- 只刷新自动来源字段
- 不覆盖分中心已填写的原始事实值
- 同步失败时记录 `QSCWYY`

## 10.3 公式重算逻辑

附表重算：

- `DKFXZBJ_NMYE = DKFXZBJ_NCYE + DKFXZBJ_DNFP - DKFXZBJ_DNZC`
- `CSLZZFBQZJ_NMYE = CSLZZFBQZJ_NCYE + CSLZZFBQZJ_DNFP - CSLZZFBQZJ_DNSJ`
- `FPHJ = DKFXZBJ_DNFP + GLFY_DNFP + CSLZZFBQZJ_DNFP`

总表重算：

- 每个项目 `BNSJS` 取附表所有机构对应字段汇总
- `TBZZ = BNSJS / SNSJS - 1`，若 `SNSJS` 为空或 0 则为空

## 10.4 提交流转逻辑

### 分中心保存草稿

- 允许在草稿或退回状态下保存
- 仅保存本机构原始事实字段
- 保存后维持当前状态为草稿或退回

### 分中心提交确认

提交前校验：

1. 已完成来源同步
2. 分配合计不大于待分配增值收益
3. 允许空值，但若填写则必须是合法金额

通过后：

- 当前机构状态改为 `已提交`
- 记录提交时间

### 市中心审核通过

- 将全部机构状态置为 `审核通过`
- 写入审核意见和审批时间

### 市中心退回

- 将一个已提交机构置为 `审核退回`
- 写入退回意见

### 市中心锁定

- 主表、总表明细、附表明细全部只读
- 状态置为 `已锁定`
- 生成导出快照

```java
    detail.setDkfxzbjNmye(nvl(detail.getDkfxzbjNcye())
        + nvl(detail.getDkfxzbjDnfp())
```

```java
void validateBeforeSubmit(ProfitAllocationFbDetail detail) {
    if (!"1".equals(detail.getQszt())) {
        throw new BizException("请先完成来源同步后再提交");
    }
    if (nvl(detail.getFphj()).compareTo(nvl(detail.getDfpzzsy())) > 0) {
        throw new BizException("分配合计不能大于待分配增值收益");
    }
}
```

## 12. 数据流转说明

## 12.1 输入来源

- 业务收支决算附表 `ZZSY`
- 上一年度增值收益分配锁定快照年末余额
- 分中心填写的本年分配事实值

## 12.2 中间处理

- 来源同步服务刷新自动来源字段
- 公式服务重算年末余额和分配合计
- 汇总服务汇总全市值并生成总表明细
- 流转服务控制草稿、提交、退回、通过、锁定状态

## 12.3 输出结果

- 总表接口：`main + details(10 行)`
- 附表接口：`main + details(机构数组)`
- Excel 导出：严格按总表、附表原结构输出

## 14. 开发注意事项

1. 前端必须区分自动来源字段、公式字段和原始录入字段，不允许混成同一编辑状态。
2. 同步来源不能覆盖分中心已保存但尚未提交的原始事实值。
3. 导出时要按 Excel 原表还原“项目 + 说明”双层结构。
4. `当年上缴` 后续若接入线上上缴流程，应通过扩展表或流水表补充，不建议污染主报表明细表。
5. 所有成功状态对外反馈前，都要先完成重算、汇总和最新校验。
