## 一、C1 三问的书面结论（区分「已同意」与「推荐」）

> 判定规则：**「已同意」= 业务方书面确认（确认人、选项、修订、日期、范围）并回填本记录**；**「推荐」= 提案，供确认，不得作为实施依据**。当前三问均只有推荐，没有已同意项。

### 问 1：是否只允许「指标/机构匹配 + currentRun 成功 + 产物完整 + 用户可访问」的来源？

- **结论状态：推荐（未获确认）**。
- **推荐结论**：是。首期 LLM 预测的训练来源只允许**同时**满足以下四项的**自动训练产物**：
  1. **指标匹配**：候选 `indicator_code` 与预测页当前四指标（jcje/tqje/dkff/dkhs）之一一致，且规则任务数据集的 `indicator_type_code` 与当前指标一致；
  2. **机构匹配**：规则任务数据集的 `institution_id` 与当前预测机构一致；
  3. **currentRun 成功且产物完整**：`task.current_run_id` 所指 run 状态为 SUCCEEDED、task 状态为 SUCCEEDED、artifact 按 taskId 存在且 `artifact_hash` 非空，来源身份链（候选固定版本、taskId、runId、snapshotHash/requestHash）可回显；
  4. **用户可访问**：当前操作人按既有属主/授权策略可访问该任务。
- **理由**：默认提示词与预测结果具备可审计来源；避免「列表看得到即可执行」和 currentRun 切换后误用旧产物；与用户要求「使用所选训练来源」一致，消除原型本地拼接默认来源的问题（原型证据 P:1091–1100/1168）。
- **必须同时记录的事实缺口（不是业务可「同意」消除的技术现状）**：当前 `LlmRuleTaskOwnership.matches` 恒返回 `true`（源码注释：「内部程序：不做数据归属校验，任何操作员均可访问/操作任意任务」），`LlmCandidateServiceImpl.requireUser` 亦为空实现。即第 4 项「用户可访问」**目前没有代码级强制**，属实现缺口，须在来源准入功能实现前补齐属主/机构授权校验，不能把现状当作已满足。
- **替代方案**：A. 放宽为同指标不限机构（不推荐，跨机构数据风险）；B. 同时支持从训练页携带来源进入基础预测并做二次验证（推荐与来源选择并存）。

### 问 2：无有效来源时是阻止还是允许自定义模式？

- **结论状态：推荐（未获确认）**。
- **推荐结论**：**阻止**该指标的 LLM 预测执行，并给出明确原因（无来源 / 来源失效 / 模板缺失 / hash 不一致 / 指标或机构不匹配 / 无访问权限）。禁止静默选最新候选、禁止回退到算法预测冒充 LLM 结果。「无产物自定义预测」是**独立新模式**，须另立授权连接、数据范围与固定约束，来源标「自定义」；不得伪填训练 run/hash，不得隐式开启。
- **理由**：防止无来源时把算法结果或本地演示逻辑冒充满来源 LLM 结果；失败必须可见、可解释。
- **替代方案**：允许「无产物自定义」独立模式（需独立契约与验收）；缺模板时允许手填（须明确此时是否仍要求完整有效训练来源，不能把「可编辑」自动解释为「可绕过训练来源」）。

### 问 3：人工产物与历史 run 是否保留兼容分支？

- **结论状态：推荐（未获确认）**。
- **推荐结论**：首期两者**均不作为默认提示词来源**，但保留显式兼容分支的决策空间，且若准入必须与自动产物显式区分：
  - **人工登记产物**：独立来源类型，**不等于成功训练产物**。若准入，必须显式标注「人工登记」，并受其既有约束（任务必须 DRAFT 且零运行、ruleJson 必填、promptTemplate 可空、字段长度上限 65535），另行确认审批策略与完整性校验；**不能按 JSON 外观判断来源类型**。
  - **历史 run**：可另行准入，但必须按该 run 自身的不可变规则/模板/快照与 hash 取用，**不能用 task 当前 artifact 冒充历史产物**。推荐首期只接受「提交时仍为 currentRun 的成功来源」；历史来源在提交时锁定，陈旧刷新后重新选择。
- **理由**：人工产物与历史 run 的身份链不完整（无 runId/requestHash 或非当前权威 run），直接准入会把「演示/草稿」混入「可执行训练来源」。
- **替代方案**：首期直接允许历史成功 run 或人工产物（须先完成只读进一步核定：不可变证据、hash 完整性、审批策略）。

## 二、自动产物与人工产物的准入差异（已核实源码事实）

| 维度 | 自动训练产物 | 人工登记产物 |
|---|---|---|
| 写入时机 | run 执行成功终态**原子提交**（`LlmRuleRunServiceImpl.java:443–452`） | 人工登记入口 `saveRuleArtifact`（`LlmCandidateServiceImpl.java:405–427`） |
| 前置条件 | task 为 RUNNING、`run.id == task.currentRunId`、artifact 槽为空、CAS 全部成功，随后 task/run 置 SUCCEEDED | task 必须为 DRAFT 且运行数为 0（「已运行任务不可人工登记产物」） |
| 内容约束 | ruleJson / promptTemplate / metricJson / manifest 由执行生成；`artifactHash = manifest 哈希`（`LlmRuleRunServiceImpl.java:428–442`） | ruleJson 非空必填；promptTemplate 可空；各字段长度 ≤ 65535 |
| 身份链 | 自动携带五键 `instruction / promptTemplate / snapshotHash / runId / requestHash`（`LlmRuleRunServiceImpl.java:431–433`） | 无 runId / requestHash；不能冒充成功训练产物 |
| 读取关联 | `findDetailSnapshot` 以 `r.run_id=t.current_run_id AND r.task_id=t.id` 取权威当前 run，artifact 按 taskId 关联（`LlmRuleRunMapper.xml:29–46`） | 同一 artifact 槽位按 taskId 读取（`findArtifactByTaskId`），**不区分自动/人工来源** |
| 指标/机构事实链 | 候选 `indicator_code`（`LlmCandidateMapper.xml:34`）→ task.datasetId → 数据集 `indicator_type_code` / `institution_id`（`DatasetDO.java:45–52,126–130`） | 同左（人工产物仍挂在同一 task/dataset 上） |

**准入差异的业务含义**：人工产物即使通过同一读取接口返回，也不具备「currentRun 成功 + 完整身份链」，若纳入来源列表必须以独立来源类型显式标注并单独设限；当前 artifact 槽位与读取 SQL 均无来源类型字段，「自动/人工可可靠识别」属工程待实现项。
