# 项目长期记忆

## 1. 记忆库定位

- `doc/记忆库` 是 Gjj 工作区跨 Agent、跨会话共享的长期记忆事实源。
- 所有 Agent 均可直接读取 Markdown 文件，不要求绑定某个专用插件。
- RAG 索引只作为检索加速层，可随时基于 Markdown 重建。

## 2. 当前接入基线

- 已选择 MemSearch 作为首个 RAG 检索实现参考。
- 已安装 `memsearch==0.4.4`。
- 记忆源从 `.memsearch/memory` 调整为 `doc/记忆库`。
- 本地索引建议使用 `/home/source/.memsearch/gjj-doc-memory.db`。
- 推荐 collection 名称为 `gjj_doc_memory_chunks`。

## 3. 稳定约束

- 不向记忆库写入密钥、Token、账号密码、私有连接串。
- 不把向量库、模型缓存、临时索引提交到仓库。
- 重要结论必须写明来源、验证状态和适用边界。
- 未验证内容必须明确标注“未验证”。

## 4. 已知状态

- 本地 ONNX embedding 首次索引需要访问 HuggingFace 下载 `gpahal/bge-m3-onnx-int8`。
- 当前环境曾出现 HuggingFace 请求 `Connection reset by peer`，因此 ONNX 端到端索引验证可能需要网络恢复后再执行。
- `memsearch[local]` 会引入 `sentence-transformers` 和大体积 `torch/nvidia-*` 依赖，不建议作为默认方案。

## 5. 签约类接口（单笔 + 批量）API 自动化测试流程

- 详见独立文档：`doc/记忆库/项目记忆/批量签约API自动化测试流程.md`（已扩展为单笔+批量两套流程）
- 自动化脚本：`D:\Probject\Gjj\scripts\plqly_caller.py`（纯标准库，顶层 `--flow single|batch` 选流程，`--mode` 选子步骤，`--dry-run` / `--encrypted-file` / `--insecure` 可调）。
- **模式选择（关键）**：调用必须显式指定 `--flow`；未指定时交互终端会主动询问，非交互环境默认 batch。Agent 侧：用户未明确单笔/批量时先用 AskUserQuestion 确认。
- **单笔签约链路**（单笔无需加密，明文账号）：
  - `POST /api/v1/ywgl/getDbqyMessage` 单笔签约
  - `POST /api/v2/ywgl/getQyztcxMessage` 单笔状态查询（路径在 `/api/v2/`，仅用账号身份 yhdm/zh/hm/zjlx/zjh/jyzhlx/zhlx，无 ywslbh/ywlsh/密文）
  - 依赖：签约返回 HTTP 200 后再查；`--mode both` 已内置此顺序。文档：`6b40ac4cd879000`(签约) / `6b40ae094070000`(状态查询)
- **批量签约链路**（批量必须加密，`gjjZipData`）：
  - `POST /api/v1/ywgl/plQyJysq` 批量签约 → `POST /api/v1/ywgl/plQyJyZtcx` 结果查询（同 ywslbh/ywlsh）→ `POST /api/v1/ywgl/plQyJyMxXz` 明细下载（`pczt=1/2` 时）
  - 加密字段名 `gjjZipData`（非图片 OCR 误读的 `gjjzjlpotdc`）；文档示例的 `"$schema":"替换银行编号"` 是泄漏描述，非真实字段。
- **yhdm 必须是 6 位**：工行 `102000`、农行 `103000`。脚本对非 6 位 yhdm 会拦截并提醒是否给错（需 `--force` 强制）；早前口头说的 `10200`(5 位) 已确认为错误值。
- 固定字段（渠道/机构/网点/系统级，用示例默认值）：`qdlx=01`、`qdbm=gt`(渠道编码，非银行)、`jbjgbh=0101`、`jbjgmc=市本级`、`wdbh/wdmc`(批量空串/单笔 null)、`xtlx=GJGL`、`ywjbjgbh=0101`、`ywqd=gt`。
