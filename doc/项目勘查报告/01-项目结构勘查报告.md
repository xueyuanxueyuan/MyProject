### 2.2 每个模块的四层结构

每个业务模块遵循统一的四层分包模式：

```
xxx-module/
  ├── xxx-basic-svc-api/      # API层 — FeignClient接口 + DTO
  ├── xxx-basic-svc-api-v2/   # API-V2层 — V2版FeignClient（部分模块）
  ├── xxx-basic-svc-busi/     # 业务层 — Service/Impl + Controller + Mapper/DAO/Entity
  └── xxx-basic-svc-app/      # 应用层 — Spring Boot启动类 + application.yml
```

**拥有 V2 API 层的模块**：
- `zjjs-ywgl`：YwglV2FeignClient + YwglV2Controller
- `zjjs-zhgl`：ZhglV2FeignClient + ZhglV2Controller
- `cwhs-jzgl`：CwhsV2FeignClient + CwhsV2Controller

## 三、模块间依赖关系（关键发现）

### 3.1 当前依赖拓扑

```
gm-agg (聚合入口)
  ├──→ ywgl-api (V1+V2) — Feign 调用
  ├──→ zhgl-api (V1+V2) — Feign 调用
  ├──→ cwhs-api (V1+V2) — Feign 调用
  ├──→ lcgl-api — Feign 调用
  └──→ sp-api — Feign 调用

ywgl-busi
  ├──→ ywgl-api
  ├──→ ywgl-api-v2
  ├──→ zhgl-api
  ├──→ cwhs-api
  ├──→ zjjs-core-common
  ├──→ zbkh-busi (直接依赖busi层！违反分层)
  ├──→ lcgl-api
  ├──→ sp-api
  └──→ 外部依赖（gjtq-jzgl, gjtq-ydzy, grdk-hk, wxzj-js...）

cwhs-busi
  ├──→ cwhs-api
  ├──→ cwhs-api-v2
  ├──→ zjjs-core-common
  ├──→ ywgl-api
  ├──→ zhgl-api
  ├──→ lcgl-api
  ├──→ sp-api
  └──→ 外部依赖

zhgl-busi
  ├──→ zhgl-api
  ├──→ zhgl-api-v2
  ├──→ ywgl-api
  ├──→ cwhs-api
  ├──→ sp-api
  └──→ 外部依赖
```

### 3.2 问题发现

1. **busi 层直接依赖其他模块的 busi 层**（如 `ywgl-busi` 依赖 `zbkh-busi`）—— 违反了"busi 仅依赖 api 层"的分层原则
2. **busi 层互相依赖**（ywgl ↔ cwhs ↔ zhgl 三个 busi 层之间有双向依赖）—— 形成循环耦合
3. **api-v2 与 api 高度重复**：每个 V2 接口与 V1 接口功能高度重叠

## 六、多地区/多渠道适配现状

### 6.1 已存在的策略模式

- **`RegionBusinessStrategy`** 接口（HSDWDM 地区码策略模式）
- **`WzStrategy`**：温州地区（HSDWDM=330300000000000）
- **`DefaultRegionStrategy`**：默认地区（北京110000000000000、临沂371300000000000等）
- **`RegionBusinessStrategyFactory`**：策略工厂（PostConstruct注册）

### 6.2 不足之处

1. **策略覆盖不全**：当前仅 `WzStrategy` 一个独立策略 + 默认策略，其他地区（枣庄、临沂、嘉兴等）也依赖差异化逻辑但未通过策略模式收敛
2. **策略粒度太粗**：一个策略处理所有业务方法，没有按业务领域拆分（收付款/转账/账户）
3. **多渠道缺失**：没有单独的渠道层（如网厅、柜台、政务平台、银行前置）
4. **代码中大量 if-else 散布**：在 `DefaultRegionStrategy` 和各 ServiceImpl 中仍有大量 `if (HSDWDM)` 条件分支

## 八、勘查结论

### 核心痛点总结

1. **代码体量过大**：37.7万行 Java 代码，仅 `YwglServiceImpl` + `CwhsServiceImpl` 两个文件就 3.5 万行
2. **上帝类反模式**：CwhsServiceImpl（21,633行）、YwglServiceImpl（13,218行）耦合了所有业务逻辑
3. **V1/V2 重复**：三个模块同时维护 V1 和 V2 API 层，路由不同但逻辑高度重复
4. **模块间循环依赖**：busi 层互相依赖，且出现 busi→busi 的直接依赖
5. **多地区适配不完善**：策略模式已有雏形但覆盖率低、粒度粗，多渠道未建模
6. **API 层接口过于庞大**：单个 FeignClient 文件（如 CwhsFeignClient）超过 2,600 行
7. **没有领域分层**：DDD 中的 entity/domain/service 混在一起，缺少明确的领域边界
