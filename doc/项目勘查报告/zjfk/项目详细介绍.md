## 1. 项目定位与阅读入口

`capinfo-gjj-busi-zjfk` 是住房公积金资金风控后端项目，围绕“数据采集 → 模型训练与比较 → 指标预测 → 流动性和收益测算 → 资金计划与报告”组织业务。它不是单独的模型算法包，也不是银行交易或结算执行系统。本次范围内没有前端页面工程，不能据此认定菜单、按钮权限和页面交互已经验证。

项目由 Java 业务服务与独立 Python 模型服务组成。Java 负责业务对象、审批、数据集、任务编排及报告；Python 负责训练、预测和流动性分布测算。Kubeflow/KServe 是另一条扩展集成路径，存在真实远程调用、模拟逻辑和未完成能力，必须与常规 Python 训练链分开理解。

推荐阅读顺序：本文 → `项目图谱.md` → `接口与数据索引.md` → 按证据定位源码。`knowledge-graph.json` 面向程序与 AI 检索；`项目架构.drawio` 可用于编辑架构图。

## 3. 业务域与功能地图

### 3.1 配置管理 pzgl

维护数据源信息、启用状态与业务标识键，支持连接测试。业务层通过数据源配置服务执行采集查询，并维护 Hikari 连接池缓存。源码包含密码加解密处理；本次没有审计密码算法或复述任何凭证值。

## 4. Python 模型服务与跨语言契约

### 4.1 服务分层

`start.py` 启动 `app.main:app`；FastAPI 主应用挂载健康检查、V1 模型、V2 模型和任务路由。V1 的 `ModelService` 保留 GRU 实现及流动性测算，V2 的 `ModelServiceV2` 使用工厂分发算法。实际注册类型为 GRU、LSTM、ARIMA、SVR、MLP。

深度学习实现位于 `models/deep_learning`，传统模型位于 `models/traditional`，通用基类与工厂位于 `models/base`。根目录 `train.py`、`predict/`、`scripts/` 是另存的脚本入口，不能仅凭文件名当作当前 HTTP 服务的执行链。

API Key 验证是配置控制的依赖；健康检查仅返回服务状态、版本和时间，不探测模型文件、业务库或外部服务。因此 `/health` 成功不足以证明训练和预测可用。

证据：`P/app/main.py:48`、`P/app/core/security.py:11`、`P/app/api/routes/health.py:7`、`P/app/services/model_service_v2.py:29`、`P/models/base/model_factory.py:1`。

### 4.2 训练请求与异步结果

1. Java 提交模型类型、机构、指标、数据传输对象和算法参数；数据通过 Base64 CSV 传输，不由 Python 从业务数据库采集。
2. V2 路由创建 `TRAINING` 任务，安排 `BackgroundTasks` 执行训练并先返回任务编号。
3. 服务解码数据，统一时间/数值列，清理、排序后调用模型 `train`。
4. 模型文件和评估图表生成后，任务结果保存 `metrics`、`charts`、`modelPath` 等字段。
5. Java 通过 V1 任务进度、结果接口读取状态并处理业务训练记录。结果响应还存在 `result` 外层封装。

这不是消息队列任务系统；请求接收、后台计算、文件落盘、Java 状态回写属于不同阶段，任意一阶段成功都不能代替全链完成。

证据：`B/mxgl/utils/PythonModelClient.java:68`、`B/mxgl/utils/PythonModelClient.java:121`、`B/mxgl/utils/PythonModelClient.java:191`、`P/app/api/routes/models_v2.py:70`、`P/app/services/model_service_v2.py:145`。

### 4.3 预测与流动性测算

预测输出主要为 `predictions[{date,value}]`，可含置信区间和评估指标。V1 使用请求提供的模型路径；V2 从路径解析类型后，依据机构、指标和类型重新构造实际路径。这种行为影响历史模型重现，不能默认用户传入哪个路径就必然加载哪个历史文件。

流动性链路为：输入历史流动资金 → 默认过滤非正数 → 对数正态拟合（位置参数固定为 0）→ KS 检验 → 蒙特卡洛模拟 → 10%、50%、90% 分位数和统计图表。它是统计分布测算，不是同时包含收益目标与现金约束的数学规划求解器。该接口同步执行，不创建训练任务。

训练、预测请求主要使用 camelCase；流动性请求使用 `liquidity_data` 等 snake_case。空样本或过滤后无数据会报错；小样本只是告警，结果适用性仍需业务与统计验收。

证据：`B/mxgl/utils/PythonModelClient.java:568`、`B/mxgl/utils/PythonModelClient.java:619`、`B/mxgl/utils/PythonModelClient.java:671`、`P/app/services/model_service_v2.py:274`、`P/app/services/model_service.py:757`。

### 4.4 文件存储与并发边界

- 任务编号采用 `task-UUID`，任务状态和结果分别写入数据目录下的 `tasks/`、`results/` JSON 文件。
- 单例和互斥锁作用于单进程；文件替换不是数据库事务，也不是分布式任务锁。
- `start.py` 读取 `WORKERS`，但实际调用 Uvicorn 时仍传 `workers=1`。
- 停止接口主要将任务标记为 `STOPPED`；所检索训练循环未发现配套停止状态检查，不能视为可靠中断计算。

- 模型路径按机构、指标、模型类型构造，未使用任务 ID 做版本隔离；同组合重复训练可能覆盖同一路径。
